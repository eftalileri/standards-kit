Scope: Every **MUST** row of the appointment lifecycle standard: time conversion, completion triggers, idempotency, timezone resolution order, the injectable clock, notification dedupe, the detach-time re-home that prevents orphaned work items, and the occupancy predicate that APL-M16 and APL-N9 name but no file previously defined.

## MUST (normative) — APL-M

| ID | Rule | Consequence | Verify |
|----|------|-------------|--------|
| **APL-M1** | localWallTimeToUtc (APL-D3) **MUST** be the only approved implementation for local `HH:mm` + date + IANA tz → UTC in appointment lifecycle code; **MUST** use DST-safe API (e.g. Intl-backed or timezone library with IANA data). | Bug — wrong instant | Static: a search for `setUTCHours` on appointment time paths returns zero matches, or each match is explicitly exempted in the architecture documentation with a reason |
| **APL-M2** | Create path: if GAPL1 YES, initial status **MUST** be `completed`; **MUST NOT** create `pending` when APL-D5 holds. | Bug | Inspect the create branch: start in past → persisted `completed` |
| **APL-M3** | If the owning timezone cannot be resolved after APL-M12 where APL-D3 is required, the handler **MUST** fail per APL-F1 — no silent UTC guess. | Bug / STOP | Review the unresolved-timezone branch: it returns a typed or structured error. |
| **APL-M4** | Expired predicate and duration resolution **MUST** treat only `durationMinutes == null` as unknown duration; `0` **MUST** be valid (APL-D7). | Bug | Inspect the predicate: duration `0` → end equals start; `null` + GAPL5 YES → complete path |
| **APL-M5** | Read-path completion **MUST** run for single-appointment read when in scope (APL-D10): if GAPL2 and GAPL4 and GAPL6, apply TR-1. | Stale status bug | Inspect the read path: only a single-record read after end → `completed` without requiring cron |
| **APL-M6** | Batch completion **MUST** exist when the product promises timely closure without read; **MUST** use batched timezone fetch per owning-entity id (no N+1 timezone fetch without a documented ceiling). | Ops / perf bug | Code review or static: batch map or documented query plan |
| **APL-M7** | TR-1 and read-path writes **MUST** be idempotent: second application **MUST** leave `completed` and **MUST NOT** double emit lifecycle side effects (use conditional update `status: pending`, or equivalent atomic filter ). | Bug | Review the conditional transition (`status: pending` in the transition filter) and its side effects; use a static check against an unconditional completed-status save only where the adopting project documents one and its limits (variable-status, cross-function and aliased writes remain review) |
| **APL-M8** | APL-F2 logs **MUST** include the event, the tenant or owning-entity key where applicable, and a correlation identifier per [logging policy](../logging-policy/logging-policy.md). | Ops bug | Inspect structured log fields |
| **APL-M9** | Decision / validation predicates **MUST** follow [decision function](../decision-function/decision-function.md): invalid input **MUST** throw or return a typed error; **MUST NOT** return `null` or `undefined` to mean invalid. | Bug | Type review; named decision files contain no `return null` on invalid branches |
| **APL-M10** | Products **MUST** document whether list endpoints omit read-path completion; if omitted, batch or client refetch **MUST** be sufficient for correct UX (no stale `pending` in detail without refetch ). | Contract bug | Architecture declaration plus inspection of the read/refetch path, or explicit N/A with reason in a Scope amendment |
| **APL-M11** | Notification dispatch **MUST** use timezone effective at dispatch time (GAPL3 note ). | Wrong gate bug | Inspect the dispatch path: timezone change + dispatch re-reads settings or invalidates cache |
| **APL-M12** | The scheduling timezone **MUST** be resolved in one documented, fixed order until the first non-empty valid IANA id: (1) an explicit settings field on the owning entity or tenant documented as authoritative for scheduling; (2) the persisted timezone on the owning entity itself when (1) is absent or empty; (3) only if the project documents an inference (for example from an E.164 phone number) to an IANA timezone, apply it when (1) and (2) fail; (4) if still unresolved, APL-F1 (STOP). **MUST NOT** reorder or skip steps per call site. | Bug / STOP | The architecture documentation lists steps (1)–(4) with field names; inspect the settings, entity, inference and unresolved branches → expected timezone or error |
| **APL-M13** | Appointment lifecycle notification enqueue / dispatch (create / update events gated by GAPL3 ) **MUST** be idempotent per business event : either a stable idempotency key (e.g. event type + record id + update instant, or a documented replay key) recorded before send , or a durable dedupe record (unique constraint or equivalent ) with a documented TTL or lifecycle. Retries **MUST** not create a second user-visible notification for the same event (APL-N5 ). | Bug | Inspect the duplicate-invocation branch and durable key schema per [idempotency](../idempotency/README.md) where applicable |
| **APL-M14** | nowUTC **MUST** be obtained from exactly one documented time source module (e.g. `getNowUtc()` / `clock.now()` ) used by all appointment lifecycle predicates (GAPL , expired checks , create past-start ) ; production uses system clock; any allowed fixed-time observation injects that same module. **MUST NOT** scatter raw `Date.now()` / `new Date()` for lifecycle decisions without going through that source. | Bug / nondeterministic clock | Static: a search for raw `Date.now()` / `new Date()` over the appointment lifecycle code shows only the time module or documented exceptions; inspect that the injected clock determines GAPL2 |
| **APL-M15** | Conditional — work-item ownership on actor removal. Actor detach (resign, removal, role change) **MUST** re-home every pending/unresolved item resolved to that actor to a deterministic fallback owner (defined by the adopting project) through the single assignment writer, before membership removal. Pending items include every stored assignment that will later create work for the actor (e.g. a paused recurring series' assignment), and every writer of such a stored assignment claims the same assignment fence as an appointment write. Unlinking an actor's account while their scheduling identity stays re-homes the same items to that identity, in the unlink transaction. Reassignment failure aborts detach. The fallback SHOULD be notified in their own language with a redirect option. Background settlement **MUST NOT** mask orphans; repair historical backlog once at the source, never add a skip/dead-letter marker state. | Bug — orphan work/infinite retry | Inspect every membership-removal caller's resolved-owner selection and reassign-before-remove ordering; no marker state. |
| **APL-M16** | Conditional — reassignment and resource availability. System orphan re-home **MUST** use the assignment primitive without interactive availability/conflict gating, even when the fallback is occupied. Keep every original time and permit genuine overlapping records through the existing overlapping-record display. **MUST NOT** auto-reschedule/find a free slot or enforce non-overlap uniqueness. | Bug — orphan remains or original time is lost | Inspect direct assignment delegation without availability calls/unique gates; same-slot display renders two or more records. |
| **APL-M17** | Conditional — shared-resource occupancy. One occupancy derivation **MUST** serve availability, warnings and query filters using APL-M1/D3 UTC instants and half-open `[start, end)` intervals; zero duration is valid. Updates exclude the moved item's exact identity. A move **MUST** be measured by the moved item's stored snapshot, and every step of one move path — the offered slots, a hold and the write — **MUST** apply the same exclusion and measure, the excluded identity taken only from the server-resolved target (otherwise the offer and the write disagree, or a client frees another item's time). Its declared role is consistent across the consumers of one write path: advisory or hard gate, never both. The role is declared per write path: a path with no human to acknowledge the advisory (an unattended public self-service write) **MUST** use the same derivation as a hard gate on that path only, and that gate **MUST NOT** spread to attended paths — nobody can accept a warning there, and a gate on attended paths would block legitimate parallel work. Advisory overlap **MUST NOT** become a write-blocking uniqueness constraint, including the APL-M16 re-home. On a fixed slot grid, a slot is occupied when an occupant's resource-holding interval intersects the slot window — never by equal start time or grid index, which silently frees slots once the grid's step or hours change; an interval that keeps the item running without holding the resource (a waiting segment) is part of its duration but occupies nothing, and the segment split **MUST** be snapshotted on the item at write time so later catalog edits do not move past occupancy. A hard gate that judges by slot windows **MUST** also refuse a resource-holding interval that lies outside every slot window (a tail shorter than one slot, a gap between slots) and meets another occupant's resource-holding interval — slot closure never sees that time, so the gate would double-book it. | Bug — wrong occupancy, self-conflict or blocked re-home | Inspect one shared import chain, UTC/half-open/self-exclusion inputs and consistent advisory/gate role; no advisory non-overlap index; no start-time equality or slot-index match in the occupancy predicate. |
| **APL-M18** | An instant of entry into a status set (e.g. "cancelled at") **MUST** be the server clock (APL-M14) of the write that enters the set, merged into that write by one stamp helper at every writer of the status, with the set read from the status rule table; a move inside the set **MUST** keep the first instant. It **MUST NOT** be derived from `updatedAt` or backfilled: an absent stamp is unknown and is left out of every fact built on it, and a fact over a window counts only the part written after stamping began, proven from the stored stamps. The model write seam all writers share **MUST** report a write that enters the set without the stamp as a registered system-class code on an unthrown carrier (see [logging policy](../logging-policy/logging-policy.md)), and let the write through. Reason: a writer added later silently loses the instant, and a proxy or backfilled value reads as a real fact. | Bug — lost or invented status instant | Census of the status writers (each merges the helper); the seam detector's record on a write that skips it; no `updatedAt` read for the instant. |

Stated enforcement limit for APL-M13: a static check can confine the notification scope component to its single authority. Event identity, durable-before-send ordering and dedupe-store constraints remain runtime and cross-file facts a static check cannot prove. A scope or fingerprint missing the event discriminator may silently replay another event ([IDEMP-M17](../idempotency/replay-authorization-and-intent-binding.md)). The transaction-dispatch fence ([TX-M-12](../transactions/transaction-policy.md)) prevents callback retries from resending; it does not prove per-event dedupe.
