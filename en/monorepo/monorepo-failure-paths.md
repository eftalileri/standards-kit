## Failure path (normative)

Type or schema mismatch between client and server after a shared change -> **MRP-M5** — fix types or revert the break; must not ship a green build with undetected drift.

**Local package path unreachable to dependency automation (MRP-M1, BE-M13):** A `file:` dependency names an npm package directory containing the manifest for the declared package name, not an arbitrary source subdirectory. Keep the shared source root and package metadata root distinct when the former is nested: the package-manager link points at the nearest owning metadata root, while TypeScript and bundler aliases can point at the source root. Regenerate the consuming package's lockfile from its manifest; verify the root declaration, linked target, manifest name and installed alias together. For each dependency-update root, resolve local targets against its checked-out tree and reject missing manifests, name mismatches, paths outside the checkout, or stale lock edges. A locally successful install alone does not prove that dependency automation can fetch the package metadata. This cross-file, manifest, and filesystem relationship needs aggregate validation.

**Shared validator runtime upgrade (MRP-M2):** When deployable packages import the same runtime schema but install its validator separately, pin the same exact validator release in each manifest and lockfile. One schema source does not guarantee one parse decision if library versions differ. Before upgrading, review changes to acceptance, normalization, and error output against affected shared fields, persistence validators, and supported clients. A compile-only pass cannot establish behavioral parity. Derive any length limit shared by persistence validation and client preflight from one exported authority, and make all validators count the same unit. In particular, changing string-length units while a persistence validator still counts UTF-16 units requires an explicit, coordinated contract decision; do not silently make the parser more permissive than the writer or stricter than installed clients. **Enforcement limit:** manifest/lock equality can be checked mechanically; semantic equivalence across vendor releases, persistence, and installed clients requires additional source and release-history review.

**Canonical string-length unit (MRP-M2, SSG-M16):** Every layer that bounds the same string — the input validator, the persistence validator, UI input caps, the response parser of installed clients and any sibling admin tool — counts in one unit. When the persistence layer and the platform’s native string length count UTF-16 code units (a JavaScript ODM `minlength`/`maxlength`, a mobile text input’s `maxLength`), the shared validator counts UTF-16 as well, even after a validator release switches its native length checks to Unicode code points. Implement the unit once, as a shared string-length procedure (maximum, minimum and exact checks) that emits exactly the native issue shape (issue code, bound, origin, inclusive/exact flags), so issue-code consumers and message mappings do not change; every string length bound whose floor exceeds 1 goes through it, while a floor of 0 or 1 decides identically in both units and may stay native. A parallel hand-written refinement per field is not the procedure — it is the drift the procedure removes. Measure after the same normalization the writer applies: when the persistence field trims, the schema trims before the length check, or a whitespace-only value passes the request gate and dies at write time. For a persisted field, the threshold lives in one exported constant that both the request schema and the persistence model read; a client preflight composes the shared field schema instead of copying it. An intermediate contract whose value is later copied verbatim into that persisted field (a queue or outbox payload) reads the same constant; a wider intermediate bound accepts work that can only fail at delivery and stays poisoned, and narrowing it is preceded by a read-only count of stored rows above the new bound. Moving to another unit later is a coordinated contract decision across persistence validators, installed clients’ response parsers and input caps, never a dependency bump. A sibling tool in a separate repository that cannot import the procedure carries it in its hand-synced contract mirror together with the mirrored thresholds, pins the same exact validator release as the authority, and binds its input caps and character counters to the same mirrored constant and measure; a version range there is the drift in waiting, because a fresh install silently changes the unit of every native bound. **Enforcement limit:** a native string length call written after the migration is not mechanically fenced — telling a string bound from a number or array bound on the same method name needs type information; review holds it, as does the manual mirror sync procedure for a sibling repository’s validator pin and procedure mirror.

**Out-of-band client that re-composes a server read-model (MRP-M1, SSG-M8):** When an independent client package — an owner-side tool, CLI or bridge outside the deployed server — rebuilds a composite read-model the server already composes (the same section fan-out, derived verdicts, a version tag, a section-failure shape), binding both to one shared DTO does not remove the defect: two producers still derive the value, and every derivation difference (missing versus explicit-`null` fields, raw error text versus a safe class identity, a copied version literal) is drift the type cannot see. Expose the server’s single composition through one read-only endpoint behind the same authorization boundary as its parts, and make the client relay the payload unmodified — no re-derivation, no local copy of any authority the payload already carries. The client then reads no contract field and needs no shared type; the shared type exists for the server producer and any consumer that reads fields. A relay also moves a section failure onto the server, where a contained failure is logged once through the category-derived background authority instead of disappearing into a partial payload. **Stated limit** (ENA-GV3): no lint rule or check detects a re-composition in an out-of-band package — a copied fan-out is ordinary code in a separate compiler root and no single file decides whether it duplicates a server derivation; review holds it.

**Type-only contract across independent compiler roots (MRP-M1/M5, BE-M13):** Keep the authored TypeScript contract in the shared source root. When a consumer package's emitted entry layout requires a narrower `rootDir`, generate a declaration from that exact source before type-check and build; import the generated declaration as a type only. Treat it as ignored build output, never as an authored second interface. Keep the package's runtime entry and runtime-floor check intact. Aggregate validation may verify the source, declaration configuration, and command order; a single-file lint rule cannot prove generated-file provenance or build ordering. A generated declaration is only needed while the consumer genuinely reads the contract’s fields (see the out-of-band relay case above).

**Shared request preflight (MRP-M2):** A client may narrow a shared request body for immediate field feedback only by deriving that view from the shared request schema and its canonical field schema. The server may retain a shape-only body gate when a domain boundary must return a specific registered field error code; the domain check then consumes the same canonical field schema. Keep the two error paths explicit so tightening the transport parser does not silently replace the registered domain code.

When a project has a canonical schema for a shared entity field, the server enforces it and fails loud on a divergent value, and client consumers import that authority instead of defining local copies. Client-local duplicates are held by review.

Runtime schema output permits explicit `undefined` where the shared DTO requires omission -> **MRP-M12** — normalize at the shared schema boundary and re-run strict exact-optional compilation.

Cross-boundary closed enum values appear in more than one literal definition -> **MRP-M13** / **MRP-N9** — keep one shared runtime schema, derive type/options, and remove every parallel value list in the same change.

A consumer holds a list of some, but not all, members of a shared closed set → **MRP-N9**: declare an intentional subset with `satisfies`, not an element-type annotation. Both `const X: T[] = [...]` and `const X = [...] as const satisfies readonly T[]` check membership, but only the latter preserves the literal set and communicates that the list is a selection rather than a mirror. The annotated form is syntactically identical whether the author wrote every member or chose a few, so neither a reader nor any single-file check can tell a mirror from a selection; the annotation buys nothing else — it widens the members away from their literal identity and permits mutation. Keep the complete set in one authority, derive its union from that set, and let consumers import it. If a mirror check flags an intentional subset, that is not a false positive: the defect it names is the shape, not the selection, and the remedy is the `satisfies` rewrite at the source — not an inline suppression and not a narrowed predicate. A shape-only predicate can confuse legitimate subsets with duplicate authorities; anchor any check to the distinction it intends to enforce.

Shared DTO declares a field that the cross-tier bridge transformer never carries -> **MRP-M4** / **MRP-M1**. The field remains `undefined` at consumers while the types still compile, so the contract is only half-landed. A repair updates both the shared declaration and the bridge. This inventory applies when both tiers declare the field; a tier-local field or a consumer declaration of `never` has a different source/intent and must be classified explicitly. A cross-file check may compare both tier declarations with the bridge; a single-file rule cannot see all three. The check can prove that a field name is carried, not that it is mapped correctly, so semantic mapping still needs review. Pairs outside its resolution model (for example, local counterparts or transforms in another direction) must be reported as out of scope rather than silently skipped. A genuine finding must be repaired at its source, not suppressed to make the check pass, and such a check lands green only after the gaps it discovers are repaired first ([**FP-M18**](../false-positive/check-design-rules.md)). The exclusion channel is the consuming tier’s `never` alone — no second, comment-based suppression exists ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)).

An enforcement check prescribes a remedy the flagged file's layer cannot reach → **MRP-M9 / MRP-N7**. The finding may be valid while the suggested fix creates a forbidden upward dependency. A check whose message names a factory or helper in an application package can give unreachable advice when it also covers the shared package; the predicate does not inspect its own message. Keep enforcement and select the remedy by the flagged file's layer. A shared package should use its own layer-local typed carrier bound to the same authority, avoiding an upward edge. Derive the boundary from the carrier's placement rather than a duplicated path constant. Where sibling checks ask the same layer question, use one imported authority. Derive the layer boundary from the prescribed carrier’s own placement, never a path constant ([**FP-M33**](../false-positive/check-verification-rules.md)). Pulling the check’s scope back out of the shared package is not an admissible repair — it removes the bad advice by removing the enforcement. Review messages and configured scope as well as predicates; a clean baseline does not prove that future findings receive reachable advice.

Illegal cross-import not caught locally -> Treat as **MRP-M11** gap — STOP; add a rule to enforcement config before relying on manual review only.

Production client bundle contains backend modules -> Release blocked — bug (**MRP-M10**); fix graph and re-run analyzer.

Unclear which package owns a new file -> STOP — confirm with architecture or user (gray procedure).
