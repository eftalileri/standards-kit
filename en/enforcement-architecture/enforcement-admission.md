**Keywords:** enforcement cost, admission test, cost-benefit, make the wrong thing impossible, lint rule vs guard, stated limit, rule removal

Scope

- Included: The preference order for closing a bug class (ENA-P), the admission test every rule, guard or gate step must pass to be added and to be kept (ENA-A), and who decides, what the default answer is, and how an unenforced decision is recorded (ENA-GV).
- Excluded: What NOT to build ([enforcement-anti-patterns.md](enforcement-anti-patterns.md), ENA-N); how an admitted rule or guard is written ([enforcement-authoring.md](enforcement-authoring.md), ENA-R, ENA-G); gate pipeline shape and the rule lifecycle ([enforcement-gates-and-lifecycle.md](enforcement-gates-and-lifecycle.md), ENA-PL, ENA-LC); once a check is admitted, predicate and scope design, which the false-positive topic owns ([**FP-MS10**](../false-positive/check-verification-rules.md), [check-design-rules.md](../false-positive/check-design-rules.md)).
- Document type: Normative — **ENA-P1**–**ENA-P3**, **ENA-A1**–**ENA-A6**, **ENA-GV1**–**ENA-GV4**.

Binding principle: Enforcement is a cost, not a free good. Every rule, guard and gate step is paid for on every run, every refactor of the code it watches, every suppression and every review — and a check that a rename defeats also pays out false confidence. A check earns its place by passing **ENA-A1** and keeps it only while it still passes.

References: [README.md](README.md); [**ENA-R6**](enforcement-authoring.md) (three proofs); [**IV-M11**](../implementation-verification/change-acceptance-bar.md), [**IV-M13**](../implementation-verification/change-acceptance-bar.md) (only-better ratchet, stated-limit shape); [**KIT-INV-8**](../authoring/kit-structural-invariants.md) (stated limit); [**SSG-M8**](../ssot/ssot-principles-and-precedence.md) (one authority).

## Principles and preference order

| ID | Rule |
|----|------|
| **ENA-P1** | Make the wrong thing impossible first; check for it only when that cannot be done. A bug class is closed by the highest rung that closes it, in this order: (1) design, type or API that makes the bug unrepresentable — a branded or opaque type, a required parameter, a closed union, a single exported authority with no alternative path, one function that performs the gate and the effect together so neither can be called alone; (2) a row in an existing table-driven rule that already asks the same question ([**ENA-N2**](enforcement-anti-patterns.md)); (3) a new syntax-tree lint rule, for a condition decidable from one file — multi-line and contextual conditions included; (4) a cross-file script guard, only when no single file can decide the condition; (5) a stated limit (**ENA-GV3**). Choosing a lower rung **MUST** name why each higher rung cannot close the class; "it was quicker" is not a reason. |
| **ENA-P2** | A fence never replaces the authority it protects. A rule that keeps a second writer out is only as good as the single writer behind it; where the authority does not exist yet, create it first ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)). When a rung-(1) change later makes the class unrepresentable, the lower-rung fence becomes a cost with no benefit and is retired ([**ENA-LC3**](enforcement-gates-and-lifecycle.md)). |
| **ENA-P3** | Fixing the defect and fencing the class are separate decisions. Correcting the root cause is always owed, and a kit rule only when a new reusable rule was settled ([**KIT-ADD-12**](../authoring/kit-rule-addition.md)); a mechanical fence is owed only when **ENA-A1** passes. Leaving the class unfenced after a correct fix is not an unfinished task — it is the default outcome, recorded per **ENA-GV3**. |

## Admission test — adding AND keeping a check

| ID | Rule |
|----|------|
| **ENA-A1** | A rule, guard or gate step is admitted — and stays — only when ALL four conditions hold. (a) Real, recurring bug class, with evidence (**ENA-A2**). (b) Serious harm (**ENA-A3**). (c) No stronger mechanism already prevents it (**ENA-A4**). (d) Small cost (**ENA-A5**). Failing any one condition means the check is not built, or, for an existing one, is removed or merged ([**ENA-LC2**](enforcement-gates-and-lifecycle.md)). The test applies identically to a lint rule, a guard, a CI or gate step, and a row added to a table-driven check — a row is cheaper, not exempt. A project may define a documented baseline for maintained compiler, linter, formatter, or dependency-audit checks; any such baseline still must satisfy (c) and (d), and its checks remain subject to review and removal when they fail the admission test ([**ENA-N6**](enforcement-anti-patterns.md)). No locally authored rule, guard, gate step or table row is exempt from this test. |
| **ENA-A2** | Recurrence is measured, not argued. Evidence is (i) at least one real defect of the class — the commit or incident that fixed it and the pre-fix `file:line` — and (ii) a count of the live surfaces where the same mistake can be written again: call sites, authoring surfaces or files outside the authority that could reproduce the shape. A class with one historical defect inside what is now the single authority, and no other surface, is not recurring: the authority plus review holds it. A hypothetical ("someone might") is not evidence, and neither is a lesson converted from prose to a rule with no defect behind it. |
| **ENA-A3** | Serious harm must be tied to a documented harm category, such as financial loss, data loss or corruption, security or permission failure, cross-tenant exposure, a crash or loss of observability, or a user-visible defect (wrong text, broken flow, lost input). Style preference, naming taste, formatting, file or document tidiness, reading ergonomics of agent-facing documents, internal convention without a user or system impact, and bookkeeping that protects only other bookkeeping do not by themselves establish serious harm. A class outside the adopting project's categories may remain a review expectation without a mechanical fence. Policy exception: an authorized, standing decision in the project's governing documentation may classify a breach of a specifically named policy — a prohibited artefact class, a banned dependency source — as harm; cite that decision in the admission record, and still satisfy (a), (c) and (d). An ordinary task approval is not a standing policy decision. |
| **ENA-A4** | Search for a stronger mechanism before building a weaker one. Check, and record what was checked: the type system (does the wrong call already fail to compile?); the authority (is there any second path at all, or is the write reachable only through one function?); the runtime (does the server, the database or the production configuration already reject or neutralise it?); an existing check asserting the same predicate under another name. Search check bodies and their registration blocks by predicate, never by name — enforcers are often named for the symptom on one side and the remedy on the other — and confirm a found check really runs on the target class (expanded scope, blocking severity); a type that merely permits a field, or a schema that checks its shape, is not a single-writer fence. Any hit makes the proposed check redundant, and a redundant check fails **ENA-A1**(c); where the same operation escapes an existing check through another syntax or file, that check's scope is extended instead of a new one written. A production runtime detector (for example a per-request repeated-read detector) is observability code governed by the logging and error policies, not a fence admitted under **ENA-A1**. |
| **ENA-A5** | Cost is four measured quantities, each against an explicit project budget. (i) Runtime share — the check's own time from the tool's per-rule timing or statistics output, or a guard's standalone wall time and peak memory, against the per-check budget declared with the adopting project's gates ([**ENA-PL3**](enforcement-gates-and-lifecycle.md)); if no budget exists, define one before admission rather than assuming a universal limit. The per-rule figure is written in the rule's header at admission. Only when a rule over budget is to be kept anyway — typically a type-aware rule, whose per-rule figure includes the checker's shared lazy inference — is its marginal cost measured: back-to-back uncached runs with the rule on and off, at least two alternating pairs. The pairs replace the per-rule figure only when every on-minus-off difference and the spread between repeated runs of one mode are under the budget; otherwise noise is never counted as zero and the per-rule figure stands. (ii) False-positive rate — findings on the clean tree at birth, and suppressions carried afterwards; a check whose live suppressions outnumber the true defects it has ever caught fails. (iii) Size and churn — source lines, configuration blocks, and how often the check had to change when the code it watches was refactored ([**ENA-N4**](enforcement-anti-patterns.md)). (iv) Bypassability — whether a rename, an alias, a second file or a moved function escapes it; a check that a routine refactor defeats buys false confidence ([**ENA-N3**](enforcement-anti-patterns.md)) and is justified only when the harm warrants the residual risk and cost. |
| **ENA-A6** | Every admitted check carries its admission record in its own header — never in a separate document ([**IV-M13**](../implementation-verification/change-acceptance-bar.md) applies the same placement to limits). The record names four things: the class; the defect commit that fixed a real instance (**ENA-A2**); the harm class (**ENA-A3**); and the known escapes (rename, alias, second file — the stated-limit shape of [**IV-M13**](../implementation-verification/change-acceptance-bar.md)). The per-rule time of **ENA-A5**(i) sits beside it. The stronger-mechanism search, the rung choice and the three proofs ([**ENA-R6**](enforcement-authoring.md)) are done at admission and carried by the change record, not the header. A proposal without the record is rejected at review. |

## Governance

| ID | Rule |
|----|------|
| **ENA-GV1** | The default answer to "should this fix become a rule?" is NO, unless **ENA-A1** passes. After every fix the question is still asked — *could a check have caught this whole class?* — and then answered by the test, not by habit. A task that corrected the root cause and declined the fence with an **ENA-GV3** limit is complete. A rule elsewhere that says a class "**MUST** be locked" or "**MUST** be fenced" by a static rule or guard names the rung an admitted check takes; it does not admit the check — **ENA-A1** does, whichever statement is narrower ([**KIT-PRE-2**](../_meta/precedence.md) rung 2). Such a sentence is reworded when its class is next fenced, audited or unfenced ([**ENA-LC5**](enforcement-gates-and-lifecycle.md)(e)). |
| **ENA-GV2** | Any author may propose a check; no check lands without its **ENA-A6** record, and no new check identity lands where a table-driven one already asks the question — that is a row ([**ENA-N2**](enforcement-anti-patterns.md)). Any author may propose a removal with an audit record ([**ENA-LC2**](enforcement-gates-and-lifecycle.md)). Removing a fence whose harm class is security, money, data or cross-tenant additionally names the mechanism that now prevents the class, or records the owner's acceptance of the gap. |
| **ENA-GV3** | A kit rule is held by review unless it names its check. A rule enforced by a lint rule, guard or gate step names that check; a rule that names none is review-held, and no "not fenced" sentence is required. A check DECLINED by the admission test may record the failed condition in one sentence ([**IV-M13**](../implementation-verification/change-acceptance-bar.md)) where the decline would otherwise be re-argued. A rule that claims a check which does not exist, or no longer fires, is a defect. |
| **ENA-GV4** | Existing enforcement that fails this standard is a removal item, not a licence to stop running it. Until a dedicated removal change retires it through the checklist in [**ENA-LC5**](enforcement-gates-and-lifecycle.md), a live rule, guard or gate step keeps running and its upkeep — regenerating an artefact it checks, answering its findings — stays binding. Nothing is disabled ad hoc to make one change easier; a kit clause that still mandates or describes such a mechanism is updated in the same change that removes it. |
