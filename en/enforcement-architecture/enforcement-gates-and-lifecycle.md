**Keywords:** fast feedback gate, complete verification gate, lint cache, formatter cache strategy, formatter scope, incremental analysis, parallel gate, gate time budget, verified autofix, safe-fix allowlist, rule audit, sunset, merge rules, removal checklist

Scope

- Included: How gates are shaped and budgeted and how an autofix run is verified (ENA-PL), and how every rule and guard is audited, merged, retired and removed (ENA-LC).
- Excluded: Which gates a repository declares and their exact membership ([**BE-M20**](../build-environment/build-environment-repository-and-scripts.md)); whether a check is admitted ([enforcement-admission.md](enforcement-admission.md)); retirement of a kit rule identity ([kit-rule-retirement.md](../authoring/kit-rule-retirement.md)).
- Document type: Normative — **ENA-PL1**–**ENA-PL6**, **ENA-LC1**–**ENA-LC5**.

Binding principle: A gate that takes long enough to be avoided enforces nothing. Gate time is budgeted like any other resource, measured on every change of the pipeline, and paid back by removing what no longer earns its place.

References: [README.md](README.md); [**BE-M20**](../build-environment/build-environment-repository-and-scripts.md) (two declared gates); [**FP-M25**](../false-positive/check-verification-rules.md) (a body no gate runs); [**DCD-M2**](../dead-code/dead-code-rules.md) (delete the superseded path in the same change); [**KIT-INV-8**](../authoring/kit-structural-invariants.md) (stated limit).

## Gate pipeline

| ID | Rule |
|----|------|
| **ENA-PL1** | A fast, scoped gate may provide early feedback. Use content-hash caching, incremental analysis, and input-aware guards ([**ENA-G3**](enforcement-authoring.md)) where supported and safe. Keep cache artifacts outside tracked source unless the project intentionally versions them. Its purpose is to catch local mistakes early; it does not replace the project's required complete verification gate. |
| **ENA-PL2** | The project's complete verification gate must cover all required checks and preserve their results. Disable caching where dependencies or cross-file inputs make invalidation unsafe — a changed type or a changed second file does not invalidate the cache entry of the file that depends on it. Run independent steps under an orchestrator with bounded concurrency when measurement supports it; preserve every child exit status and fail if a required child fails — no shell operator that masks a status. It never waits without bound: a step that exceeds a hard per-step limit, or whose descendant still holds the output pipe after the child exited, is killed with its process group and fails the gate, because its output is incomplete; an interrupted or hung-up orchestrator kills its children's process groups rather than orphaning them. Remove steps whose coverage is wholly contained in another required step (linting the same paths twice, a typecheck that a build step already performs, an audit whose scope another audit contains) unless they provide a distinct needed result. The formatter is its own step, using its cache, since formatting is per-file and cache-safe ([**ENA-N8**](enforcement-anti-patterns.md)) — but only with a cache strategy proven to invalidate: before a strategy is trusted, a same-size edit to a file the warm cache already holds as clean must fail the cached check, because a tool can silently weaken a strategy it advertises. The formatter step covers the whole tracked source set its formatter can parse, minus generated, vendored and tool-owned files (lockfiles, reports, manifests whose layout the package manager writes); a newly admitted folder is formatted once under a verified run (**ENA-PL6**) and joins the step in the same change. A project-owned script that writes into the covered set (a translation sync, a code generator) passes its output through the formatter's API with the project configuration before writing; otherwise the next run of the writer turns the step red and its repair needs another formatting run. No check fences the strategy choice, the scope list or writer conformance; all three are held by review, and a non-conforming writer surfaces as a red step after its first run. Measure tool-level parallelism before adopting it, since it can increase work or resource use — worker-based linting can be slower with type-aware rules, because each worker builds its own type program. |
| **ENA-PL3** | Each gate has an explicit total time budget, and each check a per-check budget ([**ENA-A5**](enforcement-admission.md)(i)), declared with the gate's membership. The adopting project sets budgets to fit its tree, tooling and machines; do not assume universal time limits, and scale budgets in the same declaration, never per check. A change that pushes a gate over its declared budget must be compensated before adoption — make checks cheaper or remove those that fail [**ENA-A1**](enforcement-admission.md). |
| **ENA-PL4** | Measure a pipeline change by its total and by what changed. A change to a gate records the gate's total wall time before and after, and the time of each step it added, removed or changed, with the machine load beside each figure; before/after figures are compared on the same machine state. Unchanged steps are not re-measured. An unmeasured pipeline change is rejected ([**ENA-N17**](enforcement-anti-patterns.md)). |
| **ENA-PL5** | Gate membership has one declared authority, such as the project's orchestrator configuration. Avoid a separate guard that merely re-checks the same membership list ([**ENA-N10**](enforcement-anti-patterns.md)). When a CI provider or workflow is retired, map each required check to its replacement in the same change; do not silently drop coverage. |
| **ENA-PL6** | An autofix run is admitted by verification, not by trust in the tool — and a fixer that can change behaviour is never auto-applied. Where the adopting project's governing rules admit deterministic autofixers, every run is scoped to named files or paths, never the whole tree, and is proven by its class. (a) A pure formatter is proven layout-only per run: every changed code file's syntax tree (positions, raw literal spelling and comment whitespace excluded; template-literal and regular-expression raw text compared exactly) and every changed data file's parsed value equal the pre-run version, measured by an analysis-only comparison that writes nothing into source. (b) A linter's fixer runs only through one runner that dry-runs first, records the rule behind every offered fix in every fix pass, and writes — through the linter's own output writer, with no text edit of its own — only when every offer came from a rule on a safe-fix allowlist. The allowlist is one module; each entry names why its fixer preserves program behaviour, read from the fixer's source (binding-kind tightening, an equivalent pattern spelling); it is derived from the rules actually enabled with fixers and starts conservative — a fixer with any branch that changes scope, timing, a module's side-effect evaluation, a return value or an effect's dependency list stays out, and so does a rule whose safety rests on type information, a fixer that removes a statement's leading tokens without guarding automatic semicolon insertion (the next line can fuse with the previous statement into a call or a division), and a fixer that recognises a built-in by its name without checking that the name is not rebound in scope. An offer from any other rule refuses the whole run with nothing written; that change (an inserted `await`, a removed import) is a hand edit reviewed line by line. After either run the diff is read and the gate is green before anything is staged. The comparator and the runner are proven before they are trusted: the comparator flags probes with a changed template literal, pattern, comment text and data value and passes a whitespace-only change; the runner refuses a probe carrying one allowlisted and one non-allowlisted fixable violation and applies a probe carrying only the allowlisted one. Stated limit ([**ENA-GV3**](enforcement-admission.md)): allowlist membership is a semantic judgement about a fixer's source, which no check can make — review holds it; a fixer whose behaviour changes in a dependency upgrade is caught only by the post-run gate and the diff reading, so an upgrade of a linter or plugin re-reads the fixers of the allowlisted rules. |

## Lifecycle of a rule or guard

| ID | Rule |
|----|------|
| **ENA-LC1** | Admission evidence lives with the check for its whole life ([**ENA-A6**](enforcement-admission.md)). An ordinary edit of a check that has no admission record — a message, a refactor, a false-positive fix — triggers no audit. Widening its scope or adding a predicate (an arm, a row, a new trigger) does: the record is written and the check audited under **ENA-LC2** in that change. |
| **ENA-LC2** | Audit a check when its scope widens or a predicate is added (**ENA-LC1**), and whenever its gate exceeds its budget. Per check, measure: runtime share; live suppression count; the date of the last true finding (a real defect caught, not a suppression); resolved scope size; and whether the authority, path or model it guards still exists. A check that no longer passes [**ENA-A1**](enforcement-admission.md) is merged into a table rule (**ENA-LC4**) or removed (**ENA-LC5**) — "it has always been there" is not admission evidence. |
| **ENA-LC3** | Sunset a check when a stronger mechanism supersedes it. When a type, API or single-authority change makes the class unrepresentable ([**ENA-P1**](enforcement-admission.md) rung 1), the check it replaces is removed in the same change or the next one. Pairing the removal with the replacement is what keeps the class covered. |
| **ENA-LC4** | Merge families into table-driven rules. Rules asking one question with different subjects become rows of one rule ([**ENA-R3**](enforcement-authoring.md)), registered once; their suppressions move to the merged identity with row scope ([**ENA-R8**](enforcement-authoring.md)) in the same change, because a directive naming a removed rule identity is itself an error. A row is equivalent only when measured so. Run the retired rule and the row on the same pre-fix text and path; every arm the row does not reproduce is either restored or written as a stated limit ([**ENA-GV3**](enforcement-admission.md)). Two losses recur when a per-rule check becomes a generic row kind: an import-level fence turned use-level stops seeing an aliased re-export and a function passed as a value (the call then happens under a name the row never matches), and an owner-file exemption written for the full surface silently widens to a narrower row that should still see the owner's own file. A money or security arm is never dropped on the row's convenience. Code-shaped members keep their predicate verbatim: when each member's predicate is code rather than data (its own name classifier, polarity proof or runner recognition), the member becomes a row whose kind runs the retired rule's visitor body unchanged behind a small reporting adapter (the old rule's report call is translated to the row's report; old options come from the row), so the equivalence measurement tests only the reporting path and the merge buys one identity, one registration and row-scoped allows without re-deriving any predicate. A rule-configuration `ignores` entry exempting one file becomes a row allow in that file, where the reason is visible. |
| **ENA-LC5** | Removal follows one checklist, in one change. Delete: (a) the check's source and any internal helper it was the last user of; (b) its registration — plugin index, every configuration block, the guard runner's list, package scripts; (c) every suppression naming it; (d) every reference in other checks and scripts; (e) every citation in the standards and the authority registry — each cited identity that lost its only fence gets a replacement pointer or a stated limit ([**KIT-INV-8**](../authoring/kit-structural-invariants.md)(b), [**ENA-GV3**](enforcement-admission.md)), never a silent "covered"; (f) its rows in any inventory, regenerated where an inventory still exists. Verify: the lint run reports no unknown-rule definition errors, a repository-wide search for the identity returns only history, and the full gate is green. A body left in the tree unregistered is the unclosed state [**FP-M25**](../false-positive/check-verification-rules.md) rejects; under this standard, retirement is its default exit unless [**ENA-A1**](enforcement-admission.md) passes. |
