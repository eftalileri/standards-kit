# NoSQL query safety — silently ignored declarations, index correctness and destructive writes

```kit-cover
type: normative
part-of: README.md
binds: the NoSQL obligations whose failure mode is silence rather than injection — a partial-index expression the database skips without error, a projection prefix the ODM forwards verbatim so the field arrives empty, an unscoped or wrong-field bulk destructive filter, and an unbounded request- or fan-out-derived array reaching a query, bulk write or transaction, and a search predicate no index can bound on a growing collection
open-when: shape:backend-heavy, signal:mongo-query, signal:user-input-filter, signal:destructive-write
skip-when: signal:client-only, signal:no-database-query
owns: SEC-M-NOSQL-5, SEC-M-NOSQL-6, SEC-M-NOSQL-7, SEC-M-NOSQL-8, SEC-M-NOSQL-9, SEC-M-NOSQL-11
```

Scope

- Included: The NoSQL obligations whose violation produces no error at all: an index declaration MongoDB silently skips, a projection prefix the ODM forwards verbatim so the read reports success with an empty field, a bulk destructive filter that is empty, under-scoped or names the wrong field, an unbounded `$in` / bulk-write array whose size is decided by the caller, a constraint-conversion migration whose drop/recreate order leaves the uniqueness constraint absent for a window, and a search predicate that makes the database examine every key or document of a growing collection.
- Excluded: Operator injection at the boundary — Zod-first validation, the per-query `sanitizeFilter` layer, the global-`sanitizeFilter` prohibition, projection/`select` shapes taken from raw HTTP objects, the guard-outcome policy, the webhook carve-out and the **GSEC-NOSQL1** gate ([nosql-zod-and-sanitizefilter.md](nosql-zod-and-sanitizefilter.md)); webhook HMAC and trust model ([Security backend](../security/security-backend-controls.md), **SEC-M-WH-1**); server authz (**SEC-D3** / **SEC-M-ZT-1**).
- Document type: Normative — the **SEC-M-NOSQL-5**–**SEC-M-NOSQL-9** and **SEC-M-NOSQL-11** obligations.

Environment: Backend Node services using Mongoose (or documented equivalent Mongo driver) and HTTP inputs — the same environment as the entry file.

Binding principle: Each row below names a failure the driver, the ODM and the compiler all report as success. Because none of them raises, the only fence is the declaration or budget stated here — and where a check cannot decide the whole obligation, the row states that limit rather than implying coverage ([**KIT-INV-8**](../authoring/kit-structural-invariants.md)(b)).



References: [nosql-zod-and-sanitizefilter.md](nosql-zod-and-sanitizefilter.md) (**SEC-M-NOSQL-1**, **SEC-M-NOSQL-3** — the validated-boundary path these rows sit behind; **GSEC-NOSQL1** — the gate that still governs the query path); [Security backend](../security/security-backend-controls.md) (**SEC-M-BE-NOSQL-1** bridge); [Repository](../repository/README.md) (**REP-M-5** — persistence stays behind validated boundaries); [kit-structural-invariants.md](../authoring/kit-structural-invariants.md) (**KIT-INV-8**(b) — the stated-limit obligation two of these rows discharge).

## Silently ignored declarations, index correctness and destructive writes (normative)

| ID | Rule | On violation | Verify by |
|----|------|--------------|-----------|
| **SEC-M-NOSQL-5** | A partial index `partialFilterExpression` must use only the operators MongoDB permits there — equality (`$eq` / implicit), `$exists: true`, `$gt` / `$gte` / `$lt` / `$lte`, `$type`, top-level `$and`. Must not use `$ne`, `$nin`, `$not`, `$nor`, `$or`, `$exists: false`, `$expr`, `$regex`, or any other operator: MongoDB silently skips index creation (no error), so the intended unique / performance index never exists in production (e.g. a uniqueness guard that quietly does nothing). | Bug — a missing prod index is a silent data-integrity / performance failure. | A focused static rule on the `partialFilterExpression` object literal flags non-allowlisted operators, paired with a boot-time index audit. |
| **SEC-M-NOSQL-7** | An ODM projection prefix whose meaning is *"override the schema's default exclusion for this path"* (Mongoose `+path`) must name only a path the schema actually declares as excluded by default (`select: false`). The ODM rewrites the prefix into an inclusion only for such paths; for any other path the prefix is not understood and is forwarded to the database verbatim as a field name that cannot match (`{"+path": 1}`). Inside an inclusive projection the real path is then absent from the projection and the field arrives empty — with no error from the driver, the ODM, or the type system. The read reports success; what finally fails is the caller's own downstream invariant, far from the cause. A prefix on a path carrying no default exclusion is therefore never a harmless no-op: alone it collapses the projection to *"select nothing"* (the full document comes back, which hides the mistake), and the day one plain field name joins that same string it silently starts dropping data. The inverse obligation binds too: a path the schema does exclude by default must carry the prefix, or an inclusive projection naming it plainly returns it empty. | Bug — a silently empty field from a read that reports success; wrong totals, failed downstream invariants, or a 500 on every request touching the path, with driver, ODM and compiler all green. | Cross-file gate: every prefixed path in every static projection string resolved against the schema's default-exclusion declarations — a single-file AST cannot see the schema, and binding the scan to the call form (`select(...)` argument only) misses the same string once it is extracted to a constant. Confirm with the captured wire projection: the prefix must appear rewritten (`{"path":1}`), never forwarded (`{"+path":1}`). |
| **SEC-M-NOSQL-6** | A bulk destructive operation (`deleteMany`, `collection.drop`, delete `bulkWrite`) in domain code must carry an owning-scope filter (tenant / company / user id) — never an empty or under-scoped filter that can cross tenant boundaries. Where the goal is account / record removal, prefer de-identify (detach the owner reference, retain the record + downstream history) over physical delete when other entities still reference the data. | Bug — cross-tenant data loss / irreversible deletion. | Single-file AST rule, not grep (grep finds the call and cannot read the filter). In a cascade — the ordered list of per-collection deletions that erases one tenant — the rule asserts each call's first argument is an object literal carrying at least one declared scope key, and that in a branching filter (`$or` / `$nor`) every branch carries one: a single unscoped branch matches every document, so the union is unscoped. Two failure shapes it catches, both of which compile and neither of which raises: an empty filter (all tenants erased) and a wrong-field filter (nothing erased — the tenant's data survives as unreachable orphan rows that no read path can find). Filters passed as a variable or carrying a spread are undecidable and **MUST** stay silent. Declared limit: such a rule proves every written step is scoped; it CANNOT prove the inventory — that every tenant-scoped collection has a step at all. That is a parity question, and it is unanswerable because schemas carry the scope *field* but no "this collection is tenant-scoped" *marker*; a missing step appears in no syntax tree. Record the gap rather than implying coverage ([**KIT-INV-8**](../authoring/kit-structural-invariants.md)(b)). |
| **SEC-M-NOSQL-8** | Every request- or fan-out-derived Mongo `$in` array and bulk write array **MUST** be bounded by a canonical count budget before the query/write; each key **MUST** be schema-bounded, non-empty and duplicate-free. When arrays feed one atomic unit, package/appointment/update documents and replicated embedded entries such as payments **MUST** be aggregated rather than checked model-by-model. After bounded tenant-scoped preparation reads, the exact persistence documents/update payloads **MUST** be sealed against aggregate count and serialized-byte budgets before the first business/materialization mutation; an established transaction authorization/epoch fence may precede only as a rollback-bound control-plane security mutation. The terminal writer **MUST** enforce the actual aggregate document count and serialized-byte budget again before durable mutation. A project aggregate BSON budget is not the database's single-document BSON platform limit; the two constraints **MUST** be named separately. Sanitizing operators does not bound work, and a small HTTP body containing a huge integer can still expand into an unsafe array. | Availability/security bug — unbounded memory, CPU, command size or transaction work. | Boundary Zod + actor-independent domain revalidation + prepare/seal/flush aggregate assertion + terminal reassertion; static positive schema/domain/terminal dominance rule. |
| **SEC-M-NOSQL-9** | Converting an existing index into a unique constraint **MUST NOT** pass through a state in which the constraint is absent. Which path is available is decided by whether the target differs from the live index only in fields the database can change in place. (a) Same-signature conversion — key pattern, name, partial filter and collation unchanged, only `unique` differs — **MUST** use the in-place chain (`collMod prepareUnique:true` → `collMod unique:true, dryRun:true` → `collMod unique:true`), which never drops the index. (b) A conversion that must also change a signature field — above all adding or altering a `partialFilterExpression`, which `collMod index` cannot express — **MUST NOT** be written as "drop, then recreate". The target index **MUST** instead be declared under a name of its own, distinct from the legacy index's name, so it can be created while the legacy index still stands; the legacy index is dropped only in a later, separate step, after a fresh read proves the new index live. Name plus full spec live in one authority consumed by both the schema declaration and the migration — a migration carrying its own literal copy is a second authority ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)). The legacy index's accepted shapes **MUST** be enumerated and a shape outside that set **MUST** fail loud rather than be dropped. | Bug — between the drop and the recreate no uniqueness constraint exists; a duplicate written in that window becomes permanent, the following `createIndex` then fails, and the collection is left with no constraint at all. The window is invisible in review because both statements are present and both look correct. | Read the migration's DDL order, not its intent: no drop of a constraint may precede the create of its replacement. A focused single-file AST rule can enforce the DDL order and permit a drop only when addressed through an explicitly named legacy specification. Measure the engine's limits instead of assuming them; the following engine behavior was measured on MongoDB 8.2.1 and must be revalidated against the deployed server version: `collMod` carrying `partialFilterExpression` → error 40415 (`collMod index` accepts only `expireAfterSeconds` / `hidden` / `unique` / `prepareUnique`); `createIndex` reusing an existing name with different options → error 86; the same key pattern under two different names with different partial filters → permitted, which is exactly what makes the create-then-drop order available. |
| **SEC-M-NOSQL-11** | A query on a collection whose size grows with platform or tenant data **MUST** be bounded by an indexed equality or range prefix (the tenant key, a date range, another index prefix) before any predicate that cannot bound an index scan: an unanchored or case-insensitive `$regex`, a negation (`$ne` / `$nin` / `$not`), or `$expr` applying a function to the field (`$toLower`, `$substr`). A search that must stay fast without such a bound (platform-wide) **MUST** match a stored normalized key written by its single derivation authority (folded or lower-cased; reversed for suffix search; a word-token array for word-prefix search) by equality or an anchored, case-sensitive prefix on an index over that key. **MUST NOT** add the case-insensitive flag to a match on an already-folded key. Reason: the database silently examines every key or document, the cost grows with the collection and stays invisible on small test data. | Bug — latency and pool occupancy grow with the collection; with a request time limit ([BHE-M17](../backend-http-efficiency/outbound-call-time-budget.md)) the search starts failing as data grows. | Review-held: whether the preceding bound is a live index prefix and whether the collection grows are cross-file and live-topology facts a single-file rule cannot decide. Confirm with `explain('executionStats')`: an `IXSCAN` whose examined keys track the matches, never a `COLLSCAN` or an index scan over the whole key range. |

## Deciding a filter's field names — reach and stated limit

A check answering *"is every key in this filter declared in the model's schema?"* is the mechanical fence behind **SEC-M-NOSQL-6** and behind the retired-field residue it shares a failure mode with ([dead-code.md](../dead-code/dead-code.md)). Three facts decide its reach, each learned by measuring rather than reasoning.

The filter is not always argument 0. `distinct(field, filter)` puts it second. A check assuming a fixed position does not *report* the calls it cannot read — it skips them, so the blind spot is undeclared and therefore invisible. Enumerate the filter position per method.

A filter built in a variable is decidable when its initializer is an object literal. Later `m.x = …`, `Object.assign(m, …)` and spread only add keys, so the initializer's key set is a subset of the runtime one, and "this key is undeclared" is sound on a subset. Exactly three shapes break that property and **MUST** stay undecidable: reassigning the variable, `delete` on one of its keys, and a second declaration of the same name. Call results, conditionals, parameters, imported constants, dynamically imported models and aggregation `$match` stages remain out of reach.

Publish counts, not a share. The decidable/undecidable split moves with every commit, so the check **MUST** print its own numbers each run; a share written into prose is stale the next day and then reads as coverage. Measured when the variable arm opened here: 916 of 972 resolvable sites decided (834 literal, 82 resolved variable), 56 not — and that arm caught two live always-empty predicates on its first run, one of them a write.
