## **MUST NOT** (normative) — **BE-N**

| ID | Rule | Consequence | Verify |
|----|------|-------------|--------|
| **BE-N1** | Commit sensitive values (tokens, passwords, private keys ) in `.env`, `.env.local`, `.env.production`, or source files. Placeholders in `.env.example` are allowed. | Security class defect — must not ship ; STOP (GBE2). | Pass: `.gitignore` includes `.env` and `.env.local` (`rg '^\.env$|^\.env\.local$' .gitignore` or equivalent lines ) AND no high-entropy secrets in tracked `.env*` (manual / secret scan in CI recommended ). |
| **BE-N2** | Hardcode deployment URLs, API keys, or secrets as string literals in application source files matching `*.{ts,tsx,js,jsx}`. | Bug — must not ship. | Pass: Review `rg` over `src/` (or app root ) : no embedded prod URLs / long secrets except documented public endpoints ; `rg '(api[_-]?key|secret|token)\s*[:=]\s*[\"\\'][^\"\\']{8,}' src` exits 1 (zero matches ) where `src` is the application tree. |
| **BE-N3** | Disable TypeScript `strict` or commit production secrets to templates meant for public cloning (`.env.example` with real values ). | Bug / security defect — must not ship. | Pass: **BE-M1** Verify + `.env.example` must not match patterns like `*sk_live*` / `*_SECRET=*` with value length > 20 (use placeholder text only ). |
| **BE-N4** | Rely on untracked `.env` alone for CI without documenting injected vars (**BE-M9** / GBE3 ). | Process bug — must not merge. | Pass: GBE3 review on CI YAML. |
| **BE-N5** | Add new `process.env` reads without updating `.env.example` or `docs/environment-variables.md` (**BE-M4** ). | Bug — must not ship. | Pass: Same as **BE-M4** Verify. |
| **BE-N6** | Duplicate a value that must equal another across two `process.env` vars (for example an expected email / audience kept in its own var while the same value already lives inside a credential JSON or another var). Derive the dependent value from the single source instead. Two vars that must match will drift on a paste / whitespace error and cause a silent auth or comparison failure. | Bug — config drift → silent 401 / mismatch that is hard to reason about. | Review: no two env vars documented as "must equal X"; the dependent value is computed from the one source (e.g. parsed from the credential JSON) or trimmed + compared with a documented normalization. |
| **BE-N7** | Run divergent core-toolchain versions (for example TypeScript) across a monorepo's workspaces or between local and CI. A version skew breaks `tsc` config (`ignoreDeprecations`, `baseUrl`) and CI / build non-deterministically. Align / pin one version. | Build / CI bug — non-deterministic breakage. | Review: root + workspace `package.json` declare the same `typescript` (and shared toolchain) version range; CI uses the same. |
| **BE-N8** | Declare a gate’s scope by enumerating file names, or restate a source-extension set inside a glob/pattern instead of generating it from the single extension authority (**BE-M17**). Also **MUST NOT** treat a gate’s exit code as proof of coverage without separately establishing that the gate’s file inventory matches its directory authority — a green run over an empty or truncated inventory is the failure this row exists to prevent. The commonest cause of a truncated inventory is that the shell, not the tool, expanded the selector — and it is invisible to review. Package-manager scripts run under POSIX `sh`, which has no `globstar`: an unquoted `**` collapses to a single `*`, so a pattern written to mean *the whole tree* selects exactly one directory level while the script text still reads as recursive. Nothing in the tool’s output says so either — the unmatched files are not reported as skipped, they are never named at all, so the gate exits zero and the inventory it never opened is indistinguishable from a clean one. This is why the row’s second half demands a count and not a reading: a lint gate can select a few percent of the source files, hide real findings in the rest, and still be invoked by the deployment gate, so releases ship over them. Two repairs, in order of preference: pass the tool a directory and let its own configuration own membership, which deletes the second writer of the file set entirely ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)); or, where a pattern must stay in the script, quote it, which hands expansion back to the tool’s own matcher. A single `*` is not this defect — it expands as written and does not lie. | Silent enforcement loss — new or newly-extensioned files are never checked; must not ship. | Review: gate arguments are directories; a search for hand-written extension sets in scope declarations returns none; the tool-reported file inventory equals the directory authority’s list. Static: no package-manager script body carries an unquoted `**`, in every manifest of the repository and of each sibling repository the project declares; an unreachable sibling makes the check fail loud rather than report zero ([**FP-M19**](../false-positive/check-design-rules.md)). Limit ([**KIT-INV-8**](../authoring/kit-structural-invariants.md)(b)): a text check cannot decide whether a single `*` was meant to recurse — that is an intent no text carries — nor whether a script invokes a shell that does support `globstar`; both stay with review. |
| **BE-N9** | Weaken the declared type floor of a strict codebase from inside application source. **BE-N3** forbids turning `strict` off in the compiler configuration; this row forbids the same loss written one file at a time — an unconstrained escape type (`any` in TypeScript, or the language's equivalent) in a value, parameter, return, generic argument, cast or type predicate. Two uses are legitimate and **MUST** be written as such rather than as a bare escape: (1) an intentionally type-erased boundary whose whole purpose is to accept an unmodelled external shape — a transform/serialization seam — where the erased value **MUST** be validated or narrowed before any consumer reads it; (2) a driver/ODM query or update shape the driver itself types generically, which **MUST** use the driver's own exported generic (in a MongoDB codebase, `Filter<TDocument>` / the equivalent update type — see [repository-boundary-and-atomic-claims.md](../repository/repository-boundary-and-atomic-claims.md) **REP-M-4** for the persistence-side obligation), never a bare escape. Everything else is a violation, including "the shape is complicated", a third-party type that is merely inconvenient, and an escape added to make a gate green. A project that narrows or widens these two exceptions records the decision where its type floor is declared; the exception set is never widened silently. | The strict floor becomes nominal — the compiler stops checking exactly the paths where the modelling was hardest, and a wrong shape reaches runtime with the gate green; must not ship. | Static: a search for the escape type across application source returns only sites covered by exception (1) or (2), and each carries the validation/narrowing or the driver's generic at the same site. Review: for every remaining occurrence, name which exception applies and what reads the value next; "no exception applies" means the row is violated, not that a third exception exists. |
| **BE-N10** | Feed the result of a logical-AND (`&&`) chain into a nullish-coalescing (`??`) fallback. `&&` short-circuits to the left operand's own value, which is falsy but need not be nullish — an empty string, `0`, `false`, `NaN`. `??` only steps to its right side for `null`/`undefined`, so `(A && B) ?? C` silently keeps the falsy left value and the fallback chain never fires; the type system reports nothing, because the expression is perfectly typed. The prohibition covers the direct form and the one-hop indirect form (`const x = A && B;` … `x ?? C`); `A && (B ?? C)` is outside it — there `??` does not consume the `&&` result. Write the intent instead: `(A && B) \|\| C` when any falsy value must fall through, or make "no match" produce `undefined` (`A?.trim() ? B : undefined`) when absence is genuinely what is meant. This is the whole-codebase form of the same trap [decision-function](../decision-function/decision-function.md) M2 forbids inside decision functions; the two must not drift apart. | A fallback that cannot fall back — the value the author expected to be replaced survives, and the defect surfaces far from its cause (a name, label or amount that is simply empty on screen); must not ship. | Static: a single-file AST check over application source flags both forms; the direct form is also visible to a text scan, the indirect one is not (it crosses a `const` binding and often several lines), so a grep-only verification is a stated under-measurement, not a pass. Review: for each `??` in the changed diff, name the operand that may be falsy-but-not-nullish; if none can be, the row does not apply. |
| **BE-N11** | Carry one tier's module-specifier convention across a tier boundary. A native ESM runtime resolves a relative specifier literally — the extension is part of the path, and omitting it is a start-time failure the runtime does not forgive. An application bundler resolves the same text through its own algorithm, where the extension is normally omitted and adding one can miss the platform-specific variant it would otherwise pick. A repository that runs both therefore carries two conventions legitimately, and the prohibition is not on either convention but on moving a file across the boundary with its specifiers copied: they were correct at the old path and are silently wrong at the new one. Each tier states which convention it uses, at the tier boundary, so the rewrite is a deliberate step rather than something a reviewer must notice. Which extension each tier uses is the project's ([**KIT-LIM-7**](../authoring/kit-stated-limits.md)). | A module that resolves in one tier and not in the other — failing at start, or on one platform only, and never at the point where the file was actually moved. | Static: the type check and the tier's own start command both pass — an ESM-tier miss appears at start, not at build, so a green type check alone is not evidence. Review: every file moved across the boundary in the diff had its import specifiers rewritten to the destination tier's convention. |
| **BE-N12** | Leave a module's public shape to inference. A component's props, a store's state, and every exported function's parameters and return type are the module's contract, and a contract that is only inferred changes silently when the implementation changes: a field quietly widened to `string \| undefined`, a callback that gained an argument, a return that became nullable — none of it announces itself, and the first thing to notice is a caller failing at runtime. Declare those shapes explicitly (a named interface or type alias for a composite shape; an explicit return type where the value is exported), so a change to the shape is a change to a declaration a reviewer sees. This is deliberately about the public surface: a purely local intermediate value is left to inference, because there is no consumer whose expectation could drift. Naming a shape is also what makes it citable — a rule and a review can both point at a named contract and cannot point at an inferred one. | A contract that changed without anyone deciding to change it — every consumer must be re-read to discover what the module now promises. | Static: exported functions have declared parameter and return types, and composite props/state shapes are declared as named types; a strict compiler catches the missing-annotation half where the project enables it. Review: for each exported shape in the diff, its declaration is visible at the export site, not reconstructed from the body. |

## Failure-path and invalid state (normative)

| ID | Rule | Consequence | Verify |
|----|------|-------------|--------|
| **BE-F1** | If server bootstrap fails because a documented required variable is missing, the process **MUST** exit non-zero or throw with a message that identifies the missing key (align [error-policy](../error-policy/error-policy.md) when present ). Client-only repos with no Node server : N/A — state in README one line. | Bug — must not ship silent misconfig. | Pass: Static inspection / real-run observation or manual : unset one required var → process exits ≠0 OR throws (or N/A documented ). |
