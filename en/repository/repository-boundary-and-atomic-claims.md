## **MUST** — **REP-M-1** to **REP-M-11**, **REP-M-21**

**REP-M-1**: Repository modules must not read req.body, req.query, req.params, headers, or other raw HTTP objects. Callers pass already-extracted values. [Consequence: Architecture bug — merge blocked.] [Verify: Code review; grep req. under repository paths.]

**REP-M-2**: Repository functions must accept typed arguments only (DTOs, primitives, driver/ODM types). Inputs that originate from a transport boundary must be validated before the repository call using the selected schema authority. [Consequence: Security / contract bug.] [Verify: Signature audit; call graph from handler to repo.]

**REP-M-3**: All runtime database reads and writes for application CRUD paths must go through a repository (or single documented persistence facade module per aggregate with the same obligations). Direct ODM calls from controllers or routes are forbidden. Moving an existing direct call behind the seam is equivalence-bound, and the equivalence covers the query's OPTIONS — not only filter, projection, sort and limit. A per-call option (filter sanitization, read/write concern, collation, a session) hangs off the *call*, not the filter review compares, so a conversion drops it with nothing going red: same rows, same order, and the guarantee has no symptom until the input that needed it arrives. An option carrying a guarantee belongs to the seam ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)) — left with callers it is re-decided per call site, so each new caller is one omission from the unprotected half — but widening one to a seam's every caller is the scoped form of the hazard [**SEC-N-NOSQL-1**](../nosql-query-safety/nosql-zod-and-sanitizefilter.md) records globally, so it is justified against that seam's signature first. An irreversible multi-collection cascade, and a subject-keyed identity migration, follow the same seam split: the orchestrating module keeps only the ORDER, the fences and the per-step accounting, and every collection's write predicate is one named per-collection persistence function — the branded scope key for a scoped cascade, the subject key (never a scope key, **REP-N-4b** (d)) for an identity migration. A coverage check that inspects the orchestrator for "every keyed collection has a decision" measures the NAMED function the orchestrator calls (a declared delegate), never a model call written inline; and any check that requires an explicit scope key in each irreversible delete follows the predicate into the seam file, so moving the call never narrows the fence. Two conversion limits, each named where it applies rather than silently skipped: a write that another fence pins to one named file (a single-writer or terminal-seam rule that lists the owner file, or requires the real model in that file's body) stays in that file as a named facade — the persistence fence lists it as an explicit exemption with the reason, and a new scoped model call written into an exempt file is not caught; and a read whose predicate was shaped by a measured supporting index on the record's own identity key (an "is this record referenced anywhere" probe) takes no scope key when adding one would move the planner off that index — the function names the reason and the index note it follows, per **REP-N-4b** (d). [Consequence: Architecture bug — merge blocked; a dropped option is a guarantee lost in a refactor that reviews as behaviour-neutral.] [Verify: Code review; grep model .find / .aggregate from route folders; for each converted call diff filter, projection, sort, limit and options against the pre-conversion source.]

**REP-M-3** application — explicit returned document phase. An atomic update whose consumer needs the updated row declares that phase with the installed ODM/driver's supported option. When replacing a deprecated alias, prove equivalence from the installed adapter's conversion path: preserve filter, update, validation, transaction session, projection, hydration/lean and genuine null behavior. Choose before or after from the existing consumer contract, never from a global default or warning suppression. Do not add a second read to reconstruct the post-update row. No new rule or guard is required for this maintenance: the installed typed API documents the supported option and the existing persistence seam owns it; the type still permits deprecated aliases and is not claimed to prohibit them.

**REP-M-4**: Query filters and update payloads (replacement bundles or operator documents) **MUST** use precise types where the selected language can express their shape. In TypeScript, prefer the database driver’s exported generics instead of `any`; other stacks use their equivalent schema/type constraints. [Consequence: Maintainability or injection-risk bug.] [Verify: Run the selected type checker and static-analysis rules against query/update shapes.]

**REP-M-3** identity-migration seam note: When the terminal identity delete moves away from the orchestrator, preserve every same-unit prerequisite in the API before judging a file-local finding: only the orchestrator, after complete relationship resolution AND credential/device-binding migration, produces an opaque receipt binding the subject identities and the same transaction context. Export no standalone factory; the delete accepts that receipt alone, never a separate subject or context. A private symbol and frozen payload alone do not establish runtime authenticity: reflection, copied symbols or a fabricated object can substitute the payload. Keep the immutable subject/context tuple in a private association keyed by the ORIGINAL receipt object; the public receipt carries only a type marker. Reject an unknown object with a registered error before the physical delete. This object-lifetime provenance metadata is neither distributed state nor a substitute for durable transaction or shared-store authorities. The runtime API closes assertion escapes as well, so an additional producer-only assertion row for this receipt is not retained. A file-local check requiring the resolution or post-commit session cleanup beside the delete cannot see that cross-file proof and may carry a verified line-scoped explanation only after the actual cleanup delegate and both entry paths are read. Existing ownership rows replace the old model-writer path with the canonical seam, never retain parallel writers. No extra lifecycle-shape rule is needed: the receipt API plus existing model-writer fences covers the local prerequisite escape.

**REP-M-5**: Repositories that build document-database filters or projections from caller data **MUST** comply with the applicable query-safety standard, including MongoDB-specific rules when that is the selected datastore. Validate transport input with the selected schema-validation authority before repository calls; the repository never replaces that boundary. [Consequence: Security bug.] [Verify: Apply the relevant query-safety review and boundary checks to each caller-influenced query path.]

**REP-M-6**: Public repository methods **MUST** document each parameter and the persistence outcomes they may return, including an absent-record result where the contract permits it. Use the documentation format required by the selected language and follow the error policy at callers. [Consequence: Documentation drift bug.] [Verify: Review public method signatures and their documented outcomes.]

**REP-M-7**: On driver / ODM failure, must propagate failure to the caller (throw or rejected Promise) — no empty catch that continues silently on operational paths. Must not replace errors with HTTP-level semantic codes here (**REP-N-3**). For a write containing a live credential, "propagate to the caller" ends at the immediate sensitive-data-aware domain/service boundary: that boundary must prevent the raw driver error from continuing to API / logging / crash reporting and map it per security logging [**SEC-M-LOG-2**](../security/security-logging-core.md) / [**SEC-N-LOG-2**](../security/security-logging-correlation-and-fields.md); this does not authorize HTTP-semantic mapping inside the repository. If a try/catch exists to observe or log the failure, the operation must be awaited inside the try (e.g. `return await query`); returning a not-yet-awaited query/Promise (`return query`) makes the catch unreachable on async rejection, so the logging never runs and the catch is dead code — make it reachable (await) or remove it (dead-code policy DCD). [Consequence: Reliability or sensitive-data disclosure bug.] [Verify: Code review of catch blocks in repositories and their immediate domain callers; grep `return <Model>.<op>(` (no `await`) inside try blocks under repository paths.]

**REP-M-8**: When callers run work inside a service-managed database transaction per transaction policy (**TX-M-2**, **TX-M-3**, **TX-G2**), repository methods that perform reads or writes in that unit must accept a session (or documented driver client context) argument and must pass that same instance to every ODM/driver operation in that method that participates in the unit. The same method may take optional session (e.g. undefined outside a transaction) when the signature and TSDoc state that contract explicitly. [Consequence: Integrity bug — merge blocked.] [Verify: Signature audit; call graph from service vs **TX-G2**.]

**REP-M-9**: Projection, selection, and field-list arguments (ORM/ODM selection, projection, or equivalent) must be typed in the repository API — any is forbidden where the type system can express the shape (e.g. literal unions, Pick, shared projection types). Unvalidated path lists or raw strings from HTTP must not reach the repository without prior boundary shaping (**REP-M-2**); Caller-influenced document-database projections must also satisfy the applicable query-safety standard (**SEC-N-NOSQL-4**, GSEC-NOSQL1). [Consequence: Security / maintainability bug.] [Verify: Typecheck; review select / projection parameters.]

**REP-M-10**: Detachable optional references must not be resolved with eager join/populate when their absence carries meaning. A reference field is *detachable* when any write path in the system intentionally removes it (e.g. `$unset` / set-to-null while preserving the owning row as a historical ledger record). For such a field, eager resolution (`populate`, `$lookup` into a single field, ORM eager-load) collapses two opposite states into one value: (a) field absent — the intentional detach, a normal record; (b) field present but target row missing — a genuine referential-integrity defect. Read the raw reference, preserve the absent/present distinction, resolve targets with an explicit scoped query, and classify (a) and (b) as separate outcomes: (a) is an expected/business outcome, (b) is an integrity defect per [error policy](../error-policy/error-policy.md) severity rules. Consumers that gate an operation on "is this entity healthy" must read the classified outcome, never the eager-loaded value's truthiness. Detachable fields must be listed where the project's enforcement reads them (lint rule options, registry row, or equivalent). A REQUIRED reference whose target may be deleted by design (the owning row keeps its own snapshot of the target, e.g. an issued record referencing a deletable catalog row) **MUST** keep its stored id on an eager-loaded read: the eager load nulls the path, so the read seam restores the stored value (in an ODM, the populated-path check plus depopulate) before any consumer sees the row — otherwise the owner's list fails as "reference missing". A polymorphic reference (one field holding ids of more than one collection) **MUST NOT** declare a single-collection reference target nor be eager-loaded: the load nulls every id of the other kinds, so the stored value vanishes from every read; read the raw id and resolve each kind with an explicit query. [Consequence: Correctness bug — a normal record is reported as corrupt and downstream decisions (locking an entity, refusing a legal operation) become silently wrong; in the reverse direction a real dangling reference is reported as "no data".] [Verify: Grep eager-load of every field that some write path detaches; confirm each read site distinguishes absent vs dangling; single-file lint rule where the stack allows.]

**REP-M-11**: An invariant that gates a write on "related rows exist" must count only rows that still carry the relationship. When rows are intentionally detached (**REP-M-10**) but retained as history, a bare existence check (`exists({ parentId })`) keeps counting them forever and permanently blocks the operation it guards. The predicate must include the link field's presence (or the equivalent "still linked" condition), and its name must state the narrower measure. [Consequence: Correctness bug — an entity becomes permanently unusable after a legitimate cleanup, with no path back.] [Verify: For each guard of the form "no related rows", check whether the relation can be detached; if yes, the filter must require the link field.]

**REP-M-21**: A live-topology read **MUST** distinguish an expected missing namespace from a failure to read topology. Some databases report a documented missing-collection/namespace condition before a collection has been created. Where the database contract defines that signal as “no topology exists yet,” classify it as an empty topology rather than as an infrastructure error; other driver failures **MUST** propagate unchanged. The readiness predicate still rejects an empty topology when required structures are absent. Treating absence as satisfied would violate [**REP-M-19**](repository-boot-readiness-prerequisite-proof.md); treating it as an unknown driver failure hides the required operator action. Every migration and readiness gate **MUST** use one named classification authority rather than reimplementing it at each call site. A general catch is not a substitute. A model-specific topology adapter keeps its concrete driver read, options, local index-description type and signature while delegating collection-absence classification to the existing generic authority. Search duplicate classifiers by the decision itself, including both direct error-code comparison and a numeric-code-reader comparison; one spelling's zero count does not close the class. Preserve successful returned arrays and unknown rejection identity. An empty topology is not synthetic readiness: the existing caller owns prerequisite blocking, explicit migration planning or observability-only behavior. This delegation changes none of those policies or DDL/write authorities. No new classifier, broad fallback or implicit schema creation follows from reuse. [Consequence: An un-migrated deployment is confused with an unreachable datastore, or an absent structure is incorrectly treated as ready.] [Verify: The shared classifier recognizes only the datastore’s documented missing-namespace signal and rethrows other failures; readiness still rejects an empty result. Whether every topology read uses that authority is a cross-file coverage question.]

**REP-M-19** application — keep readiness questions independent. A shared persistence prerequisite (such as durable-store availability) and a service-specific rollout or authorization gate are separate questions and **MUST** have separately named authorities ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)). A writer’s requirement for durable persistence **MUST NOT** be hidden inside an unrelated feature or provider branch; doing so can make the same writer check readiness for one event class and skip it for another. Splitting authorities **MUST NOT** relax an existing fail-closed gate: preserve the original gate for consumers that require it and add the shared prerequisite where needed. A routing-only dispatcher need not perform the writer’s check. [Verify: For each call site, name the prerequisite it needs and its authority; review that no unrelated gate is the only path to a shared persistence check.]
