## **MUST** — **REP-M-12**, **REP-M-15** to **REP-M-17**, **REP-M-26**

**REP-M-12**: An external identifier used without caller scope to select a record for a later write **MUST** be globally unique by the external authority's contract and enforced by a durable unique constraint. If the identifier is only unique within a tenant or other scope, the lookup and constraint **MUST** include that authenticated scope; arbitrary first-match selection is forbidden. Where an immutable external business identity is retained while a separate current projection may change, preserve the identity-to-owner binding for its required lifetime and update the mutable projection only using an ordering/version rule owned by the external authority. Older events **MUST NOT** regress the current projection; equal-order conflicting identities fail closed. If records can contain identities from multiple external systems that do not share one comparable sequence, preserve each identity's source and environment separately; do not use a last-writer-wins field as the current authority. A duplicate, ambiguous owner, or unsupported transfer fails closed. A transfer or rebind requires an explicit, separately authorized domain operation and **MUST NOT** be inferred from a late event.

Adding a uniqueness constraint to existing data requires an idempotent migration. Before writes or DDL, inspect duplicates, conflicting historical bindings, and missing or ambiguous ordering evidence. Fail loudly without deleting, merging, reassigning, or guessing ownership; proceed only for data whose canonical owner can be proven. A declaration in an ORM/ODM model is not evidence that the live database has the constraint, particularly where automatic index creation is disabled. Verify the live constraint after migration. [Consequence: Security or integrity bug — an ambiguous identity is attached to the wrong owner, multiple owners, or a stale projection.] [Verify: Review the lookup/upsert filter, external identity contract, immutable binding/current-projection split, and declared constraint; exercise duplicate identities under different request keys and scopes, including out-of-order events; inspect live constraint topology after migration.]

**REP-M-15**: Each index migration **MUST** have one authority for preflight, create/modify/drop, and verification. Disable ORM/ODM automatic DDL for the migration connection so model loading cannot mutate topology before preflight or during dry-run. Load connection settings through the project's validated configuration authority; bypassing it risks selecting a different database or environment.

Every irreversible migration entry point **MUST** require an explicit, mutually exclusive execution mode before connecting or writing. Missing, unknown, duplicate, or conflicting modes fail before DDL; no default is a writing mode. Dry-run **MUST** perform no mutation, **MUST** run the same data and current-topology preflight as apply, and **MUST** report intended changes. It rejects same-name/different-key, same-key/noncanonical, and ambiguous drift rather than guessing. Compare ordered compound keys, canonical name, and every behavior-changing option; normalize omitted options only when the database contract defines their default. Document legacy topology precisely. Drop an obsolete structure only when its complete live shape matches the documented legacy form; after applying, read back and verify the complete target topology. Do not let another model, migration, or runtime initializer recreate an obsolete structure.

For MongoDB, when the server version and deployment topology support in-place conversion of an existing nonunique index to unique, use the supported nonmutating uniqueness-validation operation in dry-run and the documented prepare/validate/finalize sequence in apply; verify the final index inventory with a fresh read. Do not drop and recreate the index if that creates a period without the constraint. Server version, feature-compatibility level, topology, and operator privileges are external preconditions: prove them in the target environment. Unsupported or unauthorized in-place conversion fails loudly; do not silently fall back to a less safe operation.

A declared index is not a live index. When automatic index creation is disabled, each required index needs an explicit migration and live topology read-back; the database inventory, not the model declaration, proves what exists. A dry-run or backfill that only reports topology **MUST** remain DDL-free. [Consequence: Unreviewed production DDL, skipped duplicate preflight, destructive topology guessing, a constraint gap, wrong-environment selection, or a mutating/incomplete dry-run.] [Verify: One DDL authority; validated configuration; explicit mode before connection; dry-run/apply separation; full topology comparator; no unapproved drop/recreate; and mutation followed by fresh live topology verification. For MongoDB-specific uniqueness conversion, verify the supported server operation and privileges in the target environment.]

**REP-M-16**: A persistence reader that runtime-validates required stored fields **MUST** return a type in which those fields remain required. If a pure computation uses only a smaller projection, define a minimal projection type and let the validated persistence result extend it. Do not make a validated stored field optional merely to satisfy a narrower consumer or fixture. In stacks without compile-time structural typing, enforce the equivalent contract at the serialization boundary. [Consequence: Type-level loss of a proven persistence invariant lets downstream code treat malformed stored rows as valid.] [Verify: The reader's declared result retains every field its parser requires, while pure helpers accept only the fields they actually read.]

**REP-M-17**: Every configured enforcement scope for index DDL **MUST** use one canonical classification of operations that create, alter, or drop standard indexes. Include supported ORM/ODM methods and raw database commands; resolve aliases and bound arguments far enough to prevent indirect DDL from bypassing migration-mode and topology checks. An operation is nonmutating only when the database contract explicitly guarantees it is a validation-only form with an active dry-run setting; a call's name alone is not proof. Require the explicit-mode and topology contract on every recognized mutating path, and require a fresh same-target topology read after the mutation before a continuing path reports success. Dry-run proof requires successful completion on every path that can finalize; mere call presence or source order is insufficient.

A project may enforce these properties with stack-appropriate static analysis, linting, or generated inventory. The analysis should handle lexical aliases, bounded resolution, and control-flow paths without treating unresolved calls as safe. Keep dynamic commands and database features with different semantics outside the standard-index classification unless they are explicitly modeled. Configure exact governed source scopes, verify them against representative safe and unsafe cases, and report remaining scopes as uncovered; a clean subset does not establish repository-wide coverage. [Consequence: An indirect DDL spelling bypasses a declared safety contract while checks remain green, or an overbroad check blocks unrelated database operations.] [Verify: Exercise direct and indirect DDL, aliases and raw commands; dry-run and failure paths; success-dominance of post-migration read-back; scope boundaries and known false-positive/false-negative cases.]

**REP-M-26**: A declared index topology and the DDL that creates it **MUST** derive from one specification authority. The schema/model declaration and migration **MUST** consume that specification rather than duplicating key or option literals. If a migration loads its model dynamically after disabling automatic DDL, a source check based only on static imports may miss the relationship; verify the actual runtime binding or pass the specification directly. A dry-run may inspect topology but **MUST NOT** create it; only the explicitly selected apply path invokes the single DDL authority. [Consequence: Declared and live topology drift, or dry-run performs an unintended mutation.] [Verify: Trace the same specification into declaration and migration; verify the migration's runtime binding and confirm dry-run is DDL-free.]
