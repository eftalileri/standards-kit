## **MUST**

**REP-M-30**: A live-topology authority **MUST** derive the unexpected-structure verdict from the SAME reading that derives the missing-structure verdict, and the two **MUST NOT** share a severity. A declared structure absent from live topology represents a lost guarantee and belongs on the error/alert channel. A live structure with no declared owner is an unowned cost and belongs on the metric/warning channel. These are opposite results from one comparison — live topology against declared topology — so reading the listing twice creates two sources of one truth ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)); topology can change between reads and leave contradictory verdicts. Read once and derive both results from that snapshot; the derivation function **MUST NOT** issue another topology read.

The excess verdict must exist: an unowned structure may continue serving queries and enforcing a constraint, but it still imposes an undeclared operational cost. Measuring only missing structures leaves that cost invisible. The owned set is exactly the names in declared specifications ([**REP-M-29**](repository-boot-readiness-prerequisite-proof.md)); a specification without a name cannot be matched for either presence or ownership. Store-managed structures that are not user-managed drop targets are outside this comparison. A superseded structure still targeted by an active cutover migration remains owned until that migration removes it.

Severity follows the direction of the verdict, not a local estimate of impact. Sending excess structures to the error channel can obscure missing guarantees; sending missing structures to a metric-only channel hides an unenforced constraint. Do not let each caller invent its own impact test. Where several modules answer this question, they **MUST** use one shared predicate so both verdicts have identical semantics. The mirror obligation applies too: an undeclared live structure **MUST NOT** be promoted to the error channel merely because a caller considers it expensive. The authority measures only; it **MUST** neither create a missing structure nor drop an excess one ([**REP-M-19**](repository-boot-readiness-prerequisite-proof.md), [**REP-M-24**](repository-retention-and-irreversible-operations.md)). [Consequence: An unowned structure imposes ongoing cost while checks stay green, or separate topology reads produce contradictory verdicts.] [Verify: One topology snapshot derives both verdicts; the excess branch does not reach the error/alert channel and the missing branch does not reach metric-only reporting; neither branch creates or drops structures. Check reach: source code cannot establish whether every live structure has been declared or whether an unowned structure still has a valid consumer. Keep excess as a warning-class signal for resolution; do not treat it as automatic deletion authority.]
