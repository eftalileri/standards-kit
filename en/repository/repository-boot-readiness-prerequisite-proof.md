## **MUST**

**REP-M-19**: Runtime boot/readiness **MUST** prove persistence prerequisites from bounded exact topology and versioned durable markers; it **MUST NOT** rescan an unbounded business-data inventory. Full duplicate, ownership, history, or convergence scans belong to an explicit migration/postflight authority that writes a marker only after final read-back succeeds. Boot reads that exact marker and a fixed-size set of required index/coordination facts, then fails closed on missing, malformed, or mismatched evidence. A memoized readiness promise is only an in-flight deduplication mechanism: rejection **MUST** clear the cached promise so a later bounded refresh can observe recovered infrastructure. Readiness for independently gated subsystems **MUST** remain separately observable rather than collapse into one bootstrap boolean. The public health probe **MUST** answer only from in-process state with no database call, **MUST** be mounted before the rate limiter, CORS, body parsing and access log, and **MUST** publicly return only a status; dependency detail belongs only in an authenticated view. A degraded cache is not "down": it is reported as degraded and never fails the probe. A probe that touches a dependency turns that dependency's outage into a restart loop, and one behind the middleware chain is throttled or rejected exactly when the platform needs it; review-held (the mount order and the absence of a dependency call are read from the boot graph). An installation proof is not an ongoing existence proof. A migration's read-back establishes topology at that time, not that it remains present; where a guarantee depends on a single mechanism, disappearance must be detected. Recheck the prerequisite on every process start rather than inheriting success from the installer. The check **MUST** measure and **MUST NOT** install. Where automatic structure creation is disabled ([**REP-M-15**](repository-index-migrations-and-validated-reads.md)), allowing startup to create a missing structure makes boot a second DDL authority ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)) and conceals the absence it should report. A change that declares a new prerequisite **MUST** have its explicit migration applied and read back on the target before the declaring code is deployed there: deployed first, every start in between rightly reports the prerequisite missing while its guarantee is unenforced. A check whose subject cannot break the request path **MUST NOT** control a gate that can. Report readiness defects through the appropriate health/error channel without turning a contained background issue into an unrelated full outage. State where the signal is exposed so operators can actually observe it; a source projection alone does not prove that the operational consumer can read it. [Consequence: Backlog-proportional startup, stale poisoned readiness, hidden partial unavailability, a writer opening without migration proof, or a sole-mechanism guarantee disappearing without notice.] [Verify: Boot call graph contains no collection-wide scan; exact marker version and bounded topology inventory; rejection clears the cached promise; each gated subsystem is observable; the check performs no structure-creating call. The declared-spec-to-runtime-check relationship crosses modules and may require an explicit inventory or review; report any uncovered ownership as a known enforcement limit rather than implying full coverage.]

**REP-M-29**: Every declared persistence-structure spec **MUST** have a consuming authority, and the structure name **MUST** be part of the spec. Where automatic structure creation is disabled ([**REP-M-15**](repository-index-migrations-and-validated-reads.md)), a declaration describes intent but creates nothing. A spec referenced by neither an explicit DDL authority nor a live-topology reader has no owner: it is not created in a fresh deployment and its disappearance is not detected in an existing one. Ownership is determined from the consuming graph, not the declaration site or a filename. A spec is owned when a consumer outside the declaring layer participates in DDL or reaches the live-topology authority ([**REP-M-21**](repository-boundary-and-atomic-claims.md)); membership in a declared closed set may convey ownership when that set itself has a consumer. The spec **MUST** name the structure so it can be matched exactly against live topology. Ownership is also lost by retirement. Removing a declaration does not remove a live structure. A change that retires a field or declaration **MUST** transfer every structure keyed on that field into the removal specification in the same change, including single-field and prefix forms, and record the behavior-changing options from the live description. A removal authority must compare the exact intended target rather than guess from an obsolete declaration. Consolidating declarations behind a shared specification **MUST** preserve any checks that enforce key shape or options; re-anchor such checks at the same predicate strength instead of reducing them to a name-presence check. [Consequence: A declared constraint is never created or its disappearance goes undetected; an obsolete live structure is left unowned; or a removal targets the wrong topology.] [Verify: Cross-file inventory enumerates each declared spec and resolves consumers across DDL and live-topology layers; fail when a spec has no consumer or no exact name. State separately whether the consumer creates the structure or measures its live presence: ownership alone does not prove ongoing readiness. If source declarations change shape, verify that the ownership check still observes them.]
