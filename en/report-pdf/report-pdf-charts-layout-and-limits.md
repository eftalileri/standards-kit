## **MUST**

| ID | Rule | Consequence if violated | Verify |
|----|------|-------------------------|--------|
| **RPDF-M10** | Each chart must declare a stable spec binding, such as a named constant or enum member for its chart type. Dimensions, data contracts, and required labels follow the adopting product's authoritative chart specification; no chart may be orphaned from that specification. | Bug | Static: (1) search each chart component for the binding constant; (2) assert the value exists in the authoritative chart-spec table or shared spec map (binary pass/fail). |
| **RPDF-M11** | For each chart slot, if chart data is empty or chart rendering throws, the pipeline must render the mandatory fallback mini-table for that insight (same spec). No blank insight region. | Bug — incomplete PDF | Inspect empty/error chart branches: each renders the required fallback mini-table into HTML. |
| **RPDF-M12** | Charts, tables, KPI blocks, and prose must not overlap in the laid-out output: forbidden — unbounded negative margins, absolute positioning that collides with siblings, or overflow clipping that hides required labels. User-entered free text (notes) is never truncated: it keeps its typed line breaks and wraps an unbroken token (a URL) instead of widening the table past the page edge. | Bug | Inspect a real PDF for overlap/clipping and review chart/KPI CSS bounds. |
| **RPDF-M13** | CSS `page-break-inside: avoid` must apply to chart and KPI blocks per the adopting project's shared PDF styles / design system. | Bug | Static: the class list matches the design-system checklist. |
| **RPDF-M14** | Chart wrappers must set bounded width/height or max-width; SVG must preserve aspect ratio via `viewBox` per the chart specification. | Bug | Static: wrapper and SVG attributes present per the spec checklist. |
| **RPDF-M15** | Each chart must include the title, legend (when the spec requires one), and axis or category labels required by the chart specification for that chart type. | Bug | Binary checklist: for each chart type in the report, all spec-required elements are present in the template. |
| **RPDF-M16** | Adjacent explanatory text must use the same metric keys / series identifiers as the chart’s data contract for that section: prose must be driven from the same i18n keys or constants as the chart labels (single source object or shared enum). | Bug | Static: import graph — prose and chart read labels from same module or `messages` subtree. |
| **RPDF-M17** | Chart strings and adjacent prose must use the PDF `language` argument and the same PDF i18n module; no hardcoded locale mismatch between chart and text. | Bug | Static: single `language` prop threaded to both chart and caption components. |
| **RPDF-M18** | Single-page report block order must be: cover/header (brand, report title, owning entity, range, generated-at, filter chips) → KPIs → optional explainer (if defined for type) → charts → chart fallback tables → detail tables → footer (page number + generated-at from one helper). | Bug | Order enforced by single layout component or documented template — static read. |
| **RPDF-M19** | Page breaks must occur only between table rows or after a complete chart (or its fallback table) block — not through the middle of a chart or KPI card. | Bug | Inspect a real multi-page PDF: charts and KPI cards remain whole; table breaks fall between rows. |
| **RPDF-M20** | Multi-page PDFs must repeat a consistent footer (page number and generated-at) on every page, produced by the one shared page-footer template the engine prints into each page margin — not a single footer block at the end of the body. | Bug | Inspect a real multi-page PDF: every page carries the footer. |
| **RPDF-M21** | If the same metric appears in KPI and detail table, must bind one computed value from the report DTO to both surfaces — no independent recomputation. | Bug | Static: same variable/property referenced twice. |
| **RPDF-M22** | When a report service returns null, empty where non-empty is required, or throws, the PDF path must log and surface an actionable error (root cause + remediation) per [error handling](../error-handling/error-handling.md) / [error policy](../error-policy/error-policy.md) — no silent success with empty PDF. | STOP / reject — invalid API behavior | Static review: service failure path in orchestrator returns error, not buffer. |
| **RPDF-M23** | Before rendering, must validate required metadata: a non-empty owning-entity display label, a valid timezone (IANA or the project-documented catalog) where dates depend on it, currency code, language, and resolvable display labels for every active filter dimension (or no active filters). If validation fails, must throw or return a documented error — no PDF buffer. | STOP PDF generation | Static review: the validation path is documented; the guard gates before render. |
| **RPDF-M24** | Formatter module availability: The PDF pipeline must use a single documented formatters module (location per **RPDF-M5** / **RPDF-M8** or amended architecture). The currency formatter, the date-time formatter and the date-range formatter must be resolvable (static import resolves in the build or an explicit preflight import succeeds before render). Missing export, broken import graph, or undefined formatter at job entry must STOP the PDF job (no buffer) — not catch-and-continue with ad hoc formatting. | STOP / bug | Build: a compile check that imports the module; runtime: preflight or first-call failure → **RPDF-M22** path. |
| **RPDF-M25** | Single time source: The instant used for `generatedAt`, the report period bounds (start/end passed into the date-range formatter), and footer/header “generated at” timestamps must be produced once per job in one PDF time context object: either an injected `getNow()` / `Clock` or `now` captured at job start in the orchestrator and range bounds taken from validated request/filter inputs — then passed down to templates and formatters. Sampling a fresh `Date.now()` / `new Date()` in templates or ad hoc helpers for those fields is forbidden (**RPDF-N10**). Exception: Formatter implementations may construct `Date` only to format already-supplied instants (no new unsourced “now” inside formatters for generatedAt/range). | Bug | Static: document orchestrator path; search the template and layout layers for `Date.now` / `new Date(` — must be absent except via injected context props; orchestrator may use one capture site. |
| **RPDF-M26** | Critical insight slots (each chart/fallback region defined required for the report type in the chart specification or report contract): for each slot, at least one of primary chart or mandatory fallback table must render successfully. If any slot has both chart and fallback render fail (throw or empty mandated region), the entire PDF job must STOP (no buffer). If two or more slots each suffer that double-failure in one job, must log at error severity (operational signal). | STOP | Static: chart and fallback branches documented; no silent empty slot. |
| **RPDF-M27** | Resource bounds: PDF generation must enforce documented upper limits so execution is not unbounded — at minimum in architecture or this repo’s PDF module: (a) max row / cell count or payload byte budget per report type before render, (b) wall-clock timeout for the job, (c) failure behavior when exceeded (STOP, structured error per **RPDF-M22**). No silent truncation of money/identity rows without an explicit product rule documented next to the limit. | STOP / bug | Inspect read/render bounds and timeout propagation; a real over-budget request returns the registered failure without hanging. |
| **RPDF-M30** | Report PDFs are produced per output target from one template family. The export request names the client's device class as a closed enum (a phone page or a web/print page) validated at the request boundary by a shared schema; an omitted value resolves to one documented default — the device class of every client released before the parameter existed — and an invalid value is rejected. The server alone maps the target to page geometry (size, orientation, margins) in one page-setup authority; the client never sends dimensions. Templates emit one target-agnostic markup: target differences live only in that authority and the target branch of the stylesheet (on the phone target a data table renders as label–value cards from the same markup), and per-target resource budgets (**RPDF-M27**) are keyed by the same target. Reason: a PDF cannot reflow, and a second template or a target branch inside a template drifts from its sibling. | Bug | Static: every PDF producer takes its paper from the one page-setup authority; templates contain no target branch; the query schema carries the enum and its default. |

### Resource limits — [**RPDF-M27**](#must) clauses

- (a) Row budget lives at the read seam, not after the fact. Each report source read takes a required bound (a row limit of `budget + 1` and a database query time limit) that only the budget authority can construct; the authority rejects `budget + 1` rows with a registered *too large* error. Count-first (a second query that can disagree with the read) and silent truncation are both rejected. Every consumer of the same read — data endpoint, PDF, any other caller — inherits the budget; a limit applied only in the PDF orchestrator leaves the sibling endpoint unbounded.
- (b) One job deadline, carried in the request-scoped context. The deadline starts once per job; every bounded read uses `min(per-query cap, remaining)` as its query time limit, the renderer passes the remaining time as each browser wait's `timeout`, and the render does not start when the data phase has already used the budget. The deadline sits below the client's network timeout, so the user gets a registered, translated error instead of a transport failure. A per-query cap alone is not a job deadline: N sequential reads each at the cap can exceed any budget.
- (c) Render budget is measured in the renderer's input. An HTML byte budget is checked before a page opens; it bounds both rendering time and output size (a PDF that the client cannot hold in memory is a failure even when rendering succeeds).
- (d) Browser concurrency is capped per instance, in process, fail-fast. The protected resource is the instance's own browser process, so the counter is instance-local by nature — this is not the cross-instance state [**RDS-N1**](../redis/redis-prohibitions.md) forbids keeping in memory. A full slot rejects immediately with a retryable registered code; an unbounded in-memory queue is forbidden (it becomes an invisible wait that ends in a client timeout). Cross-instance per-user fairness belongs to a shared-store-backed rate limiter ([**RDS-M8**](../redis/redis-connection-keys-and-authority.md)).
- (e) Error classes. Too large → user-correctable business rejection (warn/metric, not retryable). Deadline missed → system capacity failure (error/crash channel) marked not retryable, because a generic client retry policy would multiply an expensive job under exactly the load that caused it. Busy → operational backpressure (warn/metric), retryable.
- The adopting project MUST choose finite values from workload measurement and record the measurement basis next to the constants (for example the largest expected source row count, memory per hydrated row, and browser time/output size per rendered row).

Enforcement and its stated limits. Use the enforcement mechanism the adopting project documents; a reference to a check is not evidence that it exists or covers the full rule. A single-file check can require every page opening to sit inside the concurrency gate's callback and every content-load/print wait to carry an explicit `timeout`, and a compile-time lock can require the bound parameter on each report read seam. Not mechanically coverable by a single-file rule: a new unbounded multi-document read added to a report path without a bound parameter — deciding that needs the callee's boundedness, which lives in another file; review against this row is the control. A type assertion that forges a bound is likewise review-only.

## Failure paths (normative)

| Situation | Required behavior | Rule anchor |
|-----------|-------------------|-------------|
| Formatter module missing, import fails, or export undefined at job entry | STOP — no buffer; **RPDF-M22** message shape. | **RPDF-M24**, **RPDF-M22** |
| The currency formatter throws (invalid currency/language/value) | Do not catch and continue. Propagate or wrap per error policy; PDF job fails with logged root cause — no silent replacement string. | **RPDF-M5**, **RPDF-N8**, **RPDF-M22** |
| Clock / time context missing for `generatedAt` or range | STOP before render — same as malformed metadata (GRPDF2-class) or orchestrator defect. | **RPDF-M25**, **RPDF-N10** |
| Chart render throws or runtime fails | Render fallback mini-table for that slot; if fallback also fails, fail whole PDF with error (do not ship partial silently). | **RPDF-M11**, **RPDF-M26**, **RPDF-M22** |
| Required browser binary is missing, cannot launch, or does not match the pinned runtime | STOP build/runtime; surface through the established outer error boundary. Do not try a system browser, alternate path, download, or version guess. | **RPDF-M29**, **RPDF-N12**, GRPDF10 |
| Payload exceeds **RPDF-M27** size/row/byte limit or job timeout | STOP; structured error — no silent partial PDF unless product explicitly documents truncation (and not for money/identity without doc). | **RPDF-M27**, **RPDF-M22** |
| Timezone missing or not in allowed catalog | GRPDF2 NO — STOP before render. | **RPDF-M23**, **RPDF-N9** |
| Report service null / empty contract violation | GRPDF1 NO — STOP; **RPDF-M22** message shape. | **RPDF-M22**, **RPDF-N8** |
| Metadata partially present | GRPDF2 NO — STOP; no buffer. | **RPDF-M23** |
| i18n key missing for chart or caption | Treat as implementation defect — fail build or fail PDF per project CI policy; must not fall back to wrong-language string silently. | **RPDF-M17**, **RPDF-N8** |
