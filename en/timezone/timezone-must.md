Scope: The **MUST** rows of the timezone resolution standard that decide which zone applies and what instant a local time is. The rows that govern a recurring scheduled occurrence — **TZ-M13** (the single nth-weekday derivation), **TZ-M14** (the at-or-after due window and its durable per-occurrence claim), **TZ-M16** (the runner's declared reference zone) and **TZ-M17** (what makes widening that window admissible) — are in [timezone-recurrence-and-due-window.md](timezone-recurrence-and-due-window.md).


Topic split: The MUST rows are divided by subject. This file covers zone resolution, local-to-UTC conversion, and captured time. [timezone-recurrence-and-due-window.md](timezone-recurrence-and-due-window.md) covers recurring occurrence calculation and delivery windows. The split preserves the full obligations while keeping each section focused.

Document type: Normative part — **TZ-M1**–**TZ-M12**, **TZ-M15**, **TZ-M18**–**TZ-M21**.

References: [README.md](README.md); [timezone-resolution-standard.md](timezone-resolution-standard.md) (**TZ-C\***, **TZ-D\***, **TZ-F\***); [timezone-decision-gates.md](timezone-decision-gates.md) (GTZ\*, **TZ-GV\***); [timezone-must-not.md](timezone-must-not.md) (**TZ-N\***); [timezone-recurrence-and-due-window.md](timezone-recurrence-and-due-window.md) (**TZ-M13**, **TZ-M14**, **TZ-M16**, **TZ-M17**); [phone number](../phone/README.md) (**PHN-D3**, **PHN-M3** — the upstream of **TZ-D4**).

## **MUST** (normative) — **TZ-M**

| ID | Rule | Consequence | Verify |
|----|------|-------------|--------|
| **TZ-M1** | Resolve the applicable timezone in one documented order: (1) an explicit timezone on the record that owns the scheduled fact (**TZ-D2**); (2) the authoritative setting of that owning context (**TZ-D3**); (3) a country-to-timezone mapping (**TZ-D5** using **TZ-D4** from PHN-\*) only when the product has documented and validated that inference; otherwise follow **TZ-F1**. All callers use this same order; call sites **MUST NOT** reorder or skip steps. | Bug / STOP | Review the ordered sources and verify callers use the canonical resolver: record, setting, documented PHN-derived country mapping, then **TZ-F1**. |
| **TZ-M2** | All local time → UTC instant conversions **MUST** use only **TZ-D6** (single SSOT family ) . The family may expose distinct validation profiles for distinct authorities while retaining one conversion engine: a stored-setting writer validates the project's admitted persisted-zone contract; a device/provider runtime context validates an explicitly supplied named IANA identity against the actual conversion engine. The runtime profile must not widen the stored-setting validator, substitute UTC or the process zone, accept a numeric offset as a named zone, copy the conversion formula, or choose a different gap/fold policy. A valid engine-supported runtime zone must not be rejected merely because it is absent from a narrower stored-setting allowlist. Invalid or unavailable context retains the existing typed failure/readiness path. Limit: choosing the correct profile for a caller's authority is semantic and review-held; every profile's consumer set must be named in the adopting project's architecture documentation. | Bug | Static: rg for ad-hoc `Date` construction from local fields outside **TZ-D6** module → zero matches or listed exemptions in architecture |
| **TZ-M3** | If **TZ-D5** declares multiple IANA zones for one country without a single default, the product **MUST** require **TZ-D2** or **TZ-D3** before any **TZ-D6** call for that context . | Bug / STOP | Schema / API audit : ambiguous countries have required timezone field or default row in **TZ-D5** |
| **TZ-M4** | **TZ-D6** **MUST** use DST-safe logic : IANA rules via documented library or **ECMA-402** /`Intl` facilities that encode zone rules, not fixed numeric offsets alone unless the input is already an instant with explicit offset per API contract . When scheduling logic extracts a required **ECMA-402**/`Intl` part, that part **MUST** exist and satisfy its exact bounded domain before use; missing, non-numeric, fractional, prefix-parsed, or out-of-range output **MUST** fail through the typed error policy. A required hour uses an explicit 0..23 cycle and **MUST NOT** default a missing part or normalize an out-of-contract value such as 24 into a valid hour. | Bug | Existing DST-boundary validation + static rule/review for required-part presence, exact bounded parsing, and typed failure |
| **TZ-M5** | Decision / validation functions **MUST** follow [decision function](../decision-function/decision-function.md) : invalid inputs **MUST** throw or typed error ; **MUST NOT** return `null` meaning invalid . | Bug | Inspect invalid local-time branches and carrier types: they raise a typed error rather than invalid-as-null. |
| **TZ-M6** | Every call site **MUST** evaluate GTZ1 before **TZ-D6** or must document that IANA was pre-resolved by the same order in the immediate caller (one hop only ) . | Bug | Code review checklist or static wrapper that forces resolver first |
| **TZ-M7** | When the product uses calling-country to infer timezone, **TZ-D4** **MUST** be supplied only through **TZ-D8**: the exact ISO 3166-1 alpha-2 taken from [phone number](../phone/README.md) **PHN-D3** (b) on the same normalized E.164 result (documented property name in shared types or the API schema). Timezone code **MUST NOT** recompute calling-country from phone strings, partial digits, or duplicate **PHN-D2** invocations hidden from the PHN boundary. | Bug / STOP | Review the handoff type or parameter: the timezone package does not invoke **PHN-D2**, and the resolver accepts only the calling-country property from the parent DTO / arguments. |
| **TZ-M8** | nowUTC (**TZ-D9** ) **MUST** be obtained from exactly one documented time source module used by all timezone resolution and ordering predicates in this topic that depend on current wall clock ; production uses system clock through that module ; allowed fixed-time observations inject the same module. **MUST NOT** scatter `Date.now()` / `new Date()` for those predicates outside **TZ-D9** . | Bug / inconsistent clock | Static: `rg` `Date\\.now\\(|new Date\\(` on timezone resolver tree — only time module or documented exemptions |
| **TZ-M9** | The **TZ-D5** owner **MUST** be documented in architecture (module path and domain vs platform classification); all generated or copied map data **MUST** trace to that owner (single SSOT). | Bug | Review the documented map owner and the import graph: one upstream for map rows. |
| **TZ-M10** | When the resolution context supplies both a **TZ-D2** candidate and a **TZ-D3** candidate, both non-empty valid per **TZ-D1** and not equal, the resolver **MUST** emit exactly one structured log per resolution invocation before returning the **TZ-M1** winner, with minimum keys: `event` = `tz_resolution_source_override`, `ianaChosen` (value selected by **TZ-M1**), `ianaAlternate`, `sourceChosen` (`record` when (1) wins, `setting` when (2) wins), `sourceDiscarded`, and a correlation id when the request or job context supplies one; severity **MUST** follow [logging policy](../logging-policy/logging-policy.md) (not error unless the adopting project's audit policy requires it). If only one candidate is supplied, **TZ-M10** does not apply (no forced fetch of the other layer). | WARNING / bug (ops visibility) | Inspect divergent-candidate logging: one event contains the required fields; a single candidate emits no override event. |
| **TZ-M11** | Every **TZ-D10** value shown to users **MUST** pass through one documented calendar-day display authority. That authority **MUST** validate the canonical year/month/day and required explicit locale, preserve those components, and use either a date-only runtime facility or a fixed-zone display carrier with an explicit fixed display zone (for example `UTC`). It **MUST NOT** consult the device timezone to reinterpret the day. | Bug | Static: authority registry + import graph identify one helper; implementation review proves strict component validation and explicit locale/fixed-zone formatting |
| **TZ-M12** | A single scheduled decision that evaluates the same current instant across multiple timezone authorities **MUST** capture **TZ-D9** exactly once and pass that same UTC instant to **TZ-D11** for every branch. Each predicate must use the timezone of the aggregate that owns that fact: a person's send time and natural-day key may use the person's timezone while each tenant workday predicate uses that tenant's timezone. The decision **MUST NOT** call a “now” wrapper per branch, borrow one context's timezone for another, or collapse person and tenant time semantics into one zone. | Bug — boundary-minute drift, wrong workday, or duplicate/missed natural-day execution. | Review that one clock-source call precedes the iteration, every zoned-parts call receives the captured instant and the owning aggregate's timezone, and no branch calls the current time itself. |
| **TZ-M15** | A local date+time plus IANA zone **MUST** be resolved at candidate transition instants, never with one reference instant's offset for a whole day. Date, time and zone **MUST** be strict-valid without host-zone/string-parse fallback. Candidate offsets come from the target IANA rules; every exact candidate **MUST** format back to all requested local components. Fold chooses the earlier exact instant; gap chooses later by the gap and that resolved local date+time **MUST** round-trip. This is Temporal [`compatible`](https://tc39.es/proposal-temporal/docs/timezone.html). One named policy serves appointment, recurrence, availability, reporting and notification; callers **MUST NOT** choose offsets or disambiguation. Invalid input or unproved round-trip fails typed; silent normalization, UTC substitution and process-timezone parsing are forbidden. | Bug — wrong transition instant, first-future recurrence, or host-dependent occurrence. | Runtime: an authority table covering two transition zones plus one non-DST zone, with exact/gap/fold cases and resolved-local round-trip. Static: reject known fixed-reference-offset shapes. Limit: static analysis cannot prove candidate completeness or IANA data; the runtime table and round-trip cover those halves. |
| **TZ-M18** | When one operation needs the zone of MANY tenants at once (a list filter, a scheduled job's page), the tenant set → zone map **MUST** come from one batch authority built on the single-tenant resolver — never from a map loop written at the call site. The batch authority owns three things a call-site loop silently re-decides: (a) tenant keys are de-duplicated and extracted exactly as consumers read the map; (b) one tenant's resolution failure removes only that tenant from the map and never aborts the batch for every other tenant; (c) that failure is returned to the caller keyed by tenant, as the original thrown value — never logged at the authority and never wrapped into a new `Error` or a fixed code (the wrap copies opaque text into a message and erases the class identity). The caller routes it to its own single boundary, so it is recorded exactly once ([logging-policy M15](../logging-policy/failure-level-and-channel-routing.md)): a request path settles the set into one registered carrier with the original as `cause`; a job whose failing tenant re-enters the next run's candidate set logs each at the background boundary by category and does not fail the run ([M21 permanent-candidate corollary](../logging-policy/shutdown-watchdog-clarifications.md)). What a missing entry *means* stays with the consumer, so the authority takes no policy flag. The consumer reads BOTH halves per item with the same key extraction the authority used: resolved → use; failed → skip without a second record; neither → a registered SYSTEM invariant violation at the item boundary, never a silent skip or a free-text log. Pre-filtering failed tenants by a raw field and handing on only the map is a second key derivation: the authority's extraction normalizes (for example trims) where the raw read does not, the two drift, and the drifted item reaches a “no zone” branch that records the same failure again. A private copy is a defect even while character-identical: the failure path is where copies drift first, and nothing at the copy's site shows it. | Bug — one bad tenant silences a job for everyone, or the failure reaches the error tracker without its identity. | Static: a single-file rule rejects writing the single-tenant resolver's result into a keyed structure (`.set`, computed key, computed assignment, `[key, resolve(key)]` entry) outside the batch authority, resolving import aliases. Limit: a re-assigned variable, a value returned through another function, and a map built by array reduction are out of such a rule's reach — review obligation. (c) is carried by the type: the failure set is part of the authority's result, so no caller reads the map without receiving it; that each caller routes it to exactly one boundary spans files and is review. The per-item reading of both halves is also review: the pre-filter it forbids is an ordinary collection filter whose key read only a data-flow analysis could tie back to the authority's result. |
| **TZ-M19** | Day arithmetic on a calendar-day value (“N days ago/ahead”, week or month start) **MUST** run on the calendar-day TEXT through ONE documented civil-day helper that uses fixed-zone (UTC) components, seeded by the zone's local “today” from the single now-in-zone authority (**TZ-D11**) — never on a host-local `Date` (`setDate`, `getDay`, `setHours`, `new Date(y, m, d)`) and never on a tenant wall clock written into a host-local `Date`. A stored calendar day carried as a midnight-anchored `Date` (**TZ-D10**) **MUST** be compared in that same carrier form against a bound the one local-day-window helper builds on the civil-day helper, or be read back to its day text with the one reader and compared as text; it **MUST NOT** be shifted a second time into the tenant zone (west of Greenwich the day falls back by one and the boundary day is dropped). A window that filters stored calendar days **MUST** be expressed in that same civil form, not as the UTC instants of local midnight: an instant window compares correctly only against instant fields. A window used against BOTH instant fields and stored calendar days is built in both forms from the same day texts in one call, and the day-level question “is the stored day before the tenant's local today” is one predicate that reads the stored day as text. A calendar-day text that arrives in a request **MUST** be checked as a real calendar day (not only a `YYYY-MM-DD` pattern) at the request boundary, so `2026-02-31` is the client's 400 and never reaches the civil-day helper's server-fault code. A request that carries a day RANGE **MUST** also bound its length at that boundary with the one range-cap constant before any consumer enumerates the days (an unbounded `0001-01-01..9999-12-31` builds a multi-million-element list in the caller's own process); the cap is one number read by every range consumer, and exceeding it is the client's 400. | Bug — host-dependent boundary; boundary day dropped west of UTC. | Review: one civil-day helper exists; a search for host-local `Date` mutation on a day window returns zero hits or a documented exempt entry. Limit: telling a day-window mutation from any other `Date` use is a semantic judgement, so review holds it. The request-boundary sentences (real-day check, range cap) are also review: which request string is a calendar-day field is a name/semantic fact no single-file rule can decide; review of new request schemas holds it. Record known non-conformant instances in the adopting project's contract documentation. |
| **TZ-M20** | A day or month boundary of a tenant- or recipient-owned fact (“today”, month-to-date, the closed month, a per-day cap) **MUST** be local midnight in the owning aggregate's zone, read from the single now-in-zone authority (**TZ-D11**) on the captured instant — never UTC midnight, the server's process zone or the client device's clock. A job that closes such a period runs at a cadence fine enough to reach every owner's own midnight and chooses the period per owner, repeat-safe. A client that cannot resolve the owner's zone yet treats “today” as unknown — the read stays closed, a picker opens unselected, a selection default is derived on render once known — and never seeds or copies a device-day value. An expiry stored as an instant is compared as an instant and is never rounded to any day. | Bug — the wrong day or month is shown, frozen or counted whenever device, server and owner zones differ (a summary frozen hours before the owner's month ends; a second evening notification wave; a report opening on yesterday). | Review: the one client today authority and the server now-in-zone authority are used. Limit: whether a `new Date()` or a UTC field carries a day or an instant is semantic and spans files, so no single-file rule tells the defect from a legitimate timestamp without flooding false positives; review holds it. |
| **TZ-M21** | The country → zone map (**TZ-D5**) **MUST** offer at least one selectable zone for every distinct IANA time rule of every supported country — the country's IANA zones grouped by their offset sequence — and the persisted-zone allowlist **MUST** be derived from that map, never kept as a second list. | Bug — a tenant in a rule the list lacks picks the nearest neighbour and runs an hour off for months (no-DST regions, half-hour or 45-minute zones). | Review: completeness is measured from IANA zone data when a country or zone row changes; the allowlist has no writer of its own. Limit: the measurement needs the IANA zone table, which differs per host and changes with tz releases, so a gate step would fail on data rather than code. |

A date-only selection parsed for a Date-based picker and then serialized must preserve its validated canonical year/month/day; its UTC midnight carrier must not be read with device-local getters. A picker adapter may explicitly put those same components into the component representation the picker requires, but it is not a scheduling instant. Serialization round-trips the day and rejects an unrepresentable carrier instead of returning a shifted day. An actual instant used to seed a current local-day selection keeps its explicit existing day semantics; changing every getter to UTC is not equivalent. The adapter and fixed-zone user display share the same real-day validation authority. A stored civil-day carrier and a picker day are read as that same day text for matching and keys; the owning tenant's actual today is obtained separately from its now-in-zone authority. A timezone argument retained for local signature compatibility does not authorize reinterpreting a civil day as an instant. Where a canonical astronomical year zero is admitted, a localized numeric year must retain the calendar's era information instead of presenting year 1 as CE. A Date-based component adapter's storage hour is representation only and must never feed a scheduling instant; all consumers serialize the verified day and provide wall time separately. Limit: each Date consumer's input class and use of its hour span files; the single authority plus round-trip hold the contract, with review of consumers.

A text-based calendar preserves its validated civil-day string directly through selection, current-day and marked-day bindings. It must not introduce a local Date carrier merely to serialize it back: the carrier representability requirement belongs only to a component that actually consumes Date fields. An unavailable endpoint blocks that calendar instead of activating the widget's implicit device-day initializer; a changed explicit endpoint must also update the visible calendar month through the widget's supported initialization contract. The callback's day text, the request-boundary day, the server's day-window filter and the displayed result remain the same value. A weekday drawn beside that day uses the same fixed-zone calendar-day family and the application's canonical locale, not a private local-noon parser or a partial language map. Limit: whether a constructor carries a civil day, an actual instant or a Date clone is cross-file input semantics. A blanket constructor ban would reject legitimate instant/clone consumers; registered validation/display authorities and source-linked review hold this distinction without a syntax-level check.
