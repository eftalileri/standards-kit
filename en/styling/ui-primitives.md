Document type: Normative part file under [README](README.md) — defines the **STY-CMP**-\* rules.

Scope: Reusable visual and interactive building blocks in React Native / Expo applications. Each adopting project keeps its own inventory of shared primitives (component names, module locations, variants, consumers and guards); rules below name the primitive by its role ("the shared button primitive"). This standard does not require an abstraction for a one-off control. Where a rule says "the one X primitive", the project designates exactly one implementation of that role and documents it.

---

## Normative rules (**STY-CMP**-\*)

### **MUST**

| ID | Rule |
|----|------|
| **STY-CMP-M1** | Surfaces with rounded corners and a shadow are built with the shared card primitive; hand-writing `elevation` plus `overflow: 'hidden'` on the same view inside a screen is forbidden. |
| **STY-CMP-M2** | Shadows (on both platforms) come only from the theme's elevation levels ([**STY-M11**](stylesheet-and-theme-tokens.md)); a view that carries a shadow and its parent container use `overflow: 'visible'`. |
| **STY-CMP-M3** | Every action button — a styled pressable, or text that acts as a button ("Retry", "Select all", "Cancel") — **MUST** render through the one shared button primitive. A shape the primitive lacks (a variant, icon position, event-receiving `onPress`) is added to the primitive itself; a screen or feature **MUST NOT** keep a local button component or a hand-styled pressable copy. Reason: hand-built buttons drift into many radii, paddings, disabled looks and missing roles/labels. Out of scope: list/option rows, cards, chips, segmented choices, field triggers, and an inline link inside running text (link role). An icon-only button (header menu, back, close, step arrows) **MUST** render through the one shared icon-button primitive (44 dp touch box, required translated label, button role, optional count badge); a screen **MUST NOT** size its own icon box. A small round icon disc inside a card or row (call, message, a mode toggle, an add mark) **MUST** render through the one icon-disc primitive — a tappable disc through the icon-button primitive's disc surface, whose 44 dp box may overlap its container's padding but never leave the container. Reason: hand-built icon boxes drift to 24–32 dp touch areas and missing labels, and Android drops a touch outside the parent's bounds, so hit slop cannot widen a small disc. An action drawn in more than one place (edit, add, delete, cancel) **MUST** take its glyph from the one action-glyph authority, and an icon-only edit or delete button **MUST** be the shared edit/delete icon button (same size, so a pair sits level); a screen **MUST NOT** pick its own glyph or size for such an action. Reason: two rows showing different edit pencils side by side. Verify: review. |
| **STY-CMP-M4** | New screens build switch / toggle fields with the shared switch-row primitive. |
| **STY-CMP-M5** | New screens show a loading indicator with the shared loading primitive. |
| **STY-CMP-M6** | All shared primitives are token-only ([**STY-M4**](stylesheet-and-theme-tokens.md)); literal colors and numbers are forbidden ([**STY-N2**](stylesheet-and-theme-tokens.md) / **STY-N3**). |
| **STY-CMP-M7** | Where a tappable surface needs premium press feedback (scale + spring), it uses the one press-feedback hook; a parallel `useSharedValue` / `withSpring` press logic or a hand-written scale value is forbidden (one motion authority, [**STY-N6**](stylesheet-and-theme-tokens.md)). Values come only from the theme's motion tokens. The hook applies the operating system's reduced-motion preference in one place: with the preference on it produces no movement, and a consumer does not copy that decision with a second accessibility listener. |
| **STY-CMP-M8** | Where content needs an entrance animation (fade + rise), it uses the one shared entrance primitive; writing parallel mount-animation logic is forbidden. It is **not** used on virtualized-list rows (recycling re-triggers it on scroll); only on bounded, single-mount surfaces (empty states, banners, scroll-view card blocks). Values come from the motion tokens. Cold-start addendum (entrance starts when the cover lifts): while a launch cover (the native splash or any full-screen veil imitating it) is up, the app tree is already drawn, so an entrance sequence started at mount of a surface under the cover plays and ends unseen. A launch gate's entrance choreography therefore binds to the signal that the cover has lifted, not to mount: the one authority that lifts the cover announces "it no longer covers" on an in-process broadcast surface (single writer, not reversible, no second visibility source — **SSG-M8**), and the gate listens only to that signal. Three conditions hold together: (a) if the signal never arrives (the lift call neither resolves nor rejects) the gate is never empty forever — a single upper-bound token elapses and the sequence plays anyway, so the worst case equals the behaviour before the signal existed; (b) because the same gate can be drawn in several branches of the tree, the right to play is one per process — a remount after the cover lifted does not replay the sequence and wipe the composition, later mounts start already settled; (c) the wait does not trap the user — when the gate closes, where the composition is does not matter, and with the reduced-motion preference the wait is never installed. "How long have I been waiting" counters (a status line that appears during a long launch) also run from the moment of visibility, not from mount; otherwise the time runs out under the cover. |
| **STY-CMP-M9** | On a new tappable surface, press animation uses the shared pressable-scale primitive instead of a raw `Pressable` plus a hand-wired press-feedback hook (the canonical button/card/chip primitives already use it internally). A legacy raw `TouchableOpacity` is converted to the shared pressable-scale primitive when it is migrated — file by file, deliberately, never by a bulk script. Where the project bans raw `TouchableOpacity` / `Pressable` imports in screens and components through an import-restriction lint rule, the ban lives in the same restricted-imports entry as the other import bans (a separate block for the same files overrides that key and silently voids earlier bans); the canonical press primitives are exempt, and a modal backdrop or non-button gesture (tap outside to close, tap-to-focus) may use a raw pressable with an inline disable and a stated reason. |
| **STY-CMP-M10** | A score rendered as stars **MUST** use one shared rating primitive with separate read-only and editable contracts. Its semantic fill, outline and size come from the existing theme; aggregate text comes unchanged from the backend result. An editable change callback selects a draft only; the explicit submit action owns persistence. The primitive **MUST** expose text/shape and selected accessibility state, not color alone. In a write panel, group editable choices and the readable draft statement as one score region, with Save and recovery/destructive actions in a distinct action region; the selected styling **MUST NOT** imply that the draft was already saved. Verify: import/callback provenance by review; visual hierarchy, recognition and contrast require rendered inspection because source analysis contains neither pixels nor assistive-technology output. Product palette and score bounds belong to their own authorities, not this rule. |
| **STY-CMP-M11** | Selected common choice controls **MUST** expose a visible non-color mark and `accessibilityState.selected`. A clear/all choice **MUST** use the same selection writer as individual choices; it **MUST NOT** introduce a stored pseudo-domain value. Verify: selected-state/indicator branches and consumer writer provenance, by review. |
| **STY-CMP-M12** | Modal initial accessible focus and focus return **MUST** use one shared lifecycle authority. All dismissal paths of an in-flight write panel **MUST** apply the same pending gate; accepted persistence and failed read-back **MUST** remain distinct so retrying synchronization cannot repeat the accepted write. Verify: canonical focus/gate imports and dismissal callbacks; actual focus arrival/return requires platform execution, because native accessibility scheduling and target mount lifetime are absent from source analysis. |
| **STY-CMP-M13** | Common interactive dimensions **MUST** derive from the existing theme's semantic touch-target and component-size tokens. Minimum height **MUST** permit font scaling and wrapping; fixed height or single-line clipping **MUST NOT** silently hide primary control text. Verify: theme-token provenance and common-control layout review; whether text fits all device/font/locale combinations requires runtime measurement. |
| **STY-CMP-M14** | A control that changes context — moves the user into another mode, panel or workspace, or performs a one-way navigation — **MUST** be a button whose label names the action, not a switch whose label names a state. A switch asks the reader to interpret on/off, and when its label names the context the user is already in, the off position reads as that context's negation (a "Business Owner Mode" switch in the off position reads as "ownership is disabled"). The switch form stays right for a persisted two-way setting whose off state is a real, meaningful value. Both directions of one context change are the same button with the label derived from the target; a second "where are we now" predicate **MUST NOT** be written beside it (**SSG-M1**). Verify: rendered copy review — source analysis cannot tell a setting from a context change. |
| **STY-CMP-M15** | A control's action precondition **MUST** be the same predicate as its render gate. When the row is drawn on `A` and the handler bare-`return`s on `!B`, the two predicates drift independently and the user presses a visible control that silently does nothing and reaches no channel (**COB-RN-M11**). Either bind the guard to the gate's own value, or make the failure visible (registered error / user-facing text); a precondition the body never consumes is not protection, it is a trap. Verify: review. |
| **STY-CMP-M16** | User-entered free text (a note) on a detail, history, card or report-preview surface **MUST** render in full through the one note primitive: label above, text below at full width, typed line breaks kept, no `numberOfLines`, height cap or clipping. A 1–2 line preview is allowed only in a dense list/grid cell whose tap opens the full text. Free text **MUST NOT** sit in a `flexDirection: 'row'` beside siblings unless it can shrink (`flex: 1` / `flexShrink: 1`): a React Native `Text` does not shrink by default, so a long value is pushed past the edge and the card's clipping layer cuts every line. Reason: a silently cut note hides what the user wrote — a user-visible defect. Which notes a viewer may see stays with the field's authority, never with the primitive. |
| **STY-CMP-M17** | A read-only label–value row (optional icon, label beside its value) on a card, detail, summary, confirmation or notification surface **MUST** render through the one row primitive: icon and label keep their natural width and never shrink or wrap; the value takes all remaining width and wraps onto as many lines as it needs (no `numberOfLines`, no clipping, a long unbroken token breaks inside the value); when the label leaves the value less than its minimum share of the row, the value moves below the label at full width instead of collapsing into a sliver. A component value goes through the primitive's value renderer and takes the primitive's value style. A label **MUST NOT** share width with its value (`flex` on both, or `flexShrink` on the label): a long value then squeezes the label until it breaks character by character — a user-visible defect. Out of scope: form rows whose value is an input control, stacked label-above KPI cells, and dense virtualised list rows where a one-line preview is a density choice; user free text goes to the note primitive (**STY-CMP-M16**). |
| **STY-CMP-M18** | A centered dialog or a bottom sheet **MUST** be built on the one modal shell (dialog, sheet, anchored popover); a screen **MUST NOT** hand-build the native `Modal` + backdrop + surface. The shell owns the backdrop token, surface radius role (dialog / sheet), top elevation level, safe area, keyboard avoidance, entrance motion and every dismissal path: Android back, the screen-reader escape gesture and (opt-in) backdrop press all call the one `onRequestClose`, and `null` closes none of them — so a pending write gates all paths at once (**STY-CMP-M12**). Content and focus stay with the consumer; `contentStyle` carries layout only (**STY-CMP-N3**). A short single-select choice opens as the shell's anchored menu below its field, or above when there is no room; a sheet is only for a long, searchable, multi-step or action-carrying picker. A virtualized list inside the shell **MUST** be rendered through the shell's list wrapper (content height, shrinks to the free space, scrolls beyond); a consumer **MUST NOT** give a list box `flex: 1`, a fixed or screen-fraction height — the shell is content-sized and lays out flex children only in its layout pass, so such a box measures 0 and the list draws nothing. A sheet opens only as tall as its content: a search-filtered list keeps its largest measured content height while open (so the search field does not jump) and **MUST NOT** pin the body to the window height, which leaves an empty area under a few rows; fill sizing is only for a body that lays itself out with `flex: 1` (a tabbed picker). A content-sized frame **MUST NOT** freeze its first measured height — a list's first frame is window-high — it follows its content and locks only while the keyboard shifts it. A sheet closes by dragging its grabber or its header down, through the same `onRequestClose` (`null` springs back; reduced motion closes by fade); the list area is not a drag zone because its native scroll owns the touch. A picker sheet's title row and search field come from the shell's shared header and search components. A centred dialog's title and action group **MUST** render through the shared dialog title / dialog actions components (the alert dialog included); a dialog **MUST NOT** lay out its own title size or action row, because hand-laid dialogs drift into several title sizes and unequal button pairs. A full-screen page modal (safe-area view + header) is not a dialog, but still **MUST** pass `onRequestClose` so Android back closes it. Reason: hand-built shells drift into many radii, backdrop tints and missing back-button closes. Exception: a non-dismissable consent gate whose closure contract is held on the raw `Modal`. Verify: a raw virtualized list written directly inside a dialog/sheet element of the same file is rejected by the project's boundary check if it documents one; a list rendered by a child component in another file, the dropdown-vs-sheet choice and the dialog title / action binding are held by review. |
| **STY-CMP-M19** | Non-blocking feedback — a success, an informational notice, or the failure of a retryable side action that changed nothing (copy, share, open a link / call / map, a mark-as-read, a screen that could not open) — **MUST** go through the one toast authority (a show-toast / show-error-toast API backed by one queue, drawn by one toast viewport); a screen **MUST NOT** use a one-button alert dialog for it or build its own toast. A message that asks a question, offers more than one action, confirms a destructive step, reports the failure of a save / delete / money operation (**EHX-M4**), or carries support or recovery instructions the user must act on **MUST** stay a dialog (the in-app alert dialog, **STY-CMP-M27**, or a dedicated dialog). A form-validation failure the user corrects in a field **MUST** be drawn under that field by the field authority (the text field's error, or a field error text under a trigger, with the box in its invalid tone — **STY-CMP-M24**, **EHX-M1**), never as a toast or a dialog; a sentence shared by two fields goes under the later one and both boxes take the invalid tone. When the submit action sits below the field (a long form), the screen **MUST** scroll the errored field into view, because an error drawn off-screen reads as a dead button; an error whose field is not drawn on the current screen (a value from another screen, a filter hidden for this actor, a record outside the app) stays a dialog. A success that ends the screen shows the toast and navigates at once — the root viewport survives the navigation. The authority owns tone (icon + colour, never colour alone — **A11Y-RN-N1**), the screen-reader announcement, display time (the Android accessibility timeout applied), queueing without overlap and the host above an open modal shell; a raw native `Modal` outside the shell **MUST** mount its own toast viewport, because a toast fired while it is open is otherwise drawn behind it. A caller passes translated text and a tone, and a generic "Success / Error" title is not passed. Reason: one-button alerts interrupt every save with a modal tap, and two alerts in one handler stack on iOS. Verify: review. |
| **STY-CMP-M20** | Every selectable option in a picker shell — the anchored dropdown menu and a sheet/dialog option list — **MUST** render through the one option row primitive: one height, padding and type scale for every row, a selected state of tinted surface + semibold primary label + trailing check + `accessibilityState.selected`, press feedback from the shared pressable-scale primitive, an optional fixed-width leading mark (icon or glyph) and an optional second line. Rows are separated by the list authority's hairline (**STY-CMP-M22**), never by per-picker margins or borders. Special choices ("All", "None", "Unassigned") **MUST** be rows of the same list, not header/footer components with their own spacing. A single-select option list inside a screen, form or dialog **MUST** render through the option-group component (radio role per row, radiogroup container, one flat card surface, the shared separator); two or three short options that each need an icon and a one-line description to be understood **MUST** use the same group's tiles layout (equal side-by-side cards, radio role per card, the selected card marked by primary border, brand tint and the filled corner check — **STY-CMP-M11**); a radio card or bordered option box **MUST NOT** be hand-built. A multi-select list whose every option carries its own value field **MUST** render each option through the check-option-row component: the whole row toggles (checkbox role + `accessibilityState.checked` on a press layer spanning the row), a leading checkbox mark, the option-row selected tint and semibold primary label, a secondary-tone label when unchecked, and the value field at the end as its own accessibility element whose tap never toggles the row; while the row is unchecked the field is passive (dashed edge, transparent, faded tertiary text, not editable) and a tap on it toggles the row. Its rows stack with no gap and a leading-inset hairline between them; a chip plus a separate field box per option **MUST NOT** be used for it. A field that opens a picker (anchored menu, sheet or full-screen list) **MUST** render its trigger through the one select-trigger primitive (the shared field box of **STY-CMP-M24**; value or placeholder, optional second line and leading mark, chevron, expanded, invalid, loading, disabled; the value wraps, never clipped — **STY-CMP-M13**); the dropdown is that trigger plus the anchored menu, and a second trigger component is not written. Reason: hand-built rows drift into several selected styles and two spacing systems inside one sheet. Out of scope: chips (**STY-CMP-M23**), action-carrying card pickers and full-screen page pickers built on the card list. Verify: review. |
| **STY-CMP-M21** | A cancel / dismiss action ("Cancel", "Not now", "No", "Go back", "Stay on page") **MUST** be a button with the outlined ghost variant — always a visible button area, never bare tappable text and never the tinted secondary variant — so every cancel has one look. In an action group the order is fixed: stacked vertically, the primary action is on top and cancel below; side by side (a dialog pair), cancel is on the left and the primary action on the right. A destructive action drawn as a button on a screen, a screen header or a sheet **MUST** be the outlined destructive-secondary variant; the filled danger variant **MUST** appear only in the final confirmation (the confirmation dialog of **STY-CMP-M27**, or the full-page final step of an irreversible action). Reason: filled red means "the last, irreversible step", so it is not spent on the entry into a destructive flow; the same cancel drawn as plain text, tinted or outlined and above or below the primary action is an inconsistency. The alert / confirmation dialog derives the same order from each button's meaning (**STY-CMP-M27**). A fixed bottom action bar **MUST** render its surface through the shared safe-area footer's bar variant (white surface, one top border, inset padding, gap between stacked actions, bottom safe area); a screen **MUST NOT** hand-draw it with a top border + a background. A button block that scrolls with the content is not a bar (plain variant). A menu of secondary actions behind a ⋯ button **MUST** be the shared action sheet (a destructive row is its danger tone — red label, no button surface — and its final confirmation stays the dialog it opens; an action unavailable with a reason shown today stays as a disabled row with that reason beside actionable rows; a ⋯ with no actionable row is not drawn, and a reason that would be left alone in the sheet becomes the notice line above the primary action — the shared action footer decides this once). An action area carrying three or more actions — a fixed bottom bar, a card section or an inline row editor — **MUST** be drawn by the shared action footer (bar or inline surface): one filled primary, every other action a row of its ⋯ sheet, destructive rows red and ordered after the ordinary ones, a cancel of an edit stays the ghost button beside it; a screen **MUST NOT** hand-draw the primary + ⋯ row or keep its own sheet state, and each screen or section **MUST** define which actions exist and when in one place, derived from server state (no local flag copies). Buttons that split one job (full and partial payment of the same amount due) **MUST** merge into one entry: the action footer without a primary, a title naming the job and an icon, so a state with one action left shows that action's own button and two or more open the sheet. A multi-button alert **MUST NOT** be used as an action menu — the alert is only for a decision or confirmation (**STY-CMP-M27**); two menu patterns (alert-as-menu and sheet) would draw the same job two ways. Verify: review. |
| **STY-CMP-M22** | Every row separator **MUST** come from the one separator authority: the shared divider (a visible 1 dp line — the device hairline is too faint — in the one theme divider colour, visible on white and on the light brand tint) and, between list rows, the shared list-item separator in its hairline / leading-inset forms (the modal-shell list default). A screen **MUST NOT** draw a row or section line with `borderTopWidth` / `borderBottomWidth` or a `height: 1` view. Placement: between consecutive rows of the same kind (option rows in pickers and sheets, list rows, label–value rows, menu and settings rows) and between sections inside one surface; the line starts where the row text starts (after a leading icon, flag, avatar, radio or checkbox) and ends inset by the row's horizontal padding; never above the first or below the last row; never between cards, bordered selection cards, chips or buttons — gap separates those; full width between a sheet or dialog header and its content. The separator is its own element between rows, so it stays visible next to a selected (tinted) row. The line sits exactly midway between two rows: each row carries equal top and bottom padding, and consecutive rows have no gap or margin between them. Consecutive option rows **MUST** therefore render inside the one option group or a list whose shared item separator draws the line; they **MUST NOT** sit directly in a container with `gap` or per-row margins, and a separator is never positioned against a parent `gap`. The selected row's tint spans from separator to separator and does not move the text. Consecutive list rows of one kind that are not item cards (menu rows, people, records) **MUST** render as the shared list-row primitive inside the one grouped-list surface — the list-group component for a hand-laid group, the virtualised list's grouped mode for a virtualised list: one white card, rows separated by this line from the row's text start; a list **MUST NOT** wrap each such row in its own card with gaps between them. Item cards (**STY-CMP-M30**) stay separate cards separated by gap. Reason: per-screen borders drift into several colours and widths, and next to the selected tint a neutral line can vanish. Out of scope: structural edges (screen header, sticky footer, toolbar and tab bar edges, input and card borders, table grid lines). Verify: review. |
| **STY-CMP-M23** | A single-select view or filter selector with two to five short options (a status filter, a period scope, an output format, a content switch such as weekly/monthly) **MUST** render through the shared tabs primitive in its pill variant; a multi-select choice stays a chip; a weekday multi-select **MUST** render through the shared weekday strip (seven equal cells in one row, the selected cell filled with a corner check — **STY-CMP-M11**; as chips the seven days wrap into ragged rows), a payment-method choice through the shared payment-method chip row, and a multi-select whose options each carry a value field through the check-option row (**STY-CMP-M20**). Both tabs variants share one shape: one grey track (variant surface, control radius, small inner padding) whose segments share the width equally; pill marks the selected segment with the sliding primary indicator and white semibold text, segment with a white raised segment. A tab track **MUST NOT** scroll sideways, and a selector this rule covers **MUST NOT** sit in a horizontal `ScrollView`/list (a long toggle-to-clear chip catalogue such as a sector filter is a chip row, not this rule): segments always share the track equally, a label wraps only between words and shrinks to the word-safe floor (**STY-CMP-M31**), and when a word still cannot fit, the tabs primitive alone drops the track into balanced rows (4 → 2×2) — never clipped (**STY-CMP-M13**); a screen fixes a cramped selector with shorter natural catalogue labels, never its own layout. Reason: a sideways-scrolling selector hides options in long locales and is hard to use inside a vertical page. A selector whose second press clears the choice (an expand/collapse toggle) is not a tab. Reason: hand-built filter chips drift into wrapping two-line rows, code-id screen-reader labels and missing selected state. Verify: review. |
| **STY-CMP-M24** | A form control's visible look — label, box, focused / invalid / read-only tone, error or helper text and the gap between stacked fields — **MUST** come from the one field authority (the shared text field and its box styles), through the control type's own primitive: text field, money amount input, time input, list search bar, phone-number field (the country is chosen inside the phone box and opens the one country picker sheet; a screen **MUST NOT** pair a separate country selector with a phone text field, because the pair drifts into per-screen labels, error placement and formatting), the trigger of a select field (anchored dropdown or a picker sheet) the select-trigger primitive (values pre-filled for the person and summarised in one card use its grouped-list-row appearance inside the list group, never a hand-built row), a payment-method choice the payment-method chip row. A screen **MUST NOT** give the base text input its own box style (it owns keyboard behaviour only) or hand-build a field or trigger box; layout (margin, flex, width) goes through the field's container style. A read-only field passes `editable={false}` — a field that drops typed text in its handler while the keyboard opens is a defect. A single-line text input **MUST** take its text style from the field authority's one single-line style (no `lineHeight`, Android font padding off, vertically centred) and a multiline input adds the `lineHeight` and starts at the top; a single-line input **MUST NOT** carry a `lineHeight` (iOS puts the excess above the glyphs and Android font padding adds the face's tall ascent, both pushing the value below the box centre). The field authority **MUST** centre a single-line value optically — the cap/digit body on the box centre line, shifted once from the text face's vertical metrics token, applied only while the brand text face renders — and a screen **MUST NOT** nudge field text with its own padding or offset; a multiline input stays top-aligned. A money field's symbol comes from the tenant's currency authority, never a hard-coded default; parsing and validation stay with the field's own hook. Form fields **MUST** sit on the page ground with the field stack spacing and the label / helper text passed to the field primitive: a card (or a self-surfaced control such as a switch row) **MUST NOT** wrap a field, or a run of fields with only their helper lines and a group separator, on its own — a card groups fields only together with a section header or non-field content (switch, status row, banner, action); one card per field fragments a form into boxes and a card around a surfaced switch row draws a double frame, so a switch row grouped inside a card with other content **MUST** be passed as embedded. Reason: hand-styled boxes drift into several backgrounds, radii and error tones, a money field can render with no box at all, and a read-only phone field can open the keyboard. Verify: review. |
| **STY-CMP-M25** | A feedback surface **MUST** render through its one primitive: a notice strip (tinted or bordered status/help box — optional title, extra lines, actions, dismiss, busy spinner) through the shared banner; a nothing-here / not-found / no-access / list-unavailable view through the shared empty state (inline layout inside a card or section); a full-area read failure through the shared query-error screen and an in-place one (card, section, list footer, failure above stale data) through the shared inline retry notice; a spinner with or without its waiting text through the shared loading primitive. A screen **MUST NOT** hand-build one from a styled `View` + icon + `Text`, a pressable text as its retry control, or a raw `ActivityIndicator`; a missing shape is added to the primitive, not copied locally. A paywall / module lock (a lock card, an in-card lock, the full-area feature lock) **MUST** render through the one lock surface (drawn on the empty state), which also owns whether the purchase action is drawn; a screen **MUST NOT** draw its own lock card. A list or tab with nothing to show **MUST** render through the shared empty-state card (the card + inline empty state; the virtualised list's empty text draws it) as the first content under the header band or summary, in the same place on every layout class — never centred in the page, never a screen's own card + empty state; an empty state **MUST NOT** sit inside another card or frame, so a wide table draws neither its frame nor its column header around its empty card — the table frame takes the required row count and is the one place that decides it, a caller adds no flag or conditional header. A page-terminal state (no access, not found) stays the empty state in fill layout. Reason: three tabs would otherwise draw the same empty message centred, at the top inside a total card, and bare. Accessibility labels on these surfaces are translated text, never code ids. Reason: hand-built copies drift in tone and spacing, clip their text, read code ids aloud, put the close label on the icon instead of the touch target, and show copy belonging to another state. |
| **STY-CMP-M26** | An action that ends the user's own account, tenant or membership (deleting the account, closing the owner account, closing a workspace, resigning from / leaving a workspace) **MUST** go through the one two-step irreversible confirmation (a math step, then the final confirm), and every entry point to the same action **MUST** reach that one flow; a second entry point **MUST NOT** carry its own single-tap native confirm. When the action targets one of several records, the final confirm **MUST** name it — a subject type makes an unnamed confirm a typecheck error. Reason: a second, one-tap entry point silently bypasses the gate the first one enforces, and an unnamed confirm lets the user confirm leaving the wrong workspace. Out of scope: an administrative deletion of someone else's record inside an account that stays open — deleting one's own membership row is resigning and stays in scope — and retrying a closure the server already accepted. Verify: review. |
| **STY-CMP-M27** | A control or dialog that the platform draws differently on iOS and Android **MUST** be drawn by its one in-app authority in the product's look, never by the native control: an alert or confirmation dialog through the in-app alert-dialog API (drawn on the dialog shell — a screen **MUST NOT** call `Alert.alert` / `Alert.prompt`); an on/off switch through the shared switch row (its in-app toggle, never the native `Switch`); pull-to-refresh through the shared refresh control (brand tint, colours and surface; the virtualised list wires it for every list); a date or time choice through the shared date-picker modal / time input. The dialog's action group comes from each button's meaning, never from the platform, in the **STY-CMP-M21** order: cancel is the outlined ghost button (left of a side-by-side pair, bottom of a stack); destructive is the filled danger button, used only in this final confirmation; a single default action is primary, several default actions are equal choices (secondary). Android back and the screen-reader escape press the cancel button (or the single non-destructive acknowledgement button; a cancelable dialog dismisses), otherwise the dialog closes only by a choice — a destructive action never runs from back or escape. The chosen handler runs after the dialog has really closed (the native iOS timing), so it may open another dialog, sheet or system picker. Where the dialog draws is derived once by the root prompt arbiter: inside the top-most open user shell (iOS presents a nested `Modal` only from an open shell), otherwise in the root host above any root prompt; one dialog at a time, queued; the queue belongs to the signed-in account and is discarded without running handlers when it ends. Out of scope: surfaces the OS owns (permission prompts, the share sheet, image/document pickers, the store purchase sheet, the tracking prompt) and the spinner glyph inside the loading primitive and the button. Reason: warning cards look different on iOS and Android; Android's native alert also drops the destructive tone and any button after the third. Verify: where the project documents a boundary check for `Alert.alert` / `Alert.prompt`, record its actual scope; the switch, refresh and picker bindings are review-held. |
| **STY-CMP-M28** | A record's state shown on a card, row or detail (status, connection, permission, trial, consent) **MUST** render through the shared status label: a toned dot (or an icon for a meta line) plus the word, the word and tone read from that domain's status authority. A screen **MUST NOT** hand-draw a status dot, colour a status word without its dot, or carry a local status → colour table. A wordless dot whose meaning is carried by adjacent text or the enclosing element's accessible name (an unread mark on an icon tile) **MUST** come from the same primitive's status dot. Reason: state shown by colour alone is unreadable for colour-blind users and drifts into per-screen tones. |
| **STY-CMP-M29** | A toned icon tile at the start of a row or card **MUST** render through the shared icon tile (one size, control radius, tone → light ground + readable icon colour); a screen **MUST NOT** build its own tinted icon box. A summary figure row (icon tile, label, highlighted amount or count, optional chevron) **MUST** render through the shared summary-figure row, and three label-above figure tiles inside a card through the shared metric triplet (a muted tile, never a second white card); both take the figure colour from the one tone → figure-colour token table. Reason: the icon, ground and amount of one item stay in one tone family only when one component maps the tone. |
| **STY-CMP-M30** | A card that shows one catalogue or list item (a catalogue entry, a resource, a search result, a stock item or location) **MUST** render its surface through the one item card (on the default card variant): white ground, hairline border, card radius and lowest-level shadow when unselected, the brand tint when selected; its `style` / `contentStyle` carry layout only and reject surface keys at compile time. An item card **MUST NOT** use another card variant, a local tinted / flat / bordered box or an accent edge. Reason: sibling item kinds drift (one grey-green flat box, one grey strip, one white card). Verify: the item card's layout-style type. |
| **STY-CMP-M31** | A control label (button, chip, tabs, badge) **MUST** wrap only between words, never inside a word: it renders through the shared word-safe text component, which measures the laid-out lines and, when one word cannot fit its own line, shrinks the label step by step down to the type-scale floor (unspaced scripts — Japanese, Chinese — break between characters by design and are not measured). A control label **MUST NOT** be a plain `Text`, and a screen fixes a cramped label by giving the control room (stacked actions, a shorter catalogue label), never by a fixed font size. Reason: a word must never be split across lines — a card showed a long word broken into fragments; German, Russian and French produce long single words. |
| **STY-CMP-M32** | Screen spacing — the side gutter, the header → first content and last content → scroll end space, the gap between consecutive blocks on the page ground (control → control, tabs → their content, card → card, field → field or button, carousel → next control), the extra lead before a titled section, the gap inside a card and the card-list gap — **MUST** come from the one screen layout authority (shared screen-body, header-band and section components plus the shared scroll/list content styles) and its theme layout tokens (screen gutter, screen top, screen bottom, block gap, section lead, card gap); a list's card gap (one value for every record-card list) and end space come from the list authority — a screen **MUST NOT** give one list its own card gap. Consecutive form fields get their gap through exactly one mechanism: the field authority's field-stack style inside a plain field-run container, or a gap stack whose fields carry no field-stack style — never both (the margin plus the gap doubles); a field primitive that carries the stack spacing itself counts as carrying it, so it is not wrapped in a second field-stack style and sits in a gap stack only with its own opt-out; a label the screen writes above an unlabelled trigger groups with it through the field-label-group style. A screen **MUST NOT** build that rhythm from its own `paddingHorizontal` / `marginTop` / `marginBottom` / `paddingVertical` styles, and a card or row component **MUST NOT** carry an outer margin that spaces it from its siblings — the container's gap does. A shared content area **MUST NOT** carry the side gutter when a child draws a full-width bar (a safe-area footer bar): the gutter goes on each tab or body, so the bar reaches both screen edges; a negative margin **MUST NOT** be used to pull a bar back out (Android drops touches outside the parent's bounds). A text button (text / danger-text variants) starts at the content edge (no horizontal size-ladder inset, horizontal hit slop) and keeps the size ladder's minimum height: hit slop receives touches only inside the parent's bounds on Android, so a vertical slop in a short row would shrink the touch target below 44 pt. A self-hiding strip that sits outside the body (an offline strip under the header or a search band) **MUST** take its band position through its own placement prop rendered by the shared strip slot — a caller-side band wrapper stays rendered and leaves an empty gap while the strip is hidden, and a bare strip there has no gutter. A horizontal list (carousel) **MUST NOT** add the bottom safe-area end space — only the screen's vertical scroll ends at the safe area. A decoration a primitive draws outside its control (a highlight ring's halo and ripple) **MUST** stay inside the control room this rhythm keeps on every side (the inset token equals the screen gutter), and anything placed beside that control derives its distance from the same one value — a card's content layer and a scroll viewport clip exactly there, so a wider glow ends in a hard cut on most screens. Reason: spacing drifts into several gutters across screens, oversized gaps under tabs, a footer bar inset from the screen edges, and a carousel padded by the home-indicator inset. Verify: review; the authority's `style` type rejects spacing keys at compile time. |
| **STY-CMP-M33** | A card that opens in place to show hidden detail or actions **MUST** show it through the one expand mark (a chevron in a soft circle that turns up when open), and a card with nothing hidden **MUST NOT** show it nor clip its text. The whole card is the touch target and carries `accessibilityState.expanded` plus an open/close `accessibilityHint`; the open state is keyed by the record id at the list owner, never held in a recycled cell. Inside a virtualized list the card's height changes in one frame — no `LayoutAnimation` and no tweened height — because the list repositions neighbouring cells only after it measures, so an animated cell overlaps or jolts the cells below; the motion is the mark's rotation. Reason: an unmarked expandable card hides its content, and an animated height inside a recycled list jumps on iOS. |
| **STY-CMP-M34** | A value styled differently from the rest of its translated sentence (an amount in the due or number tone inside "400 to collect") **MUST** render through the shared sentence-with-value component: the whole sentence comes from one catalogue key with the value's placeholder, and the value is drawn where that language puts it. A screen **MUST NOT** draw the amount and a fixed word as two strings, concatenate a value before or after a translated fragment, or colour the whole sentence to emphasise the value. Reason: word order differs by language, so a value glued to one side reads wrong in half the languages, and colouring the whole sentence hides which part is the figure. |
| **STY-CMP-M35** | A third-party service logo glyph **MUST** take its brand colour from the one brand-glyph authority on a light surface, and the content colour of a filled or dark surface; the shared icon drawers (icon button, button, icon tile) apply it, so a screen **MUST NOT** colour a logo itself or leave it in a text tone. Reason: a grey or brand-green logo on one screen and a brand-coloured one on the next reads as two different actions, and a green logo on a green filled button disappears. |
| **STY-CMP-M36** | Every screen **MUST** lay out for the content column — the one area the app is drawn in on a phone, a tablet and the web — and work at every column width from the narrowest phone to the column's cap; a size derivation **MUST** also be defined for any smaller width down to 0 (a browser window, frame or collapsing pane can be narrower than any phone) and fail loud only on an impossible input (negative or non-finite), never leave the user on an error screen because the window is narrow; a screen or component that sizes, pages or breaks its layout by width **MUST** read the column size from the one content-column authority, never `useWindowDimensions` / `Dimensions.get('window')`. Only a window-level surface (a modal shell portal, a window-coordinate measurement) reads the window. Reason: on the web the window is wider than the column, so a window-sized page, card or breakpoint stretches, overflows or picks a tablet layout inside a phone-width column. Held by review. Wide clause: every screen **MUST** be designed for narrow and wide — one screen file with one data/actions source drawn in a phone arrangement and a wide (tablet/desktop) arrangement of the same content, chosen only by the one layout-class authority from the window size — width, and a phone-sized shortest side keeps the phone arrangement so a rotated phone never switches layout — never from device type or platform; the wide arrangement **MUST** be built from the shared wide primitives, **MUST NOT** add a query, total or rule the phone arrangement lacks, and **MUST NOT** leave out any part the phone shows, at any wide width (a narrowing table moves a dropped column under its row, never hides it). Reason: a per-screen breakpoint or device check splits one screen into drifting copies and leaves tablets and browsers with missing or stretched parts. Table clause: a wide list table **MUST** open every row, whatever the record kind, with the one record cell (tone icon, one title line, one meta line from the row's existing data) and draw its amounts with the shared table amount component (tabular digits, meaning tone), and a figure the page shows in a KPI tile **MUST NOT** be repeated as a total card on the same wide page. Reason: per-kind cells drift in height and secondary information, proportional digits misalign a right-aligned column, and a repeated total reads as a second number. Held by review: an uneven table row is a visual defect, not serious harm. |
| **STY-CMP-M37** | A command the phone reaches only through a touch gesture (long press, swipe, drag, hold) — and the follow-up action that undoes it — **MUST** also be reachable on a wide layout driven by a mouse through the one gesture-alternative authority: the gesture's handle opens a menu whose items call the same handlers, never a second command; the menu **MUST NOT** be mounted on the phone or a touch window, where the gesture stays the way. Pull-to-refresh is exempt (the browser's reload and the tab-return refetch are its pointer path). Reason: a mouse cannot discover a long press, so the command and its undo silently disappear on the desktop. Held by review: no automated check tells a command-bearing gesture from a decorative one. |
| **STY-CMP-M38** | A wide page's composition **MUST** come from the wide primitives' own decisions, never a screen's: (a) no layout class beyond phone / tablet / desktop — a larger window changes no arrangement, and the page column (header, body and docked context rail) stops at the one page cap the wide page layout applies and is centred right of the side nav, except a master-detail page whose master pane stays against the side nav; a screen **MUST NOT** add its own page-wide cap; (b) a capped block under a header row (a daily list, a settings pane) starts at the page's start edge, centring is only for a column that is the whole page; (c) one type scale on every class — the same content uses the same typography role as on the phone, no per-class or per-width font size, and nothing on a wide surface goes below the caption role except the tablet rail's short labels and count badges (micro role); (d) whether a page header is one row or two aligned rows (title row with badge, rail button and the one primary action at its end; toolbar row under it) is decided by the one stack function both the wide page header and any calendar header read, and a toolbar **MUST NOT** wrap raggedly or push the primary action to another line — commands that do not fit go into one overflow menu. Reason: per-screen caps, centring and header logic pull the same parts in different directions as each wide report is fixed alone, and on a large monitor the header, list and rail drift apart. Held by review: a scattered or misaligned layout is a visual defect, not serious harm. The adopting project keeps its wide-layout decision table. |

### **MUST NOT**

| ID | Rule |
|----|------|
| **STY-CMP-N1** | `elevation` (or a theme shadow level) together with `overflow: 'hidden'` on a single view — forbidden (the Android shadow is clipped). If content needs clipping, move it to an inner layer. Verify: search style files for `overflow` hidden next to `elevation` / shadow tokens; manual review — they must not share a style block. |
| **STY-CMP-N2** | In new code, a raw `<Switch>`, a raw `<TouchableOpacity>` used as an action button, a raw `<ActivityIndicator>` or a raw `<RefreshControl>` — forbidden. Use the shared primitive (**STY-CMP-M27**). Verify: a search for raw `<Switch` finds matches only inside the switch-row primitive itself. |
| **STY-CMP-N3** | The card's `contentStyle` (the inner clipping layer) **does not** draw ground, border, corner or shadow — the card edge comes from the variant; the inner layer carries only spacing and layout. Reason: a second edge on the inner layer draws a double frame inside the card and departs from the variant. State emphasis (selected, accent edge) is written to the outer `style`. A selection card that needs radio/checkbox semantics uses a non-pressable card inside a pressable layer that carries the role and `accessibilityState` (the card's `onPress` only gives a button role — **STY-CMP-M11**). |

## Canonical primitive inventory

The adopting project documents, for each shared primitive named by role above (card, button, icon button, icon disc, switch row, section header, money input, badge, chip, loading, banner, dropdown and select trigger, tabs, skeleton, divider, checkbox, empty state, modal shell with dialog / sheet / popover, text field, option row and groups, toast, progress bar, query-error screen, inline retry notice, alert dialog, refresh control, status label, icon tile, item card, word-safe text, weekday strip, list group / list row, screen layout, expand chevron, action footer, action sheet, sentence-with-value, brand-glyph colour), its single authority module, contract (variants and props), current consumers and the guard that protects it. This standard names the visual role and the rule; the inventory is the project's. A primitive missing a needed variant gains it in place; a second implementation is not written.

## Interaction / motion authority (press feedback)

| Authority | Contract |
|-----------|----------|
| Motion tokens (single authority) | The theme's motion export carries the duration ladder (instant / fast / base / slow), the press scale values, the springs (snappy, gentle), the shimmer duration and the entrance duration/rise. A literal magic number for animation is forbidden ([**STY-N6**](stylesheet-and-theme-tokens.md), [**STY-M12**](stylesheet-and-theme-tokens.md)). |
| Press-feedback hook | One hook returns the animated style plus press-in/press-out handlers (UI-thread scale + spring + a light haptic tick, with options for the target scale, haptics and disabled). With the operating system's reduced-motion preference on, no scale movement is applied; consumers do not rebuild this decision. A separate export serves toggle haptics. |
| Entrance primitive | One primitive for mount fade + slight rise, values from the entrance tokens; with reduced motion there is no rise or scale, only fade (**STY-CMP-M8**). |
| Skeleton shimmer | With reduced motion on, no shimmer loop is installed; the block is static. |
| Animated pressable (drop-in) | One pressable-scale primitive takes the usual pressable props plus target scale and haptics, with press feedback built in. It is the migration vehicle for legacy raw `TouchableOpacity` (**STY-CMP-M9**). |

The canonical press surfaces (button, card with `onPress`, chip, tabs, dropdown, checkbox, switch row with toggle haptic) use these authorities.
