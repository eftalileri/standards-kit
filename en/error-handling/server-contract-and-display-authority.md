## **MUST**

M13: When the backend error envelope provides `traceId` ([error policy](../error-policy/error-model-registry-and-boundary.md) **M17**), the client **MUST** surface it on the error / support surface (copy or share affordance) so a user-reported error correlates to backend logs and crash reports. Do not invent or alter it.

M14: When the envelope provides `retryable` / `category`, retry affordance and the error UX class **MUST** be derived from those fields, not guessed per screen: `retryable === true` → offer retry; `category` → UX class (e.g. `SYSTEM` → generic "something went wrong" + `traceId`; `BUSINESS` / `OPERATIONAL` → specific mapped message). The semantic `error` code stays the logic authority (**N9**). Automatic mutation replay additionally follows the selected client-mutation library’s standard: exactly one finite retry owner and replay-safety/idempotency proof; if an HTTP response exists, only envelope exact-true authorizes replay, while a truly response-less failure may use only the canonical structural wire-error `kind === 'network'`. Status/message/error-code strings are never retry authorities.

M15: Semantic error codes consumed by the client **MUST** come from the single cross-boundary contract defined by the consuming project (for example, a shared package in a monorepo) — not a deep import into backend internals, and not a hand-maintained copy of the code list. Codes remain server-authoritative (**N6**, **N8**). Where the project uses a shared monorepo package, follow its type-placement rules ([monorepo](../monorepo/monorepo-rules.md)).

M16: A caught error's raw text **MUST NOT** reach a user surface, and the client **MUST** convert a caught error into display text through exactly ONE authority. The message field of a throwable is a mixed channel: the transport adapter's internal diagnostic string, the HTTP client's own sentence, a validation library's text in *its* language, and the server's message already resolved in the caller's language all arrive in that one field, and none of them is written for the reader. One named client function therefore owns the whole conversion, and every surface — alert, toast, inline or field error state, blocking error region, rendered text node — calls it instead of repeating its own ladder; a second copy drifts invisibly, because each copy keeps producing text ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)). That authority's last branch is the caller-declared field text, never the raw message: the caller names the catalog key to show when no canonical branch matches, so an unclassified failure still yields owned copy instead of leaked or invented text. (a) A project-owned warning travels as a KEY, not as text. Where a client-side branch genuinely has something to tell the reader, the throw carries the catalog key on a typed carrier and the text is resolved at display time — so it survives a language change ([**SSG-M1**](../ssot/ssot-must-authority-and-derivation.md): the key is the authority, the rendered sentence is derived). Flattening such a warning into a generic string to satisfy this row is a regression, not a fix: the obligation is to move the sentence into the catalog, not to delete it, and the key owes every declared language the same completeness as any other catalog entry ([**I18N-CAT-M4**](../internationalization-rn/user-text-catalogs-and-parity.md)). (b) The diagnostic is moved, not destroyed. The same carrier keeps the developer-facing root-cause string in its message field for the log and crash-report channel; the split is between audiences, not between keeping and losing information. (c) Exactly one carrier shape. One implementation of that carrier exists and any domain-specific carrier derives from it — a per-domain copy is the same parallel authority one layer down. (d) The carried key **MUST** name its namespace (`<namespace>:<key>`), and so **MUST** any key a shared helper hands to callers it does not own. The producer does not know which surface will display it; the display authority resolves it with that surface's translator, so a bare key renders as raw key, as the caller's fallback text, or as a same-named sentence from another namespace depending on what the displaying screen happens to bind. The carrier's constructor type admits only namespace-qualified keys (enforced by the client typecheck).

Enforcement: A raw-text read reaching a display sink is decidable from one file’s syntax tree. Where the consuming project uses static analysis, enforce this over the complete client source scope; do not rely on a hand-maintained directory list. Manage pre-existing findings through the project’s documented false-positive or staged-adoption policy, and state any coverage limits.

M17: A branch that decides on a registered error code **MUST** read that code from the carrier's structural field and compare it by equality; searching the code as a substring of a text field is forbidden. This is **M16**'s mirror. **M16** stops the mixed text channel from reaching the reader; this row stops the same channel from being used as *evidence*. Where a client builds its throwable from the server's already-localized user sentence — the shape **M16** describes — the code is carried in a separate field beside it and never enters the sentence, so `text.includes('<CODE>')` compiles, type-checks, lints, runs, and can never match. The failure is not an error but an absence: a decision branch that is silently never taken, which no behavioural diff and no crash report reveals, while the user gets the generic path instead of the flow the branch existed to open. (a) Re-measure the predicate where the carrier is CONSTRUCTED, not where it is read. The reading site looks correct in isolation; only the construction site says which field holds the code and which holds prose. A predicate written against a carrier that later changes shape dies exactly this way, so a carrier change re-opens every predicate that reads it. (b) One instance is a class — sweep it from the code AUTHORITY, not from the code you found. Grepping the single code that surfaced re-measures the symptom; the sweep enumerates the authority's registered names and asks which of them any text predicate mentions.  (c) A dead predicate is rewired or deleted — measure which. Ask whether that call site can ever receive a carrier that crosses the boundary at all. If it can, rewire it to the structural field. If its input is only ever locally produced — a form validator's own already-translated output, say — the branch is not merely dead, it is *misplaced*: rewiring it there opens a second dead branch, so it is deleted with the identifiers that served only it ([**DCD-M2**](../dead-code/dead-code-rules.md), [**DCD-M9**](../dead-code/dead-code-rules.md)). (d) The correct form never needs the wrong one as a fallback. Once the code is read structurally the value is the whole code, so a prefix or substring test beside the equality test is not extra safety — it is the dead predicate kept alive as a second authority ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)).

Enforcement: The predicate “a registered code appears as the literal argument of a substring search” is decidable from one file’s syntax tree. Where static analysis is used, gate this form and derive code membership from the runtime code authority itself, never from a parallel name list ([**FP-M32**](../false-positive/check-verification-rules.md), [**FP-M33**](../false-positive/check-verification-rules.md)). This keeps the check off unregistered transport strings, locally thrown invariant identifiers, and form-validation codes that legitimately travel in text fields. Equality comparison remains the prescribed form.

## **MUST NOT**

N6: Client-only semantic error codes that contradict the backend registry in error policy.

N8: Invent new semantic API error codes on the client — codes come only from the server response and the registered set in error policy.

N9: Transform the semantic meaning of a backend error code for application logic (e.g. branching as if a different code was returned). Display copy and i18n labels may vary; logical code identity must not.

N10: Override backend error classification for authorization, billing, or compliance decisions — the server is authoritative; the client maps to UX and logs only.

N11: Duplicate the backend error-code catalog on the client — no hand-copied code list and no deep relative import into backend internals. Import the shared contract (**M15**); a local copy drifts from the server authority.

N12: Put a caught error's raw text (its message, its stringified form, its stack) on a user surface at all, or resolve display text through a screen-local ladder beside the single client authority (**M16**). This row removes **N3**'s qualifier: **N3** forbids raw text as the *only* user message, which still permits it concatenated with owned copy — it is not shown at all, alone or combined. Reading that same raw text into a log or crash-report field is out of scope here (that is where **M16**(b) moves it); using it as a classification input is prohibited on its own grounds and is not licensed by this row.

## Enforcement admission

A producer-side raw-error check is not mechanically enforced: a single typed warning carrier already owns user text, and a file-local throw cannot establish downstream display reachability or product intent (a single-file AST has no marker for either). A focused rule can lock the single-file sink half, while upstream carrier choice remains review-bound until the project exposes a machine-readable user-facing-intent marker.
