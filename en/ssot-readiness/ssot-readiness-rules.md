## **MUST**

**M1**: Single readiness gate: For multi-source screens, all required sources (lists, inits, guides) feed one derived `isReady` (or equivalent). UI (loading / form / pickers) behaves from that gate — no scattered per-source "ready" flags driving mount order. This single-gate principle applies to any multi-source derived display value (cards, rows, labels) — not only form / selection screens. Every required async source **must** be folded into the one readiness signal; excluding a required source from the readiness derivation is a violation (**N1**). A render-path derivation **must** treat a not-yet-loaded source as not-ready and wait — never throw on `pending` ([TanStack **UIP-M17**](../tanstack-query/ui-loading-and-persist-options.md) / [**UIP-N3**](../tanstack-query/ui-persist-offline.md)). This no-render-throw rule covers every recoverable query state, not only `pending`: (a) `isFetching` (background refetch) — render from cached data, never throw; (b) `isError`, including a post-cache background-refetch failure where valid cached data still exists — self-heal from the cache (resolve the value from cached data and return `ready`); if no usable cached data exists, return a non-throwing `error` status that the consumer hook surfaces via its own `isError` / `error` so the screen shows a graceful retry UI — do not `throw`. A render-path derivation (a `useMemo`, or any helper called during render) that `throw`s solely because a query is loading / fetching / errored is a bug: it converts a transient, recoverable condition into an `ErrorBoundary` white-screen. `throw` inside a render-path derivation is reserved only for genuine data-integrity invariants on already-loaded data (e.g. a successfully-loaded record missing a required field, or `isError === true` while the `error` object is `null`) — fail-loud there, never for query-lifecycle state. The `error` status **must** flow to the same graceful surface the hook already exposes for its other query errors (parity: every query error of a hook reaches `isError` / `error`, none is escalated to a render `throw`).

**M2**: Async completion: Form fields and selectable UI **must not** mount for user interaction until `isReady === true` (or equivalent) — all async prerequisites for that phase are satisfied; if that cannot be established, STOP.

**M2** is enforced by review, asked per required source (a gate may cover one source and leave a second ungated): does the mounting component withhold the form until the same readiness signal is true? No check is opened because the state-writing effect lives in the screen's hook module while the readiness gate lives in the mounting component, so no single file decides it, and a single-file predicate would open red on correctly gated async form/selection writers (**ENA-A1**(d); [**FP-N13**](../false-positive/check-design-rules.md) forbids absorbing them as a warning floor).

**M3**: SSoT guard, validation, or normalization failures **must** be logged (project logger / telemetry per stack) and **must** surface user-visible or thrown signal per [error handling](../error-handling/error-handling.md) — no silent swallow (**N3**).

**M4**: Submit **must** run only when the readiness gate is true; submit handler **must** re-check or read from the same gate state — no API calls with intentionally incomplete multi-source state. A form section exposing an imperative submit handle **must** use the same composed readiness gate for editable content and that handle; its owning submit branch **must** read it before obtaining rules or sending. A usable cached prerequisite remains ready after a failed background refresh (**M1**/**M9**); a projection consumes its query authority's readiness rather than reconstructing it from success status, so a cached prerequisite's refresh failure cannot unmount and discard an editable draft. Missing prerequisites remain unready; a prerequisite's pending and error states use its existing loading/error/retry contract. Stated enforcement limit (**ENA-GV3**): the missing fact is whether the caller's submit branch reads the same gate as the component's content/ref; it is a cross-module data-flow relation absent from a single-file AST. The existing query readiness authority and single section gate hold the behavior; a new lexical check over flag names is rename-bypassable and fails **ENA-A5**(iv). Review verifies the submit branches and retained-cache paths, so no new lint rule or guard is admitted.

M5: Calendar day strings must use YYYY-MM-DD end-to-end; parsing and formatting must use one shared helper or module — do not pass raw `Date` or `toISOString()` values for day semantics across navigation or state (N4).

**M6**: Phone / contact input **must** pass through one normalization entry point (function or service); failures **must** use [error policy](../error-policy/error-policy.md) message shape or [error handling](../error-handling/error-handling.md) user rules — detail in [phone normalization](../phone/normalization.md) (**PHONE-M1**, **PHONE-F***).

**M7**: User-facing validation copy **must** follow: `[Field label] — [validation text]. Root cause: [why]. Solution: [one action].` (same intent as [error handling **M3**](../error-handling/error-handling.md)).

M8: A selected entity must have one read/write authority; all writes must go through the documented handler set (for example, select/deselect) — no parallel write paths (N6).

M9: Offline-first / cache: If the stack uses a cache: (1) show cached data when present, (2) refresh in the background, and (3) show loading only when there is no data yet or on explicit user action — do not block the whole screen when cached data can be shown.

M10: Before changing a screen governed by a project-specific architecture contract, read that contract (agent execution contract C6).

**M16**: Readiness is derived at the query's own layer — a raw loading flag is not a gate. A disabled query reports "not loading" while holding no data: in TanStack Query v5 a query with `enabled: false` returns `isLoading === false` and `data === undefined` (the same shape applies to any client whose loading flag means "a request is in flight", not "the value is known"). Therefore a raw `isLoading` / `isFetching` flag **must not** be used as the readiness gate — it reports *not-ready* as *ready-and-empty*, and every consumer that gates on it will treat an unavailable source as an authoritative empty result.

The gate **must** be expressed as one derivation owned by the query hook itself (e.g. `isReady`), so no consumer has to re-remember the contract (**M13** / **SSG-M6**). That derivation **must** fold in every reason the value can be unknown:
1. the query is disabled (its own `enabled` inputs are unresolved — including a permanently unresolvable precondition, not just a transient one);
2. it is pending (no data yet);
3. it is in error with no usable data — an error **must not** be collapsed into "loaded but empty"; and
4. `data === undefined`.

The hook may still expose the raw flags, but only for presentation (spinner / skeleton), and its contract **must** say so. Consumers **must** read the derived gate. Corollaries:
- Empty-because-unready is not empty-because-true. A derivation that consumes the source (a display name, a validity check, a resolver that throws when it finds no match) **must** treat "source not ready" as *wait / show the documented placeholder*, never as a data-integrity violation. Classifying it as a defect sends a crash-channel event on every render for a condition the user cannot cause and the code cannot fix (see [client observability](../client-observability-rn/client-observability-rn.md) and [logging policy](../logging-policy/logging-policy.md) severity routing).
- Not-ready can be permanent. "It will arrive shortly" is not guaranteed: if the gate's precondition never resolves, the source stays empty for the whole session. A gate that is only correct for a short loading window is not a gate.
- Permanent-unavailable reason is part of the authority. A single unexplained boolean must not collapse a legitimate no-active-context state into the same terminal defect channel as a structurally broken session; the query-layer authority derives a closed reason and consumers branch on that reason.
- A multi-field readiness snapshot is readonly and **must not** escape as a mutable decision object. Its fields are readonly at the type boundary. Consumers read explicit primitive fields; if a pure downstream resolver needs part of the decision, pass the required primitive fields rather than the whole snapshot. Mutation, aliasing, spreading, returning/exporting, or passing the whole snapshot to an unknown call destroys the guarantee that the network gate and reason came from the same immutable observation.
- Negation can hide in a branch, and the enforceable predicate is narrower than the prohibition. A readiness value written as `mode ? !loadingFlag : otherReadyValue` is incorrect on the branch where the negated flag alone decides. A project-specific mechanical check may recognize a readiness binding whose value on at least one path is only the negated loading flag, including member access such as `query.isPending`. It must not report a conjunction such as `!pending && data !== undefined && error === null`: sibling conditions may close the disabled and error cases. Whether those conditions genuinely discriminate usable data and errors is not decidable from syntax alone; review the query-layer derivation.
- A closed reason is half a contract — the consumer **must** bind every member. A boolean projection of the union, or a two-armed ternary, answers for one member and silently absorbs the next one added: neither the type checker nor an exhaustiveness lint rule sees either shape. Bind every member with compiler-checked exhaustiveness: a `switch` whose `default` assigns to `never`, or an immutable object literal that enumerates the entire reason union and `satisfies Record<Reason, Result>`. A new member **must** break compilation through a missing case or key; an unchecked cast, dynamic string index or fallback is not this proof. This keeps one closed classification pipeline rather than freezing one source spelling.
- A shared prerequisite used by sibling queries produces one discriminated readiness result. Sibling endpoint hooks may retain different query keys and payloads, but they **must** delegate the prerequisite/pending/error/cache formula to one pure authority. Consumers receive that closed result together with the matching data and refetch owner; they **must not** reconstruct readiness from booleans while forwarding props through component layers.
- Presentation projections consume readiness; they do not own it again. A reusable presenter may map an existing query-owned closed reason to loading, unavailable or error presentation, provided the projection is readonly, binds every existing member with a `switch/default -> never`, and retains the original failure and same-source recovery controls. It **must not** copy the reason union, add a local loading-only presence formula, or resolve an unknown value to a fallback. A resolved value that violates its existing strict invariant remains an explicit original failure; pending, missing scope and missing data are not that invariant failure. Its memoization depends only on that value's actual inputs: a background query error **must not** recreate the same resolved invariant under a new error identity while ready source data is unchanged. Raw query errors and their upstream owner remain intact. Usable enabled, non-placeholder data belonging to the target key remains authoritative during a background error. A prerequisite presentation change **must not** remount an editable consumer or discard its independent draft intent. A different query family owns its own readiness derivation and response-shape provenance; it **must not** inherit previous-key data or manufacture a response field to resemble another family's contract. Its composed readiness/recovery carrier remains readonly at the consumer boundary. Stated limit: type exhaustiveness proves coverage of declared reasons, not that the query data belongs to the actual target, that recovery/error came from that source, or that sibling failure, original invariant identity and consumer identity are preserved; those relations require review of the query and its real consumers.

The reason union remains owned by the existing query layer, not by the presenter. Other query families retain their own response-shaped provenance/readiness authority rather than copying another family's contract. Closed types, the strict value helper, query-owned controls and observed-aware reporting are stronger local mechanisms; source/error/refetch/sibling and consumer identity relations remain review-held. No new rule, band, guard, ID or global retry policy is introduced.

Explicit entity-edit application. An editor with a route-supplied entity target reads, validates response identity, submits and reconciles that same captured target; ambient active selection is not its write authority. Its query-layer verdict excludes previous-key placeholders and proves usable data belongs to that target. Every required companion lookup joins the form/submit gate; data-less pending waits, terminal absence/error exposes its owning retry, and usable exact-key cache survives background failure. Stored fields remain display seeds: only changed user intent becomes the shared-schema optional patch ([forms **M15**](../forms/forms.md)), and submit rechecks the same gate. Post-await UI/cache publication consumes the operation's canonical current-session/scope proof; a lost lifetime cannot publish into another actor/context ([**ZSP-M7**](../zustand/store-persist-and-module.md)). Confirmed writes and separate failed/cancelled follow-up retain truthful typed outcomes ([**COB-RN-M12**](../client-observability-rn/absorbed-defaults-and-global-nets.md)); this gate does not assert transport-egress or server-commit proof. Stated enforcement limit: exact target association, prerequisite completeness and post-await lifetime are cross-file data-flow relations; required-target/types/shared schemas and the existing source verdict are the stronger mechanisms ([**ENA-A1**](../enforcement-architecture/enforcement-admission.md)). Review holds the remaining relation; no new naming-based rule or guard is admitted.

**N10**: Using a raw `isLoading` / `isFetching` flag as a readiness gate, excluding `isError` from a readiness derivation (treating a failed source as an authoritative empty one), or re-deriving readiness per consumer instead of once at the query layer — forbidden (**M16** / **M13**).

## **MUST NOT**

**N1**: Treat sources as independently "ready" and mount form pieces at different times in a way that creates broken intermediate UX (empty lists, dead controls) — violates **M1** / **M2**. Includes excluding a required async source (e.g. a list query) from the readiness aggregate so a consumer renders against an unready / empty source, or throwing from a render-path derivation while that source is still loading instead of gating on it.

**N2**: Silent catch or fallback on validation or normalization errors — no user signal and no log/telemetry (error handling **N1**).

**N3**: Submit or mutate when readiness gate is false (**M4**).

**N4**: Use `toISOString()`, raw `Date`, or ad-hoc strings for day identity when **M5** requires **YYYY-MM-DD**.

N5: Set selection outside the approved handlers (e.g. an effect that resolves an identifier and writes selection, or a direct cache write for selection) — M8 violation. A project-specific AST check may enforce recognizable value writes; a `null`/`undefined` reset inside an effect remains a review obligation unless machine-readable product intent distinguishes a lifecycle reset from an overwrite of the user's choice.

**N6**: Bypass patterns in [Anti-patterns](ssot-readiness-and-form-data.md#anti-patterns-forbidden) — STOP and refactor.

**N7**: Mega-state anti-pattern: One hook or store holding unrelated form domains (selection + unrelated lists + ad-hoc flags) as the "SSOT for the screen" — violates **M11** / **SSG-M0**.

**N8**: Skip-read anti-pattern: Implementing form/selection changes without reading the relevant rules (this topic's, and the ssot/ ones when backend/types are involved) — violates **M12** / **C10**.

**N9**: Deferred-consolidation anti-pattern: Adding a parallel authority while keeping the old one "until refactor" — violates **M14** / **C11**; STOP and merge in one change.
