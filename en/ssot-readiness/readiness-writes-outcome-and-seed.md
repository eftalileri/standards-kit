## **MUST**

**M17**: An outcome flag **must** record the outcome, not the attempt. A flag that consumers read as *"this step succeeded"* (`hasInitialized`, `isReady`, `isBootstrapped`, `hydrated`, …) **must** be written only on the path where the step actually succeeded. It **must not** be written from a `finally` block or any other always-runs cleanup path: `finally` executes on the throwing path too, so a success flag set there silently reclassifies a failed run as a successful one. Every downstream gate that reads it (splash dismissal, screen mount, "the app is usable") then opens on a half-built state, while the real error survives only as an unhandled rejection — if at all.

A lower boundary that reports an error and returns a compatibility fallback (`[]`, `null`, `0`) has still failed. When that value drives readiness, the adapter **must** preserve a separate typed failure outcome: a genuinely successful alternate authoritative read may recover the step, but the fallback alone cannot set the success flag.

Two different facts need two different signals: "the attempt is over" (release an in-flight lock / reset a mutex ref — legitimate in `finally`) and "the attempt succeeded" (what the gate consumers read). Collapsing them into one flag is the defect. Corollaries:
- The failure path **must** exist and be reachable. A failing step **must** route to the surface the product already uses for a failed startup / failed load — an error state with an explicit user retry — through the same message channel (i18n key) as the other failures of that phase. Inventing a second, parallel failure surface for one step is an SSOT violation (**M13** / **SSG-M8**).
- A fire-and-forget async initializer **must** own its rejection. `void init()` with no rejection owner reports nothing to the user and nothing to the crash channel; re-throwing inside such an initializer is equivalent to swallowing it.
- When the failure surface itself needs a resource the failed step was supposed to provide (e.g. an error message needs the i18n layer that failed to initialize), that resource **must** be brought up beforehand from a *display-only* provisional source, so the error is presentable. A provisional display value is not an authority write — see **M15**.
- Mechanically enforceable: the core of this rule is decidable from a single file's AST — a success-semantic flag assigned `true` inside a `finally` block. An adopting project may add a corresponding check if it meets the enforcement admission criteria.

M18: A navigation/route parameter is a SEED: it is derived, never written into the selection it seeds. When a screen takes the initial value of a selection from a route parameter, read the seed as a derivation. Keep any user choice as a *separate override bound to the seed it was made against* so that when the seed changes, the derivation returns to it on its own (self-healing; no effect required). Writing the seed into selection from an effect (`useEffect(() => setSelection(route.params.x), [...])`) is the forbidden shape of M8/N5. It creates two writers when the state is also seeded at initialization, can produce a visible correction after the first render, and can silently revert a user's own choice when the effect runs again after navigation.

- One shared authority, not a per-screen copy. The seed→override reconciliation is a *canonical derivation* (**SSG-M1**): it belongs in one feature-independent hook that every screen calls. Re-implementing it locally is exactly the parallel-authority defect this section exists to prevent (**SSG-M8**).
- A seed **must** outlive the derivation that reads it — and a list head is a seed too. The carrier is not always a route parameter. The same shape appears when one surface hands a *one-shot value* to another as a prop (a just-created record passed down to the sheet that will use it), and when the default is the head of a derived list (the first row of a freshly loaded set). In every form the producer **must** keep the seed readable for as long as the consumer derives from it, and the *"this has been consumed"* handshake **must** fire when the consumer is done with it — it closes, unmounts, submits — never at the moment it opens. Clearing the seed at open is what forces the consumer to copy it into its own state first, so the copy that gets flagged is a symptom and the handshake's timing is the cause; moving the handshake is the fix, and suppressing the copy is not. Where the seed is a list head, the reconciliation is the same two parts: a readiness gate decides the list is genuinely loaded — an empty list and an unloaded list are different facts (**M16**) and neither may produce a selection — and then the user's override is narrowed to the ids that actually exist, with the head as the fallback. That narrowing is the shared reconciliation authority, not a per-screen re-implementation (**SSG-M8**), and it is strictly safer than an effect that only corrects an *invalid* selection: when the list empties or goes unloaded, the derivation yields nothing while the effect leaves the stale id standing. Stated limit ([**KIT-INV-8**](../authoring/kit-structural-invariants.md)(b)): no single-file AST can decide this one. The seed's producer and its consumer are different files, and *when* the handshake fires is a call-order fact that no declaration in either tree carries. The copy it provokes is still fenced at the consumer (the selection-set-in-effect rule), so what review **must** add is the timing question — *does the producer still hold the seed while the consumer is reading it?*
- Mechanically enforceable — with a stated limit. The core is decidable from a single file's AST: inside an effect, a `set*` call whose argument traces to a route-parameter chain. Any check must follow the argument to its source rather than match a bare member expression; it must also account for defaults (`?? fallback`) and conditional branches. Limit: when the seed reaches the writer as a function parameter from another file, a single-file AST cannot see its route origin; that class needs cross-file dataflow and remains a review obligation unless the project has such a mechanism.
- When the write path CANONICALIZES, the seed comes back canonical — so a change check **must** compare the canonical form, not the raw fields. A value the authority normalizes on write (a phone number to E.164, an address, a slug, a rounded amount, a timezone-shifted instant) returns in a *different string* from the one the person entered. A dirty/unsaved check that compares raw input fields against a seed re-derived from the stored value therefore reports a change on a record that was just saved successfully, and it does so permanently — the person is asked to confirm a discard on a saved form, or learns to dismiss the warning and misses a real one. The check **must** put both sides through the same canonical derivation, and it **must** consume the authority the write path already uses ([**SSG-M1**](../ssot/ssot-must-authority-and-derivation.md)) — opening a second normalizer to serve the comparison is the parallel-derivation defect one layer down. Where that authority rejects an in-progress input, "not yet canonical" is compared as itself, not swallowed: identical raw input stays not-dirty and any difference stays dirty. The rule extends past the compared field: an input that only *feeds* the derivation and is never stored — the country selector behind a canonical phone, the unit behind a stored base quantity — is not a fact of the record and **must not** be a dimension of the comparison at all; comparing it treats a derivation's input as if it were the authority. Limit: no single-file AST can decide this, because the canonicalization lives on the write path in another tier; what would be needed is knowing which stored fields the authority rewrites on write, and no declaration in the tree carries that.

## **MUST NOT**

**N11**: Writing a success / readiness flag to `true` inside a `finally` (or any always-runs cleanup), leaving a fire-and-forget async initializer's rejection unowned, or letting a failed initialization step end without a user-visible retry surface — forbidden (**M17**).

**N12**: Writing a route/navigation parameter into the selection it seeds from an effect, re-implementing the seed→override reconciliation locally instead of calling the shared authority, or clearing a one-shot seed at the moment its consumer opens rather than when that consumer is done with it — forbidden (**M18** / **M8** / **SSG-M8**).
