## Logging (SEC-LOG) — credential containment

| ID | Rule | On violation | Verify by |
|----|------|--------------|-----------|
| **SEC-M-LOG-1** | Production logs **must not** contain tokens, refresh strings, API keys, passwords, full Authorization header, or equivalent secrets. | Bug; possible breach class. | Log review + lint. |
| **SEC-M-LOG-2** | A credential-bearing driver or connection failure is contained at its first credential-aware operation boundary, and its raw text never crosses into a general API, logging or crash-reporting boundary. (a) Write boundary. A persistence / driver operation that writes a live credential (including a replayable purchase / transaction token) classifies duplicate / idempotency evidence from allowlisted structural facts (for example a numeric driver code) into the domain's honest idempotent outcome or registered semantic error; every other failure becomes a credential-free typed `SYSTEM` error with only allowlisted non-secret context such as operation and entity id. A repository does not invent an HTTP-facing code; the immediate domain / service boundary maps it per [REP-M-7](../repository/repository-boundary-and-atomic-claims.md) / [REP-N-3](../repository/repository-contract.md) and [error policy](../error-policy/error-policy.md). (b) Connection boundary — the most dangerous instance. A datastore / cache / broker client is built from a URI that embeds the password, so its construction, connect, authentication, URL-parse, probe, handshake, cleanup and `'error'`-event failures can carry the whole connection string, so the boundary turns each into a cause-free registered `SYSTEM` carrier. This binds runtime bootstrap, health checks and operator / maintenance scripts alike, and an `'error'` / `'uncaughtException'` / `'unhandledRejection'` listener is a containment boundary exactly like `catch`. The surrounding bootstrap catch does not attach the raw rejection as `cause`, but keeps its own noncredential causes, retry timing and permission / arming distinctions; a cleanup rejection after an authority refusal does not turn that refusal into a retry. An operator script routes connect / disconnect through the same narrow credential-aware API rather than a generic output catch, and keeps the primary error and a nonzero exit over a later cleanup failure. Every other credential-bearing operation — a body write, session / commit / abort, a provider bag, a runtime error event — has its own first boundary and inherits no protection from wrapping connect / disconnect. (c) What crosses. Never the raw `Error`, `message`, `stack`, `cause`, result payload, stringification, or a truncated or locally masked form of the connection URI (that form is disclosure — emit a boolean presence flag). The carrier keeps the project's structural-evidence facts (validated error class, allowlisted driver code, transient / permanent classification), and a later aggregate carries them through the source-owned provenance reader instead of re-wrapping them, so diagnosis survives containment. (d) Key-based or value-level downstream scrubbing (SEC-M-LOG-3) is defence in depth, never permission to forward the raw throwable, because a driver may embed the credential value in opaque free text where no key remains; no second classifier, sanitizer, lifecycle runner or retry policy is introduced. The narrow connection API is the stronger mechanism ([ENA-A1](../enforcement-architecture/enforcement-admission.md)(c)), so no generic check is admitted. | Security bug; possible live-credential disclosure through logs / crash reporting. | Credential-bearing write boundary review + forced driver duplicate / validation failure log inspection + forced connect/auth failure on bootstrap and migration paths. |
| **SEC-M-LOG-3** | The single project logger wrapper **must** pass structured metadata from every level (`error`, `warn`, `info`, `debug`, `http`, or the stack-equivalent set) through the same shared credential predicate and bounded recursive scrubber before any stdout/stderr, file, hosted-log, metric, or crash-report transport receives it. The scrubber **must** be case/separator-insensitive, cycle-safe, depth/entry-bounded, and fail-safe for unreadable enumeration/getters so adversarial metadata cannot crash logging; a local surface may add stricter PII keys but **must not** replace or copy the shared credential authority. Key-based scrubbing protects keyed structured values only, so the same shared authority **must** carry a second, value-level pass applied to every string it reaches — scheme userinfo, `Authorization` schemes, JWTs, published vendor secret prefixes, and `key=value` pairs whose key the key predicate masks. Free text is therefore scanned, not deleted by field name: deleting by name erases the diagnosis at the one field that carries it and still misses the same secret under a different name. The scan is a safety net for text that reaches the sink unavoidably (the error's own message and stack); it does not relieve the credential-aware source boundary of SEC-M-LOG-2 / SEC-N-LOG-1–2, and it does not extend to the HTTP response body. Pass order is part of the rule: shape-anchored scanners (scheme userinfo, `Authorization` scheme + token, JWT, vendor prefix) **must** run before the key-anchored pass, because a key-anchored mask stops at the value delimiter and can overwrite the very anchor a shape scanner depends on. Where a credential-keyed value is a scheme word, the key pass **must** additionally consume the token that follows it; and no pass may re-scan a redaction marker another pass already wrote. Every key predicate and value scanner in that authority, and every request-snapshot or route-key normalizer that feeds it, **must** cost time linear in its input length, because it runs on client-chosen key names, paths and strings on every error response, including the unauthenticated not-found response: a nested loop over input-derived segments **must** be bounded by a length derived from the authority's own token sets, and a regex **must not** let an unbounded quantifier be retried from many start positions over the same character run (a trailing `X+$`, a line-break lead followed by `\s*`, a run that must end in a delimiter) — restructure it or consume the failed run once. Super-linear cost there is an unauthenticated event-loop denial of service. | Security bug; a lower log level or hosted-log transport can bypass redaction, malformed metadata can disable observability, or one crafted request can block the process. | Static wrapper-wiring lint + forced nested/cyclic/getter metadata inspection + hosted-log sample + timing of each predicate/scanner on a large adversarial input against the previous version. |
| **SEC-M-LOG-4** | The masking criterion is live capability: **MUST** redact passwords, secrets, API keys, access/refresh tokens, authorization headers, cookies, session ids, private keys, signatures, OTPs, purchase/transaction tokens, replay/idempotency keys and connection strings. Under the adopting project's documented readership model (for example a single-operator model), access-free identifiers and business data remain diagnostic data; [SEC-M-LOG-5](security-logging-core.md) overrides this for raw pagination values. Free-text message/stack/cause/URL/provider text **MUST** pass the shared value-level scan of SEC-M-LOG-3 and retain safe structural class/code facts alongside it; deleting text by field name is forbidden because it destroys diagnosis and misses the same secret under another name. This relaxation is observability-only, never HTTP response permission. Undefined provider bags **MUST** be redacted or held only in the access-controlled durable inbox/audit authority with its retention policy; live tokens/OTPs are omitted at source. Unkeyed low-entropy digests are not anonymization and **MUST NOT** be introduced or retained as a safety measure; use request/trace correlation or a versioned, rotation-owned keyed pseudonym. When readership widens beyond the data owner (team, enterprise or processing obligation), **MUST** re-evaluate this decision and omit provider customer/account ids, original transaction/order ids, purchase references and phone/email-derived internal ids from general logs, typed context, API errors and crash extras; use a non-PII internal id or documented pseudonym, with explicit presence booleans allowed. Tags remain governed by the separate corollary regardless of readership. Every new provider-to-server boundary **MUST** run its body through the masking authority with a canary and record live credentials or project-undefined bags in the same change. A credential name that never means business data (a recovery, reset, backup or SMS code, a PIN, a passphrase) **MUST** live in the shared key authority, which masks it at runtime whatever schema syntax carries it; a body field whose credential meaning depends on the route (an OTP named `code`) **MUST** get a row in the route-scoped masking registry in the same change. No syntax shape alone decides these semantics; review them. | Privacy/security bug in either direction: a live credential, an unproven free-text value, or an undefined provider bag reaches a broad observability sink -- or, under a widened-readership model, PII-backed identifiers do. Equally a defect: a surface-local list masks an identifier the criterion deliberately keeps visible, making the root cause unreachable and creating a second key authority (SSG-M8). | Source-boundary review + shared scrubber adversarial key sample (**must** redact credential keys and **must** leave identifier keys intact) + forced driver/connect failure free-text inspection + hosted-log / crash-report inspection. |
| **SEC-M-LOG-5** | Raw pagination/continuation values are absolutely forbidden at every observability egress: logs, crash-report events, breadcrumbs, metrics, tags, typed error context, and access logs. This is a narrow overriding exception to SEC-M-LOG-4's general identifier treatment. Vendor/provider, encrypted, signed, opaque, and first-party cursors are all omitted at source; emit only a bounded presence fact such as `hasCursor` plus the canonical request/trace id. A first-party cursor may be authorized for HTTP transport and its decoded tenant scope may be re-verified against the caller, but those are access-control/data-integrity permissions only — they never grant permission to log the encoded or decoded raw cursor. User-facing text likewise carries no raw cursor. | Privacy/security bug: a continuation payload, its scoped query state, or its embedded identifiers escape through a broad observability sink; authorization is incorrectly treated as observability consent. | AST/static negative probes for every observability sink + hosted-log / crash-report inspection; positive probe permits only presence boolean and request/trace correlation. |

SEC-M-LOG-4 tag corollary (binding -- deliberately NOT relaxed by the SEC-M-LOG-4 masking criterion; crash-report tags are a separate egress surface with their own cardinality, indexing, and retention behavior, and the criterion's single-operator scope was never tested against it, so this corollary stays binding as written regardless of readership): classify an identifier by the value it can contain, not by an `...Id` label or an assumption that internal ids are anonymous. A tenant/entity id that embeds or is derived from phone, email, or name is PII-backed. Crash-report tags are a separate egress surface from `extra` / `contexts`; scrubbing only those containers does not sanitize tags. A tag allowlist therefore accepts only independently non-PII values or a separately versioned, rotation-owned keyed correlation pseudonym, and **must** omit the raw PII-backed key on every runtime that cannot produce that pseudonym safely. Do not call or retain a plain SHA-256 digest as “non-reversible”, “anonymous”, or an acceptable tenant tag when the input may be enumerated. Legacy top-level raw PII-backed tenant metadata **must** be scrubbed without first deriving an unkeyed digest; use the existing request/trace id for correlation until a keyed pseudonym authority and its secret lifecycle are proven.

SEC-M-LOG-4 breadcrumb corollary (binding): retaining diagnostic route context does not authorize a generic navigation payload. Only a registered, type-closed UI route/screen identity from an exclusive project-owned producer may survive as one allowlisted structured field. Free-text messages, params, raw path/URL, user or business identifiers, cursor/continuation values, caller-added fields, and fallback-derived names remain omitted; the sanitizer rebuilds the object rather than forwarding the producer's bag. String shape or a familiar route-looking value is not provenance.

SEC-M-LOG-4 grouping-fingerprint corollary (binding): a crash-report fingerprint is an indexed grouping key, the same egress class as a tag, so the free-text relaxation does not reach it. Keep one only when an exclusive project-owned marker leads it and every part matches a closed identifier shape under bounded length, part count and digit run, rebuilt rather than forwarded; delete everything else. Deleting it unconditionally is equally a defect once a workflow freezes one deliberately: see [M39](../logging-policy/crash-report-delivery-receipt.md).

SEC-M-LOG-4 URL-path capability corollary (binding): a route that carries a bearer capability in its URL path (a manage or magic-link token) **MUST**, in the same change, add the path's shape — fixed segment plus the minted token's exact length and alphabet — to the shared value-level scan of SEC-M-LOG-3. Logging the route template and masking every route param is not enough: the crash SDK's request URL, a `Referer` header from the page that holds the link and the raw path of an unresolved route still carry it. Reason: the capability acts on the resource or account for anyone who reads it. Verify: one positive sample (path with a minted token is masked, the segment kept) and one negative sample (same segment with another shape untouched) through the shared scrubber.
