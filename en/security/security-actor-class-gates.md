## Zero trust — the actor-class question

SEC-M-ZT-6: Every tenant-scope path **MUST** prove both the tenant and the actor class in the same request before operational read/write.

- (a) Route middleware or a delegate may hold the gate only when its rejection is traceable. The gate precedes record reads: not-found versus denial must not reveal existence/business state to a rejected actor; rejection is independent of record existence.
- (b) Close the sibling class, not one endpoint. On measured-clean surfaces a mechanism **MUST** prevent adding an ungated sibling; a manual sweep alone does not close the class.
- (c) A narrowed check declares its measured-clean scope and residual counts (FP-M18). Open every finding's actual gate before classifying missing protection versus an unrecognized authority. Extend recognized gate vocabulary before widening file scope; otherwise correct route/delegate/self-scope/financial/owner gates become false positives. Legitimate exceptions use reasoned inline suppression, never a weakened predicate.
- (d) A gate rejects the forbidden actor class. A resolver/classifier, own-row filter or business “in use” restriction is not authorization. Read the delegate/middleware's actual denial, including when a suppression claims it holds the gate; a different criterion from the write path is not equivalent protection.
- (e) Every assignment/persistence update of a membership privilege-tier field **MUST** consume its named actor-class gate earlier in the same body. Membership birth is outside this escalation predicate. Re-pointing an existing tier-bearing membership to a caller-chosen identity (contact-identifier change, re-invite, relink) transfers its tier, so it **MUST** pass the same actor-class gate as the sibling membership writes; a gate admitting lower tiers lets them take over or detach higher-tier members. A broader read gate that admits the high-tier holder cannot authorize tier writes. Each additional privilege field needs its own admitted lock. A retired tier boolean is permanently read-only and derived at read time; writes would reopen a second authority (SSG-M8).
- (f) A failed authority read **MUST** reject. A void gate must raise; a valueless return is indistinguishable from grant.
- (g) The operation **MUST** use the target returned by the gate, not discard it and address a caller-supplied id. Request/persistence validity parity is a separate cross-file obligation.
- (h) Actor gates **MUST** precede durable idempotency/quota/attempt claims, so mutable refusal cannot seal and spend the key before later permission is granted. The local route-chain ordering predicate rejects bare middleware identifiers between claim and terminal handler without inventing a second gate-identity authority. Non-authorizing links require a justified suppression. Measure the shape green before opening the fence; handler-internal gates remain outside the route AST's reach (FP-M18/M36).
- (i) One external authority takes the closed actor requirement, resolves tenant, proves membership and delegates to the existing gate in that order. Membership primitives stay private; returned scope and tenant repository keys are branded. Non-request work uses one named origin door (REP-N-4b). The exhaustive requirement union preserves each surface's code. All-members/self-scope admission needs a nonempty product reason, never a default. Route and handler consume the same authority; after a durable claim, the handler requires the published verified route actor and fails loud if absent. Retire the superseded lint in the same change (ENA-LC3). Fence producer-only assertion escapes alongside the private-symbol type: an `as` cast still compiles. Actor derives from the persistent account, not JWT role. Its cache is request-keyed and invalidated on every request write; the route's published actor is proof only and cannot widen that cache. Whether requirement matches the endpoint, route/handler parity and prose reasons require review. Unverified request-id readers and raw-id actor derivation have separate boundaries.
