Scope: Initialize the selected crash-reporting SDK in shipped builds and before the application graph evaluates, minimize information leaving the device, use one credential-masking authority, attach useful global client context, identify the exact artifact that produced each event, and keep simulator runtimes out of the production environment.

Document type: Normative part -- **COB-RN-M1**-**COB-RN-M4**, **COB-RN-M14**, **COB-RN-M17**-**COB-RN-M19**, **COB-RN-M21**.

References: [README.md](README.md); [client-observability-rn.md](client-observability-rn.md) (definitions, agent contract, MUST NOT rows); [credential-masking-and-build-secrets.md](credential-masking-and-build-secrets.md) (**COB-RN-M8** masking criterion); [build-symbol-upload-credentials.md](build-symbol-upload-credentials.md) (**COB-RN-M10**, when symbol upload is used).

## **MUST**

| ID | Rule |
|----|------|
| **COB-RN-M1** | Initialize the selected crash-reporting SDK in every shipped build where production or tester crash diagnosis is required. A development-only opt-out is allowed only when it is explicit and documented as a noise-control decision. Verify that JavaScript and native failure surfaces supported by the selected SDK reach the intended reporting pipeline. |
| **COB-RN-M2** | Minimize or remove PII from client scope and event data before capture wherever privacy and security policy requires it. Never include raw credentials in extra context. Apply the same policy to automatic context, breadcrumbs, and manually captured events. |
| **COB-RN-M3** | Use one shared credential predicate and sanitizer wherever the application emits observability data; when client and server code share a logging boundary, both must consume that same authority rather than maintain parallel lists (SSG-M8). SDK-side and provider-side redaction are separate layers and may independently alter event values. A redaction marker does not identify which layer produced it. Verify enabled layers using a safe new event and the selected provider’s configuration; do not assume a provider setting can be changed from application code or that already-ingested events can be restored. The SDK's automatic PII collection follows **COB-RN-M9**: off by default, on only under an explicit full-visibility policy after the field-by-field review, and then every collected surface still passes the shared sanitizer -- the option widens what is collected, never what escapes credential masking. A full-visibility policy also requires provider-side scrubbing to be consistent with it, or the SDK side is widened while ingest still filters. |
| **COB-RN-M14** | Every shipped artifact MUST carry a release/build identity that distinguishes it from other artifacts whose events or symbol files must be diagnosed separately. The identity increment must be mechanical rather than a human-maintained constant. Exactly one authority owns the increment: a tracked project configuration or the build service’s supported counter, never both. If the authority changes, update or retire every check that reads the old value in the same change. Verify the identity emitted by the built artifact; configuration expresses intent but does not prove what telemetry received. Static checks may validate configuration wiring, but only a built artifact and event can confirm runtime identity and symbol matching. |
| **COB-RN-M4** | Attach minimal, non-PII global client context to the selected SDK’s scope and event path where supported (for example app identity, build type, app/runtime version, release, and channel). Native fatal and unhandled events may bypass feature-level capture calls, so configure global context at the SDK boundary. Do not invent missing business fields or add a second reader for context the SDK already emits; confirm ownership and actual population in a built artifact or safe event. |
| **COB-RN-M17** | The crash SDK's `environment` **MUST** keep a non-physical runtime (iOS simulator, Android emulator) out of the production environment, and the physical-device answer **MUST** be read from the native layer that owns it (for example the device module's compile-time simulator flag), never from the platform constant or the build profile ([**COB-RN-M15**](outbound-link-ownership-and-visibility.md)). Capture **MUST NOT** be disabled and events **MUST NOT** be dropped to achieve the split -- they are written to their own environment, and when the native answer is unavailable the event stays in production. Reason: a release-configured build run on a simulator carries the same build profile, release and build identity as the store binary, so its events and sessions count as production; a locally built simulator binary also differs from the shipped one in ways the code cannot see (an unsigned build carries no entitlements, so every secure-store call fails), and those artifacts then surface as production defects. Every other client telemetry channel that feeds a production alarm (an expected-failure outbox, a client metric batch) **MUST** read the same single "is this production telemetry?" predicate the crash SDK environment derives from ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)); a channel whose server side has no environment dimension **MUST NOT** queue or send events from a development or non-physical build. Reason: one simulator session with a stopped local proxy queues every request failure and replays it on reconnect, enough to distort an alarm baseline on its own. |
| **COB-RN-M18** | The crash SDK **MUST** be initialized before any application module is evaluated. Where the bundler gives imports ES semantics -- every `import` of a file runs before that file's body -- an init call written in the entry file's body runs after the whole application import graph (store hydration, storage opening, their failure reports); an SDK without a client discards every capture silently, and a once-per-process report gate then spends its only slot on the lost report. Initialization therefore **MUST** live in its own side-effect module that is the entry file's first import and that imports nothing from the application tree. Verify by: the transformed entry module evaluates the init module before every other import. |
| **COB-RN-M19** | Every client failure class **MUST** reach the crash channel through the classification authority (**COB-RN-M6**) when it is a defect: render errors (error boundary), unhandled promise rejections and global JS errors, native crashes, API failures classified by the server envelope's category, and client invariant failures caught in render or derivation code (reported once per process per surface, never swallowed by a neutral fallback). Every event **MUST** carry the release, the per-binary build identity (**COB-RN-M14**) and the over-the-air update identity, and each over-the-air publish uploads its own source maps. The release **MUST** be read from the same native release-identity authority as the build identity, never from the over-the-air manifest's config version: an older binary that received a newer update would otherwise report a store version it is not, and that version's release health absorbs the old binary's crashes. Reason: a class with no reporting path, or an event that cannot be mapped to the shipped bundle, leaves a defect unseen or unreadable. Enforcement: review-held; the source-map upload is a publish-procedure step outside the repository. |
| **COB-RN-M21** | A native error code that client code classifies structurally (**COB-RN-N3**, **COB-RN-M6**) **MUST** survive the release optimizer: where a native module derives its rejection code from the exception's class name instead of passing an explicit code (for example a coded-exception base that infers `ERR_<CLASS_NAME>`), the release keep rules **MUST** preserve the names of every subclass of that base, plus the inner-class attributes a nested exception's simple name depends on, in the tracked optimizer-config surface (see the optimizer paragraph below). Reason: an obfuscating optimizer renames the class, so the code reaching JavaScript becomes a meaningless token; every closed code map then misses, and an expected device condition (an app store without the requested API, a transient service outage) falls into the fail-loud unknown branch and floods the crash channel, while message-text matching stays forbidden as the workaround. A debug build never shows it, because only the release artifact is obfuscated. Enforcement: review-held ([**IV-M13**](../implementation-verification/change-acceptance-bar.md)) -- whether a native module infers its code from the class name, and whether the keep rule reached the generated native tree, is not decidable from the tracked source; closure is an event from the optimized artifact carrying the expected code ([**IV-M4**](../implementation-verification/verification-must-rules.md)). |

> Optimization and symbol upload belong in the same change. When a release build enables code shrinking, obfuscation, or minification, configure and verify the corresponding source map or native debug-symbol upload for every affected symbol kind at the same time. One uploader does not prove the other symbol type is handled. A readable crash report is the acceptance evidence: confirm a symbolicated event from an optimized artifact, rather than relying only on plugin presence or configuration flags. Provider and build tooling may generate native configuration; use the tracked configuration surface that actually drives the build and avoid maintaining a parallel, unused optimizer or upload file: a keep-rule file that no build path reads is a false authority that goes stale silently, and the keep list is written in the change that turns the optimizer on, from that day's dependency graph (a maintained dependency usually ships its own consumer keep rules, so the list is often near-empty).
>
> Build and runtime context must be verified at the layer that owns it. Provider SDK defaults may already emit platform facts. Confirm this from supported integration behavior or a safe event before adding another reader. If application code must read a build/runtime value, verify that the exact key is present in the built configuration and avoid replacing a missing value with an invented constant. When a build profile is supposed to supply a decision input, declare it in every applicable profile rather than adding an unrelated runtime guess. Whether a value is populated in a production artifact cannot be proven by a source-only check; state that limit and verify the artifact.
>
> PII retention follows policy and access. Do not assume that telemetry is visible only to one developer. Apply the organization’s privacy, access, and retention requirements to structured context; restrict access and minimize data at source. Raw credentials and untrusted free text remain subject to the shared masking rules (**COB-RN-M8**) regardless of who can view telemetry. Re-evaluate data fields whenever the audience, access, purpose, or applicable policy changes. Where the policy keeps identifiers visible (a single-reader model), the identity scope is an allowed carrier, written by exactly one derived writer per tier that reads the session / request authority (never a feature call site), and the IP address comes from the trust-boundary authority rather than a client-controlled forwarding header; under the stripping model, identity-scope writes and sensitive tags stay forbidden (**COB-RN-M9**). Widening readership is the trigger that forces the criterion to be re-evaluated.
>
> An over-the-air JS update **MUST** upload its own source maps in the same publish step. The native build's upload covers only the bundle embedded in that binary; an update bundle carries new debug ids, so without its own upload every event from that update arrives unreadable while the build-time upload looks configured. Upload from the publish output directory with the provider's upload CLI reading the user-level credential (**COB-RN-M10**), never an inline token. Where the update bundle is engine bytecode, the upload **MUST** take the debug id from the source map using the provider CLI's debug-id option: the CLI cannot read the id out of a binary bundle, and without it the map is not tied to the id the event carries, so the upload succeeds and nothing symbolicates. The provider's regional server URL **MUST** sit in the same user-level config as the credential, and the repository **MUST NOT** name it. Closure evidence is the next event from that update with resolved frames, not the upload's exit code. The publish **MUST** run through one tracked repository command that refuses an unpushed or dirty tree, reads client values from the build service's environment (never inline keys), and fails when either the update or the upload fails or the export holds no source map. Review-held beyond that: whether the operator used the command.
>
> Hang and over-the-air fallback visibility -- consequences of **COB-RN-M1** and **COB-RN-M19**. (a) App-hang tracking **MUST** be written explicitly in the SDK init (enabled flag and threshold), not inherited from SDK defaults, and a platform whose hang detector has no JS option is named with its native default beside it. (b) An over-the-air emergency launch (the update failed and the runtime fell back to the embedded bundle) **MUST** be reported once per process through the classification authority as a defect carrying the runtime's reason: the SDK context records only a flag that no event raises, so every user on a crashing update otherwise runs old code with no event. (c) The update id the SDK writes into its context **MUST** also be copied to a searchable event tag in the single send hook, read from that context (no second reader of the updates API), so a regression can be split by update. Reason: a hang left to defaults, a silent fallback and an id that cannot be filtered each hide which release broke it.
>
> Optimizer-configuration paragraph (consequence of **COB-RN-M21**). The tracked configuration surface the native project is generated from is the only carrier of optimizer keep rules; a rule file parked outside the location the build tool resolves changes nothing at build time and misleads readers into believing shrinking is configured. Mechanically fenceable half: "the optimizer is on and the native-symbol uploader is not declared" compares two plugin entries inside one tracked config file; fence both arms (uploader absent, uploader declared but its mapping path switched off) with a check that actually runs on that file type. The rest stays unreachable from source: a config proves intent only, never that the plugin was applied, that credentials existed at build time, or that the mapping reached the provider. Closure is a symbolicated event ([**IV-M4**](../implementation-verification/verification-must-rules.md)). A reference to a check is not evidence that it exists or covers the full rule; record its actual scope and limits.
