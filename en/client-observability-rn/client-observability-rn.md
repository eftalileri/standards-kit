## Definitions

| ID        | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **COB-RN-D1** | **Selected crash SDK** means the single crash-reporting SDK explicitly chosen for the application, installed at a version compatible with its React Native / Expo runtime and native modules. Use the provider’s supported installation and upgrade path. |
| **COB-RN-D2** | **PII** means personally identifiable information (names, raw phone, email, tokens) in breadcrumbs or extra context.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **COB-RN-D3** | **Scrubbing surfaces** can act independently: application-side filtering before send; SDK-side filtering based on configuration; and provider-side filtering after ingest. A redacted value in a dashboard does not establish which layer produced it. Verify each enabled layer using a safe test event and the selected provider’s documentation. |
| **COB-RN-D4** | A live credential is any value that can authenticate, authorize, replay, or prove a privileged operation. Replayable purchase / transaction tokens are live credentials even when they are described as transaction metadata rather than PII; order ids or non-secret correlation ids are not automatically credentials. |

## Agent execution contract

| ID        | Rule                                                                                                                                                                                                                                                                                                          |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **COB-RN-C1** | Do not add another crash-reporting SDK alongside the selected provider without recording the decision and obtaining the required product-owner approval; duplicate pipelines can conflict over signal ownership and retention. |
| **COB-RN-C2** | When production crash diagnosis is in scope, follow the selected provider’s supported process for uploading source maps and native debug symbols for each release/build. Keep upload credentials in the build runner’s secret mechanism. |

## **MUST NOT**

| ID        | Rule                                                                                                                                                                                                                                                                                                                                                       |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **COB-RN-N1** | Do not use `console.log` as the only production crash pipeline. Configure the selected crash SDK for the JavaScript and native failure surfaces it supports, and verify the delivered event path. |
| **COB-RN-N2** | Do not silently swallow fatal native-module errors. Rethrow or otherwise preserve the failure according to [error handling](../error-handling/error-handling.md), and capture it through the selected reporting path when safe and appropriate. |
| **COB-RN-N3** | Must not send expected client transport failures to the crash channel, but expectedness requires structural evidence: a canonical adapter-produced carrier such as `ApiWireError.kind === 'network'`, an allowlisted transport `name`/`code`, a user abort marker, or provider-SDK network/offline/timeout codes proven under explicit provider context. Raw message text such as RN `"Network request failed"` is never sufficient evidence and **MUST NOT** be matched directly; the transport adapter may convert the native condition into the structural carrier before classification. Route proven transport failures to retry/UI state and WARN/non-actionable observability; capture when no structural proof exists or there is evidence of an app defect. Must not globally demote an unscoped numeric/provider code merely because it collides with a known SDK code. |
| **COB-RN-N4** | Must not let a retry / transport interceptor classify, log, or report anything. Its single job is transient retry; every non-retry outcome **MUST** re-throw the original transport error unchanged, because the outer classification layer reads fields that only that raw object carries (request config, response, status, transport code). Two concrete failure modes are forbidden: (a) an early `return`/`reject` placed inside a `try` whose own `catch` can observe it -- deliberate flow exits (retry disabled, budget exhausted, non-retryable status) then arrive as caught exceptions, and any unconditional capture in that `catch` turns every failed request, including a dropped connection, into a crash event; the fix is to remove the observing `catch`, not to make the rejection reachable. (b) ordering the layers with classification first -- the classifier replaces the raw error with its own type, the retry layer no longer finds the fields it gates on, and retry is silently disabled. The required order is retry innermost, classification outermost, and it **MUST** be stated where the interceptors are registered. A server response whose error envelope says `retryable: false` **MUST NOT** be retried by the transport layer, whatever its status class: the server registry already decided the same request cannot succeed, and a blind 5xx retry doubles every failing mutation and its crash events. |
| **COB-RN-N5** | Must not place a query-first gate in front of a scheme that has no meaningful alternative branch -- schemes served by a stock OS app with nothing to fall back to (for example `tel:`, `sms:`, `mailto:`). There the gate's only possible outcome is a dead end, and its answer reflects a platform declaration (**COB-RN-M7**), not real capability -- so it can only add false negatives, never value. Open directly, catch the rejection, show a message describing the real failure (never a message that claims the failure is environmental, e.g. "works on a real device"), and capture it through the project's single client-observability entry point (**COB-RN-M5**, **COB-RN-N2** -- silent swallow forbidden). A gate is legitimate only when the negative branch does something genuinely different (for example native app -> web fallback), and even then **COB-RN-M7** still applies. Where the probed scheme is statically decidable in one file, this rule **MUST** be enforced mechanically by a lint rule rather than by review -- and routing every open through one validated opening authority does not retire that duty, it relocates it. Inside that authority the probe's argument is a parse result, so no scheme resolves there and a rule anchored on the probe call goes silent while still reading as coverage; the decidable point has moved to the call site, where the URL and the option that requests the probe meet in one call expression, which is still one file's AST and not a cross-file problem. Anchor the check on that requesting option, never on the authority's name or path, so a second wrapper carrying the same option stays in scope. |
| **COB-RN-N6** | Do not emit a raw purchase or transaction token into logs, breadcrumbs, provider context, request snapshots, or captured request/response bodies. Do not maintain per-surface credential lists that can drift from the shared predicate (**COB-RN-M8**). |
| **COB-RN-N7** | A layer that produces an expected refusal MUST provide structural evidence so the classification authority does not mistake it for an unknown defect. Use the transport/provider carrier appropriate to the boundary and a closed, code-owned category; do not infer expectedness from message text or globally demote an unscoped code. Route the refusal through the single classification authority, not a direct crash-level logger or provider capture call. Do not retry an operation that was refused before it was sent; if a transport-shaped carrier is required to preserve request context, ensure the retry policy explicitly excludes the refusal code. A refusal must remain fail-closed: observability changes must not change the decision. Map multiple refusal classes through one exhaustive code-to-category authority. For a refusal before a request exists, use a distinct producer that does not fabricate request configuration; keep request identity required on transport producers. Verify producer, retry, and classification behavior at their boundaries, and state which properties require cross-file review rather than single-file lint. |
| **COB-RN-N8** | Must not leave a user on a fatal or generic full-screen error (startup/initialization failure, error boundary, "service unavailable" / "something went wrong" screen) without exactly one crash-channel event for it. The event goes through the single client capture authority, is produced by the screen's single writer (not by each call site, so no path can stay silent and none is counted twice), and carries the failing step, the screen's closed reason, the original error's class, code, HTTP status and trace id, whether the device was definitely offline, the OTA/update id and the retry generation. The underlying cause's expected/operational classification (**COB-RN-N3**, **COB-RN-M6**) **MUST NOT** suppress or downgrade this event, and the transport-noise filter must not drop it; only a definitely-offline device lowers its level to warning. Reason: a user who cannot use the app is a defect, never an expected outcome, and a screen with no event cannot be diagnosed. Coverage is audited screen by screen against every writer of the screen's state, never by sampling. |

**COB-RN-N8** content-area scope clarification. The shared "could not load" surface that replaces a screen's (or a list's, a modal's) whole content area is in scope, whatever caused it: it **MUST** be the single writer of its scene event and **MUST** require a closed scene identity at every mount (type-level, so a new caller cannot stay silent), with the event gated once per process per scene through the project's single once-per-process gate so repeats are counted, not dropped. A call site **MUST NOT** write its own scene report beside it; a separate report of the underlying cause (an invariant or derivation defect) stays, and the scene event marks it as previously reported. A branch with no error object passes a closed-code carrier, so the scene identity names the reason. A compact inline retry notice that leaves the rest of the screen usable is outside **N8**: the user is not stuck, and its cause still reaches the classification authority. A non-dismissable decision card (no exit but its answers, **SEC-M-MOB-M1**) is in scope: its failed-write error line is the scene, the shared card is its single writer, and each distinct failure shown is one event. Reason: the shared surface rendered on an expected-class failure (offline, gateway 503, timeout) otherwise produced only a breadcrumb while the user sat on a full error screen.
