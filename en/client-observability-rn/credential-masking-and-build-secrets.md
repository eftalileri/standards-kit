## **MUST**

| ID | Rule |
|----|------|
| **COB-RN-M8** | **MUST** classify credential keys through one case-insensitive, separator-normalizing predicate used by every applicable client capture/log boundary and, where the same data also enters backend telemetry, by those backend boundaries too. Include generic credential suffixes and replayable transaction-token aliases across common casing and separator variants. Exact allowlists are limited to reviewed presence-only booleans. Recursive scrubbers use the shared predicate and must be safe for cycles, depth limits, container types, and getters. Mask values that grant access or permit replay/impersonation: passwords, secrets, API keys, access/refresh tokens, authorization headers, cookies, session IDs, private keys, signatures, one-time codes, purchase tokens, replay/idempotency keys, and connection strings. Preserve identifiers and ordinary business data needed for diagnosis unless the applicable privacy policy classifies them as sensitive. Free text uses value-level scanning, not blanket deletion by field name: scan strings for scheme userinfo, authorization schemes, JWTs, configured vendor secret prefixes, and key/value pairs whose names match the shared predicate. Carry structural, code-owned diagnostics beside the text; remove raw request/user objects and stack-frame local variables. Apply this permission only to observability data, not HTTP response bodies. Set the allowed diagnostic detail according to observability access, audience, purpose, retention, and privacy policy, and re-evaluate it when any of those change. No surface may maintain a competing mask list: additions must be part of the shared criterion, and a local list must not re-mask values the shared criterion intentionally preserves (SSG-M8). |
| **COB-RN-M9** | Client crash SDK default PII capture MUST remain disabled unless field-by-field data-flow review establishes that every automatically populated request, user, breadcrumb, and exception field is safe and policy explicitly authorizes collection. If identifiers may embed contact or other sensitive data, disable default PII capture unless the project's policy deliberately keeps PII visible (single-reader model, see the PII note in [sdk-setup-and-pii-scrubbing.md](sdk-setup-and-pii-scrubbing.md)), and otherwise omit them at source. Every provider capture hook (for example `beforeSend` / `beforeBreadcrumb` where supported) must use the shared sanitizer: remove runtime frame variables and either remove request/user fields (stripping policy) or keep them with every live credential masked (full-visibility policy); under either policy delete the request cookie jar and the SDK's raw request body (it bypasses route-scoped body masks, so the only body carrier is the project's masked request snapshot); value-scan exception and event text, preserve safe code-location frames, and scrub structured context. Preserve exception type when it is a safe class identifier. Delete breadcrumb `data` by default; preserve it only for categories written exclusively by the application’s classification authority and only after shared scrubbing. Blanket preservation can expose automatic SDK data; blanket deletion can erase the structured signal for expected failures. Do not rely on provider-side settings or key-only scrubbing as substitutes for source minimization and the shared sanitizer. |
| **COB-RN-M16** | In free text, a key-shaped token is not proof of a key/value pair. The value-level scan in COB-RN-M8 MUST corroborate a candidate on the value side before masking, so error codes and ordinary prose remain diagnostic. Do not narrow the credential-key class to avoid false positives: environment secrets often share the same uppercase/underscore shape. For an unquoted pair, a sentence-shaped separator (a colon or whitespace around `=`) followed by a bare alphabetic word and further text is prose and remains visible; quoted values, values with digits or symbols, terminal values, and machine-form `name=value` remain maskable. For quoted values, use the closing quote as the boundary so punctuation, spaces, or commas inside a credential cannot evade masking. Corroborate scheme words such as `Bearer`, `Basic`, `Digest`, and `Token` by position (start of text or after a delimiter). Enforce both outcomes together: diagnostic prose remains, while credentials are masked. State the residual limit where a purely alphabetic secret appears mid-sentence in unquoted `key: value` form. |

Enforcement: A project lint rule for provider identity and sensitive-field writes is optional and is justified only when its syntax is statically decidable and a recorded defect of the class exists; where the shared event sanitizer already drops the user surface before transport (a stronger runtime mechanism) and the project deliberately keeps identifiers visible, scope writes are held by that sanitizer and by review instead. If such a rule is used, cover imported aliases and scope APIs where practical, treat shadowed locals as ordinary values, and document computed keys, indirect calls, or cross-function provenance that static analysis cannot resolve. A reference to a check is not evidence that it exists or covers the full rule; record its actual scope and limits.

**COB-RN-M9** breadcrumb-category provenance clarification (the category NAME is an authority, not a string). Preserving a breadcrumb's `data` is gated on the category being written exclusively by the project's own classification authority, and that gate matches on the category name. A name typed as a literal at a call site is therefore a second writer of the gate's key (SSG-M8), and its failure is silent in both directions: a one-character difference means the protection never applies, and an exact copy works until the day the name changes — at which point the copy diverges, the breadcrumb is still written and nothing goes red. The category MUST be read from a constant owned by another module; a call site that writes it inline, omits it, or hides the whole breadcrumb behind an opaque argument is a review finding (the three shapes are single-file decidable, but a lint rule needs a recorded defect of the class to justify it, and breadcrumb calls normally live inside the observability module that owns the constant). In review, "comes from an imported binding" is the honest test: a local `const` above the call is the same second writer moved one line up.

**COB-RN-M9** static-navigation clarification. A project-owned navigation breadcrumb may retain exactly one registered, type-closed UI route/screen identity under an exclusive project category. Its producer must read that identity from the typed navigator registration, never from params, path, URL, user input, an identifier, or a fallback; it must omit free-text `message` at source (the sanitizer's value-level scan is a safety net, not a licence to emit unowned text under a project category). The shared sanitizer must rebuild the payload to the single allowed field and delete every extra key before applying the shared scrubber. Reusing an SDK-generic category, preserving an open navigation `data` bag, or accepting a name/path-shaped string as proof of static provenance is forbidden.
