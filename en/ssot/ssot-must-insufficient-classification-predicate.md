The shape survives review precisely because the comparator is the right function — it is simply asked a question with more answers than it has.
## The closed union classified at the consumer by an equality chain

When a consumer must reach a terminal verdict from a closed union it receives as data — a stored class label, a discriminated status, a reason code — that verdict **MUST** be produced by a member-by-member switch whose default branch asserts exhaustion to the type checker, never by an `if` / `else if` equality chain. The chain is the same defect as the comparator below with the arity reversed: N named arms stand in for a union whose membership is free to grow. A chain has an invisible default — the fall-through where no arm matched — and a newly added member silently receives either the widest behaviour (where the arms narrow) or none (where the arms accumulate), with no diagnostic at compile time or at run time. Three obligations. (a) The default branch must fail the build, not the request. Assigning the discriminant to the language's bottom type in the default arm turns a new union member into a compile error at every consumer; a runtime throw detects the omission only once that member is exercised, one path at a time. Where the union is a permission class, that delay is the whole cost: the missing arm is discovered by the actor who was wrongly admitted or wrongly refused. (b) A filtered special case of a set question is a membership test against the one derivation, never a second chain. Where one authority answers a set question in both an aggregate form ("which members may this subject reach?") and a single-item form ("may this subject reach *this* member?"), the single-item form **MUST** test membership in the set the aggregate form derives; two chains over the same label diverge silently, and the same question then returns different answers depending on whether a filter parameter was supplied. (c) The label is not the answer, only the choice of question. A chain over a stored class label is tolerable only while every arm re-derives the real fact for the target scope; an arm that returns a verdict from the label alone makes the label an authority it is not. Enforcement: a check for this family **MUST** cover every equivalent writing, because fencing one spelling leaves the others standing while reading as coverage: the `if`/`else if` equality chain; the deny-list conjunction (`x.r !== 'a' && x.r !== 'b'`); the allow-list disjunction (`x.r === 'a' || x.r === 'b'`); the sibling guard chain (arms in one body without `else`); and the conditional-expression dispatch, nested or as sibling guards in one markup parent. The structural anchor is the same base expression's discriminant tested against two different string literals; it **MUST NOT** require the arms to be adjacent, and a predicate anchored on one statement node type fences the decision only in that grammar — enumerate the node types the decision can take before calling the population complete. Where the same multi-step classification is written in several modules, the fix is the one authority, not N copies of the switch. Use the enforcement mechanism the adopting project documents; a reference to a check is not evidence that it exists or covers the full family — record its actual scope and limits. Limit of the check: obligation (b) cannot be decided from one file's syntax tree, because deciding that two derivations answer the *same* question needs a declaration binding both to one question identity; it rests on review and on keeping the two forms in one function body where a reader can compare them. Obligation (c) is likewise a review obligation wherever the re-derivation happens through an indirection the file does not contain. [On violation: Bug — a union member added later silently receives the widest or the emptiest behaviour, and where the union is a permission class that is a silent grant or a silent lockout] [Verify by: every terminal verdict over a received closed union written as a member-by-member switch with a bottom-type assignment in the default arm; the single-item form of any set question shown to test membership in the aggregate form's own derivation; any admitted check covering every syntax form it claims, measured at zero before it is enabled]

## The direction comparator standing in for an N-way classification

When a domain fact has more than two classes, it **MUST** be classified by one named authority returning a closed union — never by comparing a direction comparator's result in a consumer. A comparator answers *which of two is greater*; it has three outcomes but reads as two, so `compare(a, b) > 0 ? X : Y` and a gate written `compare(a, b) < 0` both fold the equal case into a neighbouring arm without a diagnostic. The shape recurs wherever the compared attribute is one field of a richer selection — a plan's rank beside its billing period, a version's major beside its release channel, a severity beside its retryability — because the equal case is then a real third class, distinguished by the *other* field the comparator never saw. Four obligations. (a) The classification is a named function returning a closed union, and every consumer switches over it exhaustively; adding a member then fails compilation at every consumer instead of silently choosing an existing arm. (b) The authority takes the whole selection, not the compared field, so the equal-rank case can be separated by the fields that remain. (c) Two consumers on opposite sides of a boundary **MUST** call the same authority: when a producer and a consumer each spell the classification by hand with different predicates, an action the user completed can leave no trace anywhere while neither side raises an error — not a wrong value, but a real event with no representation. (d) A stored classification is written from the authority, never as a literal at the write site; the write takes the classifier's output as a parameter. Enforcement: the shape is decidable from a single file's syntax tree — a comparator call whose two arguments read the *same property of two different objects* and whose result is an operand of a comparison operator; a comparison against a bare value has no sibling field to lose and is outside the population by construction. Limit of the check: a comparator result stored in a variable and compared on a later line, or wrapped in a helper, escapes it; those stay type and review obligations, stated where the authority is registered. [On violation: Bug — the third class silently takes a neighbouring class's behaviour, and where the two sides of a boundary disagree the fact is recorded nowhere] [Verify by: one named classifier returning a closed union; exhaustive switches at every consumer; the producer and the consumer of the boundary shown to import the same authority; every persisted classification field traced to the classifier's output rather than a literal; stated limits for any check]

## The classifier's own output member that no branch produces

A classifier mapping untrusted input onto a closed output union **MUST** be able to produce every member of that union; a member no branch produces is a defect, not a reserved slot. This is the producer-side mirror of the consumer chain above: schemas and consumers accept the member, yet the one function allowed to write it never does, so its real input takes the classifier's fallback class and the stored record is valid and wrong. Two obligations. (a) A vocabulary member and its producing path land in one change. (b) A secondary label resolved beside the primary one **MUST NOT** fall back to a class whose reporting rollup contradicts the primary member: when the secondary input is absent or unrecognised, a primary member that owns a secondary class takes it; a recognised explicit input still wins. Enforcement: cross-file, so a project-level check: derive the vocabulary from the classifier's declared return type (never a second list), collect every literal whose contextual type is exactly that union in the classifier and the constant tables it imports, object keys excluded, and fail on the difference; a member deliberately not yet produced sits in a shrinking baseline that fails once the member is produced. Limit, stated: the check proves a producing literal exists, not that the priority chain lets an input reach it, nor (b), whose rollups live in reporting definitions; both stay review obligations. [On violation: Bug — valid input is silently recorded under the fallback class] [Verify by: every declared output member has a producing path; the check, where adopted, green and shown red against a classifier missing a producing path]
