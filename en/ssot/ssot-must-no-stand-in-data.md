**SSG-M17**: A production path **MUST NOT** carry stand-in data or a stand-in implementation. A hard-coded value, a sample list, a fabricated response, or a function that returns a plausible answer instead of calling the authority is a second authority for data the registered authority already owns (**SSG-M8**) — and the worse one, because it never diverges *visibly*: it keeps returning something. The three shapes this takes, all forbidden alike: (a) literal domain data embedded in a component, hook, service or handler instead of read from its authority; (b) a stub/mock implementation left on a path a build can reach, including one behind a flag whose default is never exercised; (c) a "temporary" default that stands in while the real source is unavailable — that is the fallback prohibition, restated at the data layer. The correct behaviour when the authority cannot answer is to fail loudly, not to substitute. Where a value is genuinely a constant of the domain, it is a registered authority with a row of its own, not a literal repeated at each use. [On violation: Bug — must fix before ship] [Verify by: review of every literal domain value and every stub on a reachable path; a stub is either deleted or made unreachable by construction, not by convention]

A successful operation does not prove an unreturned destination. When a file picker or external adapter owns where an operation writes, success feedback states only the destination that operation establishes: the selected folder, or a destination explicitly returned and verified by the adapter. A catalogue label or a helper's historical name is not filesystem evidence; it must not turn a user-selected tree into a fixed Downloads claim. Success is shown only after the write completes; denial or rejected writing keeps its failure path. A required current-command assertion travels through picker, create, write and share awaits before later side effects or feedback; a guard only after the whole helper returns cannot undo an old command's intervening write. Stated limit: destination truth and native/provider provenance are review-held. **ENA-A1**(a)/(d) does not admit a new fence for the success site: natural-language claims across locales and native folder provenance are not a complete measured static predicate. Existing awaited native completion, the required assertion parameter and the adapter's returned URI are the stronger mechanisms.

An asynchronous required display source remains unknown until its own answer arrives. Keep unresolved/unavailable state bound to the current record; synchronously exclude a prior record's result and cancel superseded completion. Source-independent display branches may remain visible, while source-dependent formatting waits or shows contained failure with an owning retry. Retry starts a new attempt even when the record object is unchanged through cache structural sharing; reporting failure never authorizes a literal/default or previous-record source. Stated enforcement limit: a display consumer is held by source-bound result state and its branch gate; proving the resolver/consumer association is a cross-file review obligation. These are stronger mechanisms than a lexical fence, so no new check passes [**ENA-A1**](../enforcement-architecture/enforcement-admission.md)(a)/(c).

A parameter default is where a stand-in hides best, and a partially exported vocabulary is what forces one. Two shapes of **SSG-M17**(c) survive review because neither looks like data. (a) The defaulted classification parameter. A function that consumes an externally-owned classification — a billing period, a channel, an environment, a plan family — **MUST** take it as a required argument. A default (`kind: Kind = 'first'`) does not make the call site simpler; it makes the call site *silent*: a caller that cannot derive the class supplies nothing and the callee picks one, so the wrong class is committed with no error, no log and no failing branch. When the class is unknown the correct outcome is a typed failure, never the value the surrounding code happens to be about ([**SSG-M19**](ssot-must-provider-projection.md)). The class this belongs to is the same one review keeps passing over: a default reads as ergonomics, not as a second authority. It is unusually cheap to fence, because a parameter default whose annotation names the classification contract is decidable from one file's syntax tree. (b) The half-exported vocabulary. When one derivation returns several classifications at once (a parse that yields both a tier and a period; a normalizer that yields both a channel and an environment), the module **MUST** export the vocabulary — enum/schema and derived type — for every classification it returns, not only the one its first consumer happened to need. An unexported vocabulary is not private, it is *unavailable*: every consumer that needs it re-spells the same union locally, and the spellings then drift independently while the exported sibling stays correct — so the module looks like a single authority while owning only part of the semantic. Symmetry is the test: for each value a derivation returns, ask where its vocabulary is written; more than one answer is **SSG-M8**. [On violation: Bug — a silently defaulted class is committed to durable state or sent to an external provider, or one semantic acquires several vocabularies] [Verify by: every classification parameter required at its declaration; single-file AST rule rejecting a literal default on a parameter whose annotation names the classification contract; one exported vocabulary per returned classification, with consumers aliasing it rather than re-declaring the union]

A third shape: the identifier whose format depends on a dimension the code never asks about. Where an external system spells one logical object differently per store, region, tenant or plan channel, there is no single correct spelling, and settling "which one is right?" by picking one writes a stand-in for the dimension that was never read — the repository then argues with itself, because each hand-written copy is correct for its own dimension and wrong for the other. The authority is one dimensioned builder: it takes the dimension and returns that dimension's form, and it **MUST** live beside the contract that accepts that form, so a value this system builds can never be a value this system's own parser refuses. A builder in one file and the accepting contract in another are two authorities for one format and they drift the day either is corrected. Emitting a dimension-free identifier into a dimensioned call is the defect even when the value is valid for one dimension, because the call site's dimension is the question that was never asked. Segments the external console owns — a base-plan or offer suffix, a storefront or locale segment — **MUST NOT** be synthesised by the builder: absent is the correct state, because a value invented here would outrank the only system that knows it, which is **SSG-M17**(c) wearing a plausible shape. [On violation: Bug — a call to an external system names an object that does not exist in that store, and the failure surfaces as "unknown object" rather than as a contract error] [Verify by: one builder per format declared in the same module as the contract that accepts it; every emitter taking the dimension as a required argument; no console-owned segment produced in code]

A fourth shape: the unknown dimension dropped out of a match predicate. A predicate that compares a record against a classification **MUST NOT**, when that classification is unknown, fall back to comparing the *remaining* dimensions. Dropping the unknown term is not neutral and it is not lenient — it is an affirmative claim that every value of that dimension matches, which is a stand-in answer in the shape of a missing clause (**SSG-M17**(c)). Because the surviving comparison still looks like real work, review reads the branch as "we compared what we could" rather than as "we asserted what we do not know". The correct outcome is that an unknown class makes the predicate false — the answer to *"is this the current one?"* without evidence is *no*, not *maybe*, and never *all of them* ([**SSG-M19**](ssot-must-provider-projection.md)). Say it in the shape of the code: delete the early-return branch entirely rather than making it return `false`, because a `null` classification compared against a concrete one is already false, and a branch that exists invites the next author to soften it again. The cost is paid at the surface, not in the branch: the honest "we do not know" must reach the user as its own line, which is a display obligation, not a licence to guess. [On violation: Bug — a record is presented or treated as matching on evidence that was never read, and the mutually exclusive members of a dimension are all marked at once] [Verify by: every match predicate over an optional classification returning false when it is absent; single-file AST rule rejecting a nullish-test branch that returns anything but `false` inside a boolean predicate whose subject is declared as that classification `| null`]

A fifth shape: the write authority that reports an outcome it never verified. A function that persists a value and returns a result class (`stored`, `updated`, `applied`) **MUST** derive that class from the driver's own report of what the write touched — a matched/modified count, an affected-row count, the returned document — and not from the mere fact that the call did not throw. A conditional write whose filter matches nothing succeeds: it is not an error, it is an empty update, and an authority that answers `stored` for it has produced a stand-in result. The damage is second-order and therefore hard to see: the lie is not in the database, which is simply unchanged, but in every count computed from that answer — a backfill report, a reconciliation summary, a migration's own post-condition — so the operator's evidence that the work happened is manufactured by the code that did not do it. Where a filter can legitimately match nothing, that is a named outcome of its own, not a synonym for success; where it cannot, a zero match is a fail-loud contract violation with a registered code. [On violation: Bug — an operator, a dashboard or a follow-up migration acts on a success count that was never measured] [Verify by: every persisting authority branching on the driver's matched/modified report before returning a success class; a zero match either named as a distinct outcome or raised as a registered error] Stated enforcement limit: whether a particular write is required to match is a per-call intent that a syntax tree does not carry, and many writes legitimately match nothing, so a rule demanding a matched-count branch on every write would be born red, which [**FP-M18**](../false-positive/README.md) forbids. Review the contract at the authority; do not imply that a generic matched-count check covers all writes.

A sixth shape: the response transform that fills a schema-required field. A transform that turns a stored record into its wire shape **MUST** read every field the storage schema declares required — the record's own identifier, its required timestamps, its required flags — through the fail-loud gate that owns that field class (the identifier through the reference-id authority's required variant, a timestamp through the row-timestamp gate, a flag or number through a typed check raising the record's registered code). A local default — an empty identifier, a `let at = ''` later overwritten only on the happy branches, a `?? false` on a required flag — turns a corrupt record into a *valid-looking* one: the client receives an entity with no identity, a date that sorts first, or an "inactive" state nobody wrote (**SSG-M17**(c)). An optional field keeps its absence as absence (the key is omitted), but a value that *is* present and malformed is still a failure, not "absent". Typical failure: a response transform emits an empty own identifier and empty required dates on a malformed record, or a present `null` display-name snapshot becomes the literal text `"null"`. Measure the stored corpus against the gates before switching; where every stored record already satisfies them, fail-loud costs nothing on live data. [On violation: Bug — a malformed stored record reaches the client as a plausible entity] [Verify by: every required field of the wire transform read through its field-class gate; no literal default on a required field] [Not mechanically enforced — stated limit (**ENA-GV3**): a check on a *field write* of the empty literal covers only that shape; an identifier `?? ''` and a flag `?? false` are also the correct idiom for query keys, form state and optional inputs, so a name-based arm would be born red, and a `let x = ''` pre-initialisation is too rare to admit a fence (**ENA-A1**(a)/(d)); review at the transform holds them.]
