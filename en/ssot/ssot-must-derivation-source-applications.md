**SSG-M1** frozen-copy application: Once a record has captured a snapshot of configurable source data, every later derivation about that record **MUST** read the saved snapshot; the mutable source is authoritative only when creating a new record. This applies whenever a durable record preserves a value from a configurable catalog or policy at creation time and that source can later change. The values agree at creation, which is why a wrong source can pass review; they diverge only after the source changes, and consumers may then report conflicting values for the same record. (a) Name the lifecycle stage and its source. A creation path may use the current source value; a saved-record path uses the snapshot. Any helper that reads mutable source data states its allowed lifecycle stage and caller. (b) Keep the write rule and derivation rule aligned. If an update intentionally preserves the snapshot when its source selection has not changed, dependent derivations must use that snapshot too. (c) All derivations about a saved record use the snapshot. Windows, comparisons, classifications, and warnings count, not only displayed values. A comparison of two records uses the same lifecycle-stage authority for both. (d) In-place edits preserve the snapshot. Only a deliberate rebuild that creates a new record may capture the current source again. Enforcement limit: lifecycle stage is generally a call-graph fact a single-file syntax tree cannot decide. Prefer types or resolvers that make a saved-record consumer unable to accept a raw catalog value. Otherwise state the limit and review permitted callers. [On violation: Bug — a saved record is judged or displayed using data it never captured] [Verify by: birth-only source readers identify permitted callers; saved-record derivations consume their snapshots or a resolver over them; snapshot-preservation and rebuild rules are reviewed together]

**SSG-M1** provider-money application: Money, currency, withheld shares, and environment provenance from a provider event **MUST** be derived together from the provider's published contract, not selected independently by field name. A payload may contain several plausible amounts and percentages. Pair each amount with the currency that defines its unit; calculate net value from non-overlapping, contract-defined fees and taxes; preserve gross and net as distinct values; and treat missing required evidence as a loud failure rather than an assumed rate or omitted deduction. Keep a financial-write failure from suppressing unrelated, correctly evidenced access or lifecycle effects. Persist environment provenance and apply one shared scope when reporting totals. The event contract also determines which event kinds represent revenue; recurring events must be classified according to that contract, not inferred from a consumer's preferred case. A project-specific check may restrict recognizable provider fields to one derivation, but it cannot determine field meaning without the provider contract, and aliases or destructuring may fall outside a syntax-only predicate. State those limits explicitly. [On violation: Bug — reported financial totals or decisions use a mismatched amount, unit, fee, or environment] [Verify by: one derivation returns amount, currency, shares, and environment; reconcile its calculation against contract examples; every reader uses the shared provenance scope]

**SSG-M1** absent-input application: A derivation whose input could not be read **MUST** be able to answer *unknown*. When its result would be stored as an immutable fact, withhold the record rather than writing a neutral-looking member of the output set. A default source, standard category, or no-adjustment result may also be a real positive classification. Converting a failed read into one of those values asserts something the system never learned. (a) Withholding is self-healing. A later successful read can write the correct fact; an immutable placeholder cannot be corrected by retry. (b) Health signals must reflect the missing evidence. If a coverage measure counts placeholder records as success, the failure hides the outage; absence keeps the gap visible. (c) Do not add an unknown enum member casually. That can change the contract for every consumer and mirror. Prefer a closed capture outcome distinguishing "answered" from "could not be read," a single classifier that can return no honest classification, and a writer that skips persistence while emitting the appropriate diagnostic. [On violation: Bug — an immutable record asserts a classification that was never measured] [Verify by: unreadable input produces an explicit no-answer; the writer omits that record; coverage reflects the missing evidence]

**SSG-M1** past-instant application: A derivation about when a lifecycle transition happened (a trial ended, a subscription lapsed, a subject first activated) **MUST** read that instant from the append-only transition history or from a value frozen at the transition, never from a current-state field that later writes overwrite. An early end, an extension or a reopening rewrites the current-state field, so a reader of it silently moves a past instant and a closed cohort member's outcome changes after the fact; the current-state field answers only *what is true now*. A member whose transition is missing from the history is *unknown* (absent-input application above), never filled from the current field. [On violation: Bug — a past cohort's outcome or duration changes when the subject's state changes later, and nothing fails] [Verify by: every reader of the instant imports the one history-based derivation; no metric reader projects the current-state field to date a past transition]
