# SSOT MUST — provider access boundary (inbound callback and outbound reach)

```kit-cover
type: normative
part-of: README.md
binds: SSG-M21 provider callback access-loss, provider-scope provenance and materialization-fence obligation; SSG-M22 outbound provider reach - endpoint, module, native bridge name and credential ownership, plus the owner's duty to carry a corrected call when a provider wrapper is non-functional
open-when: signal:ssot-authority, signal:external-provider, signal:webhook-projection, signal:provider-callback, signal:provider-sdk, signal:provider-credential, signal:native-module-bridge
skip-when: signal:no-external-provider
```

Part of: [SSOT principles and precedence](ssot-principles-and-precedence.md). Provider projection identity, ordering and classification obligations remain in [external provider projections](ssot-must-provider-projection.md) (**SSG-M9**–**SSG-M12**, **SSG-M19**), and what the projection entitles is in [entitlement lifetime and capacity-gated admission](ssot-must-provider-entitlement-and-capacity.md) (**SSG-M13**, **SSG-M14**); this file owns both directions of the provider boundary — the inbound access-loss callback composition (**SSG-M21**) and the outbound reach toward the provider (**SSG-M22**).

**SSG-M21**: An authenticated provider lifecycle event whose published semantics do not themselves prove immediate effective-access loss **MUST NOT** directly revoke access or authorize an access-loss projection. The event may describe why a transition was requested or reported, but a fresh canonical provider-status read — bypassing shared cache and in-flight reuse — must separately establish the current access result. Compose that result with every registered local access source (for example, an administrative grant or trial) through the existing access derivation authority; only its canonical no-access result may enter the access-loss writer. A renewal-disabled or unsubscribe signal that leaves access active until the period ends must preserve that access and expiry. The callback boundary must authenticate provider scope: every side-effect-capable event carries an exact provider application identity when the provider contract supplies one, except for provider-defined application-agnostic event classes, and passes a provider-scoped credential plus the configured application allowlist at initial durable acceptance and again under current configuration before replay side effects. If the provider omits a scope identifier from the event payload, do not invent one; establish provenance through the versioned combination of the authentication boundary and configured application identity. A successful access-loss projection preserves provider event time, immutable event identity, and verified provider-scope provenance, and advances each durable materialization fence in the same conditional database write or transaction. Older events, exact replays, and already-applied idempotent outcomes do not advance that fence; equal-time events with conflicting identity or provenance fail loudly. Cache invalidation or generation is post-commit coordination, never the access or ordering authority. Access loss restricts future gated materialization only unless a separately registered terminal command owns changes to existing resources: historical or scheduled records, queued operations, and reminders are not deleted, closed, rewritten, or suppressed by the lifecycle event. A later verified purchase reopens access through its own provider evidence and writer; it does not resurrect deleted data or backfill a denied interval. [On violation: Critical access/race/security bug — cancellation cuts access that remains active, a forged cross-application callback mutates another scope, or stale evidence commits work after access is lost] [Verify by: provider event/status contract; authentication and application-scope checks at initial acceptance and replay; fresh cache-bypassing status read; canonical local-access composition; provider-time/event/provenance conditional writer with a same-write materialization fence; stale/replay outcome review; resource-writer inventory. Use a single-file check for decidable bypasses where admitted; the callback's durable-acceptance-before-acknowledgement ordering on the single callback authority is a review obligation unless the adopting project admits a check for it (provider-truth reconciliation on status reads is the safety net for a lost event); external documentation and cross-transaction chronology remain review/runtime evidence.]

---

**SSG-M22**: Everything a codebase needs to reach a third-party provider — endpoint address, SDK module, native bridge name where present, and each credential — belongs to exactly one owner. A second file **MUST NOT** open its own path to the same provider. The owner is the adapter that carries the provider contract: API version, timeout, retry/backoff, consent, payload hashing/redaction, and provider-error classification. The signals are independent: raw REST may mention only the host, SDK use may mention only a package, a native bridge may mention neither, and credentials are independent of all three. Each reach signal therefore needs its own verified ownership boundary. Several legitimate owners may exist when a provider exposes distinct product surfaces or endpoints; record each explicitly rather than assuming one owner per vendor. Credentials with different privileges must remain within the tree for their purpose: using a write credential in a read-only integration expands privilege even if the request succeeds. A provider module the project does not currently install is still owned so it cannot be introduced through an arbitrary file. [On violation: Bug — an unversioned, unthrottled, consent-free, or unredacted path reaches a provider, or credentials with distinct privileges are combined] [Verify by: per provider, identify the owner of every endpoint host, SDK module, native bridge, and credential; allow explicit multiple owners for distinct surfaces. Any admitted check must cover every syntax form of its signal: endpoint text in string and template literals; static/dynamic imports and `require`; bridge access by member, computed member, destructuring, or registry lookup; credential access by direct, computed, or destructured reads. Keep the owner map in the project's own configuration. An SDK module that is not a dependency gets no owner-map row — a row that guards no live surface fails the admission test (**ENA-A2**). Stated limit (**ENA-GV3**): where the adopting project has no admitted credential-purpose check (a credential read only in its own purpose's tree), a credential read outside its purpose tree is a review finding; record that limit rather than imply coverage.]

The native bridge name is a reach signal independent of the package specifier. A file can access a provider's native bridge by name without mentioning its package, so a package-import boundary does not cover it. Resolve the bridge registry binding through the platform-module import, not by the identifier's spelling; strip type assertions before comparing the binding. Keep this check in the same owner map because it answers the same ownership question as endpoint and module checks.

When a provider wrapper is non-functional, the owner carries the corrected call. A wrapper member that cannot be invoked correctly on a supported platform is not a reason to swallow the failure, defer it behind an unavailable upgrade, or leave it only in prose. The owner writes the corrected call once, and the unsupported call shape is rejected everywhere, including inside the owner; what is forbidden is the call shape, not the authority. If a corrected call depends on a quantity the provider may change, measure that quantity at runtime instead of hardcoding it. [On violation: Bug — a supported provider operation fails while the code appears to follow its API contract] [Verify by: one owner for the corrected call; the unsupported call shape is rejected everywhere; provider-dependent quantities are read at runtime when they can change.]

Stated limit — [**KIT-INV-8**(b)](../authoring/kit-structural-invariants.md) applies to **SSG-M22** twice. (a) Reach is fenced by mention, not invocation. A check can flag a provider host or module where it appears, but cannot prove the value reaches a transport call; tracing that dataflow crosses expressions or modules. (b) Provider inventory and semantic ownership are not inferable from source syntax alone. Whether an unfamiliar package belongs to a provider or whether a function re-derives provider-owned meaning requires dependency and domain review. A fence covers only the named set; state that boundary rather than imply exhaustive coverage.

Stated limit — **KIT-INV-8**(b) applies to the durable-outbox writer boundary. Where a durable outbox collection has exactly two writing roles — the single enqueuer and the single drainer — *who writes* is decidable from one file and **MUST** be fenced by import provenance, never by identifier name (a same-named local object passes a name-based predicate silently, and the rule stays green while the fence is open). Reads stay free: counting or inspecting a queue is legitimate, and forbidding it would accuse real consumers. *What the written payload carries* is not decidable the same way. A claim such as "no raw identity — a phone number, an email — ever enters the outbox payload" can be checked at each individual producer, but the whole-tree claim that *no* producer leaks requires following a value's origin across modules. The correct reduction is not a bigger checker but a narrower type: make the payload field accept only what the hashing/redaction authority can mint — a schema-parse output or a branded type — so attaching a raw value stops compiling and the compiler, not a lint pass, is the proof. Where the project has not done that, this half is review-bound. Equally binding in the other direction: do not fence what the type system already closed. When a discriminated union makes an illegal provenance unrepresentable, and an `Extract<…>` narrowing makes an illegal target/provenance pairing uncallable, a lint rule restating either is a *parallel* protection ([**SSG-M8**](ssot-principles-and-precedence.md)) — it adds no guarantee and drifts from the type it shadows. Fence only the arm that remains open.
