**SSG-M1** seam-row adapter application: When a derivation consumes the rows of one read seam, the step that turns a seam row into the derivation's input — identifier normalisation, the scope check, the field selection — belongs to the derivation, and the rows are passed exactly as loaded; an adapter written at the call site is the polymorphic-carrier copy above lifted one level, re-spelled once per consumer. The adapter appears because the derivation's parameter was declared as a narrower "clean" shape than the seam returns: the first consumer maps rows into it and every later consumer copies the mapping. The copies are identical on the day they multiply, and none is needed once the derivation accepts the seam's row shape. Three obligations. (a) The derivation's row parameter accepts the seam's row shape, raw identifier carriers included, normalises through the carrier normaliser above, and fails loud on an out-of-scope row rather than skipping it ([**SSG-M17**](ssot-must-no-stand-in-data.md)). The scope parameter is server-held — the caller read the seam with that same value — so a blank scope, a row with no scope and a row of another scope are all defects and raise a system-category error, never the expected-input error a request validator would use (**M33** (b)/(c)); a sibling derivation over the same rows answers the same way. (b) A consumer passes the loaded rows unchanged. Re-mapping, filtering, slicing or rebuilding them at the call site is forbidden: for a full-history derivation a filtered subset is not a narrower input but a wrong one, and it yields a plausible ordinal or count from partial history. (c) Where the language allows it, the derivation declares the parameter with a branded read-only collection type that only the seam produces — the brand key is not exported, the seam asserts it once on the query result, and the type is declared where the derivation can import it (a shared-layer module when the seam cannot live there). Every rebuilt collection — a literal, a spread, a copying collection method, a collection constructor — returns the unbranded type, so the call does not compile, whether the rebuilt value is passed inline or bound to a local first, and rows loaded by another query fail the same way ([**ENA-P1**](../enforcement-architecture/enforcement-admission.md) rung 1). Enforcement: the compiler; the one remaining escape, an assertion to the brand outside the seam, is fenced by whatever mechanism the adopting project documents for foreign brand assertions, naming the seam as producer and the shared module as the type's declaration. Limit of the check: an assertion to a type that does not name the brand (a bottom type) compiles; a seam-fed derivation that declares a plain collection parameter instead of the brand is not fenced (which parameter receives seam rows is known only across files); both remain a review obligation, and so does the error-category choice of the scope check. [On violation: Bug — the row adapter drifts between consumers, or a derivation over a full history computes from a partial one, and every copy still yields a plausible number] [Verify by: the derivation accepts the seam rows and owns their normalisation; no call-site mapper remains ([**DCD-M2**](../dead-code/dead-code-rules.md)); the parameter carries the seam-only brand and a rebuilt collection fails the typecheck]

Cross-tier boundary of obligation (a): a derivation that the client's render path also runs does not accept raw carriers — it takes only the canonical form and never throws, and the server callers that hold stored records canonicalise at their own boundary through one server-side adapter over the carrier normaliser. Obligation (a) moves the normaliser into the derivation; for a module compiled into both tiers that moves the normaliser's fail-loud rejection under every component body and memo that calls it, where a throw blanks the surrounding surface ([**PAY-UI-M3**](../payment-ssot/ui-binding.md) cross-tier hardening application). The client's wire DTO is already canonical — the producer normalised and validated it — so the client pays for a rejection it can never need. The adapter is not a second normaliser and not a second predicate: it applies the one normaliser to the named fields and returns the derivation's typed input; each caller invokes it before any write, so a corrupt reference stops the operation instead of failing in a log line after commit. Consumers of the post-transform DTO pass it directly. Limit of the check: the compiler rejects a carrier typed as unknown or as a generic object, but where the persistence layer's declared type already claims the canonical form for a field that can be resolved at runtime, a new server caller passing the raw record type-checks — review, stated where the predicate is registered. [On violation: Bug — a consistency widening turns a normal render into a blank screen, or a server path reads a resolved reference as absent] [Verify by: the shared input typed canonical; every stored-record caller routed through the adapter before its writes; DTO consumers unchanged]

**SSG-M1** named per-record decision application: A decision about one record that has a name — which of two identity shapes selects its settings, "the primary reference, else the fallback reference", the single value a set of rows must agree on, whether the record belongs to a class, whether a stored sub-document is valid — is a derivation with one owner that every consumer calls; the one-line copy is cheap because it reads like field access, and each copy picks its own answer for blank, duplicate or both-present input. Three obligations. (a) Every reader of the same stored record takes the same decision, a rare-path reader included: a recovery, repair or migration reader is still a reader, and one that spells the fallback differently produces a different answer for the same record than the path it recovers. (b) One validator per stored row shape: every reader of a persisted sub-document calls the same validator, and its result type claims only what that validator checks; a narrower second validator hands its callers a guarantee nobody checked. (c) A value named for the class is computed by the class predicate: a question that only looks similar — "is there a target to write to", "did the form select one" — carries its own name, so the name keeps saying what was decided. Enforcement: where admitted, one single-file rule per decision flags its fingerprint outside the owner — a conditional choosing between two single-key literals, the fallback operator between the two named reference reads, a set fed from the agreed field and tested for size above one, two fold helpers in one file, a class-named binding that reads the identity fields, a function taking the stored-row type and raising. Limit of the check: the fingerprints are name- and shape-based; an intermediate variable, a differently named value, an `if` block, a list instead of a set, or a copy taking an untyped row escapes and stays a review obligation, stated where each rule is registered. [On violation: Bug — the same record gets a different answer on a different path, and every copy still looks like plain field access] [Verify by: each owner registered; the copies deleted in the same change ([**DCD-M2**](../dead-code/dead-code-rules.md)); each admitted rule green on the tree and red on the pre-fix copies]

**SSG-M1** linked-identity population application: A per-record membership derivation resolves every authoritative alias of one same-tenant subject before filtering. A validated existence flag is insufficient when the membership row carries distinct roster and linked-account identities. The query prefilter and the later in-memory predicate consume the same resolved identities and declared field priority; an explicit assignee overrides the creator. Compare old and new selections over the real consumer population, and both renderings against the actual query engine; an unexplained disagreement blocks closure. Stated enforcement limit: the existing scope authority and a named membership module are stronger mechanisms (**ENA-A1**(c)); tenant-link resolution, consumer completeness and engine parity are cross-file, data-dependent review obligations, not covered by a syntax fence.

**SSG-M1** required-contribution integrity application: A complete aggregate cannot report a required contribution failure as a smaller successful population. Resolve every required contribution through its existing frozen-fact authority; if one cannot be established, reject that integrity unit and suppress dependent rows, counts and rankings. Do not fabricate weights, reload a live catalogue, or warn and skip. A bundle may preserve independently successful siblings, but its failed section returns no data and reaches the same classified boundary as a direct request. Stated enforcement limit: the authority's throw and the classified boundary are stronger mechanisms (**ENA-A1**(c)); whether a contribution is required, and whether a rejection becomes a successful omission across callers, require read-path review. A single-file success-in-catch check does not cover a catch that returns before another function emits success.

**SSG-M23** frozen contribution views application: A frozen row's multiplicity is part of the money evidence even when identifiers repeat. A per-row contribution and a subtotal for one selected identifier are distinct legitimate questions: the one contribution authority exposes explicitly named views over the same ordered allocation vector. The row view selects the actual occurrence; the subtotal includes every matching frozen occurrence once. A caller carries occurrence identity and never recomputes the allocation or collapses the vector into an identifier-keyed last-value map. Before a selected contribution is emitted, the authority proves association with every required selected identifier; an incomplete snapshot cannot turn one record's total into a full total for each selection. A known explicit amount for one proven selected item needs no invented weight, while a missing frozen row cannot be fabricated for a row view. A proportional intermediate slice never exceeds the remaining total after canonical currency rounding; the final slice receives the actual residual, preserving order and total without a negative balancing row. Distinct display, accrued-contribution and cash questions retain their named contracts; reducing duplicate derivations does not invent a shared pricing policy. Stated enforcement limit: required view types, structural rejection and the single allocator are stronger mechanisms (**ENA-A1**(c)); completeness of caller populations and of frozen association is a cross-file review obligation. No new syntax rule is admitted.
