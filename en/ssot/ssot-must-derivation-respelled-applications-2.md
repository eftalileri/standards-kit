---

**SSG-M1** polymorphic-carrier application: A value that can arrive in more than one representation — for example, as an identifier, a resolved document, or a driver-specific identifier object — has one normalisation to its canonical form, and every consumer calls it. Re-spelling the conversion at call sites (`typeof x === 'string' ? x : x.<id>`) creates multiple authorities whose answers diverge on blank, absent (a resolution whose target was deleted), or structurally invalid values. (a) Define required and optional variants. A required variant fails loudly when the value is absent; an optional variant reports absence for null, undefined, or blank input. Both reject structurally invalid carriers, such as an object without an identifier or a number. No variant returns a blank string, a stringified object, or a sentinel. Failing loud uses the layer's registered system error whose root cause names the field and shape class, never the value (identifiers may be personal data). (b) Keep the absence decision with the consumer. Whether absence means a typed error, a skip, or a counted detached record belongs to that consumer's contract; the normaliser reports absence but does not impose one policy on every caller. (c) A keyed batch and its consumer derive keys through the same normaliser; two spellings of one key agree until the first input on which they do not, and the lookup then misses with no error. The same holds for the two sides of an optimistic-concurrency comparison: the expected value captured before the write and the value observed inside the attempt come from one capture. A key-building pre-pass is not an item boundary: a carrier the normaliser rejects contributes no key there, and the per-item pass re-derives it through the same normaliser and contains the failure to its item, so one malformed row does not abort unrelated items; background work that continues per candidate follows its error-ownership contract ([**M21**](../logging-policy/shutdown-watchdog-clarifications.md) — every candidate is attempted). (d) Delete parallel helpers rather than wrapping them. A helper that only renames one variant is another name for the same derivation; remove it in the same change and point any registry entry at the survivor ([**DCD-M2**](../dead-code/dead-code-rules.md)). (e) A consumer across a typed wire contract does not repeat normalisation already guaranteed by the producer. Validate that the canonical value is non-empty and fail loudly if malformed; a client copy of the resolution branch is dead code that reads as a supported input.

Which string-only reads and trims are copies. A string-only read (`typeof x === 'string' ? x.trim() : ''`), a string coercion followed by a trim, a coercion with a literal fallback, or a plain trim of a reference field read from a persisted record — a document, a projection or aggregate row, a transform input — is a copy of the optional variant (blank answers an empty string, never "absent") and goes through the normaliser; the consumer keeps its registered absence error. Four look-alikes are not copies: a strict canonical-form fence that rejects a non-string, blank or untrimmed value (normalising would accept what it rejects); an authorisation predicate that compares exactly (a trim can only widen a grant); a parameter precondition or request/JSON narrowing its schema already typed (the caller's contract); and a consumer of an already-canonical producer — a post-transform DTO, a frozen snapshot, an event payload — whose check is the non-empty check of obligation (e). A plain coercion of a field declared as a string, with no trim and no fallback, is the identity and stays allowed; a coercion of a value that is not a stored reference is dead and is removed, not routed.

Enforcement: use the mechanism the adopting project documents. A single-file structural check can recognise the dual-representation test (the same expression path tested as a string and read through the identifier key, after stripping casts, assertions and simple aliases), the coercion-then-trim and literal-fallback spellings on reference-named operands, and — with type information — trims of reference fields declared in persisted-record types. Limit of the check: it does not see a test in one function and the read in a nested one, a copy with no string test and no converting call, a record type declared outside the configured location, a reference passed as a parameter or copied to a local first, or a local name without identifier evidence; a non-reference identifier stored on a record looks the same and needs a reasoned suppression. A reference to a check is not evidence that it exists or covers the full rule; record its actual scope and leave the rest to review.
