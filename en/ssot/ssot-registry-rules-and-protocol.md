Project-specific paths, commands and mechanisms belong to each adopting project's registry.

## Rule identifiers (registry-specific)

| ID | Rule |
|----|------|
| **SSG-R1** | Before changing or adding a semantic, search the project's authority registry (domain routing, then the applicable registry file) and read the applicable entry before coding. This applies **SSG-M6**. |
| **SSG-R2** | Authority path or contract changes **MUST** update the authority entry in the same change. The registry is the only required-authority file list (**SSG-M8**); every authority and contract-shape path it names exists, or an actually removed path is marked as removed (for example struck through) in the same cell that records the removal — never silently deleted, never left looking current. This also binds Guard addresses. When an authority gains a path, re-measure every named enforcer against that real path in the same change: prefer scope derived from the authority or registry structure; extend a genuinely explicit path list too. Expanded resolved scope, never registration text, proves protection. A row's Guard answers its own invariant: it **MUST NOT** name a check that applies identically to every row. State a registry-wide structural check once outside the table; a row whose own invariant is structural may name it only together with what it verifies. Without a mechanism write `review`, and state that limit in the governing standard. |
| **SSG-R3** | The consumer cell carries the find pattern first. The cell states the pattern that re-derives today's consumers (the exported symbol(s) and search scope, per the Section 5 recipe); a count or names may follow. Individual names are mandatory only in the **SSG-R4** class. The pattern is updated in the same change only when the authority's path or exported symbol changes — outside the **SSG-R4** class, adding or removing one import needs no registry edit. A bare count with no pattern is forbidden: nothing can re-check it. An authority with no consumer writes `no consumers — <reason>` (for example an operator-only entry point; a released client binary → **DCD-M8**); a reasonless "no consumers" is a review flag — dead code, or a measurement never performed. Counting contract and find recipe: Section 5 of the [update and consumer-measurement protocol](ssot-registry-protocol-and-consumer-measurement.md). **Limit:** consumer completeness requires cross-file and external-client knowledge; unless the project has a validated inventory mechanism, it remains a review obligation. |
| **SSG-R4** | Cache bridge consumer registration — closed, exhaustive name list. When the registry lists a cache bridge or mutation-cache orchestrator authority, every mutation hook or success path that changes the guarded entity must appear by name in the consumer cell — including indirect and cross-entity write paths per TanStack [**MUT-M20** / **MUT-M22**](../tanstack-query/mutations-invalidation-and-bridge.md) — refreshed in the same change as a new write path. For this class a number is forbidden and a closed, exhaustive list of names is mandatory — no `+`, no `~`, no `etc.`, no layer paraphrase standing in for a name. Why: a reader checks *the path I am adding* against a list of names; a count cannot be checked against a call site, and an open tail declares the list incomplete in advance. Cell label: a record in this class labels its cell with one fixed, searchable marker (for example `**Consumers (complete list — SSG-R4):**`); the label is how the class is found. Server side: the same closed-list obligation binds a server-side cache-invalidation orchestrator row (Redis [**RDS-M20** (a) / **RDS-N12**](../redis/redis-prohibitions.md)). |
| **SSG-R5** | Identifier uniqueness and allocation (**SSG-M1**). One identifier names one authority. Identifiers are unique and stable within the declared registry scope and follow the project's documented allocation policy; for numeric identifiers the default is: a new number is the highest number across all registry files + 1, gaps are not filled, and a freed number is never reused. On a collision the two rows are not merged: the row registered first keeps its identifier; the later one moves to the next free identifier and every reference to it is updated in the same change. Completed historical plan documents are not renumbered. Scope: every agent-facing numbered record file (for example an agent note ledger); each file — each section, where a file has several — is its own identifier space. Projects without a meaningful numeric identifier scheme may use stable semantic headings instead. |
| **SSG-R6** | Row granularity and content — one row per authority, contract shapes named inside it, nothing beyond the content budget. A registry row registers an authority: the single writer of a datum, the single executor of an operation, or the single canonical derivation of a value. A file that only declares the authority's contract shape — its type/interface declaration, its validation schema, its constant/enum table — is not an authority and must not get a row of its own; it is named inside the owning authority's row (contract block, contract-shape line), so one lookup answers both *"who writes this"* and *"what shape does it have"*. Test: does the file answer *"what is the correct value of this?"* → authority, row. Does it answer *"what shape does this value have?"* → contract shape, named inside the row. Why: a contract shape with its own row makes two entries for one authority, and a later reader cannot tell which of the two is the writer — the ambiguity **SSG-M1** exists to remove. In reverse: a registered contract shape whose *writer* has no row is a missing row, not a covered one. Helper split: a helper imported by exactly one authority that answers no question of its own is part of that authority — it is added as a second path in the same row's Authority cell, never as a second row. What the registry names must exist: every project-relative path the registry writes is verified on disk; a path whose file is gone is marked as removed in the same cell that records the removal. Content budget. A row carries only: its identifier, the one question or datum it owns (one sentence), the authority file(s) with function names, today's consumers (**SSG-R3**), the governing rule id, and its Guard cell (**SSG-R2**). A contract block carries only what a consumer must honour — input/output, invariants, error behaviour — plus the contract-shape line; detail readable from the code is not copied in. A binding caveat about a row goes into that row's contract block; no separate notes file or per-domain summary is written for registry rows (a second description of the row, **SSG-M8**). A rationale appears only when the choice is not obvious, in at most two sentences; a longer one goes to the project's decision records and the row links it. History, dated measurements, commit hashes, how a fix applied the row, and text repeated from another row **MUST NOT** be written ([**KIT-ADD-12**](../authoring/kit-rule-addition.md)). Row syntax. A registry table's header **MUST** start with the identifier column and name each other column by its role word (Semantic, Authority, Owner, Contract, Consumers, Related, Guard); qualifiers in parentheses or after ` — ` are free. A row **MUST** be one table line with the header's cell count (a literal `\|` inside a cell is escaped), no blank line splits a table, and the identifier cell is a live identifier or a retired tombstone (for example `~~N~~`). A pointer to row N with N = the row's own identifier is the contract pointer, and the Contract cell **MUST** link that block; any other N is a cross-reference and **MUST** resolve to an existing row. Every contract block **MUST** be linked from exactly one row — a forwarding stub or second copy **MUST NOT** exist. A non-registry table in a registry file is the preceding row's body; its caption line **MUST** name that row's identifier. Why: a lookup reads only these forms, with no hand-kept label list, so any other form is a row or block no query can reach. |

## Failure path

A registry entry that points to a missing or obsolete authority, omits a known parallel writer, assigns the same identifier to distinct authorities (**SSG-R5**), or names a bare registry-wide command in a Guard cell is stale and is a review finding that must be corrected before the change is accepted. A declared mechanical check is not proof that the new authority path is in its scope; verify the actual scope. A registry-wide structural check does not substitute for checking the invariant of an individual row. A code-level arm of a registry rule that passes the admission test (for example a populate or join of an owned relation outside its repository) belongs as a row of the project's owner-surface lint rule, not as registry text.

Stated limit ([**ENA-GV3**](../enforcement-architecture/enforcement-admission.md)): no gate enforces the registry's Markdown shape (the Guard-cell half of **SSG-R2**, **SSG-R3**, **SSG-R5**, **SSG-R6**); a lookup tool may report **SSG-R5** duplicates and **SSG-R6** row-syntax defects with `file:line` on every query and exit non-zero, but it is not a gate step; the harm is documentation ergonomics, which fails [**ENA-A3**](../enforcement-architecture/enforcement-admission.md). The rules stay binding; review enforces them.

## Maintainer checklist

- [ ] The registry was searched before implementation (**SSG-R1**).
- [ ] A row exists in the relevant registry file for each new semantic.
- [ ] Row granularity checked against **SSG-R6** — the row registers the authority; its type/schema files are named on the contract block's contract-shape line, not given rows of their own.
- [ ] Row and contract block hold only the **SSG-R6** content budget — no history, dates, commit hashes, application narrative or separate note.
- [ ] Paths and contract changed in the same change as the authority (**SSG-R2**).
- [ ] Consumer cell carries its find pattern per **SSG-R3**, never a bare count; no consumers → `no consumers — <reason>`. Recipe: Section 5 of the [update and consumer-measurement protocol](ssot-registry-protocol-and-consumer-measurement.md).
- [ ] If the row is a cache bridge / mutation-cache orchestrator (**SSG-R4**): the cell is a closed, exhaustive name list under the class label — every direct, indirect and cross-entity write path named, no `+` / `~` / `etc.` tail.
- [ ] Identifiers follow the project's allocation policy and are not reused (**SSG-R5**).
- [ ] Guard cell names a row-specific mechanism whose real scope covers the row, or `review` with the limit stated (**SSG-R2**) — a registry-wide structural check is never written there; where the row's invariant genuinely is the structural one, the cell says what is verified.
- [ ] If the project provides a lookup, it returns the new or changed row and reports zero integrity defects.
- [ ] Domain routing and local links resolve, including links from the [SSoT hub](README.md) and **SSG-M6**.
- [ ] The project's applicable registry and documentation gates pass.
