Scope: in these shapes the input source is correct, but the derivation itself is duplicated, incompletely delegated, or hidden by a misleading inventory.

**SSG-M1** guarded-arithmetic application: A derivation whose formula is valid only under a condition **MUST** be called as one unit, not re-spelled without its guard. A simple expression (`total - paid`, `capacity - used`, `quota - consumed`) can return a plausible value even when the record's state (cancelled, refunded, void, superseded) makes that formula invalid. (a) Put the guard and formula in one named derivation; a helper that returns only the arithmetic leaves the same trap at its callers. (b) Handle absent or invalid inputs in that derivation and fail loudly instead of substituting a neutral value ([**SSG-M17**](ssot-must-no-stand-in-data.md)): a substituted zero is indistinguishable from a measured zero. (c) Complementary derivations are legitimate when each is a named authority with its own condition; do not put one condition in a helper and its inverse inline. A single-file check may flag a subtraction rooted at the base field outside the named derivations, but aliases or values with different provenance can escape it; state the actual scope where the check is registered and keep undecidable cases with review. [On violation: Bug — an invalid state produces a plausible but incorrect result] [Verify by: guard and formula are one authority; absent/invalid inputs have explicit outcomes; consumers call the authority]

**SSG-M1** scale-twin application: A per-item and a bulk computation of the same measure are two authorities; the per-item path delegates to the bulk authority. A performance change may replace a query inside a loop with an aggregate while leaving the helper "for the single case." The computations can agree initially, then drift as filters or exclusions change. (a) Grouping keys are part of the measure. A bulk grouping key broader than the per-item key answers a different question and may split one subject across groups. (b) An inverted derivation is another copy. If the authority publishes a derived companion value, consumers call one named inverse derivation — placed in a tier every consumer can import and failing loud on inputs the identity forbids — rather than reconstructing it from a potentially stale cache. (c) Pass transaction/session context and other required inputs through the authority instead of restoring a separate path for one caller. Losing copies go in the same change ([**DCD-M2**](../dead-code/dead-code-rules.md)). [On violation: Bug — one measure returns different results by batch size, grouping, or cache age] [Verify by: per-item calls delegate to the same bulk derivation; filter and grouping semantics match; inverse computations use one named authority]

**SSG-M1** partially-gated-copy application: When a re-spelled derivation is reduced to the authority, compare both over inputs the persisted contract permits. A disagreement on valid inputs may be legitimate behaviour that needs an explicitly named branch ([**SSG-M23**](ssot-principles-and-precedence.md)); a difference only on contract-invalid inputs is not behaviour to preserve, and a branch built there enshrines the defect inside the authority. Record the input domain to make this distinction reviewable. (a) Measure and record which inputs cause divergence, then classify them against the persisted contract. If every disagreement is on inputs the contract forbids, delete the copy without adding an authority mode. (b) A copy that delegates some fields to canonical helpers but reimplements another can look compliant at a glance. Prefer one composed normaliser that owns the complete record, with the field-level gates importable only from it. A check may verify imports or structure, but it cannot prove that a local rewrite is semantically equivalent; state that limit. [On violation: Bug — invalid-input behaviour is preserved as a supported mode, or a partially re-spelled copy passes review] [Verify by: divergence inputs are classified against the contract; invalid-only copies are removed in the same change; one normaliser composes field-level authorities]

**SSG-M23** held-input application: A consumer that already holds the authority's first-precedence input is not exempt from the authority. Reading the field directly can bypass later normalisation (rounding to the currency's minor unit, clamping, unit conversion) and absence handling even when an upstream validity gate has passed; a gate answers whether a stored value is legal, never what the derived value is. If a consumer lacks other inputs required by the full derivation, do not call it in a way that falls through to a different source. Instead expose a named branch that accepts only the available input, applies the same normalisation and failure behaviour, and have the full authority delegate to it. Equal results over today's stored population do not prove the branch unnecessary if the difference appears only for future or malformed inputs. [On violation: Bug — normalisation or absence failures disappear at consumers that read the raw field] [Verify by: a named branch and the full authority share one implementation; consumers use the branch matching their inputs; equivalence limits are stated]

**SSG-M23** extraction-declaration application: A module extracted to replace duplicated derivations states its current remaining-copy count, scope, and date in its header. A historical motive alone can make the extraction look complete while copies remain. A stale declaration is worse than an absent one: absence prompts a measurement, a stale claim replaces it; at zero it says zero. (a) State the derivation's scope so a neighbouring, weaker variant is not mistaken for a duplicate. (b) Name each deliberately retained copy and its reason so the residue is owned rather than mistaken for unfinished work. [On violation: Bug — an extraction hides copies it exists to remove] [Verify by: header records a current dated count, scope, and reason for retained copies; remeasure when the authority changes]
