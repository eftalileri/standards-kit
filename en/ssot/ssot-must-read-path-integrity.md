# SSoT **MUST** — read-path integrity (a query path does not write; a list orders by what it shows)

```kit-cover
type: normative
part-of: README.md
binds: SSG-M20 -- the command/query separation a read or list contract owes the datum it returns; the SSG-M3 application a list contract owes a value it DISPLAYS from a derivation but could order by that derivation's raw input; and the SSG-M8 application a separate store built to be reported from owes the authorities it copies -- an ownership-bounded column set, a window-replacing refresh, and a one-way direction
open-when: signal:ssot-authority, signal:duplicate-writer, signal:read-only-endpoint, signal:list-endpoint, signal:derived-field, signal:new-semantic
```

Part of: [SSoT principles and precedence](ssot-principles-and-precedence.md). This is the read/query side of the authority rules; **SSG-M20** is defined here, while the related **SSG-M3** and **SSG-M8** rules remain defined in their owning files.

**SSG-M20**: A query path **MUST NOT** write. A read/list endpoint — any function whose contract is to return the current value — **MUST NOT** create, update, or delete the datum it reads. A find-or-create reached from a read path is a second write authority ([**SSG-M8**](ssot-principles-and-precedence.md)); caching makes the write depend on cache behavior rather than on an explicit command. (a) Split by contract, not by convenience. The read half returns the record or an explicit absent result; the write half belongs to the command that creates or changes it. Identify the subject's valid creation paths before removing an implicit create. (b) Absence is a result, not automatically a defect. Represent absence structurally, do not fabricate a record, and do not return a silently empty answer that looks like a real empty result. (c) Delete an unused write half. If the create branch has no callers after the read path is separated, remove it in the same change ([DCD-M2](../dead-code/dead-code-rules.md)). (d) Trace creation paths from the subject. For every way a subject can come into existence, ensure there is an explicit create path; listing existing write call sites alone can miss subjects whose only create was hidden in a read. Confirm that the command's key matches the read path's lookup key. Treat expected absence consistently with the product's error and observability policy. A missing settings row, for example, is not permission for a lazy create ([SSG-M3](ssot-must-read-integrity-and-aggregates.md)). Stated enforcement limit: proving that a read/list handler's transitive call graph never writes generally requires cross-file dataflow, and proving every subject-creation path also requires domain knowledge. Unless the project has a check that can establish those facts, keep both obligations with review and state that limit. [On violation: Bug — a cached read silently stops writing, or a datum acquires a writer no command owns] [Verify by: per read/list handler, review its transitive call set for writes; trace each subject-creation path to an explicit create; confirm read and create use the same key]

**SSG-M20** application — a stored copy that disagrees with its derivation. A read that holds both a stored accelerator copy and the value derived for the same read from the authority **MUST** serve the derived value and, when they differ, report the difference once per subject under a registered system-category error whose root cause names the explicit repair command; it **MUST NOT** repair the copy. Reason: the difference proves a writer skipped its recalculation, which is a defect someone must chase, while repairing on read hides the writer and gives the datum a second writer.

**SSG-M3** ordered-list application: A list that DISPLAYS a derived value and can be ORDERED by it **MUST** take the ordering key from the same derivation, and **MUST** establish that order before pagination. If display uses a canonical derivation while sorting uses its raw input, the rows can appear out of order beneath one column heading. Sorting each page after it is cut does not fix the result: page boundaries still follow the raw field. (a) Derive the value once for the full matched set and return the ordered subjects with the map used to order them; display reads that same result. (b) Values the derivation cannot measure sort consistently at one end in both directions, and a stable secondary key breaks ties so pagination does not repeat or skip subjects. (c) Measure the cost before offering the sort and state which population it scales with. [On violation: Bug — a sortable column orders by a value it does not show] [Verify by: ordering and display use one derivation result; measured cost is recorded against the population it scales with]

**SSG-M8** analytical-copy application: A separate store built to be REPORTED FROM is a derived copy, never an authority — and what keeps it from drifting into one is declared at the copy's own schema, not left to the discipline of whoever writes to it next. The copy is legitimate: no transactional store or third-party API answers a year of grouped reporting cheaply. The failure is that a reporting store looks like a database to everyone who meets it afterwards, and a database is where people put things. Three obligations. (a) The column set is bounded by OWNERSHIP, and the boundary is written where the schema is. Facts whose authority is external — what a provider delivered, spent, or recorded about its own objects — may be copied, because the copy cannot compete with an authority it does not contain. Facts the product itself owns — outcomes, revenue, anything a first-party write path already decides — **MUST NOT** be given a column. An unused column is an invitation: some later job fills it because the value was in hand, and from then on one figure has two stores that disagree silently. Declaring the exclusion beside the schema, with the reason, makes the next author's addition visibly a change of authority rather than a change of table. (b) Refresh REPLACES a declared window; it does not merge row by row. Swap a bounded, named window of the copy for the freshly read rows of exactly that window, and the window contains every row read (a source reading whole days widens the lower bound to its earliest fresh row): a re-run over an overlapping window converges instead of accumulating, so the copy self-heals. The swap is ONE atomic commit keyed by the writer's full identity (every key its loop iterates, e.g. account): split in two, a failed insert leaves the window empty; keyed narrower, one iteration deletes a sibling's rows. Per-row merge needs a stable row identity and a source-owned ordering token ([**SSG-M12**](ssot-must-provider-projection.md)); bulk delivery facts publish neither, so it becomes last-writer-wins. Where no window is expressible, SSG-M12's token is mandatory; its absence is a blocker. (c) The direction is one-way, and the copy's operational limits belong to its contract. No path reads the copy back into a write on any authority; its consumers are read surfaces, and the moment one of them writes a first-party record from a figure it read out of the copy, the copy has become the authority for that figure without anyone declaring it. The copy contract also states operational constraints: confirm the chosen storage mechanism supports the replacement operation, and place the copy where required joins can run. Platform-specific limits must be documented rather than assumed away through tuning cadence. [On violation: Bug — a reporting copy becomes a second authority for a first-party figure, a refetch double-counts, or a windowed delete silently destroys rows it never re-inserted] [Verify by: the copy's schema carries no column for a fact a first-party write path owns, with the exclusion stated beside it; every writer replaces a named, identity-scoped window in one atomic statement, or names the source-owned ordering token it merges by; no consumer of the copy writes an authority record from what it read; store locality stated with its reason] Stated limit ([**KIT-INV-8**](../authoring/kit-structural-invariants.md)(b)): (a) and (b) are unfenced — which facts have a first-party authority, and a writer's full identity, are domain knowledge no syntax tree carries; only the streamed-buffer path is fenced (a project-specific check, if one is admitted and verified). (c) is the transitive predicate **SSG-M20** above already declares unfenced.
