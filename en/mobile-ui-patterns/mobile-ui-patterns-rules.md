## **MUST**

| ID | Rule | Consequence | Verify |
|----|------|-------------|--------|
| **MUP-M9** | Query-independent list filter controls **MUST** stay outside transient cold-loading and blocking-error content branches, so the person can change the query while loading or recovering. Compact choice rows **MUST** retain all options, an understandable clear/all action and one filter-state writer. | Bug — **must not** ship. | Inspect composed screen and wrapper early returns. A single file cannot establish which controls are query-independent across wrapper boundaries: that information belongs to the product screen contract; rendered density/readability needs device and font measurements. |
| **MUP-M10** | A failed cursor-page fetch with usable earlier pages **MUST** retain those pages and expose explicit recovery. Automatic end-reached fetching **MUST** stop while that failure is unresolved. A cursor rejected after policy/version change **MUST NOT** be silently reinterpreted; a user-requested refresh starts a new traversal through the existing query/origin authority. | Bug — **must not** ship. | Inspect infinite-query error gate, stable footer recovery and refresh callback; existing cursor validation owns rejection. Cross-module response semantics and the released-client cursor horizon are not derivable from one file, so recovery correctness also needs source-flow review. |
| **MUP-M11** | When a product contract declares a conditional call action as a contact card's visible phone affordance, the card **MUST NOT** also print the same phone as a separate plain-text line. The optional published phone remains the action's target; absence hides the action without a placeholder or a fallback identity. The call control retains a target-specific accessible name and its existing failure route. A product that explicitly needs readable/copyable digits may define a different presentation in its own UI spec. | Bug — **must not** ship. | Review the product UI spec, published-field/action wiring and composed card. Stated mechanical limit: phone text is legitimate on other surfaces, while whether it duplicates a call action is a product intent across card/action components; a single-file analysis cannot decide that intent or the rendered duplication. |
| **MUP-M12** | An in-app engagement card or prompt — one whose purpose is to nudge (an invite, an upgrade reminder, a success-moment call to action) rather than to serve the screen's own task — **MUST** render inline and never block that task (no blocking modal, no gate on navigation or input), **MUST** carry a dismiss control with its own accessible name, and **MUST** read its frequency cap from one authority shared by every card of the same moment class; a card **MUST NOT** define its own cooldown or storage key. While its optional data read is not ready the card renders nothing rather than adding an error surface to a screen it does not own; that read's recovery surface belongs to the screen the card leads to. A dismissed card leans on a permanent entry ([**RTG-M16**](../routing/navigation-rules.md)). Reason: the person's task outranks the nudge, and per-card caps add up to nagging. | Bug — **must not** ship. | Review: inline placement, dismiss path and the cap authority import. Which cards share a moment class is a product fact no single file carries. |
| **MUP-M13** | A horizontally scrolling region inside a horizontal pager page **MUST NOT** leave the touch split to platform nesting behaviour: Android gives a same-direction gesture to the outer scroller and iOS to the inner one, so the same swipe pages on one platform and scrolls on the other. While the pager rests on that page and the inner region can scroll, the pager's finger scrolling is turned off and the inner region owns every horizontal swipe; a swipe toward the previous page that starts at the inner region's start edge (start-relative, so mirrored in right-to-left layout) moves the pager through the same animated path as its tab control. In a browser the pager **MUST** stay finger-scrollable and no JS edge gesture runs: the browser latches a swipe to the first scroller that can move in its direction when it starts (the same edge rule), and it cancels the pointer stream of a swipe it claims, so a JS pan ends with no distance and a locked pager can never be left by swiping. The decision reads only a settled-page signal written by the pager's own scroll event — never the mid-drag selected page, because turning the outer scroller off mid-drag strands it between pages — and programmatic paging (tab control) keeps working throughout. | Bug — **must not** ship. | Review: the pager's `scrollEnabled` derives from its settled page and the inner region's scrollability; the edge gesture recognises simultaneously with the inner scroller's native gesture. |
| **MUP-M14** | An operating-system permission prompt (contacts, location, notifications, camera and the like) **MUST** follow the person's own action and the app's own explanation of what the access is for, and every surface **MUST** reach that prompt through the one request authority of that permission; a surface **MUST NOT** call the platform request directly. The explanation offers a decline that opens no prompt; an implicit request (field focus, typing) that was declined is not asked again on every interaction; once the platform reports it can no longer ask, the authority offers a route into the operating-system settings. A prompt no user action can ask for (iOS tracking) **MUST** open only immediately before the in-app decision that depends on it, never at launch; before that the authority reads the status without a prompt. Reason: a bare system prompt on first touch is easily refused and, on iOS, cannot be asked again — the feature is lost for that person — and per-surface copies drift back into prompts without explanation ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)). Location and push notifications specialise this row in [**MAP-RN-M5**](../maps-location-rn/maps-location-rn.md) and [**NOTIF-UX-M1**](../expo-notifications/notification-opt-in-and-ux.md). | Bug — **must not** ship. | Review: the platform request call appears only inside the permission's request authority; that authority shows the explanation before the prompt and handles the cannot-ask-again state. |
| **MUP-M15** | A selector whose roster holds a single choice **MUST NOT** be drawn — the screen then shows that one choice's content without asking. Whether a choice exists **MUST** be derived once, next to the roster's authority, from the roster's own readiness and count, and every surface that draws the same selector **MUST** read that one answer (**SSG-M8**); no surface adds its own condition (a non-empty check, a field-presence filter). While the roster has not answered, the selector's place is held at its size and nothing is drawn in it, so the screen neither flashes an empty control nor jumps. A failed roster read is its own answer, never folded into "not answered": the selector is drawn and opens the surface that shows the roster's error and retry (**EHX-M2**), so the failure is neither a silent hole nor a dead end. Reason: a control with nothing to choose is noise, and per-surface tests drift — a non-empty check stays true when the list always contains its owner. | Bug — **must not** ship. | Review: each surface branches on the shared derivation only. |
| **MUP-M16** | An overlay placed by another view's window position (a coach card by its anchor, a popover by its trigger) **MUST** re-measure when that view moves, not only when the view reports its own layout: in a browser `onLayout` fires on size changes alone, so content loading or growing above the view moves it unreported and the overlay keeps covering the old place. The browser half therefore also re-measures on any content change of the overlay's host (nodes, text, classes; once per frame), while the native half keeps the view's own layout event. Reason: the stale rect puts the overlay over the very control it points at, which then cannot be pressed. | Bug — **must not** ship. | Review: the overlay host wires a web-only content watch beside the view's own layout notification. |
| **MUP-M17** | A rule that hides or moves an overlay "while the user types" **MUST** read typing per platform: the software keyboard's frame on a phone or tablet, and in a browser the focused text field inside the overlay's host — a physical keyboard reports no frame, so a keyboard-only signal never fires there. The browser signal **MUST** hold its answer until a press ends: the field blurs on pointer down, before the click, and an overlay shown on that blur takes the click meant for what the user pressed (a search result). Reason: the overlay then covers the field and its results while they are used, or swallows the selection. | Bug — **must not** ship. | Review: the overlay's typing input combines the keyboard frame with a web focus seam that defers its change to after the press. |
| **MUP-M18** | An overlay placed by another view's window position **MUST** be drawn only once that view has stopped moving — the same measurement on consecutive frames — and stay hidden (and untouchable) while it moves: a scroll, a relayout, or the keyboard closing after the user typed. Event-driven re-measuring alone lags the move by a frame or more, so a frame loop judges the end of the move; a bounded number of moving frames draws it anyway, so a screen that never settles cannot hide it for good. Reason: an overlay drawn from the last rect stands over the very control it points at until the move ends. | Bug — **must not** ship. | Review: the overlay host gates its visibility on a frame-stable measurement and resets it when it hands out a scroll band or the keyboard closes. |
| **MUP-M19** | A coach overlay whose copy tells the person to press screen controls besides its anchor (a "create" button under a list, a form's save button) **MUST** keep each of them uncovered too: the step declares them, placement treats every one of them as an obstacle (a control outside any scroll view as a fixed edge bar), and when no placement keeps all of them clear the anchor still stays uncovered. On a wide layout the overlay **MUST** first stand in free room beside them instead of over their column: beside a window or form column, in the room its region leaves on either side (the overlay is hosted outside the column's clipping box to reach it), else in another column clear of the anchor and every named control — narrowing to the room, never below a readable width, the same side first so it does not jump while the step runs; only when no side holds it does it stand over the column, and then an anchor taller than the free band (a whole form) keeps its start — the first field — in view, the overlay taking the far edge. Reason: the person is told to press a control the overlay hides, so the path the copy offers cannot be taken; a wide screen has room beside the column, and an overlay over a form's first field hides where the person starts. | Bug — **must not** ship. | Review: every step whose copy names a screen control lists it (or targets it); the placement resolver receives the controls as obstacles and the free side room (inside the host and beside a window). |
| **MUP-M20** | A wide page with both row selection and a record detail panel **MUST** keep them in two exclusive modes: while no row is checked a row press opens that record in the panel (every row kind opens one), and checking a row through its own selection control enters selection mode — the panel closes, stays closed while any row is checked, row presses toggle the selection and the floating selection bar is the only action surface, never covered; unchecking the last row returns to tap-to-open. The selection control **MUST NOT** open the panel, and the open record **MUST** be screen state cleared on entering selection mode, never derived from the selection. Reason: a panel derived from the selection opens for one row kind only and covers the selection bar. | Bug — **must not** ship. | Review: the page's panel record and selection are separate state; the row's selection mark is its own control. |
| **MUP-M1** | Any shipped contextual help block (collapsible or fixed; title + body) **must** use i18n (`t(` with a documented namespace or the equivalent project pattern) for all user-visible help strings — no literal sentence copy in JSX / TSX for that content. | Bug — **must not** ship. | Pass: review with the file list: every help title / body argument is `t(...)` or a key constant; optionally search help files for long quoted literals (none expected — i18n keys excepted by review). |
| **MUP-M2** | Each primary hub tile / shortcut (`Pressable`, `Touchable*`, or equivalent) **must** expose a stable `accessibilityLabel` (string or `t(...)` result) or **must** wrap visible text that serves as the only name with `accessibilityRole='button'` and no icon-only ambiguity (**MUP-G1** YES surfaces). | Bug — **must not** ship (a11y). | Pass: for each file with a multi-tile hub pattern (the review lists paths): the accessible-label count covers the tile count, or the review checklist records a per-tile label table. |
| **MUP-M3** | When **MUP-G3** is YES, shared visual shell styles (card rows, field outer/inner, menu-aligned shadow wrappers) **must** live in dedicated module files under the feature folder (names in the feature spec or the project's convention) and **must** obey [**STY-M4**](../styling/stylesheet-and-theme-tokens.md) (theme tokens only for covered properties). | Bug — **must not** ship. | Pass: a hex-colour search over those shell modules finds nothing (unless in the theme file), or the **STY-M4** verify recipe passes for those paths (see [stylesheet-and-theme-tokens.md](../styling/stylesheet-and-theme-tokens.md)). |
| **MUP-M4** | When **MUP-G4** is YES, `FlatList` **must** satisfy [**PERF-RLM-M11**](../performance/react-lists-and-memoization.md) (SSOT spread first). | Bug — **must not** ship. | Pass: same as **PERF-RLM-M11** Verify in [react-lists-and-memoization.md](../performance/react-lists-and-memoization.md) for that file. |
| **MUP-M5** | When both this hub and a feature normative UI document at the project's documented domain-UI specification location apply, implement the stricter layout / affordance rule; on data / navigation / error-shape conflict, follow [gray-situation decisions](../agent-gray-decisions/gray-situation-decisions.md) and STOP if unresolved. | STOP / bug. | Pass: the review links the feature document section or states "no feature UI document"; review confirms no contradiction with the linked rows. |
| **MUP-M6a** | When **MUP-G5** is YES, the screen module (`.tsx` + paired hooks file if present) **must** implement initial / cold loading presentation per [**UIP-M2**](../tanstack-query/ui-loading-and-persist-options.md) and [**UIP-M10**](../tanstack-query/ui-loading-and-persist-options.md), modified only by [**UIP-M16**](../tanstack-query/ui-loading-and-persist-options.md) if the feature document records a module exception. | Bug — **must not** ship. | Pass: the diff shows a dedicated loading branch (spinner / skeleton / documented equivalent) consistent with **UIP-M2** / **UIP-M10**; review rejects if missing. |
| **MUP-M6b** | When **MUP-G5** is YES, the screen **must** present an empty success state when bounded list / report data is empty — i18n copy + no blank main content region without feedback (see **MUP-N4**). | Bug — **must not** ship. | Pass: the diff shows an empty branch (conditional render, `ListEmptyComponent`, or equivalent); or a test asserts the empty copy; review rejects if missing. |
| **MUP-M6c** | When **MUP-G5** is YES, the screen **must** implement blocking first-load error (no usable cache) with recovery (retry / `refetch`) per [**UIP-M9**](../tanstack-query/ui-loading-and-persist-options.md), [error-handling **M5**](../error-handling/error-handling.md), and [**M8**](../error-handling/error-handling.md) (see **MUP-N5**). | Bug — **must not** ship. | Pass: the diff shows an error branch wired to `refetch` / documented retry; or a test mocks failure then asserts the recovery control; review rejects if missing. |
| **MUP-M7** | Every `Pressable`, `Touchable*`, or `Button` that submits a mutation or navigates to a new stack route as the primary forward action **must** satisfy [forms **M7**](../forms/forms.md) (accessible name) — extends **MUP-M2** to non-grid controls. | Bug — **must not** ship. | Pass: changed primary CTAs carry `accessibilityLabel` / `accessibilityHint`, or a visible `Text` child inside the button is documented in the review with a screenshot / accessibility inspector note. |
| **MUP-M8** | An option's availability does not decide its tappability. When a surface offers a set of named options and one of them cannot run right now — a permission is refused, a capability is missing, a precondition is unmet — that option **MUST** still be rendered as the same tappable control the working options use, with its accessible name and role intact. What changes is what the tap does, not whether a tap exists: run the option, ask for what it needs, or route to the place where the person can grant it. That decision **MUST** be resolved in one authority shared by every surface that offers the same option set (**SSG-M8**), never re-derived per screen, and the surface **MUST** say in text — not by colour alone — what the tap will do before it is pressed. Replacing the control with static text is the failure this row exists to prevent: it removes the press target, the role and the recovery route at once, and when one condition disables every option (a permanently refused permission disables them together) the surface is left with no tappable element at all — the dead end **MAP-RN-M4** forbids, reached from inside the option list. Removing the option from the list entirely is a different and also-forbidden shape: silent substitution (**MAP-RN-M4**). | Bug — **must not** ship (a11y + dead end). | Pass: in the branch that renders an option as unavailable, the rendered node is the same tappable primitive (`Button` / `Pressable` / `Touchable*` or a wrapper exposing `onPress`) as the available branch, and a single named helper answers "what does the tap do?" for both. Fail: the unavailable branch renders only `Text` / `View`, or the two branches call different decision code. Held by review. |

## **MUST NOT**

| ID | Rule | Consequence | Verify |
|----|------|-------------|--------|
| **MUP-N1** | Export or use a second canonical palette / parallel color object for a module — forbidden ([**STY-N4**](../styling/stylesheet-and-theme-tokens.md)). | Architecture bug — **must not** ship. | Pass: [**STY-N4**](../styling/stylesheet-and-theme-tokens.md) Verify (a single color-object export) for the app package. |
| **MUP-N2** | Ship new primary hub tiles or primary CTAs without an accessible name path (**MUP-M2**, **MUP-M7**) — forbidden. | Bug — **must not** ship. | Pass: same as **MUP-M2** / **MUP-M7** Verify for touched files. |
| **MUP-N3** | Ignore an existing authoritative feature UI spec at the project's documented domain-UI specification location for the feature being changed — forbidden. | Process bug — STOP / reject the change. | Pass: the review links the document path or states "no authoritative UI spec" with reason (new feature). |
| **MUP-N4** | Ship a **MUP-G5** YES screen with successful load and empty data but no dedicated empty UI (blank main region) — forbidden (contradicts **MUP-M6b**). | Bug — **must not** ship. | Pass: same as **MUP-M6b** Verify for touched files. |
| **MUP-N5** | Omit recovery (retry / `refetch`) on blocking first-load error when **MUP-G5** is YES — forbidden ([**UIP-M9**](../tanstack-query/ui-loading-and-persist-options.md); contradicts **MUP-M6c**). | Bug — **must not** ship. | Pass: same as **MUP-M6c** Verify for touched files. |

## Failure path and invalid states (normative)

| Dimension | Coverage |
|-----------|----------|
| Loading | **MUP-G5** YES → **MUP-M6a**; hydration / persist restore **must not** collapse into a single `isLoading` spinner alone (**UIP-M10**). |
| Empty success | **MUP-G5** YES → **MUP-M6b**; **MUP-N4** blocks blank region. |
| Blocking error | **MUP-G5** YES → **MUP-M6c**; **MUP-N5** blocks dead-end errors; background refetch error with cache: [**UIP-M1**](../tanstack-query/ui-loading-and-persist-options.md), [error-handling **M6**](../error-handling/error-handling.md). |
| Environment | Metro / RN; no server runtime for this topic. |
