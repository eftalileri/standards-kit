## **MUST**

**BHE-M15**: A caller that already holds a live authority document **MUST** feed that document to the derivation entry point instead of re-entering the cached read — unless the caller's own read is narrowed by a projection, in which case it **MUST** be left alone. A cached read authority usually exposes two entry points: one that loads the snapshot (cache first, store on miss) and one that derives a result from a snapshot the caller supplies. A caller that has already read the authority live for its own reason — an existence check, one extra field, a list page — discharges **BHE-M1**(a) through the second entry point, and gains twice: one read disappears, and the derivation becomes strictly fresher, because a live document read in this request is never staler than a TTL-bounded copy of it. Both halves matter, and the freshness half is the one that makes this a correctness improvement rather than a micro-optimization.
The boundary is the caller's projection, and it is not symmetric. Where the caller's existing read is narrowed by a `select`/projection — above all a shared repository read with other consumers — widening it to carry the derivation's fields is a trade-down: it puts bytes and coupling onto every other consumer of that read to save one read at this call site, and it converts a deliberately narrow contract into an open-ended one that the next reader will widen again. Such a caller stays on the cached entry point, and the deliverable **MUST** record which callers were left and why — an unexplained exception is indistinguishable from an oversight, and the next round re-opens the same question.
Two further limits hold regardless of projection. (a) A reduction **MUST NOT** merge two reads that observe different moments. Where one read is taken to authorize or validate before a write and the second is taken to answer after it, they are two facts, not one; substituting the earlier snapshot for the later one returns pre-write state as the post-write answer. (b) A reduction **MUST NOT** be applied to a read that feeds an authorization decision by way of a cross-request cached copy; that stays governed by the request-scope rule in **BHE-M5**'s authorization paragraph. Handing a live document to a derivation is always permitted, because live is the authority.
Litmus, in order: *would the reduction make the existing read fetch anything it does not already fetch?* → do not reduce. *Do the two reads observe the same moment?* → if not, do not reduce. Otherwise reduce, and say so in the code at the call site so the next reader does not "restore" the second read.
[Consequence: Efficiency/correctness bug in both directions — an unreduced caller pays a duplicate read and answers from a TTL-bounded copy when the authority is in hand; a reduction taken across a projection or across two moments widens a shared contract or returns pre-write state as the post-write answer] [Verify: For each caller of a cached read authority, list the reads it performs for the same key in one operation, whether its own read carries a projection, and whether the two reads observe the same moment; reduce only the unprojected, same-moment callers and record the rest with the reason — review obligation, no single-file AST shape]

## Mechanical coverage and its stated limit

**BHE-M15** is review-bound. Deciding whether a live read can replace a cached read requires knowing the projection, whether the document satisfies the derivation entry point's type, and whether both reads observe the same moment. A name-shaped cross-file heuristic would flag legitimate before/after-write reads. Review each caller, record which reads may be combined and which must remain separate, and keep the per-caller table in the deliverable; aggregate reduction counts do not explain legitimate exceptions.

**BHE-M2** is also review-bound and applies only to a key read repeatedly within one request. A blanket check on exported reads that lack a memo is declined: an exported read without a memo is not itself a defect, and request/key provenance across middleware, services and repositories is not available to a static check. Complete-derivation memoization does not deduplicate its internal reads: every repeated, session-free, same-projection read enters the existing persistence memo seam, including nested helpers. Calls after writes re-enter that seam so invalidation may select fresh state; do not force an old document through them. At planning and review time, name the repeating key and the seam that memoises it.

A datastore-loop predicate **MUST** prove the receiver's import provenance, not just a method name. Paging/migration batches, page-derived `$in` reads, chain walks, compare-and-set retries, independently leased work units, per-side-effect freshness re-checks, fixed protocol steps whose repeats follow the number of operations or elapsed time rather than data size (a cache-coherence fence read per cache operation, a lease-renewal heartbeat) per-item calls to a provider that offers no batch endpoint for the operation, a wait on an asynchronous provider job whose status is re-read until it completes (repeats follow elapsed time), and isolated writer units — each independently read source replacing its own writer scope atomically and recording its own outcome, where one combined write would make every source's atomicity and failure one — are legitimate loop classes; item-dependent request reads are the N+1 class. A provider that accepts many items per request but answers with one status for the whole request **MUST** receive the set in one request; only when that request is not fully delivered are the items resolved one by one through the single-item path, declared as the no-batch-endpoint class at that loop, because a per-item outcome (retry, fallback twin, rejection) has no batch endpoint. A per-side-effect freshness re-check — re-reading permission, lease or entitlement immediately before each irreversible external side effect (a push, e-mail or SMS provider call) — **MUST** stay per item and **MUST NOT** be batched into one read ahead of the loop: a single early read would authorise later items on state that may have been revoked meanwhile. Such a re-check, and any fence re-read before an irreversible step, **MUST** use a fresh reader, never a request-scoped memo (**BHE-M2**): the steps between two re-checks may issue no datastore write (provider, object storage), so a memo hit replays the earlier answer; a memoized accessor of the same read is a separate, named function for one-moment pre-checks (review-held). Classify each loop by that contract. A single-file predicate both flags legitimate sites and misses genuine ones reached through local aliases or helpers; it is not prescribed because request context and value provenance are unavailable. A suppression on a site is evidence about the predicate, not proof the code is defective.

A runtime repeated-command detector (reads, writes, cache commands, provider calls) exempts a loop of one of these legitimate classes only by a declaration at that loop's own command seam, made through the detector's API, naming the class from this closed list plus a non-empty reason, and scoped to the current unit of work (commands inside the declared work only). A list of routes, collections or shapes kept in configuration **MUST NOT** be used: it outlives the loop it excused and silences the next real N+1 with the same shape. A declaration is an exemption per invocation: it **MUST** wrap exactly one iteration of the loop (one page, one item, one retry, one chain step, one heartbeat), the detector **MUST** count each shape per invocation, and the same shape repeated past its threshold inside one invocation **MUST** be reported as a definite N+1. Reason: a declaration wrapping a whole loop or a whole per-item helper also excuses every repeat nested inside it, and a helper-level declaration excuses every caller's loop, including an unnecessary one. The only exception is the provider-job wait, whose provider re-reads happen inside one awaited call of a client library and grow with time; its datastore and cache commands still count per invocation. A loop whose iterations are not always a set (a derivation serving one item or many) declares the iteration only when it runs over more than one item, so a caller looping over the single form stays visible. Repetition spread across invocations stays visible on the expected-level channel; only its crash-report routing is withheld. A process-wide unit without a scope (server boot, a maintenance script's whole run) applies no declaration, so work that runs a declared loop **MUST** run inside a scoped unit (a request, a tracked background unit, a measured maintenance scope), and a script that calls only providers **MUST** still attach the observers before its first call. Reason: an unscoped declared loop reports its legitimate repeats as a definite N+1, and an unobserved script hides its real ones.

Such a detector's report **MUST** name the repeating code: a report without a call site cannot be traced to a fix. The detector reads the application frames of the stack live at the command's start, and a client library that resumes through callbacks instead of `await` (for example some cloud SDK service objects, or an auth client once its token is cached) leaves only library frames there. A seam calling such a library **MUST** run its calls inside the detector's call-site-origin API, which captures the caller's stack synchronously at the seam and serves as the fallback only when the live stack has no application frame. Whether a library keeps the frames is measured once per library with a request-creation observer that prints the stack, never assumed. Review-held: a static check cannot see runtime stacks.

For [**BHE-M6**](backend-http-efficiency.md), a multi-phase pipeline **MUST** attribute duration per phase in one completion record. Inner engines return stage durations to that record's owner instead of logging a second completion. Phase names come from existing stage/step types, never a parallel list (**SSG-M8**). An every-await timing check is not prescribed: it cannot tell a phase from an incidental await, and most duration logs time a single operation where a breakdown means nothing; the obligation is carried at plan and review time.
