## **MUST**

**M18**: A work registry admits a work order, not an observation — five conditions, all of them together, or the entry does not enter. **M16** governs when an entry *leaves*; this row governs whether it may *arrive*, because a queue whose admission test is "any real thing anyone noticed" grows without bound and buries the entries that name a live defect among the ones that merely could be written down. An entry is admissible only when all five hold. (1) Named authority — it names the specific binding rule identity that is violated, or whose promised guarantee has a declared gap, and that identity is confirmed by reading the row it resolves to, never by recognising its prefix or topic family. An identity can be real, resolvable, and from exactly the right family while governing an entirely different subject; an entry resting on one reads as authorised, survives review because the prefix looks right, and names nothing its observation actually breaches — so a wrong-row citation is condition (1) unmet, not a cosmetic slip, and it is re-resolved through the identity lookup at every freshening. "This would be better" or "no rule covers this yet" is a proposal about the *rule set*, not an entry here, and it goes to the rule set's own change procedure. (2) Concrete harm — it names what breaks, in one of: runtime behaviour; security or tenant isolation; a money or entitlement path; data integrity; or a guarantee a rule promises that nothing actually enforces. "A reader could be confused", "a sentence is stale", "a file is near its size limit" is not harm. (3) Evidence carrying a magnitude — a locator (`file:line`) and a count of how many sites, files or call sites. Without the count the extent is unknown, so no work can be defined and no completion can ever be proved. (4) Not already covered — not a duplicate of a live entry, and not already mechanically fenced, where the fence is looked for by predicate and never by name similarity ([**FP-MS9**](../false-positive/mechanism-selection.md)). (5) Effort weighed against payoff — the cost of the fix (files touched, cascade risk, external evidence needed, dependence on an owner decision) must be worth the guarantee it buys; where it is not, the entry does not enter, and one already present is dropped as a closed decision rather than deferred a second time. An entry that satisfies all five still answers one question or it is not a work order: *who closes this, in which file, with which predicate?* Where that cannot be answered, either the measurement is incomplete or the item does not belong here.

Condition (4) decays after admission, so a registry needs a periodic consolidation pass — and consolidation is not deletion. Entries opened rounds apart can each be admissible and together count one fact twice, so a keep-side pass also asks *does another live entry close with the same work?* Duplicates fold into one carrier only when (a) each absorbed body moves verbatim into a named, individually closeable leg (**M16** binds a leg as it binds an entry); (b) the carrier's authority cell carries the union of its legs' rule identities; and (c) absorbed identifiers retire under **M16** with every living cross-reference rewritten in the same change. Never fold an entry cited from production source, a hard-floor entry into a softer carrier, or an entry with a recorded owner decision into an undecided one.

Condition (5) has a floor it may never overwrite. Four classes stay in the registry regardless of cost: security and tenant isolation; a money or entitlement path; data integrity (loss, corruption, irreversible write); and a fail-loud guarantee that is not actually enforced. Dropping a live hole *because closing it is expensive* is knowingly shipping a known defect, and giving up a guarantee already promised is a regression — both are forbidden elsewhere, and cost licenses neither. Everything outside those four — performance debt, observability gaps, dead code, rule-set prose, documentation hygiene — is subject to condition (5).


A rejected item is routed, never silently dropped. Rule-text, size or placement debt goes to the rule set's own stated-limit surface; a stale documentation line is fixed on sight; a routing or vocabulary gap goes to the lookup that owns it; a product question goes to the owner-decision surface. A dropped batch leaves one declaration per class at the registry's head, and its identifiers go to the retired-identity ledger under **M16**.
