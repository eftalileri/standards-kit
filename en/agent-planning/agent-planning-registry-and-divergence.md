## **MUST**

**M16**: An actionable work registry is a queue, not a completion ledger. Once current source plus relevant change history proves that an entry's own predicate has no work left—including an accepted no-action decision or a disproved premise—the entry body **MUST** be hard-deleted in the same review; do not copy it into another archive and move the bloat. Remove or rewrite every living cross-reference in the same change so no deleted identifier remains an authority. Identifier reuse remains forbidden: preserve a monotonic next-free/high-water authority plus a compact retired-ID ledger even when old bodies are deleted. A pre-existing legacy archive may remain frozen only while unresolved old references still require its bodies; once those references are removed, migrate its identifiers to the compact ledger and delete the archive rather than preserving a second completion store. The archive **MUST** never accept new completed bodies. [Consequence: An active queue otherwise grows without bound, stale status text masquerades as open work, or a reused identifier silently rebinds an old reference.] [Verify: Recount live headings after cleanup; search the governed repository for references to every deleted identifier and removed archive path; prove next-free is above every live/retired identifier, every lower base identifier is exactly live or retired, suffix exceptions are explicit, and no retired identifier appears as a live heading.]

A cleanup pass measures the entries it KEEPS, not only the ones it removes. **M16**'s deletion test reads current source; a bulk pass naturally applies that test only where it is about to delete, so every entry it decides to *keep* passes through untouched — and its body, including any status sentence the pass rewrites, is carried forward on the authority of its own prose rather than of the tree. That is how a registry acquires a claim the repository had already falsified — a kept entry's status rewritten to "still pending" after the work it describes has landed is false when typed, and survives because later readers read a recently-touched line as a recently-measured one. So a keep decision is a measurement too: when a pass rewrites or re-dates an entry's status, that status **MUST** be re-derived from current source and change history in that pass, and an entry it leaves untouched keeps its original date rather than inheriting the pass's. A freshness marker that records when the file was edited instead of when the claim was verified converts unmeasured prose into apparently current evidence, and every consumer of the registry then inherits it. The same asymmetry governs the recency heuristic generally: a status line's age is evidence about the *writer's* activity, never about the claim's truth, so "this was written recently" is not a substitute for reading the code the line describes.

An entry can be the SOLE HOME of a fact that is not work — and **M16** deletes the RECORD, never the FACT. **M16**'s test asks whether work remains. An entry can pass that test cleanly and still be the only place some non-work fact is written down: an authorisation someone granted and the bounds it was granted within, a standing permission, a deliberate exception whose rationale is the only thing separating a decision from a defect, a lesson recorded to block a precedent. Such an entry is then commonly kept alive *for* that fact — which is itself a violation of this row, because a queue entry carrying no work is not a storage format — and the keep gets justified by the true observation that the fact has nowhere else to live. One ordering answers both halves: migrate the fact to a surface whose own purpose is to hold it, in the same change and BEFORE the body is deleted; then delete. The destination follows from what the fact is, not from where it happened to be found — an authorisation goes to the authorisation surface, a deliberate exception beside the rule it excepts, a procedural lesson into the agent's own working contract — and it is a single writer for that class: one declaration that every dependent entry points at, never a copy restated per entry, or the first divergence is between the copies. Where a candidate destination already carries the fact, the migration is a measurement: confirm it by reading that surface, then delete without adding a second copy. The asymmetry is what makes the ordering binding rather than advisory — deleting first loses the fact with no diagnostic and no way to notice the loss later, while keeping the entry costs one visibly stale row; so a pass that cannot name a destination does not delete, and records the missing destination as the work. [Consequence: otherwise a registry either accumulates work-free entries held open as an accidental archive, or a deletion pass silently destroys the only record of a grant, an exception, or a bound — and the next reader, finding no trace, treats the absent bound as absent.] [Verify: for each entry deleted in a pass, ask what its body asserted that was not a work order; for each such assertion, name the surface that carries it today and read that surface to confirm it does.]

A registry also answers WHO can close each entry, on the status line. **M16**'s vocabulary answers *is there work left*, not *can anyone act today*, so a queue reads as uniformly actionable while much of it waits on what no agent can produce. Three dispositions cover it: closable from the repository; blocked on an owner decision (a product, store, legal or authorisation sentence, or approval for a destructive or release-time step); blocked on an event or external evidence not yet happened or unreadable from the tree (post-release telemetry, an external console, another repository's head). Record it inside the existing status line — several when legs differ, each leg carrying its own — never as a second index, since a parallel blocked-on table is a second writer of one fact and the first to go stale. It is a measurement, not an intention: derived from the entry's own *closing work* sentence, absent which the entry never passed **M18**'s closing test.

**M17**: When a plan and the governing rules disagree, implement to the rules and record the divergence at the time — the rule, `file:line` evidence and why the rule-correct solution differs — bounded by a cascade-stop that records, rather than chain-fixes, further defects the fix exposes. Where those records live is the project's ([**KIT-LIM-7**](../authoring/kit-stated-limits.md)).
