# User-text catalogs — authority, recipient language and cross-language parity

```kit-cover
type: normative
part-of: README.md
binds: I18N-CAT-M1 to I18N-CAT-M5 and I18N-CAT-M10 -- which authority owns a user-visible string wherever it is emitted from, how the recipient's language is resolved on a server surface, which catalog-mechanism rows are stack-independent, the completeness every declared language owes across every catalog, the change set a reported product-term collision owes, and the per-language casing, capitals and emoji a catalog value owes
open-when: shape:backend-heavy, shape:frontend-heavy, shape:full-stack, signal:user-facing-string, signal:translation-catalog, signal:locale-sourced-label, signal:new-language, signal:notification
skip-when: signal:no-user-facing-string
owns: I18N-CAT-M1, I18N-CAT-M2, I18N-CAT-M3, I18N-CAT-M4, I18N-CAT-M5, I18N-CAT-M10, I18N-CAT-M11, I18N-CAT-M12
```

**Keywords:** message catalog, backend catalog, server-emitted text, notification body, e-mail subject, recipient language, key parity, placeholder parity, supported languages

Scope

- Included: What a catalog of user-visible text owes wherever that text is emitted from — the single catalog authority behind a server-emitted notification, e-mail or message body; the chain that resolves the *recipient's* language rather than the caller's; which of this topic's mechanism rows are catalog rules rather than client rules; and the completeness a product owes in every language it declares it supports, measured by a gate.
- Excluded: The React Native / Expo stack, the client language authority and the client-side obligations themselves ([internationalization-rn.md](internationalization-rn.md)); the prohibitions that describe a silent language downgrade ([internationalization-prohibitions.md](internationalization-prohibitions.md)); ISO country and currency labels ([locale names](../locale-names/README.md)); the registered-error message contract, whose completeness half is **M29** and is cited here rather than restated; which word replaces a reported one — where the concept has a visible surface that is [**I18N-CAT-M9**](product-term-visible-surface.md), and where it has none the term-authority limit stands in [internationalization-rn.md](internationalization-rn.md); **I18N-CAT-M5** governs only the shape of the change set.
- Document type: Normative part — **I18N-CAT-M1**–**I18N-CAT-M5**, **I18N-CAT-M10**–**I18N-CAT-M12**.

Binding principle: A catalog is the authority for *what the reader sees*, and the stack that emits the text is an implementation detail of one consumer. Splitting the obligation by stack is how a server-emitted string ends up with no rule at all: this topic's other part files legitimately close themselves for backend work, so for as long as the catalog obligations lived only there, a notification body, an e-mail subject and an SMS were governed by nothing. This part therefore carries no backend-only negative — a task that declares it is doing backend work **must** still reach it.

References: [README.md](README.md); [internationalization-rn.md](internationalization-rn.md) (**I18N-RN-D1**–**I18N-RN-D5** definitions, **I18N-RN-M5**, **I18N-RN-M6**, **I18N-RN-M9**); [internationalization-prohibitions.md](internationalization-prohibitions.md) (**I18N-RN-N3**, **I18N-RN-N6**, **I18N-RN-N7**); [transport-i18n-and-classification-rules.md](../error-policy/transport-i18n-and-classification-rules.md) (**M29** — the same completeness obligation for registered error keys); [ssot-principles-and-precedence.md](../ssot/ssot-principles-and-precedence.md) (**SSG-M8**); [mechanism-selection.md](../false-positive/mechanism-selection.md) (**FP-MS4** — why parity is an aggregate check); [check-design-rules.md](../false-positive/check-design-rules.md) (**FP-M18**, **FP-M19**).

## **MUST**

| ID | Rule |
|----|------|
| **I18N-CAT-M1** | Every user-visible string a server emits — a notification title or body, an e-mail subject or body, an SMS, a push payload, a document label — **MUST** resolve from one named catalog authority by key, and **MUST NOT** be composed from a literal at the emitting call site. The obligation does not depend on the string being an error: a registered error's `messageKey` is one consumer of a server catalog, not the boundary of this rule, and a notification body has exactly the same claim on it. Where a surface emits text through more than one catalog authority, one sentence has two homes: a correction lands in one and the other keeps shipping ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)). Text assembled from several parts is one catalog entry, assembled in one place, so no segment is left in the author's language — [**I18N-RN-M5**](internationalization-rn.md) states that obligation for client-composed text and it binds identically here. |
| **I18N-CAT-M2** | A server composes in the *recipient's* language, resolved through one named chain, before the first byte of the message is produced. The recipient's own persisted language authority is the first link. A request header, the acting user's language, the tenant default and the process locale are not substitutes for it and **MUST NOT** silently stand in — the actor who triggers a message is frequently not the person who reads it, so borrowing the actor's language is a defect that reads as correct to whoever tested it. The chain's later links are a recovery mechanism for a race or a partial deploy, never a licence to ship a permanently missing translation; **M29** holds exactly this for registered error keys and is not restated here. Where the recipient's language cannot be resolved at all, the outcome is explicit and typed: substituting a fixed language code at that point is the same silent downgrade the client prohibitions describe ([**I18N-RN-N7**](internationalization-prohibitions.md)), one layer removed from the reader. A tenant's language and a recipient's personal language preference are separate authorities. Updating the tenant language **must not** overwrite or backfill linked recipients' persisted preferences. Where the named resolution chain permits the tenant language for an absent preference, derive it when reading or composing; do not persist that derived value as a personal choice. Enforcement limit: the subject/tenant relation and complete writer inventory are cross-file runtime facts, so review verifies this separation; no new static check is admitted merely for a retired bulk-writer authority (**ENA-A2**). Use the enforcement mechanism the adopting project documents, and record its actual scope and limits. |
| **I18N-CAT-M3** | The topic's catalog-mechanism obligations bind every catalog, not only the client's. Exactly one placeholder substitution engine and one syntax per catalog, with any mechanical check scoped to the catalog it belongs to ([**I18N-RN-M6**](internationalization-rn.md)); no fixed-language fallback in any shape, including the named-constant and default-value indirections ([**I18N-RN-N3**](internationalization-prohibitions.md)); no second substitution engine run over a lookup's output ([**I18N-RN-N6**](internationalization-prohibitions.md)). What this row adds is the scope: those rows are written in files whose declared stack is React Native, and a reader doing server work would otherwise conclude they do not apply. Two catalogs remain two authorities. A client catalog and a server catalog **MUST NOT** import, mirror or copy each other's entries — a copied entry drifts, and a shared entry acquires two writers. When they use different placeholder syntaxes, each check runs against its own catalog and never across both. |
| **I18N-CAT-M4** | Every key a catalog defines **MUST** resolve in every language the product declares it supports, with the same placeholder set in each, and that promise **MUST** be measured by a gate. (a) Completeness is a gate, not a convention. The check fails closed when a key is missing or empty in any declared language. A missing entry raises nothing at runtime — the language chain renders some other language and the reader cannot tell — so a silent miss is precisely the class review can never catch. (b) Placeholder parity is measured with the keys — and parity alone is not enough. A placeholder present in one language and absent in another renders as empty text; an extra one renders unsubstituted; both are silent, and both are as damaging as a missing key. A parity measure is structurally blind to a defect its own reference carries. Parity compares each language against a reference catalog, so when the *reference* writes a placeholder in a syntax the engine does not substitute, both sides read as no-placeholder, no difference is reported, and the raw delimiters ship in every language at once — the widest form of the defect is the one form parity cannot see. Parity **MUST** therefore be paired with a syntax measure that reads each catalog against its own engine's delimiters ([**I18N-RN-M6**](internationalization-rn.md)), covering the reference locale too, and that measure **MUST NOT** be derived from the comparison.  (c) Every input of the gate is DERIVED from its authority. The key set comes from the catalog or registry that owns the keys, the language set from the supported-language authority, each catalog's location from the language code. A key list, language list or file list typed into the gate goes stale the moment a key or a language is added — the same parallel-authority defect one layer up ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)). A declared language whose catalog is missing or unreadable **MUST** fail loud; the gate **MUST NOT** shrink its own scope to stay green ([**FP-M19**](../false-positive/check-design-rules.md)), and a gate opened over pre-existing debt uses the staged ratchet with its shrinking-only exemption list in the check's own source ([**FP-M18**](../false-positive/check-design-rules.md)). Because the comparison spans two or more catalog files at once, no single file's syntax tree can decide it: it is an aggregate check ([**FP-MS4**](../false-positive/mechanism-selection.md)), and it is legitimately several gates — one per catalog — where catalogs differ in engine, location or owning registry. (d) Where the catalogs are typed source modules, the type they are all assigned to IS one such gate — but only for the keys the type declares. A key present in every catalog yet absent from that type is enforced by nothing: the compiler accepts a catalog that drops it, the language chain renders a neighbouring language, and every reviewer sees the key in every file and concludes it is covered. Adding a key to the catalogs and to the type are therefore one change, and a project whose catalogs are typed **MUST** say so where the gate is described, so that a separate cross-file gate is not written for the half the compiler already decides — and so the uncovered half is visible rather than assumed. (e) A gate over the catalogs cannot cover user-visible text the catalogs do not hold. Some strings are drawn by the *platform* — permission-purpose dialogs, the installed app name, notification-channel labels — from the app's bundle or manifest, never through a runtime catalog. Declaring a language to the platform while such a string exists in one language only makes the platform fall back silently to the development language: the product claims the language, the reader is shown another, and every catalog gate stays green because the string is in no catalog. Base text and per-language platform resources are one authority changed in one change set ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)); the pairing **MUST** have its own gate keyed on the declared-language authority, with its limit stated: a purpose string a dependency injects by default is in no manifest the project owns. |
| **I18N-CAT-M5** | A product term is chosen *in* the target language; it is not carried across from the source term by dictionary. A noun that is exact in the source language can land, in another, on an unrelated everyday object and make a whole surface unreadable to the people it was written for — while every gate above stays green, because the entry exists, the placeholder sets match and only the *word* is wrong. Two obligations follow, and both are about the change set, not about the vocabulary. (a) One change set, every declared language. When such a collision is reported, the replacement term is decided for that context and applied across every declared language at once. Patching the single locale somebody complained about leaves the identical collision standing in the locales whose readers never report anything, and splits one product concept across two vocabularies — which is the drift **SSG-M8** describes, arriving through the catalog. (b) It is a value change, not a key rename. The keys stay exactly as they are, so the rename-migration obligation ([**I18N-RN-M3**](internationalization-rn.md)) is not triggered — and **MUST NOT** be invoked as a reason to postpone the fix, since no key is moving. |
| **I18N-CAT-M10** | Every catalog value **MUST** be cased by its own language's convention, never by the source language's. Sentence case — only the first word and proper nouns capitalized — for languages whose interface convention it is (for example Spanish, French, Italian, Portuguese, Dutch, Russian); noun capitalization for German; the product's established style for its source-language catalogs (for example Title Case on buttons, titles and labels); nothing for scripts without case. Brand and product names keep their own spelling in every language, and a label quoted inside a sentence is spelled exactly as that label is. No value is written in capitals except acronyms, codes and format masks — casing lives in the catalog, never in `textTransform` ([**STY-M9**](../styling/stylesheet-and-theme-tokens.md)(e)). No label carries decorative emoji: a screen reader reads the emoji's name aloud, and the icon belongs to the component; an outbound message body (**I18N-RN-D3**) may keep its formatting emoji. A change that fixes casing is applied across every declared language in one change set (**I18N-CAT-M5**(a)). A weekday or month name interpolated into a sentence **MUST** take the form for its position — the language's in-sentence form after another word, the capitalized form at sentence start or standing alone — from the one weekday authority, never one catalog value reused in both positions; the caller picks the form by reading where the placeholder sits in that key in every declared language. Reason: the source catalog's convention is copied into every new key by whoever translates it, so a Title-Case Spanish button reads as an untranslated string and the defect grows with each feature. *(No check is claimed: casing is a typographic convention and proper nouns are undecidable without a per-language lexicon — **ENA-A1**(b); review-held.)* |
| **I18N-CAT-M11** | One user-visible text with one meaning **MUST** have exactly one catalog key. Before adding a key, search every catalog for an existing key with the same text or meaning and reuse it; when the existing key lives in a feature namespace and a second area now needs it, move it once to the shared (`common`) namespace in every declared language, repoint every consumer and delete the old key in the same change. A new key is created only when no equivalent exists. Reason: a duplicated label is a second writer of the same text, so translations drift apart between screens (SSG-M8). |
| **I18N-CAT-M12** | A catalog value **MUST NOT** attach an inflection (case suffix, apostrophe ending, elision, contraction) directly to an interpolated value — a time, number, date or name; the value stands where no ending depends on it ("label · {{value}}", "label: {{value}}", or a construction whose ending is fixed). Reason: the correct ending depends on how the value is read aloud (Turkish vowel harmony and voicing: `10:00'da`, `11:00'de`, `13:00'te`), which a static template cannot select, so some renders are wrong text in that language. *(No check is claimed: whether the characters after a placeholder are an inflection is per-language grammar, not syntax — **ENA-A1**(b); review-held.)* |

## Stated enforcement limits


| Limit | What a check would need |
|-------|-------------------------|
| Whether a catalog value's letters were TRANSLITERATED rather than legitimately unaccented ([KV2](../authoring/markdown-authoring-deliverable-shape.md) (a) — the obligation itself lives there and is not restated here). | A per-language dictionary. Diacritic stripping is decidable *only* against the language's own vocabulary, and no source tree carries one. What a tree can supply is corpus evidence: the catalog's own values, read across every namespace file of one language, prove which spelling that language normally uses, so a dominant accented form beside a rare unaccented twin is measurable without a dictionary. That is a cross-file aggregate predicate over `.json` data — outside any single-file AST, so it is the rare case where a guard, not a lint rule, is the correct mechanism ([**FP-MS1**](../false-positive/mechanism-selection.md)). Two residual blindnesses stay, and both are properties of the evidence rather than of the check. (a) Legitimate homographs are indistinguishable from corruption — a language that writes both `termine` and `terminé`, or both `esta` and `está`, offers the corpus no way to tell a present-tense verb from a stripped participle; a check that names individual values would therefore accuse correct text. The answer is not an allow-list of exceptions, which would grow into the very rule-editing the false-positive policy forbids: the check asserts only that the class did not grow, freezing the ambiguous population in a staged-ratchet baseline ([**FP-M18**](../false-positive/check-design-rules.md)) where a pre-existing false positive can never fire and a newly introduced stripping always does. (b) Letters that are not diacritics are invisible to it — folding is defined over Unicode combining marks, so a language whose distinct letters differ by more than a mark (Turkish `ı`/`i`, `İ`/`I`) has that half of its alphabet unmeasured; closing it needs a per-language letter-mapping authority, which is the dictionary again. (c) Scope is the catalog formats the check reads. A catalog kept in another file format (for example a typed source module) is not scanned; extending the check to it needs a new extraction surface, and a homograph-only stripped block stays invisible to the scan (blindness (a)), so a fence's positive proof would still miss a class member. Such a catalog's letters are held by review using that scan (see [KV2](../authoring/markdown-authoring-deliverable-shape.md)). |
