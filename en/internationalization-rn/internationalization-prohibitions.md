# Internationalization (React Native / Expo) -- prohibitions

```kit-cover
type: normative
part-of: README.md
binds: the internationalization prohibitions - fixed-language fallback in every shape, hardcoded user-visible strings, ISO label duplication, a second placeholder engine, a fixed language-code default, a catalog placeholder duplicating a fragment the formatting authority already composes, materialising every declared language's catalog on the startup path, and a validation branch left to speak the schema library's own default sentence
open-when: shape:frontend-heavy, signal:user-facing-string, signal:translation-catalog, signal:language-switch
skip-when: signal:backend-only, signal:no-user-facing-string
owns: I18N-RN-N*
```

Scope: The **MUST NOT** rows of the internationalization topic. Every one of them describes a shape that silently downgrades a user's language or splits the catalog into two authorities, and every one is invisible in review because the author reads the wrong-language output natively.

Document type: Normative part -- **I18N-RN-N1-I18N-RN-N10**.

References: [README.md](README.md); [internationalization-rn.md](internationalization-rn.md) (definitions **I18N-RN-D1-I18N-RN-D5**, agent contract, **MUST** and SHOULD rows); [ssot-principles-and-precedence.md](../ssot/ssot-principles-and-precedence.md) (**SSG-M8** - one authority, no parallel path).

## **MUST NOT**

| ID | Rule |
|----|------|
| **I18N-RN-N1** | **Must not** hardcode user-visible app strings in components for default product languages when **I18N-RN-D1** is in use on the screen (except dev-only diagnostics behind flags). |
| **I18N-RN-N2** | **Must not** use **I18N-RN-D1** for ISO country/currency label display from codes -- use [locale names](../locale-names/country-currency-ui-display.md) (LCN-\*). |
| **I18N-RN-N3** | **Must not** implement a fixed-language fallback (**I18N-RN-D4**) anywhere an app string or outbound string is produced. If the translator is unavailable, generation **must** fail loudly; emitting another language is a defect, not a degraded mode -- and it is invisible to the author, who reads that language natively. Indirection does not exempt it: the fallback is still **I18N-RN-D4** when the literal is moved behind a named constant (`const TITLE_FALLBACK = '<author-language text>'; t(key) \|\| TITLE_FALLBACK`) or passed through the translation library's default-value option on the lookup call itself (`t(key, { defaultValue: '<author-language text>' })`) -- the shape changes, the silent language drop does not. The option form is worse, not milder: the library resolves it after the fallback-language chain, so it fires exactly when the key is missing in *every* language -- the one case the locale chain was there to cover -- and it suppresses the "translation not found" signal the same lookup would otherwise raise. The correct repair is to define the key in every supported language and delete the option; a value derived from another translation (`defaultValue: t(otherKey)`) or one carrying no language (`''`) is not **I18N-RN-D4** and is out of scope. Any mechanical check for this rule **must** cover the option form and resolve a constant binding, not only inline literals -- while excluding same-named UI-framework props (uncontrolled form-field defaults) and form-library default-value fields, which are unrelated to translation; scope the object-form half of the check to the argument object of a translator call. The POSITIONAL overload is the same defect and the check **must** cover it too. Where the translation library also accepts the default as a bare second argument (`t(key, '<author-language text>')`), that form produces byte-identical behaviour to the option form while matching no property name at all -- so a check scoped only to the argument object reads green over it, and the shape is the one an author reaches for first because it is shorter. Distinguish by the argument's own type, not by a name: a string in that position is a default value and is **I18N-RN-D4**; an object is the interpolation/option bag and is judged by the option-form clause above. The same two exemptions carry over unchanged -- a value derived from another translation or one carrying no language is out of scope in either form. |
| **I18N-RN-N4** | **Must not** declare the translator optional and guard it (`t?: ...` with `t ? t(key) : 'literal'` / `t?.(key) ?? 'literal'`). That is **I18N-RN-D4** relocated to the call site; the required-parameter form of **I18N-RN-M4** is the only accepted shape. |
| **I18N-RN-N5** | **Must not** justify a fixed-language fallback as backward compatibility. Removing the optional translator and updating every caller in the same change is the correct migration; a retained literal outlives its callers and ships silently. |
| **I18N-RN-N6** | **Must not** run a second placeholder substitution engine (**I18N-RN-D5**) over the output of a translation lookup — for example a `.replace(<placeholder pattern>, value)` chain applied to the returned string. That is a parallel path: the catalog then carries two placeholder syntaxes at once, the first engine passes the shape it does not recognize through untouched, and any guard running between the two engines judges text that is not finished yet. The failure is deterministic and total for every entry that mixes syntaxes — the message never renders, in every language — and it is invisible in review because each half looks correct on its own. Fix by moving all values into the single call (**I18N-RN-M6**), not by loosening the guard: loosening keeps the parallel path and makes the guard's invariant a lie. **Must not** repair a mixed-syntax entry by teaching the guard to ignore the foreign syntax. |
| **I18N-RN-N7** | **Must not** fall back to a fixed language code (`resolvedLanguage ?? '<code>'`, `f(language = '<code>')`, `isSupported(x) ? x : '<code>'`) at any point after the client has an active language authority. This is **I18N-RN-D4** one step earlier: it fires before the translator call, while deciding *which* language to produce, so the right operand is a language code rather than text — the outcome is identical (a user of language X receives language Y, silently, and the author reads Y natively so review misses it). Inside a running client the language is already resolved: read it from the single registered client authority (the persisted user-language preference store) and, when it is not yet resolved, fail loudly; do not substitute a code and do not open a second resolver (that would be a parallel authority). One bounded exception: the startup mapping of the device locale onto a supported language, before any user preference exists (first launch / registration form defaults), is a legitimate product default, not a downgrade — mark those sites with a justified, documented exception rather than narrowing the check. Two corollaries of **I18N-RN-M4**/**N4** apply to the language parameter exactly as they do to the translator: it is required, never defaulted (a default downgrades silently whenever a caller forgets it), and typing it `Language \| undefined` with a downstream guard only relocates the defect — tighten the signature and update every caller in the same change. Passing a literal code at a call site to satisfy the compiler is forbidden: it moves the defect one layer up instead of fixing it. A mechanical check for this class **must** cover the logical (`??`/`\|\|`), ternary, and default-parameter shapes alike, and **must** see through type assertions — the ternary form is semantically identical and otherwise produces a false "clean" reading. |
| **I18N-RN-N8** | **Must not** leave a catalog entry carrying a placeholder for a fragment that a formatting authority already composes into another placeholder's value — and **must not** answer the resulting "placeholder not supplied" finding by adding a second copy of that fragment at the call site. This is **I18N-RN-N6**'s parallel path in the *supply* direction: two authorities compose the same fragment, so the sentence either prints it twice or, under the engine's usual skip-unresolved default, draws the raw `{{name}}` on screen in every declared language at once. Which half gives way is not a free choice: the authority that owns the fragment's UNKNOWN-case form wins. Where the formatter already decides what to render when the fragment cannot be resolved — dropping a parenthetical, omitting a separator — moving the composition into the catalog would require a second approved sentence for that case in every declared language, and inventing one is a new product string, not a fix. The catalog therefore gives up its placeholder and the formatter keeps the composition ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)). The converse case is [**I18N-RN-M10**](internationalization-rn.md): where the value is a limit the code enforces, no formatter owns it, so the catalog keeps the placeholder and the call site supplies the constant. A check reporting the missing supply **must not** name only one of the two remedies — a message that assumes the **M10** case pushes its reader into writing the string this row forbids.  |
| **I18N-RN-N9** | **Must not** materialise every declared language's catalog on the startup path, and **must not** load catalog modules from anywhere except the single materialisation authority. A client renders one language at a time, so evaluating the other **N-1** catalogs before the first frame buys nothing and spends the budget that is hardest to win back — and the cost grows with every language and namespace added, silently, because no gate measures it. The only accepted shape: startup materialises the active language and the fallback language — the fallback is not optional, an unresolved key is read through it and a missing fallback catalog puts the raw key on screen — and every other language is materialised by the one language-change authority. The ordering is the half most often got wrong and it fails silently: a language switch issued before that language's catalog is in the store resolves successfully and leaves the screen in the fallback language — **I18N-RN-D4** with no error anywhere. The load therefore happens before the engine is told to switch, and is awaited when it is asynchronous. A per-screen, per-namespace or per-component loader is a second authority ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)): it answers "is this language loaded?" a second time and bypasses the ordering above. Two constraints bound the change so it cannot trade a guarantee away: the loader keeps build-time path resolution — a missing catalog file stays a build error, it **must not** become a runtime surprise — and the catalogs stay files on disk under their declared-language tree, because key/placeholder parity gates discover languages from that tree; a loader that becomes the discovery source would hide a language from the parity gate while looking greener. The saving is measured, not asserted: instrument the real build on the real runtime and report before/after, because the cost is engine-specific (a bytecode engine that serialises object literals is far cheaper than a source-parsing one) and can be smaller than the noise of the surrounding startup — an unmeasured "optimisation" here is a refactor with a performance story attached.  Enforcement is split and the split is stated: the re-eagerising half is single-file decidable and is locked by a single-file check that rejects any catalog-module import outside the authority; the read a non-active language half (a translator pinned to a language the store is not on) is not decidable from one file — the language is a runtime value — and a check may not exist for it in the adopting project, so it is carried by the structural fact that the only path to a non-active language is the loader itself. (a) The loaded set is the REGISTERED list, never the directory listing — and a catalog file on disk is not a loaded namespace. Once the loader enumerates namespaces from a declared list, that list becomes a third set beside the catalog files and the per-language loader entries, and the three **must** be identical in all directions. Each divergence is a distinct user-visible defect: registered with no file, or registered but missing from one language's loader, makes that language fail loud at startup; a file that is not registered is never loaded at all, so every call into it prints the raw key — and that direction is the one no existing gate sees, because cross-language parity gates compare catalog files with each other (a namespace absent from the registry is complete in all languages and passes green) and a "does the key exist?" gate asks the files, which answer yes. Neither ever asks whether the namespace is registered. The check that closes it needs the registry, the file tree and the call sites at once, so it belongs to the cross-file gate that already resolves translator namespaces rather than to a single-file check, and it **must** assert the bijection rather than one inclusion — a one-directional check leaves the raw-key direction open.  |
| **I18N-RN-N10** | **Must not** leave a validation schema's message bound to one violation branch while the branch that fires on an absent or wrong-typed value stays unnamed. A schema library attaches a custom message to the rule it is written on; every branch the author did not name keeps the library's own default sentence, in the library's language, about its type system (`expected string, received undefined`). That is **I18N-RN-D4** produced by a dependency, and the catalog cannot rescue it: a translator finds no key for that sentence and returns it unchanged in every declared language. The unnamed branch is usually the one that fires. A required field the user never touched is *absent*, not *empty*, so a selection control (a dropdown) can never reach the "empty value" rule the author wrote — the untranslated branch is the only one its users ever see; both branches type-check, so it surfaces only on a real untouched submit. Repair by naming every reachable branch with the same catalog key (the library's type-level message option beside the rule-level one), never by translating the library's sentence at the display site — that would make a dependency's wording a second copy of product text ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)). Out of scope: a schema that explicitly accepts absence (`optional` / `nullable` / default), where "no value arrived" is a valid state; and refinements that run only after the type check has passed. A check is single-file decidable: it fires only where a custom message exists and **must** walk the chain upward as well as downward, since the absence-accepting modifier sits above the rule carrying the message. A message can also travel inside a project procedure passed to the library's generic check hook (a shared string-length procedure, [**MRP-M2**](../monorepo/monorepo-failure-paths.md)); the check recognizes those procedures from a table of names and message positions, beside the native rules. Stated limit: schemas whose failures reach only a log or a crash reporter are outside it; a procedure recognized by name is not seen under an import alias or through a variable. |
