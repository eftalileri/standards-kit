## **MUST**

| ID | Rule |
|----|------|
| **FORMS-IX-M1** | Primary submit control **MUST** be disabled or show loading state while mutation is pending (prevents double submit ). |
| **FORMS-IX-M2** | Search / filter inputs that trigger server queries **MUST** use debounce or explicit “ Search ” action — document which in component spec (avoid storm ). |
| **FORMS-IX-M3** | Optimistic UI (if used ) **MUST** rollback on mutation failure per [TanStack Query](../tanstack-query/README.md) and show error per [error-handling](../error-handling/error-handling.md). |
| **FORMS-IX-M4** | A flag that disables an input **MUST** name the one operation that makes the input unusable. A screen whose state carries a single "busy" boolean for several operations **MUST NOT** use it to lock a field that only one of those operations affects — a background request the user is not waiting on then locks a field they are meant to be typing in, silently and only on slow networks. Correspondingly, an effect that focuses an input **MUST** depend on the condition that makes the input focusable; a focus attempt made while the field is disabled is dropped without error and never retried. |
| **FORMS-IX-M5** | A data-collection step **MUST NOT** state an outcome that the contract it submits cannot produce. If the step's copy promises a result (visibility, publication, delivery, activation) that the submitted payload carries no field for, the fix is to move the question to the surface that owns that result, not to reword the sentence — a reworded step still collects answers whose promised effect nothing can deliver. |
| **FORMS-IX-M6** | A "did you mean" verdict about a user-typed value — a near-miss measured against a set of known-good values, such as a mistyped mail domain, city or provider name — has exactly one authority and it is server-owned; the client renders the verdict and never derives its own. Three halves, all binding. (a) One authority. The known-value set and the distance rule live in one module the server owns, which the client either calls or imports as a shared contract; a client-local copy of either is a second authority that drifts, and it drifts in both directions — a looser copy shows a value as fine that the server rejects, a stricter one rejects a value that is genuinely correct. It is also worthless as a control: a rule that exists only in the client means nothing to whoever edits the client. (b) A warning, never a block. A known-value set can never be complete, so a value outside it **MUST** still submit unchanged; a suspected typo surfaces as an overridable warning with a one-tap correction, the submit control stays enabled, and the copy says in words that a correct value may be kept as typed. Blocking here destroys the exact case the set cannot enumerate — a private or newly created value. (c) Exactly one candidate, or none. A suggestion is offered only when the input resolves to exactly one member of the known set within the allowed distance. Zero candidates and two-or-more candidates both yield no suggestion: picking between two near-misses is inventing the user's intent, and on a value used for account recovery a confident wrong correction is worse than no correction. The same single-candidate rule binds any bulk repair of already-stored values — an ambiguous row is left untouched and reported, never guessed. |
| **FORMS-IX-M7** | Where one shared form component serves multiple surfaces and a surface may omit a field, declare the omitted-field set once outside all consumers and require every surface to pass its choice explicitly. A surface that asks every field passes an empty set. Hiding a field must not change the submitted form state or payload. An optional parameter with a default makes omission indistinguishable from an intentional choice; a required parameter lets the type checker catch a missing decision at every call site. A field omitted from one surface must remain editable on the surface that owns it. Review still needs product context to decide whether a surface should omit the field and whether the value reaches the payload. |
| **FORMS-IX-M8** | A free-text field that parses its text into a typed value **MUST** report the validity of the raw text — not only the last accepted value — to the owner of the submit control, and that control **MUST** be disabled while the text is invalid. A field that ignores an invalid edit (empty, non-numeric, out of range) leaves the previous value in state, so the screen shows text the payload does not carry: the user clears the box to type a new number, saves, and the previous or an intermediate value is sent beneath a blank box. (a) The signal is part of the field's contract, not an option. The validity callback **MUST** be a required prop of the shared field, so a new consumer cannot compile without answering it. (b) The signal is derived from the mounted text and re-announced on mount, on every change of text or bounds, and on unmount (unmount announces "valid": the invalidity ends with the field). A signal reported only from the change handler goes stale whenever the owning state outlives the field — rows rebuilt, field remounted — leaving either a stale "invalid" (save disabled with no error shown) or a stale "valid". State that mirrors the signal MAY carry across a rebuild only for the same subject and the same accepted value; the field's mount announcement then corrects it. (c) The field is the flag's only writer. The owner stores the announced flag and reads it in its single submit-eligibility function; it never recomputes validity from the parsed value, which by construction never saw the invalid text.  |
| **FORMS-IX-M9** | A form with an explicit save control **MUST NOT** write ANY of its edits before that control is pressed: every edit — including one that needs a different operation than the main payload (removing a record from ONE scope while it stays in the list) — is a draft that goes with the save, in ONE request. When the main payload's shape cannot express the edit (a list diff cannot say "removed from this scope, still a member"), the request body is extended to carry it; a side call fired from the edit gesture is forbidden, because a form whose "remove" is immediate for one kind of edit and deferred for another lets Cancel silently keep a change and a failed save leave a half-applied form. (a) A scoped form (tabs, sections) lists ONLY the records of its scope, and the scope's membership is read from the one server authority that owns it — never re-derived from a broader set (the whole parent group's member list is not "this scope's members"), never joined client-side from a second query. A list whose scope membership is not known (loading, failed, refreshing after a write) is rendered as not ready and blocks adding and saving; it is never shown as "empty" or as stale membership. (b) Records that belong to the parent but to NO scope **MUST** stay visible and editable in a labelled section — a scoped view **must not** orphan them. (c) A draft is only valid against the server state it was made on: the draft carries a fingerprint of that state and is not read once the state differs (another device changed it, the save just refreshed it) — derived at read time, never reset by an effect, so a stale draft cannot overwrite newer data (**TX-M-9**). |
| **FORMS-IX-M10** | A shared form component that serves both a surface editing an existing entity and a surface creating it **MUST** receive every value it derives from that entity (for example its region, week start, currency or time zone) as a required parameter stated by the surface, and **MUST NOT** read the active-entity store or query itself. A creation surface derives the value from the same birth input the server's creation writer stamps the new entity with. Why: on a creation surface the entity does not exist yet — the active store is empty (sign-up) or holds another entity (an operator opening a different one) — so the component's own read either waits forever (the input never appears) or answers for the wrong entity, and neither is visible to any check. |
| **FORMS-IX-M11** | A selection list narrowed by a typed query **MUST** keep every chosen item listed and shown as chosen while the query hides other rows, and **MUST** say in one line when the query matches nothing. Where the same list is drawn on several surfaces, the list length that shows the search box and the narrowing derivation **MUST** come from one shared helper, never a per-surface literal. Reason: a choice that disappears from view looks lost and cannot be undone without clearing the query, and copied thresholds drift between surfaces. |

## **MUST NOT**

| ID | Rule |
|----|------|
| **FORMS-IX-N1** | **Must not** clear user input on recoverable validation error without product approval (Decisions / facts ). |
| **FORMS-IX-N2** | **Must not** reject a user-typed value because it is absent from a known-value set, and **must not** treat that set as an allow-list. The set exists to measure *near-misses*, not to enumerate legality (**FORMS-IX-M6**(b)). The same holds for the shape check of a mail address: it **must not** be ASCII-only — a Unicode local part and an internationalized (U-label or punycode) domain are valid addresses; the shape check's safety duty is only to exclude whitespace, control characters and header delimiters (quotes, angle brackets, commas, semicolons). Why: users of non-Latin markets own such addresses, and an ASCII gate rejects them with no correction path. |

## Enforcement

These rules state behavior, not a particular lint configuration. An adopting project may automate decidable source-level patterns, but must document the real scope and limits of each check. Timing, product-copy meaning, data-flow across modules, and whether a user-facing warning remains overridable require runtime or product review.

- **FORMS-IX-M7**, **FORMS-IX-M8**, **FORMS-IX-M10** — can be enforced by the type system rather than a lint rule: the shared component or field declares the visibility parameter, validity callback or entity-derived value as required, so a surface or consumer that omits it fails the type check at its own call site; a lint rule beside it would be a second definition of the same obligation. Limit: the type check proves every surface answered, never that the answer is right (for **FORMS-IX-M8**, that it reaches the submit control; for **FORMS-IX-M10**, that a creation surface answered from the birth input rather than the active store).
- **FORMS-IX-M9** — held by the surface's single draft derivation and the type system (the readiness gate is a required input of the save-readiness derivation). A check for this class is declined while it has one measured defect on one surface and no recurring-class evidence (**ENA-A1**(a)).
- **FORMS-IX-M11** — review-held; declined check ([**IV-M13**](../implementation-verification/change-acceptance-bar.md)): a rule cannot tell which list rows are "chosen", so it fails the detectability condition of **ENA-A1**; one shared helper holds the threshold and derivation.
- Declined checks ([**IV-M13**](../implementation-verification/change-acceptance-bar.md)): **FORMS-IX-M2** — a hand-rolled-timer rule cannot see a *missing* debounce, which is the defect class; the single debounce authority holds it. **FORMS-IX-M4** focus half — a focus-effect rule covers one defect in one shared code-input authority and no other surface. **FORMS-IX-M6** rendering and client-local-rule halves — the harm is a missing client UX hint, and the server-side verdict protects the stored value. **FORMS-IX-M6** list-singularity half — a "second known-value list" predicate cannot be written soundly: a dotted i18n key path is shape-identical to a hostname, and telling them apart would write the audited list into the rule (a second authority).
- The rollback obligation of **FORMS-IX-M3** is owned by the [mutation hub](../tanstack-query/mutations-cache-sync.md).
