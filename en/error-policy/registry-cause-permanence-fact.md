## **MUST** — **M37**

**M37**: "Can this rejection's CAUSE stop being true?" is a fact ABOUT THE CODE, so a registry whose consumers need that answer **MUST** carry it as its own REQUIRED per-code field — never derived from the transport-retry flag, and never from the status class. Retryability answers *is re-sending this exact request useful now*; the status class answers *had the write been attempted when this was settled* (**M36**); neither answers *will this request still deserve this answer after the world has moved on*. A consumer that needs the third answer and is handed one of the first two is not approximating — it is reading a different question's answer, and it will be wrong for the whole family of rejections whose cause is external mutable state (an actor's role, an entitlement, a quota, a record's existence, a conflicting row, a lock, a clock). Four obligations bind.

- (a) The field is REQUIRED on every registered code, and its value set carries no "undecided". Optional is the failure mode, not the safe start: on a registry of any size an optional field is absent on most rows, every consumer re-derives it from a proxy, and the ambiguity the field existed to close is back with a new name. Required turns the type system into the fence — a new code cannot be registered until its author answers, which is the only moment when the answer is cheap and the producer is known. For the same reason the value set is closed and total: a third "unknown" member is a fallback wearing a field's clothes, it becomes the value every hurried author picks, and consumers must then re-invent the proxy for it. Where the evidence is genuinely mixed the row still takes a definite value — the one whose error is reversible — and the mixed evidence is recorded next to the row.
- (b) Where retryability and cause-permanence are bound, the binding is expressed in the TYPE, not in prose. The binding is one-directional and total: a code asserting that an immediate re-send may succeed cannot also assert that its cause is permanent. The converse is free and is the largest class there is — *not useful to re-send now* together with *the cause may clear later* is exactly the family (**IDEMP-M7**) names. A comment saying so is checked by nobody across hundreds of rows; a discriminated union says so once and rejects the contradiction where it is written.
- (c) A consumer reads the FACT, never a proxy — and an unresolvable code is a NAMED unknown, not a default. Any decision that turns on cause-permanence resolves the registered code and reads this field. Where the code cannot be resolved — the response is not the canonical envelope, the identifier is not registered, the request ended without one — the consumer **MUST** take the branch whose mistake is reversible, and **MUST** record the unresolved case under its own event name. It **MUST NOT** fabricate the field's value, and it **MUST NOT** quietly fall back to the proxy this row replaced: a silent proxy is indistinguishable from a working field until the day it disagrees.
- (d) The classification test is one question, asked per code and answered from its producers. *If the same actor sent the same body again some time later, and no code was deployed in between, would the server be OBLIGED to give this same refusal?* Obliged — the answer is derived only from the request's own content and the actor's own identity (shape, schema, a contradictory field, an unsupported value, a comparison internal to the request) — the cause is permanent. Not obliged — any part of the answer was read from outside the request (authorization, entitlement, quota, a stored record's presence or state, a uniqueness collision, a lease, elapsed time, the client build), or the failure is the server's own defect, which a repair or a recovery can clear — the cause may clear. A code whose producers disagree is not a classification problem but a two-question code, repaired the way **M36**(b) repairs a two-moment code: split it, and let each half carry its own answer.

- (e) While a two-question code is still unsplit, the CONSUMER that can tell the two questions apart owes the user a remedy that is true for ITS OWN branch. (d) repairs the producer, and that repair is the goal; but a split can be blocked for a measured reason and the code keeps arriving meanwhile. It usually arrives somewhere that already knows the answer, because the branch establishes it: which call site invoked the reconciliation, which provider result preceded it, which command the actor actually issued. That knowledge **MUST** be used, and three obligations follow. (i) The distinguishing fact is taken from what the consumer already holds. A request or response field **MUST NOT** be opened so the producer can hand back something the consumer can derive: a wire field is permanent, is owed validation and verification the derived fact is not, and acquires released consumers no source scan can see. (ii) On the branch whose cause cannot clear, the retry affordance the code's transport flag would otherwise authorise **MUST NOT** be rendered. An action whose outcome is already fixed is not a remedy — it is worse than offering none, because it reads as progress and invites the transport, the actor, or both to repeat it. (iii) The copy for that branch **MUST NOT** assert a fact the branch disproves, and it is taken from the entry the product already publishes for the same fact rather than newly authored — most of all in languages the author cannot read. A consumer that cannot separate the questions at all records the ambiguity at the decision point and states the residue where the next reader will meet it; it does not pick the more reassuring sentence.

- (f) Where the split (d) orders is blocked by a MECHANICAL CHECK OF YOUR OWN, the check is retargeted to its invariant — it is neither edited to admit the new code nor suppressed, and it never stands as the reason the split cannot happen. A check written to protect the gate that raises a code is usually anchored on the code's name, because the name is the easiest thing in a syntax tree to match. That anchor quietly makes the check an accomplice of the defect: on the day (d) orders the split, the check reddens on the *corrected* code, and both quick answers are already forbidden — editing the check to admit the new name special-cases a finding that is not false, and the only suppression wide enough to reach a whole-file assertion retires the entire invariant the check existed to hold. The third move is the correct one and it is ordinary check work, not an exemption: re-derive the anchor from what the gate cannot avoid carrying — the guarded condition itself, and the canonical raise mechanism the codebase already mandates — leaving the code's identity to the registry that owns it. Two properties are then measured, not argued: the retargeted check is born green on the unchanged tree, and its finding set over that tree equals the old anchor's. A retarget that came out quieter has removed a gate under cover of a refactor. 

Classify from the producers, never from the name: a code named `*_VALIDATION_FAILED` can also be raised for a state-derived refusal, and a `*_PAGE_LIMIT` code can count stored rows rather than request items — both are `may-clear` and would read as `permanent` from the name alone.


Check reach of (e). (a) The undecidable input is *whether re-sending can change the outcome on this branch*. (b) Nothing in a tree answers it: the transport flag is a property of the code and is correct for the branch it was written for, so a check reading it would flag the correct branch and clear the wrong one; the branch's own permanence is a claim about the producer's world, which neither a syntax tree nor a cross-file scan holds. Nor is "this code is raised from two places" a usable proxy — one condition raised from several sites is the common and correct case, and whether two sites ask the same question is exactly the semantic judgement (d) asks a human to make. (c) The half that IS decidable is already fenced without a rule: make the branch-truth an argument the consumer's own signature requires, with no default, and the compiler rejects every call site that has not answered — a lint rule would be a weaker copy of a type. (d) The protection for the rest is review at the decision point, plus the residue written where the next reader meets it.

Application — defect-only branches. A branch only a code defect or a dependency-contract change can reach (an authorization token whose identity or attempt contradicts its own issuance) raises `SYSTEM`, not retryable: a business race code there asks callers to retry a cause no retry clears, and hides the defect from crash reporting. Branch semantics: review.

[Consequence: A refusal whose cause was temporary is treated as permanent, the caller is locked out of an answer that has already changed, and the registry cannot say which of its rows are affected; must not ship.]
