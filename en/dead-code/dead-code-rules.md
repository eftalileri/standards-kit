Scope: Same as [README.md](README.md) hub Scope. This file carries the **DCD-M** / **DCD-N** rows themselves. The reachability-horizon reasoning behind **DCD-M8** and **DCD-N5** — why a source tree is not the consumer set, and how far a mechanical check can follow — is in [dead-code-wire-surface-horizon.md](dead-code-wire-surface-horizon.md); the contract (**DCD-C**), the two-layer model (**DCD-M1**), the decision gates (GDCD) and the Verify checklist stay in [dead-code.md](dead-code.md).

Why this file declares no negative. The hub half is skipped by a change that deletes nothing, and that is correct there — its gates read a deletion candidate list. These rows are not conditional in the same way: **DCD-M7** binds *every logical change* to close with a touched-flow review, whether or not anything is removed, and **DCD-M8** binds the wire surface a change merely exposes. A "nothing is deleted here" negative would close this file for exactly the additive change **DCD-M7** was written for.

Document type: Normative part — **DCD-M2**–**DCD-M9**, **DCD-N1**–**DCD-N5**.

## **MUST**

| ID | Rule |
|----|------|
| DCD-M2 | The project's in-file unused-code checks MUST cover its supported source files at a blocking severity justified by their precision. A migration that supersedes code MUST delete the old code in the **same change** ([SSG-M8](../ssot/ssot-principles-and-precedence.md) — no parallel path). |
| DCD-M3 | A whole-graph report MUST be treated as a **candidate** list. Before deleting any candidate: (a) confirm zero **source** references, including dynamic/string usage, barrels, and cross-workspace consumers; (b) delete in **small batches**; (c) run the verification and repository gates required by the consuming project after each batch. |
| DCD-M4 | Configure any whole-graph analyzer before its output drives deletions, and ensure its declared scan set covers every relevant source class. An unconfigured run is not actionable. A file class the config never names never enters the graph, so "no findings" and "never scanned" are indistinguishable. **(a)** Derive the scan set from the project's source and workspace authorities rather than maintaining a divergent list. If the tool cannot consume those authorities, use a project mechanism that keeps the sets aligned or state the coverage limit. **(b)** Measure inclusion using at least one real file from each relevant class; do not infer coverage from configuration text alone. State any classes the measurement cannot cover.
| DCD-M5 | Proven false positives MUST be suppressed at the tool's appropriate configuration layer, with a recorded reason — not by silently ignoring real findings. |
| **DCD-M3** | A whole-graph report **MUST** be treated as a candidate list. Before deleting any candidate: (a) confirm zero source references (exclude `node_modules` and `*.d.ts` from the check), including dynamic/string usage, barrels, and cross-workspace consumers — and references inside the defining file itself: a symbol imported nowhere but read by another declaration in its own file is an unused *export* (drop the `export` keyword or the barrel line), not a dead symbol, because a scan that skips the defining file reports every in-file dependency as an orphan; (b) delete in small batches; (c) run the verification and repository gates required by the consuming project after each batch ([**BE-M20**](../build-environment/build-environment-repository-and-scripts.md)). |
| **DCD-M6** | A candidate that cannot be proven dead (dynamic registration, reflection, public API, cross-package consumer not in scope) **MUST** be kept and, if tracked, recorded as "uncertain — retained". |
| **DCD-M7** | Every logical change **MUST** close with a touched-flow dead-code review. In the same change, remove each superseded import/export/function/type/constant, unreachable or no-op branch, producerless error/i18n/diagnostic key, stale comment/reference, and ownerless compatibility path introduced or exposed by that work. Before deleting, search both the retired symbol and its dynamic/public consumers and retain anything that cannot satisfy **DCD-M3**/DCD-M6. Pre-existing unrelated findings do not authorize scope expansion, but dead code introduced or exposed by the current change **MUST NOT** be deferred or shipped. A compatibility path retained under **DCD-M8** is not ownerless — its owner is the field release it serves, and it is removed on that release's support horizon, not on this review. |
| **DCD-M9** | A leftover with zero consumers is a trap, not a neutral remnant — and the symbols that existed only to serve it die with it. When a migration lands a new authority, a superseded helper that no longer has any caller is still live risk, because what survives is its name: a plausible name (`clearPersistedSession`, `resetCache`) is exactly what the next author reaches for instead of the authority, so the leftover silently reintroduces the parallel path the migration was supposed to remove ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)) and does so without ever appearing in a behavioural diff. **DCD-M2**'s "delete the old code in the same commit" therefore binds a zero-consumer leftover exactly as it binds a called one; *"nothing calls it, so it is harmless"* is not a reason to keep it, and it is the weakest kind of harmless — a leftover whose name contradicts a written product decision of the authority (the authority states this datum is deliberately not cleared; the leftover clears it) is a defect waiting for its first caller. The deletion **MUST** also drop every identifier that existed only to serve it — its member in an operation/event-name union, its diagnostic constants, its now-unused imports — or the union keeps advertising an operation nothing can perform (**DCD-M7**). But a symbol the deletion newly orphans is NOT automatically dead. Before removing it, ask whether it is the single authority for a value that some other site restates as a bare literal. If it is, the orphaning has exposed a missing edge, not dead code: wire the duplicating site to the authority ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)) rather than delete it, and prefer the shape a sibling module in the same family already uses over inventing a third one. Enforcement limit (stated, not silent — [**KIT-LIM**](../authoring/kit-stated-limits.md)): "this export has no consumer" is a whole-graph question, so no single-file predicate can decide it and the advisory layer (**DCD-M1**, report-only per **DCD-N3**) is the only detector — but the *shape* half is single-file decidable and **MUST** be locked where it exists: a teardown whose asynchronous result is discarded (`void <call>`) can never produce an emptiness proof, and a type gate cannot see it because `void` is precisely the escape hatch that silences the floating-promise type check. Measuring "zero consumers" **MUST** follow relays to a TERMINAL reader. A search stops at the first site that mentions the symbol, but that site may be a pass-through — a hook that selects a state field and re-exports it, a mapper that copies a field forward, a barrel that re-exports a name. A body whose only readers are relays is still zero-consumer, and each relay is part of the leftover: it dies in the same deletion, or the name keeps advertising a value nobody uses. So the measurement is not "is it mentioned?" but "does any reader use the value?", walked one hop at a time until every path ends in a real use or in nothing. Two consequences. (a) The first hit is the most likely false stop; a one-line grep that finds a relay and concludes "consumed" will leave the trap in place indefinitely, because every later attempt re-measures the same way and reaches the same wrong answer. (b) When a relay sits in a file the current change is not permitted to edit — another worker owns it, a release freeze covers it, it is generated — the deletion is blocked, not disproven. Record the completed measurement (the field, each relay hop, the terminal absence) so the next round inherits the proof instead of repeating it, and do not weaken the finding to "possibly used" merely because it could not be acted on. A relay is not the only false stop. A string-keyed entry — an i18n catalog key, a flag name, a message id — is identified by its full anchored path, and its consumers are the constructed keys, never the leaf token. Searching the leaf over-reports: the same leaf recurs under other namespaces, and a variable, prop or style spelled like it is not a lookup at all, so the search answers *"used"* and the dead entry survives every later re-measurement. Searching only literal call sites under-reports: a key assembled in a template is invisible to it. Anchor on the full path, then resolve, for each dynamic site, the subtree it can reach — a template's reachable set is the closed domain of its variable segment crossed with its fixed segments. A domain that is not closed leaves the entry undecidable → kept (**DCD-M6**). |
| **DCD-M8** | A wire surface's deadness **MUST NOT** be decided from the source tree alone. A published surface (HTTP route/endpoint, response field, request parameter, event/message name, persisted schema key, versioned contract) **MUST NOT** be treated as dead *because* the current source tree has zero callers. Before removing it: (a) identify the oldest consumer release still in the field — the oldest installed/cached client build and any external integration still permitted to call — from release-channel/distribution data, not from the repository; (b) scan that release's own source (its release tag or build commit) for callers of the surface — scanning HEAD proves nothing about a frozen bundle; (c) if any such release still calls it, keep the surface as a thin compatibility alias that delegates to the canonical authority and translates only the wire envelope — never a second read path, second derivation, or second authority ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)); a kept response field whose derivation is retired is fed the same way — from the replacing authority, or its documented neutral or empty value when no equivalent exists — and the retired computation **MUST NOT** be kept alive to feed it; (d) remove it only once the last calling release is out of support. When (a) or (b) cannot be established, the surface is uncertain → kept (**DCD-M6**). Where a published wire-contract record is maintained, (a) and (b) are read from it and a guard enforces that no recorded, still-in-field surface is deleted — but the record is a floor, not a ceiling: a surface it does not list is unmeasured, and (a)/(b) must still be established by hand. A RENAME IS A REMOVAL of the old name — for any consumer not redeployed in lockstep the old name dies at that instant, and a source scan cannot see that consumer, so "no references" is not evidence. Migrate additively: add the new name; keep the old one `@deprecated` carrying the same value (never the pre-decision raw value, or the decision does not take effect); remove it only after the consumer moves, on a named, measurable condition. |

## **MUST NOT**

| ID | Rule |
|----|------|
| **DCD-N1** | **MUST NOT** delete a file/export/dependency solely because a tool reported it unused, without the **DCD-M3** verification. |
| DCD-N2 | Whether and how scripts may edit source is governed by the consuming project's root agent-rule file ([KIT-LIM-7](../authoring/kit-stated-limits.md)). Follow that policy for every dead-code removal; do not infer permission or prohibition from this row. A whole-graph tool's own fixer is not a removal path because its report is a candidate list, never a delete list (**DCD-M3**). If the project has no source-editing policy, record that gap and resolve it through the project's normal decision process. |
| DCD-N3 | MUST NOT make a whole-graph analyzer blocking in a project's required gate while it still produces known false positives — promote a finding category only when its output is sufficiently precise and configuration-stable. |
| DCD-N4 | MUST NOT "trust" a quick text search as proof of usage — generated files, dependencies, type stubs, dynamic names, and indirect consumers can give false signals. Review the source references and run the verification required by DCD-M3. |
| DCD-N5 | **MUST NOT delete a route/endpoint, a wire field, or any published contract because a search or whole-graph analyzer reported "no consumer in the source tree", without the DCD-M8 released-consumer check.** A source-tree scan is evidence about the current checkout's clients only; it is **not** evidence about clients already released. A green local verification run after such a deletion is not confirmation: it re-measures the same snapshot and may stay green while released consumers still call the surface. |
