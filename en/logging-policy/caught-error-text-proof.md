## **MUST** — **M32**

**M32**: The raw-error-text rules (**M25** / **M30** / **M31**) are bounded by PROOF that a binding carries a throwable — not by the syntactic scope the value was caught in. A containment scope (`catch`, a rejection handler, an `'error'` listener) is the *common* origin of a throwable, not its definition. A rule or review that models only those scopes reports "clean" while the class ships: the heaviest leaks sit in a typed function parameter on a plain helper, several call frames away from any `catch`. When a check keeps missing the same class, suspect the source model before the rule's verdict. Three obligations follow.
- (a) The type annotation is the evidence. A binding proves it carries a throwable when its annotated type name matches the language's throwable naming contract (an `Error`/`Exception`-suffixed type). For a union or intersection, any single member proving it is enough — the raw text can still flow through that member.
- (b) A variable NAME is never evidence, and neither is the top type. `err` / `error` / `e` name DTO fields and unrelated locals just as often, so name-based widening buys no coverage and only manufactures false positives — and every false positive becomes a suppression line that later hides a genuine finding. The same reasoning excludes the top/unknown type: a value that genuinely *is* a throwable already reaches the sink through a containment scope, which the scope arm already sees, so admitting the top type adds zero coverage and pure noise. Widening a source model is only justified when it adds provable coverage; measure it before widening.
- (c) The predicate has exactly ONE authority. Every rule that asks "does this binding carry a throwable?" imports the same shared predicate. A second copy is a parallel authority ([SSoT](../ssot/ssot-principles-and-precedence.md) **SSG-M8**) and its drift is invisible, because both copies keep reporting findings while covering different sets.

Enforcement: this predicate is decidable from a single file's syntax tree, so where the adopting project uses type-aware source checks it **MUST** be locked mechanically through one shared predicate rather than left to review; otherwise verify the same type contract in review. The observability-sink half of **M25**/**M30** is held by the runtime boundary instead of a source fence: the single log and crash-report boundary scans every string value (credential and connection-string userinfo patterns) and every key, and the adopting project's visibility decision keeps error text visible by intent. Only the response-body half needs a static fence. Record the actual scope and limits of any check used.

Before choosing among the **M25** remedies, measure whether the flagged emitter is REACHABLE — an unreachable one is deleted, never rewritten. The three-case remedy table assumes the field or function has consumers; that assumption is itself a claim and must be measured, because the last consumer often leaves during the very migration that produced the finding. Where a whole-tree search shows no importer, no barrel re-export and no dynamic reference, the emitter is dead code and the answer is deletion in the same commit ([dead-code](../dead-code/dead-code.md) **DCD-M2**) — not a rewrite. Rewriting a dead emitter into a "correct" form is doubly wrong: it re-authors, beside the tier's single user-facing-text authority, a second authority for the same question ([SSoT](../ssot/ssot-principles-and-precedence.md) **SSG-M8**), and the result is still unreachable, so the repository pays maintenance for a path nothing executes. Keep the file's still-consumed exports and say in its header why the rest left, or the next reader restores them. 

A ratchet probe **MUST** sit at a binding the predicate actually recognizes; a probe at an unrecognized binding returns green and is read as proof the rule works. The ratchet step of a check's proof introduces a deliberate violation and requires it to fail. That step silently degenerates when the sample is planted where the source model does not reach — for a rule bounded by throwable proof, at a parameter of the top/unknown type, which (b) deliberately excludes. Nothing distinguishes "the rule is correctly silent here by design" from "the rule is broken" in the exit code alone, so a clean run at an invalid probe site certifies the opposite of what it seems to. Obligation: place the probe at a binding the predicate provably covers, and when a probe comes back silent, resolve which of the two it is against the check's own declared limits before recording the proof. 

Classification follows the same authority rule as logging. Since **M25** forbids `Error.message` as a classification input, a consumer **MUST NOT** recognize an upstream failure by substring-matching its message (`message.startsWith('SOME_CODE')`, `message.includes('not found')`). Such a match only appears to work when the carrier sets `message = code`, and it silently misclassifies any unrelated failure whose opaque text happens to contain the same substring — including a driver error that names the field it failed on. The thrower owns the recognition contract: it exports a structural predicate or a closed code set over its own typed carrier, and every consumer imports that one predicate instead of writing a private text matcher (**SSG-M8**).

Two forms of this class survive a text-matcher hunt because neither *looks* like text matching. (a) Equality against a shared sentinel string — `throw new Error(SENTINEL)` on one side, `error.message === SENTINEL` on the other — reads as a constant-based contract, and the shared constant makes it feel type-safe. It is still `Error.message` deciding control flow: any other failure whose message happens to equal that string is accepted, and the carrier's own `message` is a display field no one guarantees. The remedy is the same and costs nothing: the throwing module keeps a module-private carrier type and exports only a boolean predicate, so there is exactly one recognition path and no second one can be written. (b) A consumer that parses a code the thrower already carries structurally. Before writing any extractor, read the throwers on the path: where they already raise the registered error carrier, the code is a field, and the extractor is pure loss — it can only be *less* correct than the field it re-derives. 

A predicate shared by a client form and a server boundary returns a closed violation name; it does not throw. A throw forces every consumer to catch and then choose its branch from the carrier — and when the carrier is a plain error whose text doubles as the code, each consumer rebuilds a text matcher, while the server boundary sees an unregistered raw error and reports an expected user rejection as a defect. Returning the name lets each surface map it once: the server to a registered code chosen by provenance ([error-policy **M33**](../error-policy/error-category-provenance-and-client-text-set.md)), the form to a message key, a schema to its issue text.

The lock over a code-bearing raw throw has a matching blind spot: a predicate that only reads the argument's own literal text is bypassed by moving the code one line up into a `const`, so the check **MUST** resolve a same-file constant identifier to its string initializer.

Enforcement: this class is decidable from a single file's AST and **MUST** be locked by a static rule rather than review, with two blind spots that a line-oriented search provably misses — (1) the same ternary split across lines, and (2) a metadata object assigned to a variable first and only then passed to the sink. A rule that models source → propagation → sink must follow the value through intermediate variables, template/concatenation, and text-preserving string methods, while treating boolean classification calls as terminating the flow.

A sink arm that models an output CHANNEL must settle shape AND ownership; shape alone is not enough to open it. *Shape:* raw text handed directly to a call, unwrapped by any object literal, is an emission only where the call's return value is discarded — an effect-only call exists for its side effect and is therefore a channel, while a call whose value is consumed is a transformation or classifier whose real sink lies downstream and is already reached by the other arms. The discriminator is structural and must never be a callee-name list ([**FP-M32**](../false-positive/check-verification-rules.md)). *Ownership:* shape does not say which authority owns the surface reached, and a single file's syntax tree cannot, because the destination sits behind a callback the file only passes along. Where sibling rules divide this class by sink — one observability, one user-facing — an arm opened on shape alone re-reports what the other already adjudicated, and each re-report needs a second suppression on the same line ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)). Where ownership is unresolved, record the arm as a stated limit in the rule's own body instead of opening it. 

Enforcement guidance for the sink boundary. Route production logging and crash-report events through one shared sanitizing authority, and keep a source check (where the adopting project uses one) that requires the shared value-level scan inside the error-description boundary, the logging library's exception/rejection sanitizer and each crash-report event sanitizer, and rejects an underlying logger level call whose structured metadata bypasses the shared metadata scrubber. Whether the SDK collects PII is the adopting project's visibility policy, not a fence — the sanitizer holds the credential harm whatever the SDK collects. Treat user-facing responses, logger metadata, crash-report fields, breadcrumbs and grouping keys as separate egress surfaces and identify which authority validates each one. Do not add a source rule that merely pins the internal shape of an authority file (the shared cursor-key parity, the canonical request-id writer, the safe route-template source, the access-log allowlist, the grouping-fingerprint marker of [**M39**](crash-report-delivery-receipt.md)) when the boundary scan or a runtime proof already holds the harm; an unreported scheduled run is likewise caught at runtime, by the supervisor reading the trace (**SJO-M10**), which is stronger than a source lock. **M29** launch parity requires a cross-file check because the package scripts, development launcher, container command, PaaS command and entry-module import graph are separate authorities unless checked together. The crash-SDK capture members (capture of exceptions, messages and events; scope configuration) are reserved for the exact canonical SDK bootstrap and logger transport files, and the scope factories additionally for the request-context middleware — a module-owner table rule can enforce this, resolving namespace/default imports, named imports, `require`/dynamic-import bindings, single-assignment aliases and destructuring. Reach: a capture reached through a scope object the middleware obtained, a parameter-carried binding or a computed member is outside such a rule, because a single-file tree does not follow values across functions; keep unmapped carriers and cross-module flows under review rather than silently widening a source rule.

Observability-channel policy (the adopting project states its visibility decision under [**M25**](background-boundaries-and-sink-safety.md) as its own criterion): where the project has decided on full crash-report visibility, raw caught-error text — `.message`, `.stack`, `.cause`, and the driver/runtime detail fields — may reach the operator's log and crash-report sink, personal data included, because only the operator reads that channel. The single redaction authority for that text is the sink's value-level scrubber (**M25**), and it masks live credentials only (plus any class the project forbids separately, such as raw coordinates); no call site adds a second, wider redaction of its own (**SSG-M8**). The decision does not reach two neighbouring surfaces, which stay binding as written: the HTTP response body (error-policy **M30** a/b) and classification by message text (above). **M25**, **M30**(a) and **M31** state the same per-destination answer: into the observability sink the text crosses whole and the sink's scan is its only redaction; every other destination keeps the authored-text / validated-fact test.
