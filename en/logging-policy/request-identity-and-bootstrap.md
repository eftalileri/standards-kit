## **MUST** — **M26** to **M31**

**M26**: Opaque pagination and continuation values are sensitive request-state, not safe diagnostics. The shared case/separator-insensitive scrub authority **MUST** classify canonical and suffixed `cursor` / `nextCursor` / continuation-token keys as redacted, and every request body/query snapshot **MUST** consume that same authority. Base64, hex, encrypted-looking, bounded-length, or “opaque” values are not safe by shape: they may encode ids, time/order state, filters, or subject-derived data. Presence-only booleans may be explicitly allowlisted; raw values are omitted from messages, metadata, breadcrumbs, metrics, and crash context (security **SEC-M-LOG-5**).

**M27**: Request correlation has one canonical writer. An inbound request-id header is accepted only as exactly one string satisfying the documented canonical UUID schema. Missing, repeated/array, malformed, whitespace-padded, or non-canonical input is ignored and replaced with a fresh cryptographically secure server UUID; the rejected raw value is never logged, tagged, echoed, interpolated, or returned. The accepted/generated id is written once to request-local context and is the sole source for structured `requestId`, API trace id, and crash correlation. No downstream handler reparses the raw header or invents a second id (security **SEC-M-LOG-CORR-2**; **SSG-M8**). The correlation id **MUST** be written as a searchable crash-report TAG under the name the API envelope and the client use for it, on every tier that reports. Writing the one id under both names from the single resolved value is not a second writer; publishing it under only one, or only as unsearchable context, is a correlation gap. Every crash/tracing SDK init, on every tier, **MUST** set its trace-header propagation targets explicitly to origin-anchored first-party patterns — an empty list where the tier calls no first-party service — and a zero trace sample rate **MUST NOT** be recorded or relied on as "tracing off". Reason: SDK defaults attach trace context (`sentry-trace`, `baggage`: trace id, environment, release, public key) to every outgoing host whatever the sample rate, and a plain string target matches any URL that merely contains it, so the telemetry reaches third-party providers. Review-held ([**IV-M13**](../implementation-verification/change-acceptance-bar.md)): one init site per tier.

**M28**: Production request access/latency logging has one structured authority and an exact safe field/literal allowlist: normalized method, server-owned static route template (or a fixed unresolved sentinel), numeric status, bounded numeric duration, canonical request id, fixed-enum/fixed-literal action and slow tier, bounded numeric per-datastore command counts and summed command durations (read / write / cursor-batch / other, cache round trips), a boolean client-aborted flag, value-free command shapes, and fixed credential/PII-free root-cause/solution literals. The message may interpolate only those already-allowlisted normalized/bounded values. A command shape is derived from the driver's command event and carries only the command name, the server-owned collection or key-family prefix, and the sorted field/operator-name skeleton of the filter; every value, and every name segment outside a fixed identifier charset or shaped like an id/number, is masked — a raw filter, key or argument **MUST NOT** be logged. Counts and shapes **MUST** come from the driver's own command events (one listener set), never from call-site counters, so a memo hit or a forgotten counter cannot misreport. The access summary may carry the bounded list of shapes repeated at or above a fixed per-store threshold; how a repeated shape is routed is decided by [**M17**](failure-level-and-channel-routing.md)'s runtime-defect corollary, not here, and a per-shape record is never a second access summary. Reason: a bare total cannot tell a slow request's database time from CPU or outbound time, nor name the repeated query. The authority **MUST NOT** read or emit raw `url`, `originalUrl`, client request target/path/query, params, headers, body, cursor, user/tenant ids, or arbitrary client text. Route-template resolution fails closed to the fixed sentinel; it never falls back to client input. Other middleware/services do not emit a second per-request access summary (security **SEC-M-LOG-ACCESS-1**; **SSG-M8**).

**M29**: A backend that relies on crash-SDK auto-instrumentation where the runtime requires early registration (for example a Node ESM service) **MUST** initialize the SDK through the runtime-supported preload mechanism before the application entry module is evaluated. The canonical package start command owns that preload contract (for Node, the `--import` option naming the instrumentation module before the entry path); the declared runtime engine **MUST** meet that option's documented minimum version, container and PaaS launchers **MUST** delegate to the one command, and the development launcher **MUST** preserve the same ordering through its module loader. A static side-effect import inside the entry module is not sufficient evidence: ESM dependency evaluation may load framework modules before the SDK registers instrumentation. Startup parity is cross-file and **MUST** be guarded by the enforcement mechanism the adopting project documents (record its actual scope and limits); production readiness evidence includes absence of the SDK's “framework not instrumented” diagnostic. Enabling that instrumentation changes the program every later boot step observes, so any boot-time assertion that walks the framework's own route/middleware structures **MUST** be designed and verified against the instrumented shape. Auto-instrumentation replaces handlers with delegating wrappers, and a wrapper preserves only enumerable string properties — and, through them, the identity of the objects those properties return. It does not preserve the original handler's function identity, its symbol-keyed metadata, or its non-enumerable properties. A boot inventory, access-declaration gate or mount registry **MUST** therefore key on an enumerable string property, or on an object reached through one, and **MUST NOT** key on handler identity or hidden metadata; repairing such a check by reading a vendor-private unwrap field (`__original`, `__wrapped`, or an SDK-specific equivalent) is forbidden, because it re-couples the check to one SDK's internals and breaks silently at the next wrapper. Since the SDK is typically switched on by a crash-reporting endpoint setting that local development leaves unset, a check verified only locally has measured a different program: verification **MUST** execute the built artifact both with and without the production start configuration (preloader plus endpoint setting), and the two runs **MUST** agree on the check's reported inventory counts — not merely both boot. A check that boots under instrumentation because it resolves fewer items has been blinded, not fixed, and the count comparison is the only thing that distinguishes the two outcomes. [Consequence: A fail-closed boot gate crash-loops in production while passing every local run, or — worse — passes production by silently skipping what it can no longer resolve.] [Verify: Run the built entry twice, with and without the SDK preloader plus endpoint setting, and diff the gate's reported totals and per-category counts; grep the check for handler-identity keys, symbol-keyed metadata and vendor unwrap fields.] The validated environment schema **MUST** reject a production configuration without the crash-reporting endpoint setting, so the process refuses to boot instead of running with its crash channel off; development and maintenance runs stay free to omit it. Reason: an optional endpoint setting lets one missing variable switch every crash report off with no signal. Held by the schema's own refinement (boot fails); no separate check.

**M30**: A credential-bearing datastore / cache / broker connection failure — in runtime bootstrap, health checks and operator scripts — follows security [**SEC-M-LOG-2**](../security/security-logging-core.md): it is contained at its first credential-aware boundary and its raw text never reaches the sink; this is the one exception to **M31**'s "caught text crosses whole into the observability sink", and the **M25** value scan stays defence in depth.

**M31**: **MUST** apply one caught-text policy per destination. Observability follows [**M32**](caught-error-text-proof.md) and the connection exception [**SEC-M-LOG-2**](../security/security-logging-core.md); no layer replaces diagnosis with a sentinel. Outside that sink — response bodies, user-visible fields, metric labels/tags and decisions — only application-authored literals/registry codes or canonical closed-set/validated structural evidence may cross. A helper that derives a root-cause/diagnostic string reaching any destination outside the observability sink is bound exactly like a call site — such a helper is the class's central leak, because a sink-based rule sees only direct materialization and one raw-text helper re-opens the class for all its callers. Runtime class, runtime-enumerated system error code, errno, syscall token and validated signal are carried to the final sink (re-attached to metadata where a transport lifts the error carrier out of it); paths/arguments are not structural evidence, and error-code shape cannot replace registry membership. The error class **MUST NOT** be flattened to one hard-coded name, and the system error code **MUST** be validated against the runtime's own error-name table, never a hand-maintained list. Operator programs **MUST** type the stop reason at its throw site rather than reconstructing it from redacted catch text, and carry that typed stop reason and bounded scalar resume/progress fields (counts, chunk index, closed-set mode), rather than relying on redactable free text; identifiers, payloads and arbitrary paths are not progress scalars.
