## **MUST** (normative) — **SJO-M1** to **SJO-M6**

**SJO-M1**: Every recurring unit of work **MUST** carry a declaration at its registration site, and the registration **MUST** be impossible without one. The declaration names, in one machine-readable place beside the schedule: the job's stable identity; the cadence it is expected to complete on; the grace it may exceed that cadence before it counts as late; and its outcome class per **SJO-M3**. Documentation beside the code does not satisfy this — the obligation is that a *new* job cannot be added without declaring, which only the registration signature and a build-time check can guarantee. A declaration kept in a second hand-maintained list of job names is forbidden for the same reason an enumeration cannot answer a membership question ([**IDEMP-M21**](../idempotency/ledger-scheduler-and-membership-predicate.md)): the list cannot name the job nobody added to it, so the newest job is the one that is never supervised. [Consequence: A job ships unsupervised and its silence is indistinguishable from health; the gap is invisible precisely for the jobs added most recently.] [Verify: the registration parameter is required by the type system + a check over every registration site reporting zero undeclared jobs + a positive probe registering a job without the declaration and seeing it flagged.]

**SJO-M2**: A run **MUST** leave a durable trace of its last SUCCESSFUL completion, written by exactly ONE authority in the shared scheduling seam — and that authority is the record the scheduler already keeps, never a second one. The trace survives process restart and is visible to every instance, so it lives in shared storage, never in process memory that diverges the moment a second replica runs. Where single-flight coordination already persists a per-job record (a lock/lease row, a claim record), the liveness fact is added to that record or derived from it; opening a separate "last run" collection beside a record that already knows when the job last held the lock is a second writer of one fact ([**SSG-M8**](../ssot/ssot-principles-and-precedence.md)) and the two will disagree. The writer sits in the shared seam every job passes through — never per job, which would make the trace exactly as reliable as the job that is failing to write it. Acquisition time is not completion time: a lock record touched on acquisition proves the tick began; the completion fact is a distinct field written after the work returns, and a rule that reads the acquisition timestamp as "last run" is reading **SJO-M3**'s tick, not its work. Completion is not successful until its durable trace is written: trace failure **MUST** fail the run and **MUST NOT** emit `completed`/`ok`. A shared lease/trace record **MUST** atomically write trace + release under the owner token; with an external lease the order is revalidate owner → persist trace → release → `ok`. [Consequence: Either no durable answer to "when did this last succeed", or two answers that drift — and the drift appears exactly when one replica stops, which is the case the trace exists for.] [Verify: one writer in the shared seam (grep the completion field's assignment: exactly one site) + the field is distinct from the acquisition/lock timestamp + a restart leaves the value intact + no second collection carrying the same fact + forced trace failure yields no `completed`/`ok` + shared-record completion is one owner-token CAS.] [Limit: AST locks order; repository CAS and driven failures prove atomicity/ownership.]

**SJO-M3**: A heartbeat proves a tick, not work — so where "produced nothing" is decidable it **MUST** be recorded, and the declaration **MUST** state which of three outcome classes the job is in. The run trace of **SJO-M2** carries the job's own output magnitude wherever one exists (rows written, candidates processed, messages dispatched). That magnitude **MUST** count committed work, never sub-pipelines, providers or phases that merely returned; a handler that computes those counts and only writes them to a log line has not recorded them, because a log line is not queryable by the supervisor. The declared class is one of: (a) empty is normal — an empty candidate set is the ordinary case and an empty run is healthy; (b) empty is bounded — the job must produce at least once per stated window (a periodic aggregation, a per-period rollup), and a window that closes with zero output is a supervised condition exactly like a missed run; (c) not decidable by the job — the handler cannot distinguish "nothing to do" from "structurally unable to do anything", typically because it returns early when an external credential, feature flag or configuration is absent. Class (c) **MUST** be declared rather than silently treated as (a), and the early return **MUST** be recorded as its own terminal outcome carrying the reason, so a permanently disabled integration is visible instead of being counted as a healthy run; leaving it undeclared is the silent absence [**KIT-INV-8**](../authoring/kit-structural-invariants.md)(b) forbids. Two typical cases: a monthly aggregation completed on schedule for three consecutive periods and wrote zero rows because it read a field name that did not exist — every tick reported success; and a daily ingestion job returns early with an informational log whenever its provider credentials are unset, and likewise reports success. A tick-only signal called both healthy. [Consequence: The most expensive failure class in scheduled work — the job runs, the monitor is green, and the product silently produces nothing for as long as anyone believes the green.] [Verify: the output magnitude is persisted, not only logged + the declaration names the class + for class (b) the supervisor's window predicate exists + for class (c) the early-return path writes a distinct outcome with its reason.]

**SJO-M4**: ONE supervising job **MUST** evaluate every declaration, and its alert unit is the EPISODE, not the evaluation. The supervisor reads the declarations of **SJO-M1** and the traces of **SJO-M2**/**SJO-M3** and decides, per job: late (no successful completion within cadence + grace) or output-starved (class (b) window closed empty). A breach opens an episode and raises exactly ONE registered error through the adopting project's ordinary error authority — the same registry, carrier and boundary every other backend failure takes ([**M12**](../error-policy/error-model-registry-and-boundary.md), [**M13**](../error-policy/error-carrier-and-severity-derivation.md)) — carrying the job identity, the expected cadence and the measured silence. Every later evaluation inside the same open episode stays at `warn` on the same action label with its counter still incrementing, so a query on that label still sees the true number ([**M18**](failure-level-and-channel-routing.md)). The episode closes on the next successful completion, and that recovery is itself recorded, so an operator can tell "it came back" from "nobody looked". ONLY a recorded completion may close it. A state meaning the judgement could not be made — the declaration missing or unreadable, the trace unparseable, no first completion yet — **MUST NOT** take the closing branch: the recovery record would assert the one thing that did not happen, and a false recovery is worse than a missing alarm because it retires a true one and nobody looks again. Such a row keeps its episode open and is reported as unmeasurable, so "it came back", "it is still breaching" and "we can no longer measure it" stay three distinct answers. Where the health judgement is a closed set of states, the closing decision is written as an exhaustive branch over that set with no catch-all, so a state added later cannot inherit the recovery branch by default. Raising per evaluation is forbidden: a supervisor on a five-minute cadence turns one stopped job into twelve alerts an hour for as long as it stays stopped. This is the same episode unit the sustained-outage rule already defines ([**RDS-T-SUSTAINED-DISCONNECT-ALERT-MS**](../redis/redis.md)) — reuse it; a second episode pattern in one system is a second answer to one question. The supervisor iterates the DECLARATIONS and reconciles traces against them, never the reverse. Walking traces alone makes a declared job whose trace is missing indistinguishable from a healthy one — that absence is itself a breach and opens an episode. The reverse difference is not: a trace no current declaration claims is an ORPHAN, reported but never judged late, so deleting a job resolves itself instead of alarming forever. A per-member status kept below one job (one row per provider account, integration or other enumerated member) follows the same reconciliation: members are judged only against the roster the job's latest successful enumeration produced; a row whose member that roster no longer contains, or whose integration is no longer configured, is removed by the status authority instead of ageing into a breach; and a failure recorded against a run stage rather than a member is cleared by that stage's next success. A member the provider itself reports as closed or cancelled (its published status value, never inferred from absence) is shown as inactive with that status and never alerts; it returns to judgement on the run that reports it active. A per-member alert names the channel and member it is about. A failure key that no success path ever writes cannot close, so its alert never retires and "clears itself on recovery" is false. [Consequence: Either alert flooding that trains everyone to ignore the channel, or — with no recovery record — a resolved incident that still looks open, or — with one written on an unmeasurable row — an unresolved incident that looks closed.] [Verify: one supervisor module + one raise site + an episode key per job with open/close transitions + a driven run in which a stopped job produces exactly one error and N−1 warns on one label, and its resumption writes the recovery record + a driven row whose declaration becomes unreadable while its episode is open, producing no recovery record and keeping the episode.]

**SJO-M5**: The supervisor **MUST** itself be watched from OUTSIDE its own runtime, and where that external capacity is scarce it is spent on the supervisor and nothing else. A watchdog that shares the process, scheduler and host it watches cannot report its own death: when the runtime stops, the supervisor stops with the jobs, and the resulting silence is the signal nobody receives. Exactly one external liveness signal — an external cron/uptime monitor, a dead-man's switch, a separate platform's scheduled probe — **MUST** observe the supervisor's completion. Where the external provider's capacity is limited (a plan that grants a small number of monitored schedules), the capacity is spent on the supervisor, not distributed across ordinary jobs: N seats on N jobs buys per-job resolution for the jobs that happen to hold a seat and leaves the whole system blind the moment the runtime itself stops, while one seat on the supervisor covers every declared job through **SJO-M4**. When the supervisor ships, the external signal moves to it in the same change; leaving it on an ordinary job afterwards keeps a weaker parallel answer to the question the supervisor now owns. [Consequence: Total, silent blindness — the runtime stops, the watchdog stops with it, and the absence of alerts reads as health.] [Verify: the external monitor's configured target is the supervisor's identity + the supervisor's completion check-in is its last statement + the seat's previous target no longer checks in. The external console is outside the source tree, so this is read there and recorded, not derived from a checkout.]

**SJO-M6**: Any surface that reports job health **MUST** derive it from the declarations and traces the supervisor reads — it **MUST NOT** keep a second stored status. An operator screen, a health endpoint or an admin projection answers "is this job alive?" by reading the same authority and applying the same predicate, so one set of facts has one interpretation ([**SSG-M1**](../ssot/ssot-must-authority-and-derivation.md)). A job-status field maintained by a second writer is forbidden: the writer that would keep it current is, in the failure case, precisely the thing that stopped — so the stored status stays green exactly when it is wrong. [Consequence: A health screen that is most confidently wrong in the case it exists to reveal.] [Verify: the reporting surface imports the supervisor's predicate + no persisted job-status field with its own writer + the surface's value changes when the underlying trace ages, with no other write.]

**SJO-M11**: When a job's declared cadence or grace changes, lateness **MUST** be measured from the later of its last completion and the instant the changed declaration was first stamped, and that instant **MUST** move only when the cadence or grace itself differs from the stored one — never on an unchanged re-stamp at boot. Until the job completes under the new declaration the row is unmeasured: an open episode is held, never closed, and no new episode opens before the new cadence + grace has elapsed. The alarm **MUST** state its cause from the frozen measurement — the reference instant and what it is (last completion, first stamp, declaration change), the measured silence or starvation and the tolerance — and an evidence field absent from an older frozen intent is omitted, never read as "none". Reason: a completion owed to the old cadence judged against a tighter one is a false breach on every cadence change, and a generic alarm sentence sends the operator to re-derive what the supervisor already measured. [Consequence: Every cadence tightening pages a healthy job, and every page reads the same whatever the cause.] [Verify: review-held — the predicate is the one pure derivation of **SJO-M6**; a driven run of a row whose last completion predates a cadence change yields "awaiting first completion" before the new tolerance and `late` with the change instant after it.]
