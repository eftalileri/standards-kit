## **MUST** — **M21** to **M25**

**M21**: Background outermost-catch boundaries (**M15**'s exception — fire-and-forget dispatch `.catch`, cron / job / worker per-item catches) **MUST** derive the log level from the error's category exactly like the HTTP boundary does — expected (`OPERATIONAL` / `BUSINESS`) → `warn` + metric channel; `SYSTEM` / unknown → `error` → crash reporting. An unconditional `logger.error` in such a catch bypasses the category spine (**M16**–**M18**) and floods crash reporting with expected lifecycle outcomes (e.g. a not-found for a legitimately deleted record). A provider's structurally validated failure result that did not throw is still classified through a registry-backed carrier before this boundary: expected recipient lifecycle and transient-capacity outcomes do not become a generic internal-error code, while malformed payload/configuration/unknown-provider outcomes remain `SYSTEM`. A transaction-owned internal payload schema failure **MUST** likewise be translated at the owning schema seam into a registered `SYSTEM` carrier with a fixed operation and bounded structural facts; allowing a raw parser/validator exception to reach the shared background boundary collapses distinct contract drift into an unknown bucket. Raw issue messages and values remain forbidden, and the outer boundary does not guess the lost semantic type. The error handed to the boundary (and to any failure log or crash sink) is the caught throwable itself, or a registered carrier that keeps it as `cause` where the source boundary permits; a freshly built fixed-text `Error` **MUST NOT** stand in for either — it resolves to no registered code, groups every failure under one constant, sends expected outcomes to crash reporting and discards the real cause. This classification **MUST** live in one shared helper next to the boundary handler (single resolution authority — no per-catch-site copies of the carrier→category→severity logic). A per-item catch INSIDE a request that folds the failure into a response row instead of re-raising is such a boundary too: the row is the user's answer and never reaches the HTTP boundary, so the same helper reports it at the point of conversion — a `SYSTEM` member (corrupt stored data, persistence defect) → `error` → crash reporting, an expected one → `warn` + metric. A row that carries a `SYSTEM` code without that report hides a data defect for good (the user sees "could not be saved", the operator sees nothing). Rejecting the whole request is not required for this: whether one failing item aborts the batch is the operation's own contract (all-or-none settlement rejects it as a unit and still answers per item); reporting is independent of that choice. Whether a catch turns an error into a response row is a cross-statement data-flow fact that a single-file check cannot reliably see; the single conversion seam holds it, and review confirms it.


**M21** lifecycle corollary: the process-local lifecycle authority that tracks every background handle and in-flight promise, the ordered graceful-shutdown sequence with its monotonic deadline, abort propagation and drain dependencies, and the bounded logger flush that ends it, are banded in [background-lifecycle-authority.md](background-lifecycle-authority.md); it binds exactly as if written here.

**M21** further clarifications: the boot-watchdog placement/kill-target contract, the two narrow direct-FD terminal-evidence exceptions, the bounded-batch settlement corollary, the contained-failure settlement rule and its permanent-candidate corollary are banded in [shutdown-watchdog-clarifications.md](shutdown-watchdog-clarifications.md); they bind exactly as if written here.

**M22**: The category→severity→channel spine applies PER TIER, not only on the server. Any tier with its own crash-reporting channel (mobile / web client, worker, CLI) **MUST** have its own single classification authority with the same three steps, and its unconditional capture sink **MUST** sit behind that authority as the sink's only caller — feature code never reaches the crash SDK directly (**SSG-M8**: a second writer is a parallel authority). A client tier derives the category from what it already receives: the error envelope the boundary returns (category / retryable / trace id) for API failures, and structural transport markers otherwise; unknown stays a defect (**M16** — classification, never demotion). Where the tier has no metric exporter, the expected-error signal (**M18**) **MUST** still be preserved on a non-event channel (trace/breadcrumb record, counter) so suppressing crash noise does not blind the tier. Client-side detail: client observability [**COB-RN-M6**](../client-observability-rn/classification-authority-and-outbound-links.md) / [**COB-RN-N4**](../client-observability-rn/client-observability-rn.md).

**M23**: The application logger facade **MUST** scrub structured metadata at its entry point for every supported level before any transport runs. One shared credential predicate + bounded recursive scrubber must cover `error`, `warn`, `info`, `debug`, and `http` (or the configured equivalent set), so stdout, local files, hosted logs, and crash reporting cannot receive different secret-redaction behavior. Feature code must not scrub ad hoc: **M20**/**N8** already forces it through the facade, and where the adopting project uses static checks, facade wiring should be enforced wherever a single-file syntax tree can see every underlying logger call (use the enforcement mechanism the project documents and record its actual scope and limits). The scrubber must tolerate cycles, excessive depth/container size, binary values, and throwing getters/enumeration without making logging throw. This is structured-key protection, not free-text sanitization: an opaque `Error.message` / `stack` or first-argument message may contain an unkeyed credential and must be contained at the source boundary per **N2** and security **SEC-M-LOG-2** / **SEC-N-LOG-2**.

**M24**: A durable inbox/outbox worker logs failures at its outermost attempt boundary, once per attempt, through the same category→severity→channel authority as **M21**. Structured metadata **MUST** include the safe event/message identifier (or a threat-model-appropriate correlation pseudonym when the identifier is sensitive), worker/job action, the claim-time attempt number, and resulting durable state (`failed` or terminal equivalent). A plain unkeyed digest must not be described as anonymization for low-entropy input. The attempt value comes from the atomically incremented durable attempt counter (the durable attempt counter field), never from an in-process retry variable. The raw provider payload, replayable credential/token, and opaque persistence error from a credential-bearing record **MUST NOT** enter message, metadata, stack, or crash context. Exhaustion into a terminal state is an explicit data-integrity/operations signal and **MUST** remain visible; do not silently stop retries or delete the record. A durable inbox/outbox/queue row created inside a request **MUST** store that request's canonical correlation id ([**M27**](request-identity-and-bootstrap.md)) at enqueue, read from the request-context authority and never minted; a row born outside a request stores none, and an upsert that re-arms an existing row replaces the stored value with the re-arming enqueue's id or removes it. The worker's attempt failure and outcome records **MUST** carry the stored value as a separate origin field beside its own unit and row identifiers, never under the worker's own correlation name. Reason: once the in-process request context is gone, a deferred failure cannot otherwise be joined to the user action that caused it. Review-held ([**IV-M13**](../implementation-verification/change-acceptance-bar.md)): which writes create durable queue rows is a cross-file census, not a single-file pattern.

**M25**: In the observability channel a sink **MUST NOT** delete free error text by FIELD NAME; it **MUST** scan the text by VALUE and mask only what a name cannot excuse. A name-based deny-list (`message`, `stack`, `cause`, `url`) deletes without reading, so it destroys diagnosis at exactly the field carrying it while still missing the same secret under any other name. The criterion is the adopting project's own (live credential, plus any separately-forbidden class such as raw coordinates); everything else — driver `errmsg`, validation issues, stack frames, field names, tenant and business identifiers — stays visible. One authority owns the scan and every sink calls it (**SSG-M8**): scheme userinfo in connection strings/URLs, `Authorization` schemes, JWTs, published vendor secret prefixes, and `key=value` pairs whose key the key authority already masks. It applies to every string the traversal reaches, not to a fixed field list, and the runtime's own exception handler — which bypasses the wrapper — applies it too. Two surfaces stay removed: the SDK's raw request/user objects (cookies and auth headers wholesale) and stack-frame local variables (an arbitrary value bag, not text); code-location frames stay. The permission covers the operator's observability channel only. The HTTP response body is outside it — root cause still **MUST NOT** go there in production (error-policy **M30** a/b) — and so is any decision made on that text (a branch, a retry choice, a classification: the third remedy below). Inside the channel the caught error's own `message`/`stack` MAY reach the sink whole, including from a call site that places it in metadata: the one value scan at the sink is the only redaction authority for it, so no call site, helper or layer adds its own sentinel, truncation or name-based deletion (a second redaction policy is forbidden, **SSG-M8**), and closed-set structural evidence still travels beside the text (counter-cost below). Cost of deleting by name: an endpoint can return 500 for days while the one text explaining it is erased from both log and crash report, so the cause can be found only by re-running the query against production data. On the backend, the crash SDK's pre-send hook stays a sanitizer-only boundary: category/severity routing happens before the sink, and that hook **MUST NOT** return `null` or otherwise drop a SYSTEM event from caller-controlled `event.extra`, tags, metadata, message, or feature flags. A caller-controlled “non-actionable” marker is never crash-drop authority.

**M25** command-line boundary application: A command-line tool is an observability surface, not an exemption and not a reason to ban its diagnostic console output. Credential-bearing datastore connection/authentication/write failures are contained at their first credential-aware operation boundary under **SEC-M-LOG-2**, with a cause-free registered SYSTEM carrier and the existing validated class/runtime/driver facts; the general sink's value scan does not authorize forwarding that raw driver throwable. A provider's diagnostic text printed by an operator tool uses the same existing value scanner for both a parsed-message branch and an unparsed-body branch, rather than a second field-name deny-list, sentinel policy or local regular expression. Keep operation/status/product evidence and disclose the scanner's heuristic limits; unknown arbitrary embedded secrets are not proven absent. The existing single APIs are the stronger mechanism; do not add a parallel console rule or an all-CLI guard beside them.

**M25** lifecycle provenance and settlement application: Reconstructing a typed lifecycle failure must preserve its already-classified safe evidence through the actual terminal output owner. Read registered context from the established canonical reader rather than re-deriving raw-driver facts from the replacement Error; compose or select that context so generic caller facts cannot overwrite the original safe operation/class/runtime/driver evidence. Keep the original domain's preflight/progress/primary-error disposition and protected omission contract; a stage-bound private carrier does not gain permission to render arbitrary provider/domain context. Preserve the unregistered/raw-error branch and current sink choice. A rejecting cleanup promise must be observed by the terminal that owns the command's nonzero outcome; reporting the primary failure alone does not settle a second cleanup rejection. These are applications of the existing source boundary and canonical carrier APIs, not a new classifier/sanitizer/logger or a universal raw-body privacy guarantee. Runtime bootstrap/error-event and credential-bearing body-write/session/commit scopes retain their separate authorities and explicit unresolved limits.

**M25** counter-cost — a scanned text still needs closed-set STRUCTURAL identity beside it, and the set **MUST** cover the persistence driver. Text answers "what happened"; it does not give a field an alert or a filter can bind to, and a heuristic scan is a safety net rather than a proof. Two observed shapes: a process-spawn failure surfaced only as redacted text plus `child_process` frames while `code`/`errno`/`syscall` held the cause; and a database aggregation failure surfaced as a class name alone while the driver carried `code` (numeric) and `codeName`. The second exposes a specific trap: an OS/libuv evidence producer validates `code` against the runtime's string error table, so a driver's numeric code matches nothing and is silently dropped. Obligations: (a) every failure family whose runtime answer is structural gets its own evidence producer — OS/runtime, persistence driver, upstream/network — and the sink attaches each as a separate namespaced field, never merged into the message; (b) each producer carries only values validated against a closed set the runtime itself owns (a system-error table, a signal table, a driver's symbolic code names) or a numeric/pattern-checked field, and omits what it cannot read rather than inventing a placeholder; (c) the driver's detail fields (`errInfo`, `keyValue` and equivalents) are carried through the value-level scan, not deleted — under the criterion above a document value is diagnosis, and a field whose text the driver already copies into `message` is not duplicated into a second producer; (d) each producer has exactly one authority module and the sink imports it (**SSG-M8**) rather than reading driver properties inline; (e) a runtime-schema rejection of a third-party response is such a family: one producer turns the validator's issues into field path + closed issue code (bounded count, no values or messages), and every "response invalid" raise in the failure branch carries it; a check on the parsed data never shares that condition (`!ok || data.x !== y`) — it raises in its own branch with a closed violation name — a raise naming only the operation loses a contract drift's cause once logs age out. Check reach: "this sink is missing a family's producer" spans the sink, the producer modules and the family set, so set completeness is a review obligation; what is locked mechanically is the inverse — only closed-contract producers may reach the sink (**M32**).

**M25** remedy at a flagged CALL SITE — the fix is decided by what the sink's own boundary already writes, and one common shape is not a leak at all. When a check flags a hand-copied `message`/`stack` field, ask first whether the logger boundary already renders the typed throwable it was handed: where it does, the correct fix is deleting the field, not substituting a derived description — substituting duplicates the boundary's own output under a second name and splits one fact across two fields. Example: a client initialisation catch carried `errorMessage` + `errorStack` beside a typed error argument whose sink already expanded name, message and stack; removing both cost no diagnosis. Where the boundary does NOT take a typed throwable (a `warn(message, meta)` surface), the field stays but its value comes from the single root-cause derivation authority — and a fixed diagnostic constant (`'unknown error'`, `'unexpected failure'`) is replaced in the same edit, because a constant makes every event identical and is exactly the defect the derivation exists to remove. Second, a framework-owned state container is not an observability sink. A call-site rule that treats every object escaping a function as an observability surface will flag a UI error boundary storing the throwable in framework state (a `getDerivedStateFromError` return, a `setState` call), which no single-file syntax tree can distinguish from a metadata object; that is a false positive, suppressed in the source with a rule-scoped, reasoned directive and never by editing the rule ([false-positive](../false-positive/README.md)). The obligation before suppressing is to confirm the stored throwable is read only for user-facing copy and never re-enters a log, crash-report or response surface; if it does, it is a genuine finding.

**M25** remedy, third case — the flagged field is a CLASSIFICATION INPUT, and then neither of the two answers above applies: send the registered code, not the text, and re-measure the predicate. Where a hand-copied `message` feeds a *decision* rather than a sink (a recovery branch, a retry choice, a user-affordance switch), deleting it removes the decision and substituting a derived summary keeps an unstable input. The remedy is to carry the registered error code across that boundary — the structural evidence this row already prefers — so the raw carrier never crosses at all, and the boundary's parameter type says `code`, not `message`. Two obligations come with it. (a) Re-measure the predicate against the carrier's construction site before assuming behaviour is preserved. A predicate of the shape `text.includes('<CODE>')` is *permanently dead* wherever the transport builds that carrier from the server's localized user sentence and carries the code in a separate structural field: the substring can never appear, the branch never runs, and nothing reports a rule that silently stopped applying. A raw-text hop is therefore not only a disclosure risk but a place where a business rule can quietly die — which is why "it already works, only the field name is unsafe" must be measured, not assumed. (b) Do not dodge a key-name-based check by renaming the field. Where the check keys on a name (`error`, `message`), renaming the property to something the predicate does not know silences the finding without changing what crosses the boundary; that games the predicate and is worse than an honest, reasoned suppression. Send different data or suppress with a measured reason — never rename to hide.
