**M21** lifecycle corollary: A process that starts background work **MUST** own one process-local lifecycle authority for scheduler handles, datastore bootstrap/retry, in-process debounce timers, and every real in-flight promise that can consume a shutdown-managed resource. An HTTP/request path may remain fire-and-forget from the caller's perspective, but its background promise is still lifecycle-tracked; “fire-and-forget” never means process-unowned. Every tracked promise **MUST** carry a bounded, closed-schema, secret/PII-free work class so a stuck drain is attributable without logging tenant, user, payload, or provider identifiers. Graceful shutdown **MUST** install one monotonic process deadline and every earlier resource/telemetry cutoff before the first shutdown log, callback, abort, scheduler call, close call, or Promise factory is evaluated; passing an already-created Promise to a timeout wrapper is forbidden because its synchronous prefix is outside the bound. It initiates the new-HTTP-intake close first and then, in the same event-loop turn before awaiting HTTP drain, closes the bootstrap/work-factory gate for new background registrations (the one exception is work from a request the HTTP drain is still finishing — see the fire-and-forget paragraph below); that gate transition **MUST** snapshot the bounded work classes/count before later scheduler or drain code can starve, and the gate check **MUST** happen before invoking the Promise factory, never after the work has already started. The same authority synchronously aborts pending retry/debounce delays without a fallback path, stops/destroys scheduler intake, rejects or explicitly skips new intake, and drains every already-started datastore/domain/cleanup promise before closing resources those jobs consume. The lifecycle `AbortSignal` **MUST** be propagated through the canonical scheduler context into long-running loop, provider retry/backoff/fetch, and mutation-fence boundaries; only the exact lifecycle abort reason may become a shutdown-skip result, while lease loss and unrelated failures retain their original failure classification. Cancellation **MUST NOT** manufacture `completed`, `ok`, or equivalent success evidence, and a persistent write may begin only after both the lifecycle signal and the scheduler's ownership fence are revalidated. JavaScript timers cannot preempt a same-thread synchronous callback: every abort listener and scheduler stop/destroy synchronous prefix on this path **MUST** therefore be inventoried and proven bounded/non-blocking; iterative scheduler calls **MUST** yield event-loop control and re-check the monotonic cutoff before each invocation. A same-process timer is therefore not a hard deadline against event-loop/native-callback starvation. The in-process shutdown grace **MUST** be shorter than the platform's stop/drain timeout, so the process finishes its own ordered shutdown before the platform kills it. Where the hosting platform imposes a finite drain window, the lifecycle authority **MUST** arm an event-loop-independent watchdog before any callback/factory/abort/logger work; the watchdog uses an absolute deadline inside the platform window, proves the target is still its original parent before signaling, fails closed on handshake or IPC loss, and is disarmed atomically only after final logger flush. Its emergency evidence is the sole permitted direct-FD lifecycle record: fixed-schema, bounded, secret/PII-free and best-effort; when committed before the terminal signal to avoid teardown loss it **MUST** state only the verified ownership and pending signal intent, never claim that the later signal was already sent. It **MUST NOT** become a second feature logger or a normal-success path. Every Promise awaited inside a critical shutdown phase **MUST** also race the same abort/deadline boundary and re-check it after settlement; an outer timeout that returns while an inner phase stays pending is not terminal phase evidence. Each resource and critical synchronous subphase **MUST** emit a fixed-schema, secret/PII-free started/completed/failed-or-timeout record with monotonic elapsed/remaining evidence; names/counts may be logged only when their safety is part of that closed schema. An abort may cancel a pending delay; work already executing is drained to its real settle point. A scheduler library's callback-level “busy” flag is not proof of drain when callbacks fire-and-forget a longer promise. HTTP and background-runtime drains are a dependency prerequisite: if either fails or times out, report-rendering, browser and datastore clients they may still consume **MUST** remain open; the process reports the typed aggregate, flushes crash/telemetry last, and exits non-zero rather than manufacturing cleanup success. Only after both drains succeed may dependent resources close (independent datastores may close in parallel). The single logger module owns one idempotent shutdown function (not a second feature logging surface): it **MUST** attach the logging library's stream-finish listener before ending the logger, await all transport finish, close the logger, and await stdout/stderr write barriers inside a bounded final reserve before `process.exit`. A logger-routed record written before that await **MUST** describe success as pending logger flush, never “shutdown complete”; clean exit after the awaited finish/close is the completion proof. Logger timeout/failure produces non-zero exit and **MUST NOT** open a raw-console or second-logger fallback. The sum of sequential timeout budgets, counting parallel phases once by their maximum and including crash telemetry plus logger flush, **MUST** stay below both the monotonic process deadline and the platform drain window; the process deadline itself **MUST** retain a positive platform margin. Timeout/flush failure is a typed SYSTEM shutdown failure, not a warning. This authority is process-local lifecycle state, not cross-instance business/cache state, and **MUST NOT** create a second distributed-store client or an in-memory fallback for distributed coordination.

One-shot script processes. An operator or migration script that calls domain services is a process that starts background work: a service may register a tracked promise after its write commits (a notification to a record's owner, say). The script's single exit path therefore drains the SAME inventory — the authority's own bounded stop-and-drain, never a script-local list of pending promises — then closes the datastores it opened, flushes the logger, and only then exits. `process.exit` inside a `.then`/`.catch` ahead of that sequence is the defect: it cuts the in-flight work and also skips any trailing `.finally`.

Fire-and-forget entries and the closed list of untracked `void`. Detached work enters the inventory through one of two shapes, both owned by the lifecycle authority's single detach module so the intake-closed policy is written once: (1) an operation whose every caller is fire-and-forget registers itself at its own entry and returns the tracked promise — callers keep `void op()` and a new caller is inventoried without knowing it; (2) work started inline at a call site (an async IIFE, a promise chain) is handed to the detach helper as a factory. Work registered from inside a request the HTTP drain is still finishing is admitted until that drain settles, and the background drain does not conclude before it: the process agreed to finish that request, so its promised effect (a post-response idempotency completion, a notification the response reported) is not dropped because the gate closed first; the work receives the already-aborted shutdown signal. Without this window every mutation finishing during the drain skips its completion, and after lease expiry a same-key retry by a client whose response was lost re-runs the mutation. Otherwise both skip the work when intake is already closed and record that skip as a WARN (never as success), both route an unclassified rejection to the background failure boundary instead of the unhandled-rejection path, and both run the work with the request clock removed, because no client waits for it. An untracked `void` is acceptable only for: the terminal crash or shutdown path itself; a settle or handled-rejection handler attached to a promise that is awaited elsewhere; a lease heartbeat whose owner's stop awaits the in-flight pulse; work the HTTP response still awaits; the deadline loser of a request-owned flight, bounded by its own deadline re-checks ([**BHE-M10**](../backend-http-efficiency/outbound-call-time-budget.md)); an expression that is not a promise; a call whose callee registers itself. A static untracked-`void` rule would need many reasoned suppressions and still miss a promise stored in a variable and started later, so this list is held by review and the shared detach helper rather than by a source check alone.

**M21** durability corollary: A detached in-process continuation (fire-and-forget promise, in-memory queue or channel) **MUST NOT** be the only carrier of a durable consequence of a committed write. Such a consequence **MUST** be recorded as a durable intent in the same write or transaction as the change that owes it (an intent field on the written document, or an outbox row) and **MUST** be re-taken by a scheduled worker that runs it idempotently and clears the intent compare-and-set, so a newer intent written meanwhile survives; the post-response run is only its first attempt. Every detach site **MUST** declare which case it is — the intent and the job that re-takes it, or why its loss is tolerable (a signal, a stamp the next request rewrites, a state the user can see and act on) — and the detach entry takes that declaration as a required parameter, so an undeclared site does not compile. Reason: graceful drain runs only on an orderly stop; a crash, out-of-memory kill or forced restart loses every in-process continuation with no record, and nothing ever retries it.
